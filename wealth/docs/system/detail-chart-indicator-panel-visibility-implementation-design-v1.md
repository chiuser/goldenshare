## 1. 交付范围

股票和指数详情页的日线图及现有分钟图，都通过底部 `VOL`、`MACD`、`KDJ` 按钮独立控制成交量、MACD、KDJ 副图。分钟线在现有本地开发环境验收，频率由页面现有能力决定。视觉依据是管理员确认的标签条和页面现有样式，继续使用当前高亮样式、字体和布局尺寸。

| 编号 | 已确认的行为 |
|---|---|
| R1 | 三个按钮独立。点亮时展示副图，点灭时整块收起，标题、读数、坐标、标注、图形及副图内控件随之隐藏。三项可任意组合，重新点亮即恢复。 |
| R2 | K 线、MACD、成交量、KDJ 按现有顺序排列。保留的副图从独立底轴上缘往上紧贴排列。标题和可见绘图区与同视口全开时等高。隐藏 KDJ 时，MACD 和成交量整体下移，K 线获得 KDJ 的可见内容高度。全关时 K 线占满底轴上方区域。图表外框、底轴和标签条位置固定。 |
| R3 | 同一周期内切换副图时保留当前可见 K 线范围、缩放和主图指标。日线和分钟线各有一条独立底轴，固定在标签条上方、最下方可见图的下方。三项全关时底轴在 K 线下方，缩放按钮留在主图右下角的时间轴上方。 |
| R4 | 首次打开三项全亮。同一标的切换周期、数据加载或重试时沿用选择。换标的或刷新页面后恢复全亮。 |
| R5 | 两个日线标签条保留原有顺序、均线、BOLL、趋势通道及成交额的行为。股票分钟图在现有底部轨道加入三个按钮，指数分钟图在同一条标签栏加入三个按钮并保留均线、BOLL 和状态提示。 |
| R6 | 交互只改变显示，行情和指标继续走现有请求、计算和字段映射。分钟线入口、运行配置、空态和错误提示沿用现行行为。 |

副图的高度以全开时实际可见的副图内容为基准，包括标题和绘图区。现有底轴占用的空间单独计入，保持底轴高度和整个工作台高度。隐藏 KDJ 后，成交量图贴在独立底轴上方，画柱子的高度保持原样。主图 Tooltip 和右侧技术信息属于各自区域，副图开关只作用于对应副图。

## 3. 设计与影响面

- 每个详情页持有一份当前标的的开关状态，并传给日线与分钟线。状态只在页面内存。切换周期继续复用页面状态，换标的只重置这份状态。按钮的高亮和副图显示读取同一份状态。
- 四个图表适配组件保留自己的标签排列和业务行为，复用同一个副图按钮。共享图表只调整纵向布局，保留四个图表实例和原有同步。日线继续使用共享日期轴，分钟线继续从原 KDJ 图实例绘制底轴。KDJ 点灭时仅保留底轴条，KDJ 的标题、读数、图形和价格刻度一起收起。底轴仍在原位置，其他图的绘图区高度保持原样。
- 现有请求、响应、指标计算、权限、分页、分钟线能力和图表数据标识保持原口径。可见时间范围、横向拖动、十字线联动、主图纵轴和图层由共享图表现有逻辑继续处理。影响范围在 `wealth` 的两个详情页、四个图表适配组件、共享图表和对应测试。
- 实现只处理三个确定的键和一次点击的取反。状态用现有页面生命周期管理，沿用现有数据就绪、失败和清理流程。右侧价格区宽度、首尾时间和可见根数只做前后对照验收。宽度和范围仍交给现有逻辑，禁止为未复现的变化加锁宽、拦回调、恢复范围或延时逻辑。

## 4. 性能与中断

一次点击只变更一个副图的显示状态。状态大小以现有三个副图为上限，布局涉及四块图和独立底轴。在行情数据未变化时，点击新增行情请求、图表实例、序列数据装载和业务写入均为零。主图依现有尺寸观察流程重绘。开关不新增指标计算流程，页面重新渲染仍会执行已有的渲染逻辑。这里是根据现有结构推导的增量约束，实际布局和请求以浏览器验收为准。

点击没有后台任务或待提交数据。分钟切换期间加载失败，保留当页选择并继续使用现有错误和重试入口。刷新即回到三项全开。开发中断后从当前代码与测试继续，验收仍使用每页一只已有数据标的、现行页面请求窗口和缓存路径。若出现副图遮挡、范围漂移或额外请求，先在同一视口和样本复现并修正，验收失败不进入交付。若需撤回实现，以该次前端变更为单位处理，页面数据和配置无需恢复。

## 5. 开发和验收

1. **Figma 交互审阅已通过。** 以股票和指数日线、分钟线的现有图表和标签为基准，核对全亮、隐藏 KDJ、隐藏中间副图、全部关闭及恢复，以及同一标的跨周期沿用选择。审阅稿作为本轮交互基准。
2. **实现前量测和复核已完成。** 在本机 Chrome 以 `1600 × 1200` 和 `1360 × 1200` 量测股票和指数的日线、5 分钟线。两档布局的分配比例与现行 CSS 一致，日线日期轴 `24px`、分钟刻度画布 `28px`、标签条 `34px`。实测可作为实现和开发后验收的全开基线。[量测记录](./detail-chart-indicator-panel-visibility-low-level-design-v1.md#61-编码前量测记录)
3. 按 LLD 接通页面状态、按钮、共享布局和独立底轴。实现完成后逐项核对 R1～R6。
4. 执行受影响测试、Wealth 类型检查和构建。在本地用真实响应驱动股票、指数的日线与分钟图，记录切换前后布局、当前时间范围和网络。四类图表、跨周期保留及换标的重置均通过后再交付验收。

阶段边界为 Figma 交互审阅、当前页面量测与方案及 LLD 评审、前端开发、浏览器验收。Figma 表达交互和尺寸关系，开工量测以当前真实页面为准。

## 6. 通用开发原则对照

| 原则 | 本次落点与检查 |
|---|---|
| 单一事实源 | 行情沿用现有响应。按钮和副图使用同一份页面选择。真实页面核对字段与可见结果。 |
| 契约先行 | R1～R6 和 LLD 固定交互与前端参数，现有 API 原样消费。 |
| 配置一致 | 沿用分钟线现有本地配置，开关只有页面内存状态。 |
| 默认明确 | 全亮、切周期保留、换标的和刷新重置，覆盖自动化与浏览器验收。 |
| 顺序确定 | 图表顺序由共享组件固定，标签保留各现有位置。用隐藏 KDJ 和隐藏中间成交量验证。 |
| 性能预算 | 按第 4 节记录额外请求、实例及序列装载为零。 |
| 状态与异常 | 继续使用现有模块提示和重试，验收 Loaded、Partial 和错误路径。 |
| 用户可见结果 | 检查整块显隐、底部紧贴、正确点亮、时间轴和浏览位置。 |
