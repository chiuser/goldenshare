## 1. 交付范围

股票和指数详情页的日线图及现有分钟图，都通过底部 `VOL`、`MACD`、`KDJ` 按钮独立控制成交量、MACD、KDJ 副图。分钟线在现有本地开发环境验收，频率由页面现有能力决定。视觉依据是管理员确认的标签条和页面现有样式，继续使用当前高亮样式、字体和布局尺寸。

| 编号 | 已确认的行为 |
|---|---|
| R1 | 三个按钮独立。点亮时展示副图，点灭时整块收起，标题、读数、坐标、标注、图形及副图内控件随之隐藏。三项可任意组合，重新点亮即恢复。 |
| R2 | K 线、MACD、成交量、KDJ 按现有顺序排列。保留的副图从独立底轴上缘往上紧贴排列。标题和可见绘图区与同视口全开时等高。隐藏 KDJ 时，MACD 和成交量整体下移，K 线获得 KDJ 的可见内容高度。全关时 K 线占满底轴上方区域。图表外框、底轴和标签条位置固定。 |
| R3 | 同一周期内切换副图时保留当前可见 K 线范围、缩放和主图指标。日线和分钟线各有一条独立底轴，固定在标签条上方、最下方可见图的下方。三项全关时底轴在 K 线下方，缩放按钮留在主图右下角的时间轴上方。 |
| R4 | 首次打开三项全亮。同一标的切换周期、数据加载或重试时沿用选择。换标的或刷新页面后恢复全亮。 |
| R5 | 两个日线标签条保留原有顺序、均线、BOLL、趋势通道及成交额的行为。股票分钟图在现有底部轨道加入三个按钮，指数分钟图在同一条标签栏加入三个按钮并保留均线、BOLL 和状态提示。 |
| R6 | 交互只改变显示，行情和指标继续走现有请求、计算和字段映射。分钟线入口、运行配置、空态和错误提示沿用现行行为。 |

副图的高度以全开时实际可见的副图内容为基准，包括标题和绘图区。现有底轴占用的空间单独计入，保持底轴高度和整个工作台高度。隐藏 KDJ 后，成交量图贴在独立底轴上方，画柱子的高度保持原样。主图 Tooltip 和右侧技术信息属于各自区域，副图开关只作用于对应副图。

## 3. 设计与影响面

- 每个详情页持有一份当前标的的开关状态，并传给日线与分钟线。状态只在页面内存。切换周期继续复用页面状态，换标的只重置这份状态。按钮的高亮和副图显示读取同一份状态。
- 四个图表适配组件保留自己的标签排列和业务行为，复用同一个副图按钮。共享图表只调整纵向布局，保留四个图表实例和原有同步。日线继续使用共享日期轴，分钟线继续从原 KDJ 图实例绘制底轴。KDJ 点灭时仅保留底轴条，KDJ 的标题、读数、图形和价格刻度一起收起。底轴仍在原位置，其他图的绘图区高度保持原样。
- 现有请求、响应、指标计算、权限、分页、分钟线能力和图表数据标识保持原口径。可见时间范围、横向拖动、十字线联动、主图纵轴和图层由共享图表现有逻辑继续处理。影响范围在 `wealth` 的两个详情页、四个图表适配组件、共享图表和对应测试。
- 实现只处理三个确定的键和一次点击的取反。状态用现有页面生命周期管理，沿用现有数据就绪、失败和清理流程。右侧价格区宽度、首尾时间和可见根数只做前后对照验收。宽度和范围仍交给现有逻辑，禁止为未复现的变化加锁宽、拦回调、恢复范围或延时逻辑。

## 4. 性能与中断

一次点击只变更一个副图的显示状态。状态大小以现有三个副图为上限，布局涉及四块图和独立底轴。在行情数据未变化时，点击新增行情请求、图表实例、序列数据装载和业务写入均为零。主图依现有尺寸观察流程重绘。开关不新增指标计算流程，页面重新渲染仍会执行已有的渲染逻辑。这里是根据现有结构推导的增量约束，实际布局和请求以浏览器验收为准。

点击没有后台任务或待提交数据。分钟切换期间加载失败，保留当页选择并继续使用现有错误和重试入口。刷新即回到三项全开。开发中断后从当前代码与测试继续，验收仍使用每页一只已有数据标的、现行页面请求窗口和缓存路径。若出现副图遮挡、范围漂移或额外请求，先在同一视口和样本复现并修正，验收失败不进入交付。若需撤回实现，以该次前端变更为单位处理，页面数据和配置无需恢复。

## 7. 量化结构实施方案

依据[量化结构需求方案](detail-chart-quantitative-structure-requirements-v1.md)。第 1–6 节提供原布局和交互基线，本节覆盖新增入口、三栏上限与识别展示分离。具体实现及验收见 [LLD 第 8 节](detail-chart-indicator-panel-visibility-low-level-design-v1.md#quantitative-structure-lld)。

### 7.1 页面行为

| 场景 | 已确认的行为 |
| --- | --- |
| 指数标签 | 在已加载图表的 KDJ 标签之后显示「量化结构」。本机已开通识别的指数及周期可以点击，默认点灭。未开通的指数、周期或环境仍显示标签，置灰且不可点击。 |
| 股票标签 | 在现有日线、分钟图的 KDJ 标签之后放置默认点灭的可点击占位。点击后页面保持原样。 |
| 三栏上限 | 默认显示成交量、普通 MACD、KDJ。随时可关闭已显示的副图。已有三栏时，点击未开启的可用指标，提示「最多展示3个技术指标，请取消一个后再打开」。关闭任一项后可打开另一项。按当前实际展示的副图计数。 |
| 副图位置与样式 | 从上到下为 K 线、普通 MACD、量化结构、成交量、KDJ，按当前选择收起相应位置。量化结构沿用 MACD 的绘图和读数样式，标题显示「量化结构(12,26,9)」。底轴、标签条与原图表浏览范围沿用现行规则。 |
| 悬停与预判 | 打开量化结构时，同时间的识别摘要沿用现有主图悬停位置。关闭时识别摘要一同收起，原行情悬停继续工作。右侧「下一根预判」由现有技术面页签逻辑独立驱动。 |

### 7.2 影响面与数据

- 两个详情页仍管理本标的的副图选择，四个日线和分钟图入口共用开关与标签样式。股票入口和未开通的指数入口使用各自的显示状态。指数可用时，共享图表在普通 MACD 下方接入一个独立副图，参与原有横向联动，曲线、标记、标题读数和纵轴都取本副图的数据。
- 普通 MACD 继续消费原行情接口的指标字段。量化结构直接使用已有指数识别接口返回的首批 `points` 和 `events`，沿用现有识别结果与 K 线时间的对应关系。普通 DIF、DEA 和柱值的比较已从日线和分钟共用的前端校验中删除，已有测试和本机接口验证见 LLD 第 8.3 节。新增副图直接使用这份结果。原 r4.1 的识别和预判继续使用现有数据源、算法、权限及配置。
- 上证普通日线历史续页沿用现有链路。量化结构请求和绘图范围以首批为限，历史续页对应的副图区域留空。识别加载中、空数据、滞后、失败和重试都在新副图内呈现。切换标的、周期、日期或核验模式时按当前窗口接收响应。
- 进入日线或切换到支持的分钟周期时，首屏从当前行情的最新一根向前显示。量化结构随共享图表移动，由共享图表处理拖动和缩放。识别回包前，量化结构中只有日期的空白序列不能改变其它图表的显示范围。

### 7.3 请求、失败与验收

复用现有首批识别接口、请求时机、调度、超时和重试范围。分钟线仍按现有顺序加载行情、普通技术指标和识别结果。点击标签带来的新增请求、实例创建及序列数据重装均为零。允许首次创建当前可用指数图表时建立量化结构宿主，允许首批识别回包和普通历史插入时更新其序列。数量约束来自实际窗口和图表结构，具体计算与中断续验见 LLD。

复用原三栏的页面实测和布局基线，本轮新增的行为以已确认的需求为准。完成方案及 LLD 评审后，依次核对页面按钮、共享绘图、识别接口回包与真实页面的同时间读数。若出现错位、串图、额外请求或显示超栏，按原窗口复现并修正后重验受影响用例。撤回时按本轮前端变更整体处理。

## 8. 主图下拉菜单移除与 MA 显隐补充

### 8.1 目标与依据

股票和指数详情页的主图指标统一从下方标签条操作，左上角不再保留第二个选择入口。底部 MA 标签沿用页面现有「均线」名称，点亮时同时显示均线和左上角对应读数，点灭时两者同时隐藏。

依据管理员本轮需求及已修改的 [股票详情主稿](https://www.figma.com/design/RADlZzREU4lPVviYfkLy6x/Goldenshare-Web?node-id=345-3)、[指数详情主稿](https://www.figma.com/design/RADlZzREU4lPVviYfkLy6x/Goldenshare-Web?node-id=417-2)和[指标显隐评审稿](https://www.figma.com/design/RADlZzREU4lPVviYfkLy6x/Goldenshare-Web?node-id=2191-419)。2026-11-14 已删除主稿及相关日线、分钟、状态和交互稿中的下拉条背景、文字和箭头，并读回确认其余标题子节点的位置、尺寸、文字、字体和显隐状态未变。Figma 修改证据只证明下拉条删除；MA 的开关、取值和运行过程仍按本节开发验收。

本节更新原 R5 中“保留均线、BOLL 原行为”的适用边界：主图入口及 MA 点灭行为按 R7～R14 执行；原副图规则、历史验收和量化结构规则继续适用。

### 8.4 性能、失败与实施顺序

开关只复用已加载的 K 线和 MA 值，新增行情、指标、趋势、九转、历史请求及业务写入均为零。原副图开关的“序列不重装”预算不套用到本步：现有主图指标切换本来就会更新主图序列；没有历史续页回调的入口还会沿原流程重建图表。按这两种现有路径分别核算，具体数量与序列构造开销见 LLD §9.5，不将其写成零开销。

本步没有后台提交、数据恢复或续跑文件。请求失败与重试沿用当前入口；重试同一工作区不能覆盖明确关闭的选择。开发或验收中断后从未通过的用例继续，重开页面按原默认和原有首屏请求恢复。真实验收只用已有页面有界窗口，历史用例只触发一次现有续页；若因中断重开，只重复对应页面的原请求流程。没有本轮主图切换的耗时实测，不写毫秒承诺或另设数据读取上限。

管理员已确认本节与 LLD 第 9 节，并授权先提交文档，再实施三个入口及测试，随后执行类型检查、相关回归、全量前端检查和真实页面核验。本次不部署，不把 Figma 删除或原副图验收当作本步完成依据。

### 8.5 开发原则对照

| 原则 | 本步落点 |
| --- | --- |
| 单一事实源 | 标签、线和读数由同一主图选择控制，数值仍来自同一根接口 K 线。 |
| 契约先行 | R7～R14 与 LLD 定义局部空选择；HTTP 与共享图表参数合同沿用。 |
| 配置一致 | 没有新增配置或存储，只保留工作区内选择。 |
| 默认明确 | R12 保留现行默认；明确关闭与未操作分开。 |
| 顺序确定 | 原标签顺序、七项 MA 顺序与 K 线时间对应规则保持原样。 |
| 性能预算 | LLD §9.5 分别核算现有实例更新、重建与中断复验。 |
| 状态与异常 | 原加载和失败提示继续使用，迟到回包不能重新点亮 MA。 |
| 用户可见结果 | 验收菜单消失、均线与数值一起开关、无缺值伪零，以及原浏览范围和其它图层。 |
