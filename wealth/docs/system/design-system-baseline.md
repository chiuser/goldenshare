# 财势乾坤行情系统 Design System v1

## 1. 目的与适用范围

本文是财势乾坤行情系统当前唯一的系统级视觉基线。它把已经落地并经页面验收的市场总览、股票详情页，以及历史设计资料中仍然有效的设计意图收敛为一套可执行规则，用于后续页面设计、组件开发与视觉验收。

适用范围：`wealth/` 下的用户侧行情页面、共享组件、页面状态与图表交互。

不适用范围：运营后台 `frontend/`、数据基座页面、后端 API 契约、历史参考资料中的旧字段或旧路由。

## 2. 事实源与冲突处理

设计资料存在多个历史版本。为避免“按旧稿实现”导致页面漂移，发生冲突时必须按以下顺序决策：

1. 用户最新明确指令。
2. 当前实际页面的 DOM、CSS、共享组件与已经验证的交互行为。
3. 本文与[组件规范基线](./component-guidelines-baseline.md)。
4. 当前评审通过的 Figma、页面级设计文档、implementation design、LLD 与验收账本。
5. `wealth/docs/reference/**` 的 HTML Showcase、Design 文档、组件集合页与 Review 资料。

第 2 项是当前视觉事实源。历史 HTML 和组件集合页可用于补足未覆盖状态、组件意图和视觉细节，但不得覆盖当前实现的尺寸、布局、颜色、交互或组件边界。历史资料中的旧 token、旧 API、旧页面组合不进入新代码。

## 3. 设计定位

财势乾坤是深色、高信息密度的 A 股行情终端，不是普通后台管理界面，也不是营销大屏。

设计关键词：专业、克制、可读、可信、紧凑、连续工作流。

必须遵守：

- 深色金融终端风，层次来自暗色材质、细边框、有限金色强调，而非大量发光或渐变边框。
- 红涨绿跌是 A 股固定语义，不可反转。
- 信息优先于装饰；在相同空间内优先保证数字、标签、趋势与状态可读。
- 页面保留明确的内容密度，不扩大字体或留白以做成“大屏”。
- 不以颜色单独传达状态。关键状态需同时有文字、数值、图例、边框或图形差异。

禁止：普通 SaaS 卡片风、浅色默认皮肤、紫色主视觉、霓虹泛滥、凭个人审美重排已验收模块、用行情红充当系统错误主色。

## 4. Foundations

### 4.2 行情方向语义

| 业务含义 | 展示类 | 颜色 |
|---|---|---|
| 上涨、正涨跌幅、正涨跌额、净流入、涨停 | `.up` | 红色 |
| 下跌、负涨跌幅、负涨跌额、净流出、跌停 | `.down` | 绿色 |
| 平盘、零值、无方向 | `.flat` | 中性灰白 |
| 数据缺失、停牌、不可用 | 文字占位 + 次级色 | 不伪造行情方向 |

`success`、`error` 等通用 UI 语义不可替代行情语义。系统成功可用绿色，系统错误可用错误红，但二者必须在组件文案和上下文上与行情数据区分。

### 4.3 字体与数字

| 类型 | 当前 token | 规则 |
|---|---|---|
| 正文与中文 | `--cs-font-family-base` | 系统字体、`SF Pro Display`、苹方、微软雅黑等回退 |
| 行情数值 | `--cs-font-family-number` | `DIN Alternate` 优先，`Roboto Mono`、`SF Mono`、`JetBrains Mono` 回退 |
| 数字展示类 | `.num` | 必须启用 `font-variant-numeric: tabular-nums` |

数值、百分比、时间、代码、坐标轴、表格数列优先使用 `.num`。标题、中文标签、解释文案使用基础字体。不要把书法或营销字体带入行情主界面。

### 4.4 间距、圆角与阴影

正式 token：`8 / 10 / 12 / 16 / 20 / 24px`，分别对应 `--cs-space-*`。新布局先从这些尺寸组合，而非随手使用任意值。

| 元素 | 基线 |
|---|---|
| 一级 Panel | `12px` 圆角，`--cs-shadow-panel`，细边框 |
| 内部 Card / 指标卡 | `10px` 圆角，轻边框 |
| 常规模块间距 | `12px` |
| 页面横向安全边距 | 市场总览当前为 `18px` |
| 页面纵向起始边距 | 市场总览当前为 `14px` |

任何新增值如确有必要，应先在页面级设计中说明原因，并补回 token，而不是只写在单个 CSS 选择器里。

## 5. 页面模式

财势乾坤已经形成两种不同、但共享基础视觉的页面模式。不能把其中一种错误套用到另一种。

### 5.1 市场总览：可纵向浏览的终端仪表盘

- 内容容器：最小宽度 `1460px`，最大宽度 `1840px`。
- 页面可随模块纵向扩展和滚动；不强制固定 `100vh`。
- 模块采用 12px 间隔的组合网格，Panel 内保持高信息密度。
- 常见组合包括：新闻双列、总结与主要指数双列、三列数据模块、榜单/板块矩阵。
- 页面模块独立加载：单模块 loading、empty、error、delayed 不得阻塞或回填其他模块。

### 5.2 股票详情：固定视口交易工作台

- `100vh`、最小宽度 `1180px`、页面级不滚动。
- 顶部共享栏之后是紧凑的面包屑/操作带、周期工具栏、左侧图表工作台、右侧固定信息栏。
- 左右比例以当前 CSS 为事实：图表主区约 `76fr`，右侧信息栏约 `24fr`，右侧最小 `344px`。
- 图表工作台四区比例为主图 `44fr`，MACD、成交量、KDJ 各 `17fr`；不能因文案或某个图表缩放破坏四区对齐。
- 详情页右侧信息栏与图表区独立滚动/裁切规则应遵循当前页面，不可按普通内容页随意延长。

## 6. 共享框架与通用组件

具体组件路径、职责和交互见[组件规范基线](./component-guidelines-baseline.md)。本节只定义视觉和页面层级。

### 6.1 TopMarketBar

所有行情页面复用同一个 `TopMarketBar`，不得复制一套 Header。

- 高度固定为 `56px`，左右内边距 `18px`。
- 结构：品牌区、系统导航、滚动指数 ticker、用户入口。
- 品牌图标当前为 `36 x 36px`，标题 `16px`，副标题 `11px`，两行与图标垂直居中。
- ticker 在宽度不足时以从右向左的慢速跑马灯完整呈现；鼠标 hover 暂停；`prefers-reduced-motion` 时停止动画并允许横向查看。
- 顶栏不可因页面局部控件、时间或状态文本被撑高；不再额外堆叠已收盘、刷新延迟等非必要信息。

### 6.2 Panel 与 Card

Panel 承担页面一级分区，Card 承担同一模块内的原子事实或可点击实体。

- Panel 背景保持暗蓝黑，不使用纯黑洞式块面。
- Card 必须比 Panel 略亮，边框可见但克制。
- 标题、帮助入口、右侧切换/状态在同一行对齐；标题不得被状态文字挤压为换行。
- 金色只用于 active、品牌、重点入口和有限的最高层级强调；不能把整块 Panel 涂成重金色。

### 6.3 指标卡和数字

- 标题使用次级色，主值使用数字字体并满足红涨绿跌。
- 副值用于日期、环比、比例、单位或简短事实；不在 card 内堆入解释段落。
- 同组指标卡必须统一高度、左右对齐、数字基线稳定。
- 缺数值显示 `--` 或明确状态，禁止用模拟数字填充。

### 6.4 切换、Tabs 与按钮

- `RangeSwitch` / Tab 为紧凑胶囊边框控件，active 使用品牌弱底色、金色文字和金色边框。
- 默认态使用暗底、次级文字与默认边框；hover 仅轻微提亮。
- 不可用项保留原型可见性时，应标出 disabled/unsupported，点击以轻量 toast 说明，不假装已实现。
- 功能切换必须实际切换所控制的数据或图层，不允许只有 active 外观变化。

### 6.5 表格、榜单与实体行

- 表格/排行榜以行密度优先，表头、数列、代码使用对齐规则和 tabular numbers。
- 股票、指数、板块实体必须有清晰主体标识，名称与代码不可混成一个无语义文本块。
- 可跳转的股票行遵循“模块上报 `tsCode`，页面统一导航”的规则；不在模块中直接拼路由。
- 行 hover 只能轻提亮，不使用大型遮罩或跳动动画。

## 7. 图表与数据可视化

### 7.1 通用图表规则

- 纵轴必须符合数据语义。计数、金额、成交量等非负量不得显示负刻度。
- 同一模块内并列图表的网格、绘图区左右边界、轴标签宽度和线条密度必须对齐。
- 坐标轴、网格、零轴、标签分别使用 `--cs-color-chart-*` token；不要把数值主色当作网格线。
- 图例、tooltip、交互标记与数据区域不得遮挡重要数据，且必须在容器边缘自动避让。
- 用有限色数表达有限系列；颜色不能仅靠视觉好看决定，必须和图例、数值文字保持一致。

### 7.2 市场总览图表

- 既有 SVG/CSS 图表保持目前的轻量实现；新增复杂可交互图表先在页面方案中说明渲染方式和验收方式。
- 涨跌分布的“涨跌家数 / 涨跌分布”属于内容切换，不是时间范围切换；`1m/3m` 可以保留为 API 历史数据键，但不得继续出现在该模块按钮文案中。
- 分桶柱状图数字应置于对应柱顶上方固定视觉距离，不能被等高容器顶部对齐而脱离柱体。

### 7.3 股票详情图表工作台

当前详情页的图表引擎为 `lightweight-charts`，外层由 React/CSS 负责工作台编排与可控覆盖。它是既定实现，不受历史“禁止重型图表库”说明约束。

- 主图、MACD、成交量、KDJ 的 x 轴必须同步。
- 十字线的垂直线应跨四个图表区，所有 pane 在同一时间点显示对应标记。
- 十字线为细密虚线，不使用粗长稀疏虚线。
- 鼠标离开图表工作台后，tooltip、十字线与所有同步标记必须一起消失。
- tooltip 需要在 K 线绘图区内部根据鼠标所在半区避让：接近右边时固定展示在绘图区左侧，接近左边时展示在绘图区右侧；不是机械地跟在十字线旁边。
- 右侧价格轴/指标轴预留宽度必须在四个 pane 一致，图表实际绘图区右边界与右上角设置按钮对齐。
- 日线时间轴在数据较多时采用“最左年份 + 月份标记”密度；十字线所在时间必须以标签形式展示。
- 底部时间轴使用半透明渐变层，不可用实心遮罩盖住 KDJ 或其他底部指标。
- 主图 MA 系列颜色固定：MA5 金色、MA10 蓝色、MA20 紫色、MA30 青色、MA60 橙色、MA90 粉红色、MA250 灰白色。系列标签文字颜色与曲线一致。

## 8. 状态、反馈与动效

### 8.1 四态和时效状态

每个数据模块至少要可表达 loading、empty、error、loaded；若数据日期未达到该模块期望日期，还要表达 delayed/partial。

- loading：使用局部 skeleton 或局部占位，不展示旧 mock 数据。
- empty：说明暂无数据的业务原因，不伪装成错误。
- error：使用系统错误色和可读原因，不使用行情方向色。
- delayed：显示数据时效事实；页面级状态由模块状态聚合，但 debug 细节只在开发/调试模式展示。
- partial：部分模块延迟或缺失时使用；所有关键模块延迟才显示 delayed。

### 8.2 Toast、抽屉和悬浮层

- 首版未落地功能用轻量 toast 反馈，不改变页面布局。
- 抽屉、popover、tooltip 必须有关闭方式：关闭按钮、遮罩或 ESC 视交互类型而定。
- 悬浮层必须高于容器内容、低于全局阻断层；避免因 `overflow` 被裁切。
- 任何悬浮层都要考虑靠近四边时的方向翻转和可见区域。

### 8.3 动效

- 交互 transition 以 `160ms` 左右的短反馈为基线。
- 指数 ticker 和新闻滚动属于信息可达性功能，不是装饰；均需 hover 暂停和 reduced-motion 降级。
- 不得让闪烁、跳动、循环高亮干扰数值阅读。

## 9. 响应式与可访问性边界

- 当前用户侧行情系统以正式宽桌面终端为基线，`body` 最小宽度为 `1460px`。
- 小于该宽度时允许横向查看，不得偷偷压缩为另一个不经设计的移动端布局。
- 可点击元素要使用真实 `button`/链接语义，具备键盘焦点和可读 label。
- 图表、ticker、新闻滚动必须尊重 `prefers-reduced-motion`。
- 颜色不可作为唯一信息来源；涨跌方向应有符号、文字或位置辅助。

## 10. 新页面设计与验收门禁

新页面或新模块在进入编码前，必须在评审通过的 Figma/页面设计、implementation design 或 LLD 中明确：

1. 使用哪一种页面模式，或为什么需要新的页面模式。
2. 使用哪些现有 token 和共享组件，是否存在必须新增的 token/组件。
3. 数据状态、延迟状态、空态和错误态的视觉与交互。
4. 图表坐标语义、系列颜色、tooltip/crosshair 或等价交互。
5. 与市场总览、股票详情的共享部分是否保持一致。

视觉验收至少覆盖：默认态、hover、active、disabled、loading、empty、error、delayed，以及有数据/无数据两种边界。高保真任务必须先量测当前实际页面，再建立或更新设计稿；不能凭旧 HTML 估算尺寸。
