## 1. 产品口径

在股票详情页和指数详情页的日 K 图表底部指标栏各增加一个「单阳测顶」按钮。用户在弹窗中选择测算目标和交易日，页面读取当前标的的日线行情，带入可修改的默认系数，点击「计算」后显示目标价或目标点位。股票详情页同时清理当前不可用的指标占位。

| 当前详情页 | 单阳测顶默认系数 | 单阴测底默认系数 |
| --- | ---: | ---: |
| 所有指数 | **0.90** | **1.10** |
| 所有个股 | **0.85** | **1.15** |

四个值是本期产品决定，匹配依据只有证券类别和测算方式。此前讨论的指数分组、股票类型、波动率分档和参数校准均退出本期。日期和测算方式由用户选择，阳线大小、阴线大小、阶段高低位及涨跌方向由用户自行判断。入口只打开弹窗，不产生新的指标副图或主图图层。

## 2. 入口和弹窗

1. 按管理员截图，入口放在图表日期轴下方的底部指标栏，排在现有指标之后。「单阳测顶」沿用未选中指标标签的文字样式，透明底、无可见外框。股票和指数使用同一个测算弹窗。该按钮是打开工具的操作，不占副图名额，也不切换已选指标。
2. **只有股票和指数的日 K 图表显示测算入口。** 周 K、月 K、分钟 K 和分时的指标栏均不显示这个按钮。每次测算读取用户所选日期的日线。
3. 弹窗默认选中「单阳测顶」，标题随「测算目标」切换为「单阳测顶」或「单阴测底」。当前股票或指数的名称与代码位于标题右侧的居中区域，名称在上，代码在下且字号更小。交易日由用户选择，系数输入框可编辑。切换目标带入对应默认系数，同一目标下换日期保留用户已经输入的系数，关闭重开后恢复初始值。
4. 选定日期即读取行情。「日线行情」展示开盘价、最高价、最低价、收盘价、涨跌幅、前一交易日收盘价及其日期。股票行情卡右上角标明「前复权」。用户可修改系数，点击「计算」时使用输入框里的值。日期、测算目标或系数变化后，右侧结果恢复为「—」，直到再次计算。尚无结果时，单位随数值一起留空。
5. 换标的或离开详情页时关闭弹窗。弹窗支持关闭按钮和 Esc，关闭后焦点返回入口。打开、关闭和计算均保持底部时间轴、当前图表范围、缩放和图层选择。

## 3. 行情口径与公式

| 内容 | 来源与含义 |
| --- | --- |
| 所选日开盘、最高、最低、收盘 | 所选日对应的 `bars[].open/high/low/close`。股票使用与详情页日 K 一致的前复权价格，指数沿用现有日 K 点位。 |
| 当日涨跌幅 | 同一行的 `bars[].changePct`，沿用详情页日 K 涨跌幅的口径与展示。 |
| 所选日收盘价 \(C\) | 交易日严格等于用户所选日期的日 K 的 `close`。 |
| 上一交易日收盘价 \(C_1\) | 同一回包中该标的上一根日 K 的 `close`。这里的上一交易日指该标的上一根有行情的日 K，周末、休市和停牌无日 K 的日期自然跳过。 |
| 系数 \(K\) | 点击计算时输入框中的有限正数。默认值来自第 1 节，无额外上限。 |

**股票必须用同一批前复权 K 线的两个收盘价。** 当前股票接口把前复权开高低收和日线来源的 `preClose` 分别映射，不能直接把 `preClose` 代作上一根前复权收盘价。用两根日 K 的 `close` 也能明确向用户展示前一根 K 线是哪一天。指数沿用同样的取值结构。 [股票日线价格组装](../../../src/biz/services/wealth/market/stock_detail/stock_daily_kline_service.py) · [股票字段映射](../../../src/biz/services/wealth/market/stock_detail/stock_detail_field_mapper.py) · [指数日线查询](../../../src/biz/queries/wealth/market/index_detail/index_detail_kline_query_service.py)

测顶与测底统一使用 \(A=C^2/(C_1\times K)\)。弹窗底部左侧放「计算」按钮，右侧单行显示「前复权目标价：xxxx元」或「目标点位：xxxx点」。标签、数字和单位按垂直中心对齐，沿用 Figma 评审稿原有字号。测顶结果数字用行情红色，测底结果数字用行情绿色。股票价格口径与详情页日 K 一致。用接口原始数值计算，结果按现有详情页价格精度展示，不提前舍入公式输入。

### 3.1 请求与状态

选定日期后调用当前标的对应的已有接口，参数 `period=day`、`tsCode`、`endDate=所选日`、`limit=2`，股票沿用 `adjustment=forward`。两根是计算所需的选定日和上一根日 K。接口允许返回所选日及之前的行情，弹窗只将日期严格命中的行作为所选日。复用原接口鉴权、行情来源、技术指标计算、期限和错误响应。前端计算的目标位仅由行情事实和用户输入生成，属于弹窗即时结果。

| 状态 | 页面行为 |
| --- | --- |
| 尚未选日、正在读取 | 行情卡分别显示「选择交易日后查看行情」和「正在读取日线行情…」，计算按钮不可用。 |
| 选中周末、休市、停牌日或未回包的日期 | 提示「所选交易日暂无日线行情」。已有更早的日 K 不能替代所选日。 |
| 已有当日行情，上一根日 K 或计算所需收盘价缺失 | 已返回的行情照常展示，缺值按页面现有规则显示，并提示缺少哪项计算所需行情。 |
| 系数为空、无法解析、不是有限正数，或公式结果超出可表示范围 | 提示输入有效系数，清空测算结果。 |
| 读取失败 | 行情卡显示「日线行情读取失败」及「重试」，重试只读同一日期。快速改日、关闭和换标的时，取消旧请求并丢弃迟到回包。 |

## 4. 股票底部指标栏清理清单

| 处理 | 标签及理由 |
| --- | --- |
| 删除股票日 K、周 K、月 K 中的旧占位标签 | **成交额、大单净量、主力密码、融资融券、陆股通资金、陆股通持股、AI机构活跃度、资金抄底、资金仓位、更多**。这些标签由股票页常量生成，点击只弹出「指标暂未支持」，没有副图或叠加内容。 |
| 删除股票的「量化结构」占位标签 | 股票日 K、周 K、月 K 共用的工作台，以及股票分钟工作台，都把它作为无点击动作的占位。此次清理覆盖这些股票入口。指数仍按当前周期和能力展示原有量化结构入口。 |
| 保留已可用的功能 | `VOL`、`MACD`、`KDJ`、九转序列、均线、`BOLL`、趋势通道，各周期仍以当前入口和能力为准。特别是 `VOL`，虽然早期列表将它标成 `supported: false`，实际渲染使用独立副图开关，可正常显示成交量。 |

旧标签定义来自 2026-05-30 的模拟股票详情页提交 `0318353a7`。股票的「量化结构」占位在 2026-11-10 的提交 `2a82952e0` 加入当前工作台。清理范围只到股票图表底部入口。同名行情字段仍可在原有报价、图表悬停或信息区正常显示，例如股票的成交额。 [股票标签常量](../../src/features/stock-detail/model/stockDetailConstants.ts) · [股票日周月工作台](../../src/features/stock-detail/chart/StockChartWorkspace.tsx) · [股票分钟工作台](../../src/features/stock-detail/chart/StockMinuteChartWorkspace.tsx) · [原量化结构需求](./detail-chart-quantitative-structure-requirements-v1.md)

## 6. 验收

| 验收项 | 通过条件 |
| --- | --- |
| 固定参数与手动覆盖 | 上证指数与至少一个不同指数的默认值均为 `0.90 / 1.10`。两只不同类型股票均为 `0.85 / 1.15`。检查切换方向、换日期与手改后的重新计算，确认实际使用输入框中的值。 |
| 独立手算对照 | 前收 `100`、所选日收盘 `105` 时，指数测顶 `122.50`、股票测顶 `129.71`。前收 `100`、所选日收盘 `95` 时，指数测底 `82.05`、股票测底 `78.48`。系数改成 `1` 后，前一组价格计算结果为 `110.25`。 |
| 真实接口和页面 | 用普通路由对股票和指数各核对一次历史选日，比较当日 `tradeDate/open/high/low/close/changePct`、前一条 `tradeDate/close` 与弹窗显示。股票再核对一个已知除权日，确认两根都取前复权 `close`，且价格与详情页日 K 同日期的行情一致。用一个周末或休市日期验证无当日 K 线时不替换日期，用有界停牌前后样本核对上一根日 K。 |
| 状态与请求 | 覆盖未选日、仅一根日 K、请求失败重试、快速换日、关闭及换标的。核对实际请求数、返回根数、响应体与延迟。只修改系数、方向或重算时，网络面板无新增行情请求。 |
| 底部入口与清理 | 两页日 K 的按钮与截图所示指标栏同一行。切到周 K、月 K、分钟 K 或分时后，测算按钮不出现，切回日 K 恢复。股票清单中的占位按钮不出现在 DOM 中，保留标签能继续显示或切换已有指标。指数原有标签和量化结构开关照常工作。 |
| 图表及浏览器回归 | 对照 Figma 核对动态标题、名称在上且代码更小、左侧计算按钮、右侧单行结果、垂直居中及红绿数字。关闭弹窗后核对原周期、图层、底轴、缩放及可见范围。检查窄窗口、键盘焦点、控制台和网络，并覆盖当前可用的分钟周期。 |

编码后执行 `npm --prefix wealth run typecheck`、`npm --prefix wealth run test` 和 `npm --prefix wealth run build`。组件和页面回归从现有 `StockChartWorkspace.test.tsx`、`StockMinuteChartWorkspace.test.tsx`、`IndexChartWorkspace.test.tsx`、`IndexMinuteChartWorkspace.test.tsx`、`StockDetailPage.test.tsx`、`IndexDetailPage.test.tsx` 切入。真实接口的回归入口为 `tests/web/test_wealth_stock_detail_api.py`、`tests/web/test_wealth_index_detail_api.py` 和 `tests/web/test_wealth_index_detail_dg_kline.py`，另以真实 HTTP 回包驱动浏览器核对页面。验证中断后从未完成的标的和日期继续，单个案例的行情请求规模同上。

## 7. 评审与开发顺序

1. 产品交互已通过评审，以已确认的 Figma 和本方案为准。
2. [LLD](./detail-chart-single-candle-price-target-low-level-design-v1.md)记录代码入口、取数合同、测试和编码门禁。开工前复核日线接口及前端装配的并行修改，并按 LLD 核对两条现有日线接口的有界样本。
3. LLD 评审通过后，按其实施顺序接入共享弹窗、两页日线入口与股票标签清理。按验收表记录实际结果。
