# 财势探查｜ETF 动态技术实施方案 v1

2026-11-26。桌面 Figma、方案及配套 LLD 已确认。第 1 阶段本地后端与 API 已实现，真实 DG 数据对账通过，待管理员确认后进入桌面前端开发。[需求与交互基线](./etf-activity-benchmark-requirement-v1.md) · [第 1 阶段验收记录](./etf-activity-low-level-design-v1.md#8-第-1-阶段验收记录)

## 1. 目标与范围

在 Wealth 财势探查中新增 ETF 动态子页面，由本机 Wealth 后端读取 DG 已落盘的沪深场内 ETF 日线，为每日成交额趋势和最新日线成交额前 50 名提供数据。DG 本机的 ETF 基础信息仅补充名称，交易日历确定日期。全部行情读取范围为本机正式 DG Lake。首期不涉及 Prod 数据集、Tushare 请求、Lake 写入、Dagster 定义或任务执行、实时行情、其他 ETF 页面。

前端交付范围为桌面版。在财势探查增加「ETF 动态」快捷入口，子页左侧是成交额趋势，右侧是前 50 名排行榜。两面板并排、等高，榜单七列同屏，表头保持可见，表体独立纵向滚动。1 个月／3 个月的选择只改变左侧图表，右侧日期、榜单和滚动位置保持一致。

## 2. 当前实现与最小数据读取范围

| 已核对的实现 | 用途 |
| --- | --- |
| `WealthRouter`、`resolveWealthExplorationRoute`、`WealthExplorationShell`、`ExplorationShortcutBar` | 增加精确子路由及快捷卡片，复用现有页面结构。现有 Shell 会读取市场上下文和主要指数。按确认稿，ETF 子页保留顶栏品牌、导航、账户入口和面包屑路径，跳过这两个行情请求和对应的顶部行情及时间状态。 |
| `src/app/api/v1/router.py` 的本地路由装配和 `src/app/web/app.py` 的本地页面访问限制 | App 按环境决定是否挂载接口，并向 Biz 注入行情认证依赖。 |

下列路径均相对于本机正式 DG Lake 根目录 `/Volumes/datasource/data_lake`。

| 读取对象 | 路径、字段和用途 |
| --- | --- |
| **DG ETF 日线（`silver_etf_daily`）** | `silver/quote/etf_daily/trade_date=YYYY-MM-DD/part-000.parquet`。主数据，按交易日和 ETF 代码各一行。读取 `trade_date`、`ts_code`、`amount` 计算每日成交额、均线与两日排名。读取当日 `close`、`pct_chg` 用于现价和涨跌幅。成交额以千元储存，涨跌幅以百分比储存。 |
| **DG ETF 基础信息（`silver_etf_basic`）** | 读取 `silver/basic/etf_basic/snapshot_id=<hash>/part-000.parquet` 的一份快照，用 `ts_code` 关联当日前 50 只，按 `csname → extname → cname` 取第一个非空名称。实际日线文件没有名称列。 |
| **DG 交易日历** | `silver/calendar/trade_calendar/full/part-000.parquet`。按 `exchange=SSE` 读取 `trade_date`、`is_open`、`pretrade_date`，确定开市日、前一开市日与均线窗口。交易日历能区分周末、节假日与应有日线却缺文件的开市日。 |
| **本机 DG 物化元数据** | 按榜单交易日读取 `silver_etf_daily` 的一条物化记录。使用 `goldenshare/basic_silver_uri`、`goldenshare/basic_raw_snapshot_hash` 定位日线实际引用的基础信息快照。仅榜单名称需要这条记录。 |

ETF 纳入范围取自每日银层日线实际记录，包含 DG 已筛选的沪深场内 ETF 类别。ETF 基础信息只补名称，历史样本不按当前上市名单重新筛选。日常查询所需的辅助数据就是一份 ETF 基础信息快照、一份交易日历和一条本机物化元数据。读取过程在本机完成，不访问 Prod、Raw ETF 日线、ETF 分钟线、复权因子或 Tushare。

源依据见 [DG ETF 日线接入方案](../../../../lake_console/docs/design/dagster-etf-daily-data-onboarding-plan-v1.md)、[DG ETF 日线 LLD](../../../../lake_console/docs/design/dagster-etf-daily-data-onboarding-low-level-design-v1.md)、[基金日线成交额单位](../../../../docs/sources/tushare/ETF专题/0127_ETF日线行情.md)。

## 3. 日期、计算与接口

每个请求按上海日期和 DG 交易日历，选取不晚于当天、已有正式 DG ETF 日线文件的最近开市日作为 `tradeDate`。页面始终显示实际日期。当天尚未落盘时可显示上一可用日，已选中的文件若不可读取则按错误处理。用于排名比较的日期固定为 `tradeDate` 的前一开市日。前一开市日文件缺失时显示缺失提示，前一日无单只 ETF 排名时该行使用「—」。比较日期不顺延。

趋势按日期汇总 DG ETF 日线 `amount`，每 1 千元转换为 1,000 元。区间以实际 `tradeDate` 往前回推 1 或 3 个自然月，含起止日中的开市日。用每个交易日的合计成交额计算含当日的 5 日和 20 日简单移动平均值，窗口内所有开市日都具备有效成交额时才返回对应均线。3 个月开始日前最多读 19 个开市日作为均线计算所需的前序数据。缺失开市日的成交额为 null，实际成交额为零时返回 0。图表用断线表示缺失。

当前日和前一交易日分别在各自的全体有效 ETF 日线中按 `amount DESC, ts_code ASC` 编连续名次，随后截取当前日前 50 行。每行的名次变化为「前一交易日排名 − 今日排名」。正、负、零分别表示上升、下降、持平，前一日无排名时返回 null。名称使用同日物化引用的 ETF 基础信息文件，按中文简称、扩位简称、全称依次取第一个非空值。名称单独左连接，取不到时保留有日线的 ETF 和它的原排名。

榜单列序按已确认 Figma，依次为「今日排名」「ETF 代码」「ETF 名称」「现价（元）」「涨跌幅」「成交额（亿元）」「较前一交易日」。排行榜现价和涨跌幅分别取当日日线 `close` 和 `pct_chg`。后端按原百分比数值返回涨跌幅，例如 `-1.57` 表示下跌 1.57%。前一日文件缺失时当日现价及涨跌幅照常展示。价格涨跌方向与名次方向各自表达。

新增本地页面 `/wealth/exploration/etf-activity` 和 `GET /api/v1/wealth/market/etf-activity`。同一个请求确定实际数据日期并返回 3 个月趋势、1 个月起始日期和该日榜单。前端按这里提供的日期切换显示范围、按需要格式化展示，统计与事实字段由后端统一生成。字段、画板链接和状态的完整对照见 [ETF 动态低层设计](./etf-activity-low-level-design-v1.md)。

## 4. 本地边界与失败处理

- 后端仅在显式 `APP_ENV=dev/local` 时挂载新 API。沿用现有行情认证，账户认证使用本地环境既有配置。ETF 数据读取不依赖行情数据库 Session，注入的日线源只允许现有 `GOLDENSHARE_LAKE_ROOT` 指向正式 `/Volumes/datasource/data_lake`。DG 元数据仅向 `127.0.0.1:3000/graphql` 发只读查询，不经环境代理。
- 快捷入口仅由本地 Wealth 开发模式或本地构建模式 `local-dg` 启用。常规构建不启用入口，非本地 Web 对直接访问该页面返回 404。ETF 页复用现有布局，但跳过现有的市场上下文和主要指数请求，日期由 ETF API 提供。
- Lake 根目录、交易日历或趋势读取失败时返回模块错误。来源可读取且确实没有日线时返回空态。前一交易日文件缺失时显示当前日榜单、当日涨跌幅和无法对比的说明。榜单所需基础信息或物化引用不可用时，左侧趋势照常展示，右侧显示错误与重试。每次重试按最新实际日期重读三个数据集及必要元数据。前次中断无持久化状态，下一成功响应按同一新日期更新两栏。

## 5. 性能预算与本机样本

日期选择仅枚举 ETF 日线分区名，通过同一份交易日历核对开市日。趋势每次最多读取 3 个自然月内的开市日与此前 19 个开市日。3 个自然月相隔最多 92 天，含两端理论上最多 93 天，故即使这些日期每天均开市，趋势也最多读取 112 个日线文件。榜单最多额外读当前日和前一日各一份日线、一个 ETF 基础信息文件和一条本机 DG 物化元数据。每次请求只有有界投影与内存查询，Lake/数据库写入、Dagster 调度、源接口请求和读写分页数均为 0。DuckDB 完成聚合、均线、排序和名称关联。趋势查询最多返回 93 个开市日点，榜单最多返回 50 行。

| 2026-11-26 DG 有界只读核验 | 实际观测 |
| --- | --- |
| 排行日期 | 2026-11-25，交易日历前一开市日为 11-24。两日各 1,739 行，两个 Parquet 文件合计 109,378 字节。 |
| 3 个月及预热 | 2026-07-29 至 11-25 共 80 个开市日日线文件，61 日展示、19 日预热。文件大小合计 4,234,517 字节，包含 133,318 行、1,744 个不同代码，无重复日期和代码、无空或越界的收盘价和成交额。1 个月显示 23 个开市日。文件大小合计为整文件大小，不代表 DuckDB 实际读取字节。 |
| 样本结果 | 11-25 合计约 5,400.29 亿元，MA5 约 5,584.35 亿元，MA20 约 5,537.04 亿元。前 50 名均有名称和涨跌幅，12 只上一交易日排在第 50 名之后。第 3 名 `510330.SH` 当日涨跌幅 −1.57%，名次上升 31 位。 |
| 本机元数据与名称 | 只读核查 11-24、11-25 两个 DG 物化事件，均指向同一 ETF 基础信息文件，文件大小 119,193 字节。 |
| 查询耗时及边界 | 以现有 DuckDB 单线程本机读取 Calendar 和 80 个日线文件并计算区间均线，一次样本约 0.39 秒。读取仅使用内存，无 Parquet 改写、临时落盘或配额调用。这是 SQL 样本实测。 |

延用财势探查现有请求的 5 秒客户端预算，覆盖读取、响应和前端解析。后端为日历、DG 元数据和 SQL 共用本次处理的剩余预算。用同一代表性窗口分别记录首次访问、故障后一次重新读取和最终真实展示验收的耗时、文件数及最慢阶段。切换区间只切本次响应的数据。超出预算时按测量结果定位日历、DG 元数据、SQL 或响应环节，修正后再验收。日线行数随上市对象增长。上表是有界只读实测，页面端到端性能仍待实现后验证。

## 6. 交付约束

| Wealth 模块原则 | 本模块落点 |
| --- | --- |
| 事实源单一 | 同一请求以 DG ETF 日线取得收盘价和涨跌幅，并计算成交额、排名和均线。基础信息补名称，交易日历供日期查询。前端负责呈现。 |
| 契约先行 | LLD 冻结字段、可空策略、示例和核心测试。 |
| 配置一致 | 本地前端模式、`APP_ENV` 和现有正式 Lake 根目录的生效方式写入 LLD。 |
| 默认行为显式 | 最近可用日、1 个月默认、前一开市日缺失和空态均有用例。 |
| 排序筛选确定 | 使用原始成交额、代码顺序和 DG 日线已确定的范围。 |
| 性能预算前置 | 按交易日期下推 SQL，控制文件范围和返回行数，实测对照 5 秒预算。 |
| 可观测与异常统一 | 复用 Web 异常处理。专用异常码在编码前登记。用户文案显示具体失败的区域和重试入口。 |
| 以用户结果验收 | 真实路由与浏览器分别核对趋势、榜单七列及列序、区间切换、实际日期和失败重试。 |

## 7. 实施与验收顺序

1. 核对技术方案、LLD 和已确认的 Figma。按仓库流程确认本地读数、错误和 API 合同后再进入编码。
2. **第 1 阶段已交付验收结果。** 正式 Web API 使用真实本机 DG 数据，对账了 61 个趋势点和前 50 名的全部七列。隔离 Prod 配置下，API 和页面路径均返回 404。测试范围、重试与性能实测见 [LLD 验收记录](./etf-activity-low-level-design-v1.md#8-第-1-阶段验收记录)。
3. **第 2 阶段。** 管理员确认第 1 阶段验收结果后，接入桌面入口与双栏页面。
4. **第 3 阶段。** 用本机正式 DG 有界样本和真实 API 验收两个区间、七列字段、滚动和状态。回读浏览器网络请求、控制台和实测耗时，按 LLD 门禁逐项对账。
