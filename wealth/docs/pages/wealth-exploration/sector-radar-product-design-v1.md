# 财势探查｜板块雷达产品设计方案 v1（首版研究稿）

> 文档性质：产品设计方案，不是技术实施方案、API 契约或数据库设计。
> 当前状态：首版研究稿；本轮只聚焦东财行业的父子层级下钻、横截面排行和趋势追踪，所有申万相关产品讨论与实现暂缓。
> 产品归属：财势乾坤 / 财势探查。
> 首期数据时效：A 股盘后数据。
> 版本日期：2026-08-20。

---

## 1. 文档结论

“板块雷达”作为财势探查的第一个功能，目标不是再做一个板块排行榜，而是建立一套可以持续回答下列问题的板块研究工具：

1. 今天哪些东财一级行业最热，市场排名如何？
2. 哪些板块在最近一段时间内多次上榜，哪些只是单日脉冲？
3. 哪些板块的价格强度和成交活跃度正在稳步变化？
4. 同一个板块在 20、30、60 个交易日中的趋势有何不同？
5. 当前结论的数据是否完整、稳定、可解释？

本方案的核心决策是：

1. 把“同日全市场横向比较”和“单一板块跨日纵向变化”拆成两套量化体系。
2. 不再要求一个综合热度分数同时承担强弱、资金、成交、持续性和趋势解释。
3. 将热度拆解为价格强度、内部扩散、资金支持、成交活跃、持续性、集中度与拥挤度等独立事实。
4. 热度只描述市场参与状态，不直接等同于未来收益、买入价值或交易信号。
5. 所有公式、窗口、权重和阈值在上线前必须经过历史重建、分段回放和样本外验证；本稿只给出首版候选口径。
6. 首版只展示东财行业；申万数据基础保留，但产品入口、回测和交互全部暂缓。
7. 默认从“1 日一级行业总榜”开始，点击一级行业查看直属二级行业，点击二级行业查看直属三级行业。
8. 二、三级默认只比较当前父行业的直接子行业；全市场同级总榜只作为辅助研究入口。
9. 榜单周期固定提供 `1/5/10/20/30`：1 日是当前范围当日完整排名，5 日以上统计窗口命中次数、命中率和上榜日平均排名。
10. 趋势图只向用户提供最近 `20/30/60` 个已发布交易日的显示范围；趋势判断第一轮固定观察最近 10 日。
11. 纵向热度历史基线首轮只保留 `60/120` 两个回测候选，不作为正式用户控件；选择方法以[量化因子与回测设计](./sector-radar-quant-factor-backtest-design-v1.md)为准。
12. 页面业务交易日统一来自 `pageContext.tradeDate`；来源延迟时展示最近完整交易日并明确提示“当前展示 YYYY-MM-DD 盘后数据”。

### 1.1 本轮产品功能清单

本轮只设计和验证以下能力；列表之外的能力不进入本轮 Demo、回测和后续首版技术方案。

| 功能区 | 本轮能力 | 用户控制 | 数据与产品边界 |
|---|---|---|---|
| 公共日期 | 遵循财势乾坤 `pageContext.tradeDate`；延迟时回退最近完整盘后日 | 不单独控制 | 模块不得自行用当前时间推导交易日 |
| 行业体系 | 只展示东财行业 | 无体系切换 | 申万整体暂缓 |
| 行业层级 | 一级总榜 → 一级直属二级榜 → 二级直属三级榜 | 点击行业下钻、面包屑返回 | 父级内比较为主 |
| 榜单范围 | 当前父级 / 全市场同级 | 二、三级可切换 | 当前父级为默认，全市场同级为辅助 |
| 市场横截面 | 今日热度研究值、价格强度、成交活跃 | 排序维度 | 无效分量不补值 |
| 榜单周期 | 1 日完整排名；最近 `5/10/20/30` 日命中统计 | `1/5/10/20/30` | 多日统计不要求连续命中 |
| 趋势追踪 | 当前选中行业的价格、成交和候选热度状态曲线 | 图表范围 `20/30/60` | 固定 10 日趋势判断；不展示基线控件 |
| 历史基线研究 | 离线比较 `60/120` 日自身历史标准化结果 | 无用户控制 | 按独立量化回测文档执行 |
| 行业详情 | 当前排名、涨跌幅、成交额、活跃度、上榜统计、趋势说明、数据日期 | 选择行业 | 本轮不展示依赖历史成员有效期的历史扩散和贡献 |
| 数据状态 | Ready、Delayed、历史不足、Empty、Error | 无 | 缺失不补零；Delayed 展示最近完整日及日期提示 |

### 1.2 本轮明确不做

1. 不做任何申万产品入口、交互、回测、映射、相关性或“共识/分歧”结论；相关讨论整体暂缓。
2. 不做概念工作台和行业—概念联动；先把东财三级行业下钻和趋势能力做清楚。
3. 不使用当前成员回算历史扩散、历史龙头贡献或历史成员资金覆盖；这些能力继续等待历史成员有效期语义验收。
4. 不实现自动动态选择历史基线；第一轮只比较固定的 60/120 日候选，250 日不进入当前研究。
5. 不把回测候选直接包装成正式热度模型；历史基线和标签阈值必须由回测结果决定。

首版交互讨论使用独立 [板块雷达交互 Demo](./sector-radar-interaction-demo-v1.html)。Demo 使用演示数据，只验证信息架构、控制器职责和状态表达，不代表 API、正式公式或上线数值。因子、信号与回测需求由独立 [量化因子与回测设计](./sector-radar-quant-factor-backtest-design-v1.md) 管理，产品稿不再承担回测执行契约。

## 2. 背景与产品机会

### 2.1 为什么不继续扩充首页板块速览

首页板块速览的职责是让用户快速看到当日客观事实，适合展示涨幅榜、跌幅榜、资金榜、概念热度和简要详情，不适合承载复杂筛选、跨周期比较、关系分析和模型解释。

财势探查则应承接“从事实继续研究”的任务：

```text
乾坤行情 / 市场总览
  └─ 快速发现：今天发生了什么

财势探查 / 板块雷达
  └─ 深入研究：为什么发生、持续多久、内部结构如何、是否形成联动
```

两处可以共享同一批已发布事实，但不能共享同一种信息密度和交互深度。

### 2.2 当前 Heat 口径暴露出的产品问题

现有概念 Heat 已证明盘后物化、历史回放和质量门禁能够运行，但前序审计也暴露出以下问题：

1. 同日横截面分位被直接当成跨日温度序列，板块相对名次变化会造成热度值大幅跳变。
2. 涨跌幅、上涨家数、资金流等因素在强势交易日高度同向，可能重复放大同一市场冲击。
3. 趋势标签通过连续确认获得稳定性，而图表展示的分数仍是原始横截面分数，容易出现“标签平稳、曲线剧烈跳变”。
4. 一个总分无法说明板块是价格驱动、资金驱动、成交驱动还是少数龙头驱动。
5. 当前榜单更适合展示结果，不足以支持用户研究热点的持续、扩散、轮动和关联。

因此，新能力应作为 Heat V3 的产品和研究重构，不在 Heat V2 上继续叠加展示规则。

## 3. 产品定位

### 3.1 一句话定位

> 板块雷达是一套以盘后客观数据为基础，从东财一级行业总榜逐级下钻，用于发现、解释和跟踪 A 股行业冷热变化的研究工作台。

### 3.2 目标用户

1. 需要在收盘后识别市场主线和弱势方向的主动研究者。
2. 需要跟踪热点持续性、资金与成交结构的复盘用户。
3. 希望从行业进一步下钻到原始价格、成交和后续成分事实的专业用户。

### 3.3 使用时点

首期以收盘后研究为主：

1. 当日必需数据全部发布后生成结果。
2. 用户看到的是已完成交易日的最终事实，不是盘中估算。
3. 盘中热度、分钟资金、实时预警不进入首版范围。

### 3.4 产品目标

1. 发现：从东财一级行业中找出当日最热、最冷及变化最大的行业。
2. 甄别：区分一日脉冲、连续热点、稳步升温、高位稳定与开始降温。
3. 解释：说明热度由价格、扩散、资金还是成交驱动。
4. 穿透：在当前窗口内查看行业详情、原始价格和成交事实；历史成员衍生能力后置。
5. 下钻：从一级行业进入直属二级行业，再从二级行业进入直属三级行业，默认不跨父行业混排。
6. 验证：任何模型结论都可以回到分类体系、分类版本、原始指标和交易日解释。

### 3.5 非目标

1. 不输出买入、卖出、加仓、减仓或仓位建议。
2. 不把热度分数解释成未来收益概率。
3. 不直接生成自动交易策略。
4. 不用新闻标题数量替代真实市场参与度。
5. 不在第一版引入不可解释的黑盒机器学习综合分。
6. 不把行业、概念和地域放入同一横截面混排。
7. 地域板块暂不进入板块雷达首版；继续作为市场总览的客观排行维度，后续有独立研究问题时再评估。
8. 不在本方案中确定技术架构、表结构、API、任务编排和前端组件。
9. 本轮不展示或讨论申万行业能力；既有申万数据基础不等于当前产品范围。
10. 不做跨分类体系映射、比较或自动对比能力。
11. 不自动动态选择历史基线；后续若研究动态选择，必须作为独立量化模型评审。
12. 本轮不建设概念工作台；概念继续保留在首页板块速览和既有 Heat V2 中，后续是否进入板块雷达另行评审。

## 4. 设计原理

### 4.1 横向比较和纵向变化必须分开

横向热度回答“今天谁比别人热”，纵向状态回答“这个板块相对自己的历史是否在升温”。两者不可直接复用同一分数。

| 维度 | 比较对象 | 主要用途 | 推荐标准化方式 |
|---|---|---|---|
| 横向 | 同一交易日的同类板块 | 今日排行、热点分布 | 同日横截面分位 |
| 纵向 | 同一板块自己的历史 | 升温、降温、持续性 | 自身历史稳健标准化 + 平滑 |

东财一级行业在全部一级行业中比较。进入一级行业后，二级行业默认只在该一级行业的直属子行业中比较；进入二级行业后，三级行业默认只在该二级行业的直属子行业中比较。全市场同级总榜只作为辅助研究入口。概念若未来重新进入板块雷达，必须另设独立横截面，不能与行业混排。

### 4.2 先展示事实，再给综合结论

完整的长期热度研究可能涉及以下七类事实；本轮只把价格强度、成交活跃和多日活跃作为可展示、可回测分项，其余事实继续保留为后置候选：

| 事实 | 解释 |
|---|---|
| 价格强度 | 板块相对同类和市场表现是否强 |
| 内部扩散 | 上涨是否覆盖多数有效成分股 |
| 资金支持 | 净流入是否显著、持续并具有覆盖面 |
| 成交活跃 | 成交是否相对板块自身历史放大 |
| 多日活跃 | 板块是否在统计窗口内多次处于市场前列，不要求日期连续 |
| 集中度 | 是否主要由少数龙头贡献 |
| 拥挤度 | 是否出现过热、巨量、过度集中或背离 |

本轮“热度研究值”只能由本轮已通过数据门槛的分项形成候选结果。综合热度只作为排序入口；详情必须展示实际参与计算的分项、原始值、历史位置和数据质量，不得用尚未启用的成员或资金分项占位。

### 4.3 热度、趋势与风险是三件事

1. 热度：当前市场参与程度。
2. 趋势：热度状态正在上升、稳定还是下降。
3. 拥挤风险：热点是否高度集中、加速过快或出现量价资金背离。

拥挤度不直接从热度中扣分。一个板块可以同时“很热”和“很拥挤”，产品必须允许这两个事实同时成立。

### 4.4 描述模型和预测模型分离

板块雷达第一版是描述和研究工具。未来如果需要估计热点延续概率，应新增独立的“延续性模型”，明确预测目标、预测周期和样本外表现，不能把预测逻辑隐藏在热度权重里。

### 4.5 每个结论必须带数据置信度

缺少关键事实时不重新分配剩余权重，不用零值代替缺失，也不沿用前一交易日结果伪造连续性。

本轮价格与成交研究的数据置信度定义为关键覆盖率中的最弱一项：

```text
dataConfidenceCurrent = min(
  quoteCoverage,
  amountCoverage,
  historyCoverage,
  publicationCompleteness
)
```

成员、资金等后置能力启用后，再按对应功能实际依赖扩展为：

```text
dataConfidenceExtended = min(
  memberCoverage,
  quoteCoverage,
  moneyflowCoverage,
  historyCoverage,
  publicationCompleteness
)
```

原因是关键输入之间不存在可替代关系：当前价格与成交完整不能补偿历史不足；未来启用资金或成员能力时，行情完整也不能补偿资金或成员缺失。未进入本轮的输入不得反过来把本轮价格与成交结果判为不可用。

### 4.6 先可解释，再追求复杂

首版优先采用稳健分位、历史中位数、MAD、线性斜率和 EWMA 等透明方法。机器学习可以在未来作为候选模型，但必须与透明基线进行样本外比较，并提供稳定的解释方式。

### 4.7 东财父子层级优先

本轮只使用东财行业体系。产品必须遵守：

1. 页面默认显示一级行业 1 日总榜。
2. 点击一级行业后，进入该行业并展示直属二级行业榜。
3. 点击二级行业后，进入该行业并展示直属三级行业榜。
4. 面包屑始终显示当前父子路径并允许返回任一上级。
5. 二、三级默认采用当前父级范围；全市场同级榜不作为主路径。
6. 趋势和详情始终绑定当前选中行业，不能因为切换榜单范围而改变研究对象。
7. 申万相关能力整体后置，未来重新启动时必须另行评审，不能自动回到当前首版范围。

## 5. 产品信息架构

### 5.1 一级结构

```text
财势探查
└── 板块雷达
    └── 东财行业工作台
        ├── 父子层级榜单
        ├── 当前行业详情
        └── 当前行业趋势
```

### 5.2 父子层级榜单

回答“今天市场在交易什么”。

主要能力：

1. 默认展示全部东财一级行业的 1 日总榜。
2. 点击一级行业后展示该行业直属二级行业榜。
3. 点击二级行业后展示该行业直属三级行业榜。
4. 通过面包屑返回任一上级，不使用平铺的一级/二级/三级切换替代父子关系。
5. 二、三级默认使用“当前父级”，可辅助切换到“全市场同级”。
6. 查看今日热度研究值、价格强度和成交活跃等分项排名。
7. 榜单周期支持 `1/5/10/20/30`；1 日是当日完整排名，5 日以上显示命中次数、命中率和上榜日平均排名。
8. 查看数据置信度和实际盘后数据日期。

### 5.3 当前行业趋势

回答“当前选中行业是否正在发生持续变化”。

主要能力：

1. 稳步升温。
2. 加速升温。
3. 高热稳定。
4. 成交温和放大。
5. 量价背离。
6. 降温和峰值回落。
7. 图表可视范围在 `20/30/60` 个交易日间切换。
8. 趋势判断第一轮固定观察最近 10 日，不在主界面暴露分析周期切换。
9. 历史基线由独立量化回测选择，不在产品主界面暴露 `60/120` 控件。
10. 趋势始终绑定当前面包屑选中的东财行业，不建立脱离父子路径的全市场趋势候选榜。

### 5.4 后置能力：行业体系与概念联动

本节原有能力不进入本轮功能清单、交互 Demo、首轮回测或后续首版技术方案。所有申万、跨体系相关性、领先滞后、成员重合以及行业—概念联动均后置。保留下列研究问题仅用于未来重新立项时追溯，不代表当前承诺。

回答“热点之间是什么关系”。

主要能力：

1. 从东财行业查看最相关的申万行业，从申万行业反向查看最相关的东财行业。
2. 从任一行业体系查看相关概念及其成分重合度。
3. 从概念查看其成分股分别分布在哪些东财行业和申万行业。
4. 观察两套行业体系以及行业与概念的价格、资金、热度状态是否同步。
5. 检查概念相对行业、东财行业相对申万行业的历史领先或滞后关联。
6. 识别双体系共识、体系分歧、行业共振、行业内扩散、孤立题材和高度重合。

### 5.5 本轮统一行业详情

本轮选中任一东财行业后，详情区展示：

1. 今日横向热度和同类排名。
2. 自身热度状态和趋势标签。
3. 价格强度。
4. 成交活跃度。
5. 1 日排名，或最近 `5/10/20/30` 日上榜记录、命中次数和上榜日平均排名。
6. 当前图表范围 `R` 和固定 10 日趋势判断说明；不展示历史基线选择控件。
7. 行情、成交、历史窗口和发布完整性。
8. 当前分类体系、分类版本和层级。

内部扩散、资金流入、龙头贡献、成分股贡献和跨体系对应关系均不进入本轮详情。未来只有在数据覆盖和回测分别通过后，才能作为独立分项加入，不能改变本轮价格与成交事实的有效性。

图表优先使用共用横轴的多行小图，不把不同单位强行叠加在同一纵轴。

## 6. 量化框架总览

### 6.1 口径状态说明

本章将量化口径分为三种状态：

| 状态 | 含义 |
|---|---|
| 已确认原则 | 产品逻辑已经确认，后续不能反向合并 |
| 首版候选 | 可用于历史验证的第一批公式，不代表最终生产值 |
| 待验证参数 | 必须通过数据分布、回放和样本外结果选择 |

### 6.2 基础符号

| 符号 | 含义 |
|---|---|
| `i` | 某个带分类体系与分类版本身份的行业板块 |
| `t` | 某个已发布交易日 |
| `G` | 当前横截面；一级为全部东财一级行业，二、三级默认为当前父行业直属子行业 |
| `M(i,t)` | 板块在交易日 `t` 的有效 A 股成分池 |
| `Pcs(x)` | 指标 `x` 在同日同类横截面的 0～100 稳健分位 |
| `Zts(x)` | 指标 `x` 相对该板块自身历史的稳健标准分 |
| `W` | 指标计算窗口，首批候选为 5、10、20、30 个交易日 |
| `R` | 图表可视范围，固定为 20、30、60 个交易日 |
| `B` | 自身历史标准化基线，研究候选为 60、120、250 个交易日 |

横截面极端值先做稳健缩尾；时间序列标准化优先使用历史中位数和 MAD，避免均值和标准差被极端行情扭曲。

### 6.3 有效 A 股成分池

所有成员类量化都基于目标交易日真实有效成分池：

1. 成分关系必须是目标交易日当时有效的关系，不能使用今天的成员回算历史。
2. 只保留当时已经上市且尚未退市的人民币 A 股。
3. 停牌证券保留为板块成员，但不进入当日可报价分母。
4. 缺少有效行情的非停牌成员进入缺失计数，不按下跌或零收益处理。
5. 板块样本过小或行情覆盖不足时，相关指标标记无效。

这是所有回测的首要门禁。没有历史成分时，只能验证板块级指标，不能伪造历史扩散度和成分贡献。

## 7. 基础量化维度

### 7.1 价格强度

#### 用户问题

这个板块今天相对同类和市场究竟强不强？

#### 首版候选事实

```text
relativeReturn1d(i,t)
  = sectorReturn1d(i,t) - median(sectorReturn1d(G,t))
```

东财行业按当前比较范围分别计算。横向价格强度候选为：

```text
priceStrengthCs(i,t) = Pcs(relativeReturn1d(i,t))
```

纵向价格趋势不再重复叠加“当日涨跌幅、五日相对强度、日度加速度”，而是单独观察累计相对收益序列的 5、10、20、30 日斜率和回撤。

#### 设计理由

1. 板块绝对上涨可能只是全市场普涨，相对收益更能说明同类中的强弱。
2. 当日涨幅同时进入多个高度重合的子指标会重复放大同一冲击。
3. 行业动量研究表明行业层面的相对表现具有独立研究价值，但公开研究多基于海外和较长周期，不能直接证明 A 股日频有效，必须单独回测。

#### 待验证

1. 直接使用板块官方涨跌幅，还是使用有效成分股等权/流通市值加权收益作为主事实。
2. 同类中位数与宽基市场基准哪个更适合作为超额收益基准。
3. 日频、3 日和 5 日趋势的响应速度与噪声权衡。

### 7.2 内部扩散度

#### 用户问题

板块上涨是多数股票共同参与，还是少数龙头拉动？

#### 首版候选事实

```text
upRatio(i,t)
  = count(memberReturn > 0) / validQuoteCount

positiveExcessRatio(i,t)
  = count(memberReturn > marketMedianReturn) / validQuoteCount

medianMemberReturn(i,t)
  = median(valid member returns)

limitUpRatio(i,t)
  = limitUpMemberCount / validQuoteCount
```

扩散度候选：

```text
breadthCs = weighted_mean(
  Pcs(upRatio),
  Pcs(positiveExcessRatio),
  Pcs(medianMemberReturn),
  capped Pcs(limitUpRatio)
)
```

首版不冻结分量权重。涨停比例只作为补充，且需要限制小样本板块被一只涨停股夸大的影响。

#### 设计理由

1. 板块涨跌幅无法区分普遍参与和少数股票拉动。
2. 上涨家数比和成分收益中位数对极端龙头不敏感。
3. 扩散与龙头集中度同时展示，能解释“热但不广”和“涨幅一般但内部普遍改善”两种状态。

#### 待验证

1. 有效成分数量下限。
2. 涨停比例的小样本收缩方式。
3. 等权扩散与流通市值加权扩散是否同时展示。

### 7.3 资金支持度

#### 用户问题

上涨是否得到资金支持，资金是否持续，流入是否覆盖多数成分？

#### 首版候选事实

```text
netFlowRate(i,t)
  = sectorNetInflow(i,t) / sectorAmount(i,t)

positiveFlowStreak(i,t)
  = 截至 t 连续净流入交易日数

positiveFlowHitRateW(i,t)
  = W 日内净流入天数 / W

cumulativeFlowRateW(i,t)
  = sum(sectorNetInflow) / sum(sectorAmount), over W days

flowSlopeW(i,t)
  = W 日 netFlowRate 的稳健线性斜率
```

若未来具备可靠的个股资金流，可增加：

```text
memberFlowBreadth(i,t)
  = count(memberNetInflow > 0) / validMemberFlowCount
```

#### 设计理由

1. 绝对净流入金额偏向成交规模大的板块，净流入占成交额比例更适合横向比较。
2. 连续天数、窗口命中率和累计流入分别表达连续性、容错性和资金规模，不能互相替代。
3. 板块级净流入可能由少数权重股贡献，未来需要成员资金覆盖面辅助解释。

#### 待验证

1. 当前板块资金流字段跨日期、行业和概念的覆盖率及稳定性。
2. 小额流出是否允许作为连续流入中的“噪声容忍”，以及容忍阈值。
3. 资金流口径是否具有结构性修订或源站回补。

### 7.4 成交活跃度

#### 用户问题

板块成交是否相对自身历史放大，是温和扩张还是一次性巨量？

#### 首版候选事实

```text
amountRatio20(i,t)
  = sectorAmount(i,t) / median(sectorAmount(i,t-20...t-1))

activityLevel(i,t)
  = Zts(log(amountRatio20(i,t)))

amountSlopeW(i,t)
  = W 日 log(amountRatio20) 的线性斜率

amountMonotonicityW(i,t)
  = count(amountRatio20(t) > amountRatio20(t-1)) / (W-1)

amountCVW(i,t)
  = std(amountRatio20 over W) / mean(amountRatio20 over W)
```

#### “温和放量”首版候选条件

同时满足：

1. `amountSlopeW > 0`。
2. `amountMonotonicityW` 达到候选门槛。
3. `amountCVW` 不处于同类历史高位。
4. 单日成交放大量未超过“脉冲成交”阈值。
5. 有效成员和行情覆盖达标。

门槛不在本稿写死，首批建议研究 `W=5/10`、单调率 `60%～80%`、历史分位阈值 `80%～95%`。

#### 设计理由

1. 绝对成交额无法跨不同规模板块直接比较。
2. 与自身 20 日中位数相比可以降低板块规模差异。
3. 正斜率只能说明上升，低波动和单日脉冲限制用来区分“温和放大”和“突然巨量”。
4. 公开量价研究表明历史成交量与价格动量的强度和持续存在关系，但不能据此把放量直接解释为看涨。

### 7.5 龙头贡献与集中度

#### 用户问题

板块表现由多少只股票贡献，是否过度依赖少数龙头？

#### 首版候选事实

成分股贡献需要同时计算等权和规模加权两个视角：

```text
equalContribution_j = memberReturn_j / memberCount

floatWeightedContribution_j
  = floatWeight_j * memberReturn_j

top3PositiveContributionRatio
  = top3 positive contributions / total positive contributions

top5TurnoverShare
  = top5 member amount / total member amount
```

集中度可以同时使用 Top3/Top5 占比和 HHI，不强行压缩成一个不可解释的数字。

#### 设计理由

1. 等权贡献适合看参与面，规模加权贡献适合解释板块指数表现。
2. 龙头集中不是天然负面事实，但会改变热点的稳定性和可扩散性。
3. 集中度应作为独立诊断和拥挤提示，不直接从热度中扣分。

#### 数据前提

需要可靠的目标交易日流通市值或自由流通市值。缺少该数据时只能展示等权贡献，不能用总市值或当前市值倒推历史权重。

### 7.6 拥挤与背离

#### 用户问题

板块虽然很热，是否出现集中、巨量或内部跟随不足？

#### 首版候选信号

| 信号 | 候选量化条件 |
|---|---|
| 高热高集中 | 今日热度进入同类高分位，且 Top3/Top5 贡献处于自身历史高分位 |
| 巨量脉冲 | `amountRatio20` 进入历史极端分位，但成交斜率与单调率不支持温和放量 |
| 价涨扩散弱 | 相对收益为正且排名靠前，但 `upRatio/medianMemberReturn` 未同步改善 |
| 资金价背离 | 价格强度上升而 `netFlowRate` 下降，或相反 |
| 热度见顶 | 热度状态高位，趋势斜率转负且回撤扩大 |

这些信号是研究提示，不是风险预测，也不直接触发交易建议。

## 8. 横向热度设计

### 8.1 定义

“今日热度”表示板块在同日同类市场中的相对参与程度，用于当天排名，不用于直接绘制板块跨日温度趋势。

### 8.2 首版候选公式族

候选基础分量：

1. `priceStrengthCs`
2. `breadthCs`
3. `capitalFlowCs`
4. `activityCs`

候选公式不是只保留一套，而是进入回测比较：

| 候选 | 价格 | 扩散 | 资金 | 活跃 | 用途 |
|---|---:|---:|---:|---:|---|
| H0 等权基线 | 25% | 25% | 25% | 25% | 最简单透明基线 |
| H1 均衡候选 | 30% | 25% | 25% | 20% | 保留价格识别力但避免过度主导 |
| H2 参与优先 | 25% | 30% | 25% | 20% | 强调内部参与而非单日涨幅 |

候选总式：

```text
marketHeatScore(i,t)
  = weighted_sum(priceStrengthCs, breadthCs, capitalFlowCs, activityCs)
```

所有分量为 0～100 的同日同类分位。某个关键分量无效时，综合分数无效，不重分配权重。

### 8.3 今日榜单

1. 所有板块展示完整排名，不只返回 Top N。
2. “上榜”首版候选定义为同类横截面前 20%，而不是统一固定 20 名。
3. 前 20% 对不同样本规模的行业层级具有更可比的覆盖比例。
4. 页面仍可显示 Top10、Top20 等快捷视图，但持续性计算使用分位门槛，避免一级行业样本较少时榜单过宽。

### 8.4 今日热度等级

“沸腾 / 高热 / 活跃”等产品语言可以保留，但阈值不直接沿用 Heat V2。首版研究同时比较：

1. 固定分数阈值。
2. 横截面分位等级。
3. 分数 + 分量一致性的联合等级。

等级只有在数据分布和跨行情阶段稳定后才冻结。低热板块不必强制贴负面标签，可以直接展示热度值、排名和降温状态。

## 9. 纵向热度状态与趋势

### 9.1 定义

“自身热度状态”表示同一个板块当前的市场参与事实相对其自身历史处于什么位置。

它不直接使用每日横向名次，而是对板块自己的价格、扩散、资金和活跃原始事实做历史标准化。

### 9.2 状态输入

```text
stateInput(i,t) = weighted_sum(
  Zts(relativeReturn1d),
  Zts(upRatio and medianMemberReturn),
  Zts(netFlowRate),
  Zts(log(amountRatio20))
)
```

历史基线 `B` 首轮只保留 60、120 个交易日两个研究候选。250 日周期过长，不进入当前研究。状态输入经过有界映射转为 0～100，再进入平滑。

两条候选序列的职责是验证板块对不同历史长度的敏感度，不等于正式页面同时展示两个互相竞争的热度结论。一级行业、二级行业、三级行业、概念和地域分别研究一套适用于该类别全部对象的统一参数；同一类别内不为具体板块配置专属基线，也禁止每天根据当日结果自动挑选最有利基线。

### 9.3 平滑候选

首版使用透明的指数加权移动平均作为基线候选：

```text
heatState(i,t)
  = lambda * stateInput(i,t)
  + (1 - lambda) * heatState(i,t-1)
```

`lambda` 越大，响应越快但噪声越高；越小，曲线越平稳但识别新热点更慢。首批建议比较 `0.20、0.30、0.40、0.50`，不在产品稿中提前确定最终值。

NIST 对 EWMA 的说明表明，它通过对更早数据赋予逐步降低的权重来监测较小、渐进变化；这里借用的是“平滑与小变化检测”思想，不把工业过程控制阈值直接照搬到金融市场。

### 9.4 趋势量化

```text
stateSlopeW
  = W 日 heatState 的线性斜率

trendMonotonicityW
  = count(deltaHeatState > 0) / (W-1)

trendFitW
  = W 日线性趋势拟合优度 R²

maxStatePullbackW
  = W 日内从局部高点到后续低点的最大状态回撤

normalizedSlopeW
  = stateSlopeW / robustResidualVolatilityW
```

### 9.5 趋势状态候选

| 状态 | 候选量化逻辑 | 产品含义 |
|---|---|---|
| 稳步升温 | 正斜率 + 较高单调率 + 较高拟合度 + 回撤受控 | 热度持续抬升且路径平稳 |
| 加速升温 | 短窗斜率显著高于长窗斜率，且分量同步改善 | 热度上升速度加快 |
| 高热稳定 | 自身状态处于历史高分位，斜率接近零且波动受控 | 维持高位但没有继续加速 |
| 脉冲升温 | 当日状态跳升，但单调率、拟合度或连续确认不足 | 可能是一日事件，需要继续观察 |
| 峰值回落 | 高位状态下斜率转负，回撤扩大 | 热点开始失速 |
| 持续降温 | 负斜率 + 较高下降单调率 + 连续确认 | 参与度持续减弱 |
| 无明确趋势 | 方向和稳定性门槛均不满足 | 波动或横盘，不强行贴标签 |

具体门槛通过回测选择。趋势标签必须与页面曲线使用同一 `heatState` 序列，禁止标签和平滑曲线各用一套数据。

## 10. 多日上榜设计

### 10.1 定义

```text
hitCountW(i,t)
  = 最近 W 日满足上榜条件的天数

hitRateW(i,t)
  = hitCountW / W
```

本轮用窗口命中识别持续活跃：只要最近 W 日内达到规定的上榜天数即可，中间允许未上榜，不使用“必须连续”作为筛选条件。

### 10.2 首版候选筛选

| 统计窗口 | 多日上榜门槛 | 同时展示 |
|---|---:|---|
| 最近 5 日 | 窗口内至少 3 日上榜 | 5 日命中次数、命中率、上榜日平均排名 |
| 最近 10 日 | 窗口内至少 5 日上榜 | 10 日命中次数、命中率、上榜日平均排名 |
| 最近 20 日 | 窗口内至少 10 日上榜 | 20 日命中次数、命中率、上榜日平均排名 |
| 最近 30 日 | 窗口内至少 15 日上榜 | 30 日命中次数、命中率、上榜日平均排名 |

这些门槛作为本轮产品筛选口径固定下来。回测仍需先报告它们在东财一级行业中的命中规模与区分度；未来扩展二、三级时按父行业直属子行业分别报告。若出现绝大多数或几乎没有行业命中的情况，必须回到产品评审，不得在实现中偷偷改阈值。

### 10.3 持续度候选分数

```text
persistenceScoreW = 100 * (
  a * hitRateW
  + b * averageRankQualityW
  + c * rankStabilityW
)
```

建议首先比较简单的等权基线与“命中率优先”候选。多日上榜不进入今日横向热度原始分，避免用历史结果反过来强化今天的横向排名；它作为独立榜单和解释维度展示。

## 11. 纵向专题量化

### 11.1 稳步升温

候选评分：

```text
steadyHeatingScoreW = 100 * (
  0.35 * positiveNormalizedSlope
  + 0.30 * trendMonotonicity
  + 0.20 * trendFit
  + 0.15 * controlledPullback
)
```

权重只是首版候选。四项分别防止以下误判：

1. 只有方向、没有速度。
2. 只有期初期末差、路径剧烈反复。
3. 斜率由单日跳点决定。
4. 总体向上但中途回撤过大。

### 11.2 后置候选：连续资金流入（本轮申万不做）

本节不进入申万首轮回测或当前交互 Demo，只保留为东财后续研究候选；其上线前必须单独通过资金数据覆盖与口径验收。

页面同时展示：

1. 当前连续净流入天数。
2. 5、10、20、30 日净流入命中率。
3. 窗口累计净流入占成交额。
4. 资金流强度斜率。
5. 若数据可用，成分股资金流入覆盖率。

候选评分：

```text
flowPersistenceScoreW = 100 * (
  0.35 * normalizedPositiveFlowStreak
  + 0.25 * positiveFlowHitRate
  + 0.25 * Pcs(cumulativeFlowRateW)
  + 0.15 * positiveFlowSlope
)
```

绝对流入金额只作为解释值，不作为跨板块主排序。

### 11.3 成交温和放大

候选评分：

```text
gentleExpansionScoreW = 100 * (
  0.35 * positiveAmountSlope
  + 0.30 * amountMonotonicity
  + 0.20 * moderateActivityLevel
  + 0.15 * lowPulsePenalty
)
```

其中 `moderateActivityLevel` 偏好相对历史明显放大但未达到极端脉冲的区间；`lowPulsePenalty` 对单日巨量和高波动扣分。最终区间必须由历史分布决定，不能凭经验固定为某个量比。

## 12. 后置研究备忘：行业体系与概念联动（本轮不做）

本章整体后置，不进入本轮功能列表、交互 Demo、首轮回测或首版技术方案。只有未来重新确认跨体系关系具有明确产品价值后，才允许恢复评审；保留原候选仅用于避免研究问题丢失。

### 12.1 先分开计算，再研究关系

东财行业、申万行业和概念是三个不同的分类空间：

1. 东财行业和申万行业都具有一级、二级、三级，但层级边界和成员不相同。
2. 同一体系内只有同层比较才有意义，两套行业体系不能进入同一个原始排名。
3. 概念通常跨行业，可能同时对应多个东财行业和申万行业，不能与行业直接混排。
4. 三个分类空间的热度、持续度和趋势先各自计算，再建立关系层。

### 12.2 成分重合

```text
jaccardOverlap(A, B, t)
  = |membersA ∩ membersB|
    / |membersA ∪ membersB|

aCoveredByB
  = |intersection| / |membersA|

bCoveredByA
  = |intersection| / |membersB|
```

`A/B` 可以是东财行业与申万行业，也可以是任一行业与概念。三个指标分别表达对称重合和两个方向的覆盖程度，不能只留一个重合比例。

具备历史流通市值后，可增加加权重合度，用于判断重合是否集中在少数权重股。

### 12.3 双体系比较口径

东财和申万可以对比，但不能把来源不同的原始板块分数直接相减。首版比较分为三层：

1. **成员层**：同日 Jaccard 和双向覆盖率，解释两套体系实际上覆盖了哪些相同股票。
2. **统一事实层**：用同一套股票行情、个股资金流、流通市值和有效池规则，分别按两套历史成员聚合价格、扩散、资金和成交事实。
3. **体系内结果层**：比较各自在本体系、同层级中的分位、趋势状态和多日上榜情况，形成“共识”或“分歧”，但不生成跨体系混合名次。

来源方直接提供的板块涨跌幅、成交额和资金流保留为本体系参考事实和聚合结果校验。若一个体系使用来源板块资金、另一个体系使用成员资金聚合，页面必须明确口径不同，不得包装成完全可比的同一指标。

### 12.4 同步与领先滞后

候选关系事实：

1. 20、60 日市场调整后相对收益相关。
2. 20、60 日热度状态相关。
3. 资金流强度相关。
4. 在 `-5...+5` 个交易日内的领先滞后相关峰值。

领先滞后必须满足：

1. 样本长度和有效日期覆盖达标。
2. 最大相关显著高于零滞后或相邻滞后。
3. 在滚动窗口中方向稳定。
4. 剔除重合成分贡献后仍保留关系，或明确标注“主要由成员重合解释”。

产品只表述“历史领先关联”或“历史滞后关联”，不表述为因果关系。

### 12.5 关系标签候选

| 标签 | 候选条件 |
|---|---|
| 双体系共识 | 相关东财行业与申万行业同时处于各自同层高热或升温状态，且成员关系置信度达标 |
| 体系分歧 | 高重合行业在价格、扩散、资金或趋势状态上明显分化，且差异不能由数据缺失解释 |
| 行业共振 | 行业与相关概念同时高热或升温，收益/状态同步且关系置信度达标 |
| 概念领先 | 概念状态变化在滚动窗口中稳定领先相关行业，剔除重合影响后仍成立 |
| 行业内扩散 | 行业状态改善，同时升温的相关概念数量和行业内部扩散度持续增加 |
| 孤立题材 | 概念高热，但与主要行业的状态、资金和成分覆盖关系均弱 |
| 高度重合 | 成分与权重重合度高，表面联动主要由同一批股票解释 |
| 关系不足 | 历史、覆盖或稳定性不足，不生成关系结论 |

公开研究曾观察到部分行业收益包含对更广市场的领先信息，这支持我们测试行业与概念的领先滞后关系，但不能直接证明 A 股日频概念与行业存在稳定因果链。

### 14.5 数据质量要求

1. 日期一致：同一结果不得混用不同交易日的行情、成员和资金。

3. 成分有效：历史成员必须按当时有效关系计算。
4. 缺失显式：缺失不等于零，不做前向填充伪造资金或热度连续性。
5. 源修订可追踪：源数据回补或修订后，研究结果能够识别版本差异。
6. 样本可比：东财一级行业先统一设定最小样本数和覆盖门槛；子行业扩展时按父级比较范围重新设定。
7. 资金可信：资金流必须审计日期覆盖、代码覆盖、异常极值和源站回补行为。
8. 范围隔离：一级总榜、父级下直属子行业榜和全市场同级辅助榜必须记录各自比较范围，不能混用名次。

## 15. 量化因子与回测要求摘要

详细公式、实验版本、信号事件、未来结果、对照组、样本外门禁和交付格式，以独立的[东财行业板块雷达量化因子与回测设计](./sector-radar-quant-factor-backtest-design-v1.md)为唯一研究口径。产品稿只保留用户需要理解的边界：

1. 首轮只研究东财一级行业，只使用价格和成交事实。
2. 横向“成功”必须用信号日之后的每日独立同级榜单验证，不能用热度自身继续上升证明自己。
3. 分别统计次日、未来 3 日和未来 5 日的榜单确认；进入榜单与留在榜单分开报告。
4. 固定比较 60、120 日历史基线，趋势判断窗口固定为 10 日；不在同一轮同时搜索其他参数。
5. 基线选择同时看成功率提升、覆盖率、误报率、提前量和不同市场阶段的稳定性，不只挑历史最好看的结果。
6. 回测必须按时间切分研究期、校准期和最终保留期，并采用 walk-forward；任何信号日只能使用当时已发布数据。
7. 第一轮不做行业级动态基线选择，也不把 60/120 暴露成用户控件。
8. 如果两种候选均未通过样本外门禁，产品结论是暂不发布正式转热信号，而不是强行选择一项。

## 17. 产品效果指标

板块雷达上线后的产品有效性不以点击量单独衡量，首版建议关注：

### 17.1 主要指标

1. **可解释覆盖率**：有有效综合结论的板块中，能够完整展示关键分项、原始值和数据质量的比例。目标方向为 100%。

3. **发现到穿透率**：用户从横向榜或趋势筛选进入板块内部解释的会话比例，用于判断产品是否真的支持研究，而非只看排名。

1. 用户在一级总榜、父级下钻榜和全市场同级辅助榜之间的使用分布。

3. 数据不足导致的功能降级率。
4. 用户查看价格、成交、上榜统计和趋势解释的比例。
5. 同一板块在多个交易日被重复研究的比例。

### 17.3 防误导护栏

1. 不展示未经验证的收益预测概率。
2. 不把热度标签写成操作建议。
3. 无效数据不进入排行。
4. 数据或历史不足时不生成正式热度标签，也不把演示值包装成生产结果。

## 18. 公开研究与开源实践参考

本节只解释产品原理来源，不代表公开研究可以直接迁移到 A 股日频板块。

1. [Moskowitz & Grinblatt, Do Industries Explain Momentum?](https://onlinelibrary.wiley.com/doi/10.1111/0022-1082.00146)：行业层面的收益动量具有独立研究价值，支持将行业作为研究对象，而不只是股票的分类标签。
2. [Moskowitz, Ooi & Pedersen, Time Series Momentum](https://w4.stern.nyu.edu/facdir/lpederse/papers/TimeSeriesMomentum.pdf)：明确区分横截面动量和基于对象自身历史的时间序列动量，为本方案拆分横向热度与纵向状态提供方法论依据。
3. [Lee & Swaminathan, Price Momentum and Trading Volume](https://onlinelibrary.wiley.com/doi/abs/10.1111/0022-1082.00280)：历史成交量与价格动量的强度和持续性存在关系，支持把成交活跃作为独立解释维度，而非涨跌幅的附属展示。
4. [Hong, Torous & Valkanov, Do Industries Lead the Stock Market?](https://escholarship.org/content/qt6x49x543/qt6x49x543_noSplash_d7fe8ea2dceecd78b673a460a0dd47c1.pdf)：部分行业历史上表现出对更广市场的领先信息，支持研究行业与概念的领先滞后关系，但不能直接推断因果。
5. [NIST EWMA 说明](https://itl.nist.gov/div898/handbook/mpc/section2/mpc2211.htm)：EWMA 对渐进变化的监测适合用作透明平滑基线，具体参数仍需用金融数据校准。
6. [Quantopian Alphalens](https://github.com/quantopian/alphalens)：其分组收益、信息系数、换手和分组分析框架值得用于候选因子的诊断；本方案只借鉴评估思想，不决定引入该依赖。
7. [Freqtrade](https://github.com/freqtrade/freqtrade)：其未来数据泄漏和指标预热稳定性检查，支持把无前视与历史稳定性做成自动门禁；本方案只吸收验证思想，不引入其交易系统或代码。
8. [QuantConnect LEAN](https://github.com/QuantConnect/Lean)：其回测与生产同核、时间前沿、目标与约束分离及样本外验证原则，支持本方案的研究生产一致性；不引入订单、组合或 C# 引擎。
9. [Bailey et al., The Probability of Backtest Overfitting](https://papers.ssrn.com/sol3/Papers.cfm?abstract_id=2326253)：支持限制参数搜索、预先登记候选和保留最终样本外窗口。
10. [Kenneth French Data Library](https://mba.tuck.dartmouth.edu/pages/faculty/ken.french/data_library.html)：公开行业组合长期数据说明行业组合是一类成熟研究对象，但其市场、频率和行业分类不能直接作为 A 股阈值来源。

公开资料对本产品的作用是提供研究问题和验证方法，不替代生产数据审计与 A 股历史回测。

## 19. 分阶段推进建议

### 阶段 P0：产品口径评审

1. 评审市场横截面和趋势追踪两个工作台是否覆盖本轮核心研究问题。
2. 确认横向热度、纵向状态、持续性和拥挤度的边界。
3. 确认默认一级总榜、父级下钻和全市场同级辅助榜的职责边界。
4. 确认趋势固定绑定当前行业，历史基线不作为用户控件。
5. 确认本稿中的待拍板项。

### 阶段 P1：生产数据研究审计

1. 盘点每类数据的真实日期、数量、唯一性和覆盖率。
2. 东财继续核验目录、层级版本、历史成分、行业日行情、流通市值、资金流和涨跌停明细可用性。
3. 东财一级行业形成可回测日期集合、不可验证范围和数据置信度门槛。
4. 核验 B 预热期、有效输出期和每日一级行业覆盖，不以“某个代表代码历史很长”替代全行业覆盖。

### 阶段 P2：离线候选计算与回测

1. 实现研究级而非生产级候选公式。
2. 按独立量化设计固定趋势判断、权重、平滑和信号阈值，只比较 `B=60/120`。
3. 输出信号日之后 1/3/5 日的独立榜单确认、对照组、覆盖率、误报率和提前量。
4. 完成 walk-forward、不同市场阶段和最终保留期验证。

### 阶段 P3：产品口径冻结

1. 根据回测选择正式公式、窗口和阈值。
2. 冻结产品词汇、榜单定义、数据置信度和降级规则。
3. 冻结正式历史基线、信号阈值和不可比指标的表达规则；研究参数不自动变成用户控件。
4. 明确哪些功能首发，哪些因数据不足后置。
5. 将正式结果升级为板块雷达标杆需求文档。

### 阶段 P4：交互设计

1. 先用独立 HTML Demo 评审市场横截面和趋势追踪两个工作台，再用真实回测样本替换演示值。
2. 行业页面只提供东财父子层级下钻，保持榜单、详情和趋势结构稳定。
3. 图表范围与上榜统计周期使用不同名称与控件职责；分析窗口和历史基线不对用户开放。
4. 完成 Demo 讨论和真实样本替换后，再制作正式 Figma。
5. 设计正常、数据不足、历史不足、部分可用和延迟状态。
6. 完成可读性和典型案例走查。

### 阶段 P5：技术方案与实施

在产品口径和 Figma 评审通过后，再进入数据物化、自动任务、API、前端和验收方案。本产品稿不提前规定这些实现方式。

## 20. 待拍板项

以下问题不会阻塞首轮数据审计，但需要在 P0/P2 后确认：

1. 页面正式功能名使用“板块雷达”还是“板块冷热探查”。本稿暂用“板块雷达”。
2. 横向分数命名使用“今日热度”，纵向分数使用“自身热度状态”是否足够清晰，还是需要避免两个 0～100 分数同时出现。
3. 今日热度是否保留一个综合分，或先只展示价格、成交等已通过回测的独立分项与综合排名。
4. 二级、三级全市场同级辅助榜是否默认折叠，还是保留为显式范围开关。
5. 新闻、公告和讨论热度是否仅作为解释事件，还是未来独立形成“注意力”维度。
6. 热度高端继续使用“沸腾 / 高热 / 活跃”还是在回测后重新校准产品语言。

## 21. 与现有板块速览的关系

1. 本方案不修改首页板块速览 V2 的当前功能和 Heat V2 生产口径。
2. 板块雷达完成研究验证并发布 Heat V3 后，首页可以消费经过确认的简化摘要。
3. 首页只保留快速事实；趋势、多日上榜和分量解释留在财势探查。
4. Heat V2 与未来 Heat V3 必须通过独立版本区分，不能覆盖历史结果后假装口径未变化。
5. 财势探查中的父级下钻和回测信号不自动回流首页；任何摘要回流必须另行评审。
