# 财势探查｜板块雷达产品设计方案 v1（首版研究稿）

> 文档性质：产品设计方案，不是技术实施方案、API 契约或数据库设计。
> 当前状态：首版研究稿；双行业体系产品口径已确认，申万首版生产前置数据口径已冻结，等待数据集实施、历史覆盖验收和两套体系回测。
> 产品归属：财势乾坤 / 财势探查。
> 首期数据时效：A 股盘后数据。
> 版本日期：2026-08-16。

---

## 1. 文档结论

“板块雷达”作为财势探查的第一个功能，目标不是再做一个板块排行榜，而是建立一套可以持续回答下列问题的板块研究工具：

1. 今天哪些行业或概念最热，市场排名如何？
2. 哪些板块是连续成为热点，哪些只是单日脉冲？
3. 哪些板块正在稳步升温、持续获得资金流入或温和放量？
4. 一个板块的上涨是多数成分股共同参与，还是少数龙头拉动？
5. 东财与申万行业之间、两套行业与概念之间是否存在成分重合、同步共振、扩散或领先滞后关系？
6. 当前结论的数据是否完整、稳定、可解释？

本方案的核心决策是：

1. 把“同日全市场横向比较”和“单一板块跨日纵向变化”拆成两套量化体系。
2. 不再要求一个综合热度分数同时承担强弱、资金、成交、持续性和趋势解释。
3. 将热度拆解为价格强度、内部扩散、资金支持、成交活跃、持续性、集中度与拥挤度等独立事实。
4. 热度只描述市场参与状态，不直接等同于未来收益、买入价值或交易信号。
5. 所有公式、窗口、权重和阈值在上线前必须经过历史重建、分段回放和样本外验证；本稿只给出首版候选口径。
6. 行业同时支持东财和申万两套分类体系，页面允许切换；两套体系独立计算、独立排名，再通过同日成分重合和标准化事实进行比较，禁止混成一个行业榜。
7. 申万首版只采用 `SW2021`；“特钢Ⅲ”统一使用业务标准码 `850412.SI`，来源异常值必须保留审计痕迹。具体生产来源和存储口径以[数据覆盖审计](./sector-radar-data-coverage-audit-v1.md)为准。

## 2. 背景与产品机会

### 2.1 为什么不继续扩充首页板块速览

首页板块速览的职责是让用户快速看到当日客观事实，适合展示涨幅榜、跌幅榜、资金榜、概念热度和简要详情，不适合承载复杂筛选、跨周期比较、关系分析和模型解释。

财势探查则应承接“从事实继续研究”的任务：

```text
乾坤行情 / 市场总览
  └─ 快速发现：今天发生了什么

财势探查 / 板块雷达
  └─ 深入研究：为什么发生、持续多久、内部结构如何、是否形成联动
```

两处可以共享同一批已发布事实，但不能共享同一种信息密度和交互深度。

### 2.2 当前 Heat 口径暴露出的产品问题

现有概念 Heat 已证明盘后物化、历史回放和质量门禁能够运行，但前序审计也暴露出以下问题：

1. 同日横截面分位被直接当成跨日温度序列，板块相对名次变化会造成热度值大幅跳变。
2. 涨跌幅、上涨家数、资金流等因素在强势交易日高度同向，可能重复放大同一市场冲击。
3. 趋势标签通过连续确认获得稳定性，而图表展示的分数仍是原始横截面分数，容易出现“标签平稳、曲线剧烈跳变”。
4. 一个总分无法说明板块是价格驱动、资金驱动、成交驱动还是少数龙头驱动。
5. 当前榜单更适合展示结果，不足以支持用户研究热点的持续、扩散、轮动和关联。

因此，新能力应作为 Heat V3 的产品和研究重构，不在 Heat V2 上继续叠加展示规则。

## 3. 产品定位

### 3.1 一句话定位

> 板块雷达是一套以盘后客观数据为基础，可切换东财与申万行业体系，用于发现、解释、比较和跟踪 A 股行业与概念冷热变化的研究工作台。

### 3.2 目标用户

1. 需要在收盘后识别市场主线和弱势方向的主动研究者。
2. 需要跟踪热点持续性、资金与成交结构的复盘用户。
3. 希望从行业、概念进一步下钻到成分股事实的专业用户。

### 3.3 使用时点

首期以收盘后研究为主：

1. 当日必需数据全部发布后生成结果。
2. 用户看到的是已完成交易日的最终事实，不是盘中估算。
3. 盘中热度、分钟资金、实时预警不进入首版范围。

### 3.4 产品目标

1. 发现：从全市场中找出当日最热、最冷及变化最大的行业和概念。
2. 甄别：区分一日脉冲、连续热点、稳步升温、高位稳定与开始降温。
3. 解释：说明热度由价格、扩散、资金还是成交驱动。
4. 穿透：查看板块内部的成分表现、龙头贡献和集中程度。
5. 关联：识别东财与申万行业之间、两套行业与概念之间的重合、共振、扩散和领先滞后关系。
6. 对比：观察东财和申万对同一市场方向的划分、排名和趋势是否一致，解释差异来自分类边界还是成分结构。
7. 验证：任何模型结论都可以回到分类体系、分类版本、原始指标、交易日和成分池解释。

### 3.5 非目标

1. 不输出买入、卖出、加仓、减仓或仓位建议。
2. 不把热度分数解释成未来收益概率。
3. 不直接生成自动交易策略。
4. 不用新闻标题数量替代真实市场参与度。
5. 不在第一版引入不可解释的黑盒机器学习综合分。
6. 不把行业、概念和地域放入同一横截面混排。
7. 地域板块暂不进入板块雷达首版；继续作为市场总览的客观排行维度，后续有独立研究问题时再评估。
8. 不在本方案中确定技术架构、表结构、API、任务编排和前端组件。
9. 不把申万称为监管部门的法定行业分类；产品中应表述为市场广泛使用的专业行业分类体系。
10. 不按行业名称强行建立东财和申万一对一映射，不把两套体系的代码、层级、名次或来源分数直接混用。

## 4. 设计原理

### 4.1 横向比较和纵向变化必须分开

横向热度回答“今天谁比别人热”，纵向状态回答“这个板块相对自己的历史是否在升温”。两者不可直接复用同一分数。

| 维度 | 比较对象 | 主要用途 | 推荐标准化方式 |
|---|---|---|---|
| 横向 | 同一交易日的同类板块 | 今日排行、热点分布 | 同日横截面分位 |
| 纵向 | 同一板块自己的历史 | 升温、降温、持续性 | 自身历史稳健标准化 + 平滑 |

行业与概念分开计算。行业还要先按东财、申万分开，再按一级、二级、三级分组；只有“同一分类体系、同一层级”的候选才能进入同一个横截面排名。

### 4.2 先展示事实，再给综合结论

热度研究至少涉及以下七类事实：

| 事实 | 解释 |
|---|---|
| 价格强度 | 板块相对同类和市场表现是否强 |
| 内部扩散 | 上涨是否覆盖多数有效成分股 |
| 资金支持 | 净流入是否显著、持续并具有覆盖面 |
| 成交活跃 | 成交是否相对板块自身历史放大 |
| 持续性 | 板块是否连续处于市场前列 |
| 集中度 | 是否主要由少数龙头贡献 |
| 拥挤度 | 是否出现过热、巨量、过度集中或背离 |

综合热度只作为排序入口；详情必须展示分项、原始值、历史位置和数据质量。

### 4.3 热度、趋势与风险是三件事

1. 热度：当前市场参与程度。
2. 趋势：热度状态正在上升、稳定还是下降。
3. 拥挤风险：热点是否高度集中、加速过快或出现量价资金背离。

拥挤度不直接从热度中扣分。一个板块可以同时“很热”和“很拥挤”，产品必须允许这两个事实同时成立。

### 4.4 描述模型和预测模型分离

板块雷达第一版是描述和研究工具。未来如果需要估计热点延续概率，应新增独立的“延续性模型”，明确预测目标、预测周期和样本外表现，不能把预测逻辑隐藏在热度权重里。

### 4.5 每个结论必须带数据置信度

缺少关键事实时不重新分配剩余权重，不用零值代替缺失，也不沿用前一交易日结果伪造连续性。

建议的数据置信度定义为关键覆盖率中的最弱一项：

```text
dataConfidence = min(
  memberCoverage,
  quoteCoverage,
  moneyflowCoverage,
  historyCoverage,
  publicationCompleteness
)
```

原因是关键输入之间不存在可替代关系：行情完整不能补偿资金缺失，当前完整也不能补偿历史不足。

### 4.6 先可解释，再追求复杂

首版优先采用稳健分位、历史中位数、MAD、线性斜率、EWMA、相关和重合度等透明方法。机器学习可以在未来作为候选模型，但必须与透明基线进行样本外比较，并提供稳定的解释方式。

### 4.7 双行业体系独立计算，关系层再比较

东财行业和申万行业同时进入产品，但承担不同价值：

| 行业体系 | 主要价值 | 首版边界 |
|---|---|---|
| 东财行业 | 与首页板块速览一致，贴近市场用户和现有行业三级交互 | 当前历史共同窗口较短，行业层级只有当前版本 |
| 申万行业 | 分类规范、研究使用广泛，成员具备有效期字段，适合独立验证长历史行业规律 | 首版固定 SW2021；生产数据集尚未实施、历史完整率尚未验收，不能提前承诺 3～5 年可用 |

产品必须遵守：

1. 页面切换只改变当前行业体系，不改变指标含义和工作台骨架。
2. 每套体系分别维护对象身份、层级、成员有效期、排名、历史状态和数据置信度。
3. 跨体系比较使用同日成分重合、统一股票事实和各自体系内标准化结果，不直接比较来源方不可解释的原始分数。
4. 同一行业名称不代表同一对象；没有成员证据时不自动关联。
5. 页面始终显示当前行业体系和分类版本，避免用户误把申万结果理解成东财结果，或反之。

## 5. 产品信息架构

### 5.1 一级结构

```text
财势探查
└── 板块雷达
    ├── 市场横截面
    ├── 趋势追踪
    └── 行业体系与概念联动
```

### 5.2 工作台一：市场横截面

回答“今天市场在交易什么”。

主要能力：

1. 行业 / 概念切换。
2. 进入行业后切换东财行业 / 申万行业。
3. 每套行业体系内分别查看一级 / 二级 / 三级。
4. 今日综合热度排名。
5. 价格强度、资金流入、成交活跃、内部扩散等分项排名。
6. 最近 5、10、20 个交易日持续上榜筛选。
7. 热点集中度和数据置信度筛选。
8. 选择一个板块后查看右侧解释面板和成分贡献。

### 5.3 工作台二：趋势追踪

回答“哪些板块正在发生持续变化”。

主要能力：

1. 稳步升温。
2. 加速升温。
3. 高热稳定。
4. 连续资金流入。
5. 成交温和放大。
6. 量价、资金与扩散背离。
7. 降温和峰值回落。
8. 5、10、20 日观察窗口切换。
9. 行业视图沿用当前选择的东财 / 申万体系，不在趋势榜中混排两套行业。

### 5.4 工作台三：行业体系与概念联动

回答“热点之间是什么关系”。

主要能力：

1. 从东财行业查看最相关的申万行业，从申万行业反向查看最相关的东财行业。
2. 从任一行业体系查看相关概念及其成分重合度。
3. 从概念查看其成分股分别分布在哪些东财行业和申万行业。
4. 观察两套行业体系以及行业与概念的价格、资金、热度状态是否同步。
5. 检查概念相对行业、东财行业相对申万行业的历史领先或滞后关联。
6. 识别双体系共识、体系分歧、行业共振、行业内扩散、孤立题材和高度重合。

### 5.5 统一板块详情

选中任一行业或概念后，详情区按相同时间轴展示：

1. 今日横向热度和同类排名。
2. 自身热度状态和趋势标签。
3. 价格强度。
4. 内部扩散度。
5. 资金流入强度。
6. 成交活跃度。
7. 龙头贡献和集中度。
8. 最近 5、10、20 日上榜记录。
9. 有效成分股、停牌、缺行情和资金覆盖情况。
10. 成分股贡献明细。
11. 当前分类体系、分类版本，以及可切换的对应体系关系。

图表优先使用共用横轴的多行小图，不把不同单位强行叠加在同一纵轴。

## 6. 量化框架总览

### 6.1 口径状态说明

本章将量化口径分为三种状态：

| 状态 | 含义 |
|---|---|
| 已确认原则 | 产品逻辑已经确认，后续不能反向合并 |
| 首版候选 | 可用于历史验证的第一批公式，不代表最终生产值 |
| 待验证参数 | 必须通过数据分布、回放和样本外结果选择 |

### 6.2 基础符号

| 符号 | 含义 |
|---|---|
| `S` | 分类体系；首版包括东财行业、申万行业和概念 |
| `i` | 某个带分类体系与分类版本身份的行业或概念板块 |
| `t` | 某个已发布交易日 |
| `G` | 同类横截面；概念单独成组，行业按“东财/申万 × 一级/二级/三级”分别成组 |
| `M(i,t)` | 板块在交易日 `t` 的有效 A 股成分池 |
| `Pcs(x)` | 指标 `x` 在同日同类横截面的 0～100 稳健分位 |
| `Zts(x)` | 指标 `x` 相对该板块自身历史的稳健标准分 |
| `W` | 观察窗口，首批候选为 5、10、20 个交易日 |

横截面极端值先做稳健缩尾；时间序列标准化优先使用历史中位数和 MAD，避免均值和标准差被极端行情扭曲。

### 6.3 有效 A 股成分池

所有成员类量化都基于目标交易日真实有效成分池：

1. 成分关系必须是目标交易日当时有效的关系，不能使用今天的成员回算历史。
2. 只保留当时已经上市且尚未退市的人民币 A 股。
3. 停牌证券保留为板块成员，但不进入当日可报价分母。
4. 缺少有效行情的非停牌成员进入缺失计数，不按下跌或零收益处理。
5. 板块样本过小或行情覆盖不足时，相关指标标记无效。

这是所有回测的首要门禁。没有历史成分时，只能验证板块级指标，不能伪造历史扩散度和成分贡献。

## 7. 基础量化维度

### 7.1 价格强度

#### 用户问题

这个板块今天相对同类和市场究竟强不强？

#### 首版候选事实

```text
relativeReturn1d(i,t)
  = sectorReturn1d(i,t) - median(sectorReturn1d(G,t))
```

东财行业各层级、申万行业各层级和概念分别计算。横向价格强度候选为：

```text
priceStrengthCs(i,t) = Pcs(relativeReturn1d(i,t))
```

纵向价格趋势不再重复叠加“当日涨跌幅、五日相对强度、日度加速度”，而是单独观察累计相对收益序列的 5、10、20 日斜率和回撤。

#### 设计理由

1. 板块绝对上涨可能只是全市场普涨，相对收益更能说明同类中的强弱。
2. 当日涨幅同时进入多个高度重合的子指标会重复放大同一冲击。
3. 行业动量研究表明行业层面的相对表现具有独立研究价值，但公开研究多基于海外和较长周期，不能直接证明 A 股日频有效，必须单独回测。

#### 待验证

1. 直接使用板块官方涨跌幅，还是使用有效成分股等权/流通市值加权收益作为主事实。
2. 同类中位数与宽基市场基准哪个更适合作为超额收益基准。
3. 日频、3 日和 5 日趋势的响应速度与噪声权衡。

### 7.2 内部扩散度

#### 用户问题

板块上涨是多数股票共同参与，还是少数龙头拉动？

#### 首版候选事实

```text
upRatio(i,t)
  = count(memberReturn > 0) / validQuoteCount

positiveExcessRatio(i,t)
  = count(memberReturn > marketMedianReturn) / validQuoteCount

medianMemberReturn(i,t)
  = median(valid member returns)

limitUpRatio(i,t)
  = limitUpMemberCount / validQuoteCount
```

扩散度候选：

```text
breadthCs = weighted_mean(
  Pcs(upRatio),
  Pcs(positiveExcessRatio),
  Pcs(medianMemberReturn),
  capped Pcs(limitUpRatio)
)
```

首版不冻结分量权重。涨停比例只作为补充，且需要限制小样本板块被一只涨停股夸大的影响。

#### 设计理由

1. 板块涨跌幅无法区分普遍参与和少数股票拉动。
2. 上涨家数比和成分收益中位数对极端龙头不敏感。
3. 扩散与龙头集中度同时展示，能解释“热但不广”和“涨幅一般但内部普遍改善”两种状态。

#### 待验证

1. 有效成分数量下限。
2. 涨停比例的小样本收缩方式。
3. 等权扩散与流通市值加权扩散是否同时展示。

### 7.3 资金支持度

#### 用户问题

上涨是否得到资金支持，资金是否持续，流入是否覆盖多数成分？

#### 首版候选事实

```text
netFlowRate(i,t)
  = sectorNetInflow(i,t) / sectorAmount(i,t)

positiveFlowStreak(i,t)
  = 截至 t 连续净流入交易日数

positiveFlowHitRateW(i,t)
  = W 日内净流入天数 / W

cumulativeFlowRateW(i,t)
  = sum(sectorNetInflow) / sum(sectorAmount), over W days

flowSlopeW(i,t)
  = W 日 netFlowRate 的稳健线性斜率
```

若未来具备可靠的个股资金流，可增加：

```text
memberFlowBreadth(i,t)
  = count(memberNetInflow > 0) / validMemberFlowCount
```

#### 设计理由

1. 绝对净流入金额偏向成交规模大的板块，净流入占成交额比例更适合横向比较。
2. 连续天数、窗口命中率和累计流入分别表达连续性、容错性和资金规模，不能互相替代。
3. 板块级净流入可能由少数权重股贡献，未来需要成员资金覆盖面辅助解释。

#### 待验证

1. 当前板块资金流字段跨日期、行业和概念的覆盖率及稳定性。
2. 小额流出是否允许作为连续流入中的“噪声容忍”，以及容忍阈值。
3. 资金流口径是否具有结构性修订或源站回补。

### 7.4 成交活跃度

#### 用户问题

板块成交是否相对自身历史放大，是温和扩张还是一次性巨量？

#### 首版候选事实

```text
amountRatio20(i,t)
  = sectorAmount(i,t) / median(sectorAmount(i,t-20...t-1))

activityLevel(i,t)
  = Zts(log(amountRatio20(i,t)))

amountSlopeW(i,t)
  = W 日 log(amountRatio20) 的线性斜率

amountMonotonicityW(i,t)
  = count(amountRatio20(t) > amountRatio20(t-1)) / (W-1)

amountCVW(i,t)
  = std(amountRatio20 over W) / mean(amountRatio20 over W)
```

#### “温和放量”首版候选条件

同时满足：

1. `amountSlopeW > 0`。
2. `amountMonotonicityW` 达到候选门槛。
3. `amountCVW` 不处于同类历史高位。
4. 单日成交放大量未超过“脉冲成交”阈值。
5. 有效成员和行情覆盖达标。

门槛不在本稿写死，首批建议研究 `W=5/10`、单调率 `60%～80%`、历史分位阈值 `80%～95%`。

#### 设计理由

1. 绝对成交额无法跨不同规模板块直接比较。
2. 与自身 20 日中位数相比可以降低板块规模差异。
3. 正斜率只能说明上升，低波动和单日脉冲限制用来区分“温和放大”和“突然巨量”。
4. 公开量价研究表明历史成交量与价格动量的强度和持续存在关系，但不能据此把放量直接解释为看涨。

### 7.5 龙头贡献与集中度

#### 用户问题

板块表现由多少只股票贡献，是否过度依赖少数龙头？

#### 首版候选事实

成分股贡献需要同时计算等权和规模加权两个视角：

```text
equalContribution_j = memberReturn_j / memberCount

floatWeightedContribution_j
  = floatWeight_j * memberReturn_j

top3PositiveContributionRatio
  = top3 positive contributions / total positive contributions

top5TurnoverShare
  = top5 member amount / total member amount
```

集中度可以同时使用 Top3/Top5 占比和 HHI，不强行压缩成一个不可解释的数字。

#### 设计理由

1. 等权贡献适合看参与面，规模加权贡献适合解释板块指数表现。
2. 龙头集中不是天然负面事实，但会改变热点的稳定性和可扩散性。
3. 集中度应作为独立诊断和拥挤提示，不直接从热度中扣分。

#### 数据前提

需要可靠的目标交易日流通市值或自由流通市值。缺少该数据时只能展示等权贡献，不能用总市值或当前市值倒推历史权重。

### 7.6 拥挤与背离

#### 用户问题

板块虽然很热，是否出现集中、巨量或内部跟随不足？

#### 首版候选信号

| 信号 | 候选量化条件 |
|---|---|
| 高热高集中 | 今日热度进入同类高分位，且 Top3/Top5 贡献处于自身历史高分位 |
| 巨量脉冲 | `amountRatio20` 进入历史极端分位，但成交斜率与单调率不支持温和放量 |
| 价涨扩散弱 | 相对收益为正且排名靠前，但 `upRatio/medianMemberReturn` 未同步改善 |
| 资金价背离 | 价格强度上升而 `netFlowRate` 下降，或相反 |
| 热度见顶 | 热度状态高位，趋势斜率转负且回撤扩大 |

这些信号是研究提示，不是风险预测，也不直接触发交易建议。

## 8. 横向热度设计

### 8.1 定义

“今日热度”表示板块在同日同类市场中的相对参与程度，用于当天排名，不用于直接绘制板块跨日温度趋势。

### 8.2 首版候选公式族

候选基础分量：

1. `priceStrengthCs`
2. `breadthCs`
3. `capitalFlowCs`
4. `activityCs`

候选公式不是只保留一套，而是进入回测比较：

| 候选 | 价格 | 扩散 | 资金 | 活跃 | 用途 |
|---|---:|---:|---:|---:|---|
| H0 等权基线 | 25% | 25% | 25% | 25% | 最简单透明基线 |
| H1 均衡候选 | 30% | 25% | 25% | 20% | 保留价格识别力但避免过度主导 |
| H2 参与优先 | 25% | 30% | 25% | 20% | 强调内部参与而非单日涨幅 |

候选总式：

```text
marketHeatScore(i,t)
  = weighted_sum(priceStrengthCs, breadthCs, capitalFlowCs, activityCs)
```

所有分量为 0～100 的同日同类分位。某个关键分量无效时，综合分数无效，不重分配权重。

### 8.3 今日榜单

1. 所有板块展示完整排名，不只返回 Top N。
2. “上榜”首版候选定义为同类横截面前 20%，而不是统一固定 20 名。
3. 前 20% 对概念和不同层级行业具有更可比的覆盖比例。
4. 页面仍可显示 Top10、Top20 等快捷视图，但持续性计算使用分位门槛，避免一级行业样本较少时榜单过宽。

### 8.4 今日热度等级

“沸腾 / 高热 / 活跃”等产品语言可以保留，但阈值不直接沿用 Heat V2。首版研究同时比较：

1. 固定分数阈值。
2. 横截面分位等级。
3. 分数 + 分量一致性的联合等级。

等级只有在数据分布和跨行情阶段稳定后才冻结。低热板块不必强制贴负面标签，可以直接展示热度值、排名和降温状态。

## 9. 纵向热度状态与趋势

### 9.1 定义

“自身热度状态”表示同一个板块当前的市场参与事实相对其自身历史处于什么位置。

它不直接使用每日横向名次，而是对板块自己的价格、扩散、资金和活跃原始事实做历史标准化。

### 9.2 状态输入

```text
stateInput(i,t) = weighted_sum(
  Zts(relativeReturn1d),
  Zts(upRatio and medianMemberReturn),
  Zts(netFlowRate),
  Zts(log(amountRatio20))
)
```

历史基线首批研究 60、120、250 个交易日。状态输入经过有界映射转为 0～100，再进入平滑。

### 9.3 平滑候选

首版使用透明的指数加权移动平均作为基线候选：

```text
heatState(i,t)
  = lambda * stateInput(i,t)
  + (1 - lambda) * heatState(i,t-1)
```

`lambda` 越大，响应越快但噪声越高；越小，曲线越平稳但识别新热点更慢。首批建议比较 `0.20、0.30、0.40、0.50`，不在产品稿中提前确定最终值。

NIST 对 EWMA 的说明表明，它通过对更早数据赋予逐步降低的权重来监测较小、渐进变化；这里借用的是“平滑与小变化检测”思想，不把工业过程控制阈值直接照搬到金融市场。

### 9.4 趋势量化

```text
stateSlopeW
  = W 日 heatState 的线性斜率

trendMonotonicityW
  = count(deltaHeatState > 0) / (W-1)

trendFitW
  = W 日线性趋势拟合优度 R²

maxStatePullbackW
  = W 日内从局部高点到后续低点的最大状态回撤

normalizedSlopeW
  = stateSlopeW / robustResidualVolatilityW
```

### 9.5 趋势状态候选

| 状态 | 候选量化逻辑 | 产品含义 |
|---|---|---|
| 稳步升温 | 正斜率 + 较高单调率 + 较高拟合度 + 回撤受控 | 热度持续抬升且路径平稳 |
| 加速升温 | 短窗斜率显著高于长窗斜率，且分量同步改善 | 热度上升速度加快 |
| 高热稳定 | 自身状态处于历史高分位，斜率接近零且波动受控 | 维持高位但没有继续加速 |
| 脉冲升温 | 当日状态跳升，但单调率、拟合度或连续确认不足 | 可能是一日事件，需要继续观察 |
| 峰值回落 | 高位状态下斜率转负，回撤扩大 | 热点开始失速 |
| 持续降温 | 负斜率 + 较高下降单调率 + 连续确认 | 参与度持续减弱 |
| 无明确趋势 | 方向和稳定性门槛均不满足 | 波动或横盘，不强行贴标签 |

具体门槛通过回测选择。趋势标签必须与页面曲线使用同一 `heatState` 序列，禁止标签和平滑曲线各用一套数据。

## 10. 持续上榜设计

### 10.1 两种事实不能混淆

```text
currentStreak(i,t)
  = 截至 t 连续满足上榜条件的交易日数

hitCountW(i,t)
  = 最近 W 日满足上榜条件的天数

hitRateW(i,t)
  = hitCountW / W
```

连续上榜适合识别当前主线；窗口命中适合识别反复活跃但中间有间断的板块。

### 10.2 首版候选筛选

| 观察窗口 | 连续上榜候选 | 同时展示 |
|---|---:|---|
| 最近 5 日 | 当前连续至少 3 日 | 5 日命中次数、平均排名 |
| 最近 10 日 | 当前连续至少 5 日 | 10 日命中次数、平均排名 |
| 最近 20 日 | 当前连续至少 10 日 | 20 日命中次数、平均排名 |

这些是用户提出的首批研究口径，不在回测前冻结。需要分别检查它们在东财行业各层级、申万行业各层级和概念中是否过松或过严。

### 10.3 持续度候选分数

```text
persistenceScoreW = 100 * (
  a * normalizedCurrentStreak
  + b * hitRateW
  + c * averageRankQualityW
  + d * rankStabilityW
)
```

建议首先比较简单的等权基线与“连续天数优先”候选。持续度不进入今日横向热度原始分，避免用历史结果反过来强化今天的横向排名；它作为独立榜单和解释维度展示。

## 11. 纵向专题量化

### 11.1 稳步升温

候选评分：

```text
steadyHeatingScoreW = 100 * (
  0.35 * positiveNormalizedSlope
  + 0.30 * trendMonotonicity
  + 0.20 * trendFit
  + 0.15 * controlledPullback
)
```

权重只是首版候选。四项分别防止以下误判：

1. 只有方向、没有速度。
2. 只有期初期末差、路径剧烈反复。
3. 斜率由单日跳点决定。
4. 总体向上但中途回撤过大。

### 11.2 连续资金流入

页面同时展示：

1. 当前连续净流入天数。
2. 5、10、20 日净流入命中率。
3. 窗口累计净流入占成交额。
4. 资金流强度斜率。
5. 若数据可用，成分股资金流入覆盖率。

候选评分：

```text
flowPersistenceScoreW = 100 * (
  0.35 * normalizedPositiveFlowStreak
  + 0.25 * positiveFlowHitRate
  + 0.25 * Pcs(cumulativeFlowRateW)
  + 0.15 * positiveFlowSlope
)
```

绝对流入金额只作为解释值，不作为跨板块主排序。

### 11.3 成交温和放大

候选评分：

```text
gentleExpansionScoreW = 100 * (
  0.35 * positiveAmountSlope
  + 0.30 * amountMonotonicity
  + 0.20 * moderateActivityLevel
  + 0.15 * lowPulsePenalty
)
```

其中 `moderateActivityLevel` 偏好相对历史明显放大但未达到极端脉冲的区间；`lowPulsePenalty` 对单日巨量和高波动扣分。最终区间必须由历史分布决定，不能凭经验固定为某个量比。

## 12. 行业体系与概念联动

### 12.1 先分开计算，再研究关系

东财行业、申万行业和概念是三个不同的分类空间：

1. 东财行业和申万行业都具有一级、二级、三级，但层级边界和成员不相同。
2. 同一体系内只有同层比较才有意义，两套行业体系不能进入同一个原始排名。
3. 概念通常跨行业，可能同时对应多个东财行业和申万行业，不能与行业直接混排。
4. 三个分类空间的热度、持续度和趋势先各自计算，再建立关系层。

### 12.2 成分重合

```text
jaccardOverlap(A, B, t)
  = |membersA ∩ membersB|
    / |membersA ∪ membersB|

aCoveredByB
  = |intersection| / |membersA|

bCoveredByA
  = |intersection| / |membersB|
```

`A/B` 可以是东财行业与申万行业，也可以是任一行业与概念。三个指标分别表达对称重合和两个方向的覆盖程度，不能只留一个重合比例。

具备历史流通市值后，可增加加权重合度，用于判断重合是否集中在少数权重股。

### 12.3 双体系比较口径

东财和申万可以对比，但不能把来源不同的原始板块分数直接相减。首版比较分为三层：

1. **成员层**：同日 Jaccard 和双向覆盖率，解释两套体系实际上覆盖了哪些相同股票。
2. **统一事实层**：用同一套股票行情、个股资金流、流通市值和有效池规则，分别按两套历史成员聚合价格、扩散、资金和成交事实。
3. **体系内结果层**：比较各自在本体系、同层级中的分位、趋势状态和持续上榜情况，形成“共识”或“分歧”，但不生成跨体系混合名次。

来源方直接提供的板块涨跌幅、成交额和资金流保留为本体系参考事实和聚合结果校验。若一个体系使用来源板块资金、另一个体系使用成员资金聚合，页面必须明确口径不同，不得包装成完全可比的同一指标。

### 12.4 同步与领先滞后

候选关系事实：

1. 20、60 日市场调整后相对收益相关。
2. 20、60 日热度状态相关。
3. 资金流强度相关。
4. 在 `-5...+5` 个交易日内的领先滞后相关峰值。

领先滞后必须满足：

1. 样本长度和有效日期覆盖达标。
2. 最大相关显著高于零滞后或相邻滞后。
3. 在滚动窗口中方向稳定。
4. 剔除重合成分贡献后仍保留关系，或明确标注“主要由成员重合解释”。

产品只表述“历史领先关联”或“历史滞后关联”，不表述为因果关系。

### 12.5 关系标签候选

| 标签 | 候选条件 |
|---|---|
| 双体系共识 | 相关东财行业与申万行业同时处于各自同层高热或升温状态，且成员关系置信度达标 |
| 体系分歧 | 高重合行业在价格、扩散、资金或趋势状态上明显分化，且差异不能由数据缺失解释 |
| 行业共振 | 行业与相关概念同时高热或升温，收益/状态同步且关系置信度达标 |
| 概念领先 | 概念状态变化在滚动窗口中稳定领先相关行业，剔除重合影响后仍成立 |
| 行业内扩散 | 行业状态改善，同时升温的相关概念数量和行业内部扩散度持续增加 |
| 孤立题材 | 概念高热，但与主要行业的状态、资金和成分覆盖关系均弱 |
| 高度重合 | 成分与权重重合度高，表面联动主要由同一批股票解释 |
| 关系不足 | 历史、覆盖或稳定性不足，不生成关系结论 |

公开研究曾观察到部分行业收益包含对更广市场的领先信息，这支持我们测试行业与概念的领先滞后关系，但不能直接证明 A 股日频概念与行业存在稳定因果链。

## 13. 页面核心功能与量化映射

| 产品功能 | 用户看到什么 | 核心量化事实 | 为什么需要 |
|---|---|---|---|
| 今日热度排行 | 分数、名次、分项雷达/条形 | 同日同类横向分位综合 | 回答今天谁最热 |
| 分项排行 | 价格、扩散、资金、活跃榜 | 各独立分量横向分位 | 防止综合分掩盖驱动差异 |
| 5/10/20 日持续上榜 | 连续天数、命中次数、平均名次 | streak、hitRate、rankQuality | 区分主线和反复活跃 |
| 稳步升温 | 趋势状态、斜率、单调率、回撤 | 平滑状态趋势组合 | 区分平稳演进与跳点 |
| 连续资金流入 | 连续天数、累计流入率、流入斜率 | 净流入占成交额及其历史 | 判断资金支持是否持续 |
| 温和放量 | 活跃比、成交斜率、波动、脉冲标记 | 相对 20 日中位数的成交序列 | 区分增量参与和单日巨量 |
| 板块内部穿透 | 上涨比例、收益中位数、龙头贡献 | 成分行情与贡献分解 | 判断上涨是否具有扩散 |
| 拥挤与背离 | 高集中、巨量、价量/价资背离 | 集中度、极端分位和方向差 | 揭示热度背后的结构风险 |
| 行业体系与概念联动 | 双体系共识/分歧、行业概念重合、同步、领先和扩散关系 | 同日成分重合、统一成员聚合事实、残差相关和滚动领先滞后 | 解释分类差异、主线传导和重复暴露 |
| 数据置信度 | 有效/部分/不足及原因 | 各关键覆盖率的最弱项 | 防止无效数据被包装成结论 |

### 14.1 首版必需数据

| 数据域 | 需要的事实 | 主要用途 | 建议历史长度 |
|---|---|---|---:|
| 交易日 | 开闭市日期、前序交易日 | 所有窗口和日期对齐 | 全历史 |

| 板块资金流 | 直接板块资金与统一成员聚合资金 | 体系内资金支持、跨体系可比事实和持续流入 | 至少 250 日，目标 3～5 年 |

当前 Heat V2 已使用的生产事实包括东财板块目录、板块日行情、板块成分、板块资金流、个股日行情、证券资格、停牌、涨停和交易日，可以作为东财路线的首版基础。[数据覆盖审计](./sector-radar-data-coverage-audit-v1.md) 已确认东财共同历史为 400 个交易日；申万分类、有效期成员和行业日行情来源存在，首版已固定只做 `SW2021`，但生产前置数据尚未实施，全量历史完整率仍未验收。双体系回测必须分别建立可用日期集合，不能用东财验收结果代替申万验收。

申万生产前置数据还必须遵守以下产品事实：

1. 分类和父子层级、带有效期的成员关系、行业指数日行情是三类不可互相替代的产品事实。
2. 申万分类代码、指数代码和股票代码是不同身份，页面与研究结果只消费经过确认的标准身份，不直接使用源接口异常值拼接。
3. “特钢Ⅲ”的分类身份是 `industry_code=230501`，业务指数代码固定为 `850412.SI`；`850401.SI` 只作为来源异常值留痕，`840401` 是输入笔误、不属于产品数据。
4. 节省重复存储不能削弱产品所需的来源可追溯、历史成员有效期和数据完整性要求。

### 14.2 强烈建议补充的数据

| 数据 | 价值 | 没有时的降级 |
|---|---|---|
| 历史流通市值/自由流通市值 | 规模加权贡献、加权成分重合、避免小股票和大股票权重失真 | 只做等权扩散和贡献 |
| 个股换手率 | 比成交额更直接表达交易活跃 | 使用成交额相对历史中位数 |
| 个股资金流 | 判断资金是否覆盖多数成分，而非少数权重股 | 只展示板块级资金流 |
| 涨停明细、炸板、连板高度 | 加强强情绪与拥挤结构识别 | 只用涨停家数比，不做更细情绪解释 |
| 板块官方指数权重 | 精确解释板块指数贡献 | 使用流通市值近似，并明确口径 |

### 14.3 可后置探索的数据

| 数据 | 潜在用途 | 首版态度 |
|---|---|---|
| 新闻与公告 | 解释热点事件和信息扩散 | 只作解释层，不进入首版热度主分 |
| 搜索/讨论热度 | 补充注意力维度 | 来源稳定性、合规和抗操纵性未验证前不接入 |
| 龙虎榜 | 观察短线资金集中 | 作为专题事实，不代表全板块资金 |
| 分钟行情与分钟成交 | 盘中热度与启动时点 | 首版盘后产品不需要 |
| 盘口与封单 | 盘中情绪强度 | 后续实时版再评估 |

### 14.4 数据质量要求

1. 日期一致：同一结果不得混用不同交易日的行情、成员和资金。
2. 时间可得：回测只能使用当时已经发布的数据。
3. 成分有效：历史成员必须按当时有效关系计算。
4. 缺失显式：缺失不等于零，不做前向填充伪造资金或热度连续性。
5. 源修订可追踪：源数据回补或修订后，研究结果能够识别版本差异。
6. 样本可比：东财行业各层级、申万行业各层级和概念分别设定最小样本数和覆盖门槛。
7. 资金可信：资金流必须审计日期覆盖、代码覆盖、异常极值和源站回补行为。
8. 体系隔离：东财和申万分别维护代码、层级、版本、成员和结果，任何跨体系关系必须带映射日期和覆盖证据。
9. 比较同源：跨体系比较优先使用同一股票事实聚合；使用来源方板块指标时必须展示来源和口径差异。

## 15. 历史回测与量化验证方案

### 15.1 回测目的

本产品的第一目标是描述市场状态，因此回测不能只看未来收益。验证分为三层：

1. 状态质量：分数是否稳定、及时、可解释。
2. 结构有效性：分项是否真的对应价格、扩散、资金和成交事实。
3. 前瞻研究：不同热度和趋势状态之后的收益、延续和反转分布，仅作为探索，不反向定义热度。

### 15.2 数据窗口

1. 60 个有效交易日只能验证计算链路、幂等和基本连续性，不足以选择模型。
2. 首轮模型研究最低使用 250 个有效交易日。
3. 目标使用至少 3 年数据，优先争取 5 年以上，以覆盖不同市场阶段。
4. 历史成分不足的日期不能用当前成分替代，应缩短成员类指标窗口或标记不可验证。

### 15.3 对照模型

至少比较：

1. Heat V2 现行分数。
2. 只使用当日涨跌幅的简单横向排名。
3. 四维等权横向热度 H0。
4. 均衡候选 H1。
5. 参与优先候选 H2。
6. 不平滑纵向输入。
7. 多个 EWMA 参数的纵向状态。

不能只展示最终胜出的模型，所有候选及淘汰原因都要保留。

### 15.4 状态质量指标

| 指标 | 定义 | 希望解决的问题 |
|---|---|---|
| 日变化绝对值分布 | `abs(score_t-score_t-1)` 的中位数、P90、P95 | 是否仍然大幅跳变 |
| 一阶自相关 | 同一板块相邻日状态相关 | 状态是否具有合理连续性 |
| 排名跳变 | 相邻日绝对名次变化 | 横向榜单是否过度换手 |
| Top 分位留存 | 今日前 20% 次日仍在前 20% 的比例 | 热点榜是否只有随机轮换 |
| 标签切换率 | 相邻日状态标签变化比例 | 产品语言是否频繁反复 |
| 事件响应延迟 | 明显价格/资金/扩散事件到状态识别的交易日数 | 平滑是否过度迟钝 |
| 无效率 | 因成员、行情、资金、历史不足而无效的比例 | 数据能否支撑产品 |
| 分量支配率 | 单一分量对总分变动和方差的贡献 | 是否又退化为涨幅榜 |

首版不写死绝对合格值，先使用相对 Heat V2 的改善幅度建立门槛。候选目标可包括：

1. P95 日跳变下降至少 30%，同时显著事件识别延迟不超过 1～2 个交易日。
2. Top 分位次日留存明显高于简单涨幅榜和随机基线。
3. 任一单一分量不能长期解释绝大多数综合分变化。
4. 标签与曲线方向一致率接近 100%，不允许再次出现标签稳定而展示曲线方向相反。

具体阈值在首轮分布报告后再冻结。

### 15.5 分项有效性验证

#### 价格强度

1. 与同类相对收益排序一致。
2. 不被全市场普涨或普跌完全主导。
3. 东财行业各层级、申万行业各层级和概念分别观察分布。

#### 扩散度

1. 高扩散板块应具有更高的上涨成员比例和收益中位数。
2. 与板块涨跌幅相关但不能完全等价。
3. 小样本板块不应因为一只涨停股进入最高分位。

#### 资金支持

1. 净流入率比绝对金额更少受板块规模主导。
2. 连续流入、窗口命中和累计流入能区分不同资金路径。
3. 回补或缺失日期不会被误判为零流入。

#### 成交活跃

1. 相对历史成交比不应长期偏向大板块。
2. 温和放量与单日巨量在历史案例中可被区分。
3. 不把无价格扩散支持的巨量自动解释为正面状态。

### 15.6 前瞻探索

热度不是预测模型，但仍需要观察其后续行为，以了解产品语言是否误导用户。

建议按东财行业各层级、申万行业各层级和概念分别统计：

1. 热度五分组未来 1、3、5、10 日相对收益分布。
2. 稳步升温、脉冲升温、高热稳定、峰值回落后的延续率和回撤。
3. 连续资金流入与温和放量组合后的收益和扩散变化。
4. 高热高集中与高热高扩散两类板块的后续差异。
5. 横向热度、纵向状态和未来收益之间的信息系数，仅作研究记录。

这些结果不决定“热度是否正确”，但如果某个标签长期诱导出与产品直觉相反的理解，需要修改产品语言或增加风险解释。

### 15.7 样本外和防过拟合

1. 按时间划分研究期、校准期和最终保留期，禁止随机打乱时间序列。
2. 使用滚动或扩展窗口做 walk-forward 验证。
3. 牛市、熊市、震荡、高波动、低波动阶段分别报告。
4. 东财行业一级/二级/三级、申万行业一级/二级/三级和概念分别报告，不能只给全体平均，也不能只给合并后的行业平均。
5. 在验证前登记候选公式、权重和窗口，限制参数搜索数量。
6. 最终保留期只允许使用一次；失败后新增模型版本，不能反复调参直到通过。
7. 检查参数敏感性：相邻参数应产生方向一致的结论，不能只有一个孤立参数点表现最好。
8. 保留数据修订和回放版本，避免历史结果不可复现。

公开的回测过拟合研究指出，从大量历史模拟中挑选最好结果容易得到样本内假象。本产品因此不采用“遍历所有权重后挑最好看曲线”的方式。

### 15.8 案例复核

自动指标之外，至少选择以下案例做人类可解释性复核：

1. 连续主线行情。
2. 单日政策或事件脉冲。
3. 龙头独涨、板块内部不跟随。
4. 资金持续流入但价格尚未明显上涨。
5. 成交温和放大后形成扩散。
6. 巨量冲高后快速降温。
7. 行业与多个概念同步共振。
8. 高度重合造成的表面联动。
9. 数据缺失、停牌比例高或成员变更明显的异常日期。

每个案例必须能回到分项值、成分贡献、原始交易日和数据置信度解释。

## 16. 首版研究通过门槛

以下门槛通过后，才进入正式交互设计和技术方案阶段。

### 16.1 数据门槛

1. 明确各数据域可用起止日期、完整交易日数量和缺口。
2. 历史成分关系可按交易日还原；不能还原的范围被显式排除。
3. 行情、资金、停牌、涨停和成员具有一致的交易日语义。
4. 东财、申万各层级与概念的有效样本数分别满足量化计算要求。
5. 资金流和流通市值的覆盖率能够支持对应功能，否则功能明确降级。

### 16.2 模型门槛

1. 横向热度与纵向状态已经完全分离。
2. 热度跳变相对 V2 显著改善，且不过度牺牲事件响应速度。
3. 各分量不重复计算同一事实，相关性和方差贡献得到报告。
4. 状态标签与展示曲线使用同一序列。
5. 主要结论在不同市场阶段和相邻参数下保持基本稳定。
6. 所有无效结果有明确原因，不生成伪分数。

### 16.3 产品门槛

1. 用户可以在一次查看中回答“谁热、为何热、持续多久、内部是否扩散”。
2. 综合结论可以展开到独立事实，不形成黑盒。
3. 东财与申万、行业与概念的关系都能够区分真实同步、分类边界差异和成分重合。
4. 页面不暗示热度等于收益预测或投资建议。
5. 至少完成一轮典型案例评审并修改产品语言。

## 17. 产品效果指标

板块雷达上线后的产品有效性不以点击量单独衡量，首版建议关注：

### 17.1 主要指标

1. **可解释覆盖率**：有有效综合结论的板块中，能够完整展示关键分项、原始值和数据质量的比例。目标方向为 100%。
2. **研究结论稳定性**：相邻交易日无事实支撑的标签反复率和极端跳变率。目标以 Heat V2 为基线显著下降。
3. **发现到穿透率**：用户从横向榜或趋势筛选进入板块内部解释的会话比例，用于判断产品是否真的支持研究，而非只看排名。

### 17.2 诊断指标

1. 用户在东财行业、申万行业、概念和三个工作台之间的使用分布。
2. 5、10、20 日窗口使用分布。
3. 数据不足导致的功能降级率。
4. 用户查看分量、成分贡献和联动关系的比例。
5. 同一板块在多个交易日被重复研究的比例。

### 17.3 防误导护栏

1. 不展示未经验证的收益预测概率。
2. 不把热度标签写成操作建议。
3. 无效数据不进入排行。
4. 关系置信度不足时不生成“领先”或“共振”标签。

## 18. 公开研究与开源实践参考

本节只解释产品原理来源，不代表公开研究可以直接迁移到 A 股日频板块。

1. [Moskowitz & Grinblatt, Do Industries Explain Momentum?](https://onlinelibrary.wiley.com/doi/10.1111/0022-1082.00146)：行业层面的收益动量具有独立研究价值，支持将行业作为研究对象，而不只是股票的分类标签。
2. [Moskowitz, Ooi & Pedersen, Time Series Momentum](https://w4.stern.nyu.edu/facdir/lpederse/papers/TimeSeriesMomentum.pdf)：明确区分横截面动量和基于对象自身历史的时间序列动量，为本方案拆分横向热度与纵向状态提供方法论依据。
3. [Lee & Swaminathan, Price Momentum and Trading Volume](https://onlinelibrary.wiley.com/doi/abs/10.1111/0022-1082.00280)：历史成交量与价格动量的强度和持续性存在关系，支持把成交活跃作为独立解释维度，而非涨跌幅的附属展示。
4. [Hong, Torous & Valkanov, Do Industries Lead the Stock Market?](https://escholarship.org/content/qt6x49x543/qt6x49x543_noSplash_d7fe8ea2dceecd78b673a460a0dd47c1.pdf)：部分行业历史上表现出对更广市场的领先信息，支持研究行业与概念的领先滞后关系，但不能直接推断因果。
5. [NIST EWMA 说明](https://itl.nist.gov/div898/handbook/mpc/section2/mpc2211.htm)：EWMA 对渐进变化的监测适合用作透明平滑基线，具体参数仍需用金融数据校准。
6. [Quantopian Alphalens](https://github.com/quantopian/alphalens)：其分组收益、信息系数、换手和分组分析框架值得用于候选因子的诊断；本方案只借鉴评估思想，不决定引入该依赖。
7. [Microsoft Qlib](https://github.com/microsoft/qlib)：其研究、回测、评估和滚动实验流程说明量化研究需要完整的可复现链路；首版板块雷达仍优先使用透明模型，不以机器学习复杂度为目标。
8. [Bailey et al., The Probability of Backtest Overfitting](https://papers.ssrn.com/sol3/Papers.cfm?abstract_id=2326253)：支持限制参数搜索、预先登记候选和保留最终样本外窗口。
9. [Kenneth French Data Library](https://mba.tuck.dartmouth.edu/pages/faculty/ken.french/data_library.html)：公开行业组合长期数据说明行业组合是一类成熟研究对象，但其市场、频率和行业分类不能直接作为 A 股阈值来源。

公开资料对本产品的作用是提供研究问题和验证方法，不替代生产数据审计与 A 股历史回测。

## 19. 分阶段推进建议

### 阶段 P0：产品口径评审

1. 评审三个工作台是否覆盖核心研究问题。
2. 确认横向热度、纵向状态、持续性和拥挤度的边界。
3. 确认东财和申万同时建设、页面切换、各体系分层独立计算、关系层对比；地域暂不进入首版。
4. 确认申万是专业行业分类体系，不在产品文案中表述为监管法定分类。
5. 确认本稿中的待拍板项。

### 阶段 P1：生产数据研究审计

1. 盘点每类数据的真实日期、数量、唯一性和覆盖率。
2. 东财继续核验目录、层级版本、历史成分、行业日行情、流通市值、资金流和涨跌停明细可用性。
3. 两套体系分别形成可回测日期集合、不可验证范围和数据置信度门槛。
4. 核验跨体系同日成分重合和统一成员聚合事实是否可稳定生成。
5. 申万先完成已确认的 Prod 前置需求：首版只做 `SW2021`，补齐分类层级、有效期成员和行业日行情三类生产事实，并完成完整性、历史覆盖、成本、时效和代码校准验收。

### 阶段 P2：离线候选计算与回测

1. 实现研究级而非生产级候选公式。
2. 东财、申万和概念分别对比 H0/H1/H2、不同历史基线和不同平滑参数。
3. 输出体系内状态质量、分项有效性、前瞻探索和案例报告。
4. 输出东财—申万成分重合、统一事实相关、体系内排名共识/分歧报告。
5. 完成样本外和市场阶段分组验证。

### 阶段 P3：产品口径冻结

1. 根据回测选择正式公式、窗口和阈值。
2. 冻结产品词汇、榜单定义、数据置信度和降级规则。
3. 冻结行业体系切换、体系版本展示、跨体系关系和不可比指标的表达规则。
4. 明确哪些功能首发，哪些因数据不足后置。
5. 将正式结果升级为板块雷达标杆需求文档。

### 阶段 P4：交互设计

1. 用真实回测样本设计三个工作台。
2. 行业页面提供东财 / 申万切换，并保持工作台、层级和指标结构稳定。
3. 联动工作台设计东财—申万对应关系及两套行业—概念关系，不用名称强行一对一。
4. 先完成信息结构和交互，再制作正式 Figma。
5. 设计正常、数据不足、历史不足、部分可用和延迟状态。
6. 完成可读性和典型案例走查。

### 阶段 P5：技术方案与实施

在产品口径和 Figma 评审通过后，再进入数据物化、自动任务、API、前端和验收方案。本产品稿不提前规定这些实现方式。

## 20. 待拍板项

以下问题不会阻塞首轮数据审计，但需要在 P0/P2 后确认：

1. 页面正式功能名使用“板块雷达”还是“板块冷热探查”。本稿暂用“板块雷达”。
2. 横向分数命名使用“今日热度”，纵向分数使用“自身热度状态”是否足够清晰，还是需要避免两个 0～100 分数同时出现。
3. “上榜”使用同类前 20% 还是不同分类分别设定 Top N。
4. 5/10/20 日连续上榜候选门槛是否采用 3/5/10 日。
5. 今日热度是否保留一个综合分，或只展示四维分项与综合排名。
6. 行业体系与概念联动首发采用双向关系表、关系矩阵还是网络图；应在真实的东财—申万—概念关系密度出来后决定。
7. 新闻、公告和讨论热度是否仅作为解释事件，还是未来独立形成“注意力”维度。
8. 热度高端继续使用“沸腾 / 高热 / 活跃”还是在回测后重新校准产品语言。

## 21. 与现有板块速览的关系

1. 本方案不修改首页板块速览 V2 的当前功能和 Heat V2 生产口径。
2. 板块雷达完成研究验证并发布 Heat V3 后，首页可以消费经过确认的简化摘要。
3. 首页只保留快速事实；趋势、持续性、分量解释和行业体系与概念联动留在财势探查。
4. Heat V2 与未来 Heat V3 必须通过独立版本区分，不能覆盖历史结果后假装口径未变化。
5. 首页当前东财行业交互不因板块雷达新增申万体系而自动改变；是否将申万摘要回流首页必须另行评审。
