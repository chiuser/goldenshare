# 财势探查｜板块雷达数据覆盖审计 v1

> 文档性质：生产数据、正式 Lake 与 Tushare 来源能力的只读审计，不是技术实施方案。
> 审计日期：2026-08-16。
> 对应产品稿：[板块雷达产品设计方案 v1](./sector-radar-product-design-v1.md)。
> 审计边界：Prod 与正式 Lake 审计真实覆盖；Tushare 已完成三个申万接口的请求形态和分页核验，其中分类与当前/历史成员完成全量键集验收，日行情完成单日全集及代表代码分页核验；尚未执行全代码历史完整率审计，不回补。
> 已确认产品决策：东财行业与申万行业同时建设，页面可切换；两套体系独立计算，通过成分重合和统一股票事实进行比较。申万生产前置数据首版只做 `SW2021`，采用 Tushare 直达 `core_serving` 的 direct-serving 路径，不建设重复 Raw 表。

## 1. 结论

板块雷达首版不是从零开始。当前数据已经能够支持最近一段时间的横向排行、持续上榜、资金连续性、温和放量、内部扩散和成分穿透研究，但还不能宣称满足 3～5 年、无前视的完整回测。

决定是否可以进入正式量化回测的关键结论如下：

1. **最近 250 个交易日的核心输入已对齐。** Prod 的板块目录、板块行情、历史成员、板块资金，以及股票行情、每日指标、个股资金流、停复牌和涨跌停，在 `2025-08-05..2026-08-14` 的 250 个上交所交易日内均有日期事实。
2. **东财路线最长共同板块窗口只有 400 个交易日。** 东财板块目录和成员从 `2024-12-20` 开始，至 `2026-08-14` 共 400 个交易日；这是当前东财行业和概念中所有需要历史成分研究的共同上限。申万路线的上限尚未完成审计。
3. **400 日不等于 250 日纵向模型已经充分回测。** 需要 250 日自身历史时，只能产生 151 个有效输出日；若再预留未来 5～10 日观察期，有效样本还会减少。它可以做候选计算，不能作为已经满足长期稳健性验证的证据。
4. **股票层事实比板块历史充足。** Prod 至少覆盖最近 1,250 个交易日的股票行情、每日指标、个股资金流、停复牌、涨跌停和龙虎榜；正式 Lake 的股票日线从 `2014-01-02` 开始，共 3,068 个连续交易日分区。
5. **历史流通市值、换手率和个股资金流已经有生产数据。** `equity_daily_basic` 和 `equity_moneyflow` 足以支撑规模加权贡献、成员资金覆盖面和换手活跃度研究，不需要仅因为这些字段再新增一套来源。
6. **东财行业三级关系只有当前版本。** 当前 496 行层级包含一级 31、二级 128、三级 337，但没有历史版本序列。用今天的父子关系解释更早日期会有分类修订和前视风险。
7. **没有东财板块官方权重。** 现有 `index_weight` 是正式指数月度权重，不覆盖东财或申万板块，不能冒充板块权重。首版应使用等权或目标日流通市值近似，并明确口径。
8. **同花顺长行情不能自动解决历史成分问题。** `ths_daily` 有 1,361 个交易日，但 Prod 中 451,832 行 `ths_member` 的 `weight/in_date/out_date` 均为空，只能视为当前成分快照，不能用于无前视历史扩散和贡献回测。
9. **申万行业数据链已具备 LLD 基线。** SW2021 分类共 511 行，当前/历史成员共 7,899 行，`2026-08-14` 日行情共 439 行；分类和成员全集分页、唯一键与层级闭包已经验证。申万仍须完成日行情全代码历史完整率、成员剔除日边界和生产承载验收；两套体系的代码、层级或排名不得混用。
10. **申万生产前置数据首版口径已经冻结。** 分类版本只接 `SW2021`，来源固定为 `index_classify`、`index_member_all`、`sw_daily`；采用 direct-serving，不建设 `raw_tushare` 镜像，不接 `SW2014`。
11. **“特钢Ⅲ”存在真实的跨接口代码冲突。** 当前 `index_classify(SW2021)` 返回 `850401.SI`，但本地 Tushare 来源表、`index_member_all`、`sw_daily`、Prod `index_basic` 以及多个外部行业指数目录均使用 `850412.SI`。首版统一以 `850412.SI` 为业务标准码，同时保留源值 `850401.SI` 和规则版本；`840401` 是输入笔误，不进入任何映射。
12. **Tushare 新增东财题材库可作为注意力/解释候选。** `dc_concept` 已单点返回 `hot/strength/z_t_num/main_change/lead_stock`，但本地来源说明其数据从 `2026-02-03` 开始，不能承担 3～5 年纵向基线，也不能未经回测直接并入主热度分。
13. **三个申万 Prod 数据集的 LLD 已形成。** 分类、成员、日行情分别使用 `core_serving.sw_industry_classification`、`core_serving.sw_industry_member`、`core_serving.sw_industry_daily`；三者均 direct-serving，不新增 Raw、Lake、账号或连接。

因此，东财路线当前可以开始 20/60/120 日候选研究和最近 250 日横截面研究；申万路线已经可以进入三数据集实施评审，但必须在日行情全代码历史覆盖和成员有效期边界验收后才能进入同口径无前视回测。在解决东财长历史成员、验收申万历史覆盖之前，不应冻结 250 日纵向状态、3～5 年稳定性结论和双体系历史联动。

### 1.1 双行业体系是否可实现

可以实现，但必须是“两套独立行业事实 + 一层关系事实”，不是在现有东财行业表中增加一个来源标签：

1. **页面层**：行业页面提供东财 / 申万切换，两套体系复用相同工作台骨架和指标含义。
2. **计算层**：东财一级/二级/三级、申万一级/二级/三级分别建立横截面候选池，独立排名和计算历史状态。
3. **关系层**：用目标交易日真实成员计算 Jaccard 和双向覆盖率，建立东财行业与申万行业的多对多关系。
4. **可比事实层**：跨体系比较优先使用同一套股票行情、个股资金流、流通市值和有效池规则聚合，避免用不同来源方分数制造虚假可比性。
5. **产品表达层**：显示当前分类体系和分类版本；申万表述为市场广泛使用的专业行业分类，不表述为监管法定分类。

当前阻断项不是交互能否切换，而是申万历史覆盖尚未验收、两套分类版本尚未形成可追溯事实。

## 2. 审计方法与限制

### 2.1 Prod

通过仓库既有远程连接脚本读取生产 PostgreSQL，每条查询均进入 `READ ONLY` 事务。审计内容包括：

1. 目标表、字段、主键和索引是否真实存在。
2. 起止日期、日期数量和行数。
3. 最近 250/750/1,250 个上交所交易日的日期覆盖。
4. 2026-08-14 的板块分类、代码、成员和关键字段空值。
5. 当前有效 A 股成分池与股票行情、每日指标、资金流、停牌和涨停的代码覆盖。

未导出明细数据，未写库，未执行迁移、任务、回补或物化。

### 2.2 正式 Lake

只读取正式根目录 `/Volumes/datasource/data_lake`：

1. 读取 Parquet 文件名、文件元数据、行数和 schema。
2. 用正式 `silver_trade_calendar` 对账分区日期连续性。
3. 不读取 Dagster instance，不触发 job、sensor、asset、backfill 或 runless event。
4. 不使用旧 Lake 路径，不读取 staging，不执行任何写入。

### 2.3 Tushare

按本轮明确边界，只回答三件事：

1. 接口是否存在。
2. 是否提供板块雷达需要的关键字段。
3. 当前凭据是否能拿到最小样本。

首轮执行了 5 次单点探针：

| `index_classify` | `SW2021 + L1` | 成功，返回 31 个申万一级行业及父级、层级、发布状态 |

首轮没有请求日期区间，没有翻页，也没有据此判断 Tushare 历史是否完整。

随后针对“特钢Ⅲ”代码冲突执行了对象级核验：

| 接口与参数 | 返回结果 | 结论 |
|---|---:|---|
| `index_classify(index_code=850401.SI, src=SW2021)` | 1 行：`230501 / 特钢Ⅲ / is_pub=1` | 分类接口当前确实返回异常源值 `850401.SI` |
| `index_classify(index_code=850412.SI, src=SW2021)` | 0 行 | 分类接口未返回其他来源共同使用的代码 |
| `index_member_all(l3_code=850401.SI, is_new=Y/N)` | 0 / 0 行 | `850401.SI` 没有当前或历史成员事实 |
| `index_member_all(l3_code=850412.SI, is_new=Y/N)` | 13 / 12 行 | 成员接口使用 `850412.SI`；历史剔除日覆盖到 `2026-06-30` |
| `sw_daily(ts_code=850401.SI)` | 0 行 | `850401.SI` 没有行情事实 |
| `sw_daily(ts_code=850412.SI)` | 3,410 行 | 行情覆盖 `2012-08-01..2026-08-14`，最新名称为“特钢Ⅲ” |

外部交叉核验也一致支持 `850412`：申万 2021 分类资料给出分类代码 `230501`；RiceQuant 的当前申万指数目录记录 `850412` 自 `2003-10-15` 起有效且无终止日期，同时收录 2021 新增的钢铁三级指数，但没有 `850401` 或 `840401`；JoinQuant 和 2022 年后的新浪股票行业归属也使用 `850412`。乐咕乐股虽然存在一个 `850401.SI` 的孤立页面，但其当前行业总览没有收录该代码，不能作为有效指数证据。

因此，本文将该问题定性为 Tushare `index_classify(SW2021)` 的跨接口单行错码或错误别名，而不是 `2026-08-14` 的单日行情问题。由于 `index_classify` 是无日期快照接口，当前证据不能确定异常值最早出现时间。

### 2.4 申万 LLD 前置全量与分页核验

在进入三数据集 LLD 前，使用项目当前 `TushareHttpClient` 补充了以下只读实测。这里的“全量”只指当前分类快照或成员关系全集，不代表日行情全代码历史已经完成审计。

| 接口 | 正式请求形态 | 分页/行数 | 关键质量结果 |
|---|---|---:|---|
| `index_classify` | `src=SW2021, limit=200` | `200/200/111`，511 行 | L1/L2/L3=`31/134/346`，`is_pub=1/0`=`414/97`，身份重复 0，父节点缺失 0 |
| `index_member_all` 当前成员 | `is_new=Y, limit=2000` | `2000/2000/1895`，5,895 行 | `in_date` 空值 0，当前成员 `out_date` 均为空 |
| `index_member_all` 历史成员 | `is_new=N, limit=2000` | `2000/4`，2,004 行 | 与当前成员合并后业务身份重复 0，三级分类孤儿 0 |
| `sw_daily` 单日全集 | `trade_date=20260814, limit=2000` | 439 行 | 414 个当前发布分类代码，另有 25 个非行业分类申万指数 |
| `sw_daily` 代表对象历史 | `ts_code=850412.SI, limit=2000` | `2000/1410`，3,410 行 | `20120801..20260814`，业务主键重复 0 |

发现两个需要写入正式契约的接口行为：

1. `index_classify` 不传 `src` 返回 359 行且全部为 `SW2014`，因此正式请求必须固定 `src=SW2021`。
2. `index_member_all` 来源文档写单页最大 2,000 行，但当前连接器不传 `limit` 返回 3,000 行；该默认结果仍会截断 5,895 行当前成员，正式请求必须显式 `limit=2000` 并以短页终止。

`sw_daily` 不传日期恰好返回 4,000 行，已经命中接口上限，只覆盖最近若干日，不能作为全集或历史基线。正式维护必须由交易日计划逐日生成 `trade_date` 请求。

### 4.2 Lake 能补什么、不能补什么

Lake 能补：

`tushare-data` 的接口家族定位也确认三者职责互补：`index_classify` 提供分类与层级，`index_member_all` 提供带有效期的成员关系，`sw_daily` 提供行业指数日行情；任一接口都不能单独替代另外两类事实。

首版生产前置数据口径已经确认：

1. **分类版本**：只接 `SW2021`；不请求、不落库、不为 `SW2014` 建兼容字段或分支。
2. **来源范围**：只建设 `index_classify`、`index_member_all`、`sw_daily` 三个 Prod 数据集，不把可选的其他申万接口顺带纳入首版。
3. **存储路径**：Tushare 拉取、字段校验和标准化后直接写入 `core_serving`；`raw_dao_name/raw_table` 明确为 `None`，不建设重复 `raw_tushare` 表、不做双写。
4. **源字段保真**：direct-serving 不等于丢弃源事实。三张服务表必须保留各接口全部源字段以及必要的抓取/规则版本信息；数据源页面显示服务表，不伪造 Raw 表。
5. **代码标准化**：分类事实以 `industry_code=230501` 定位“特钢Ⅲ”，保留 `source_index_code=850401.SI`，对外和跨表关联使用 `index_code=850412.SI`，并记录稳定的 `normalization_rule/version`。成员和行情本来就使用 `850412.SI`，不得反向改写为 `850401.SI`。
6. **禁止项**：`840401` 不存在于本次有效证据中，确认是输入笔误，禁止加入映射表；也禁止按日期只修补 `2026-08-14`。

它们仍必须满足三个产品边界：

1. 申万行业与东财行业是不同分类体系，代码、成员和层级不得混用。
2. 分类 511 行和成员 Y/N 共 7,899 行已经完成全量分页与唯一键验收，不再把这两项写成未知。
3. 日行情仍只完成单日全集与代表代码历史分页，尚未完成全代码历史覆盖、成员 `out_date` 边界、源修订和生产承载验收，不能写成已经满足 3～5 年回测或可以直接上线。

## 7. 必须先解决的产品与数据决策

### P0：双行业体系已确认

产品已经确认同时建设两条行业路线：

1. **东财行业路线**：与首页行业三级关系一致，保留现有市场认知和当前 400 日共同历史。
2. **申万行业路线**：作为独立专业行业体系，使用自己的分类版本、层级、历史成员、行业行情和回测结果。
3. **页面切换**：两个体系使用相同工作台骨架，但当前选择、榜单、详情、趋势和数据置信度分别维护。
4. **关系对比**：使用同日成员重合和同源股票事实形成共识/分歧，不合成一个行业排行榜，不按名称强行映射。

当前不再讨论二选一；剩余问题是分别补齐和验收两条数据链。

### P0：确定首轮历史目标

建议把目标写成两层：

1. **近期候选研究**：使用东财共同 400 日，先验证横向/纵向拆分、20/60/120 日状态、持续上榜、资金和成交结构。
2. **正式模型冻结门槛**：补齐或明确降级东财历史成员，同时完成申万有效期成员和行业行情验收后，再分别进行至少 3 年、争取 5 年的分段和样本外验证。

不得把“最近 250 个交易日数据完整”写成“250 日纵向模型已有 250 个有效回测样本”。

### P1：东财长历史来源可行性审计

东财路线继续单独审计：

1. `dc_member` 在 Tushare 当前账号下真实可取的最早日期。
2. `dc_index` 与 `dc_daily` 更早日期的代码、名称和分类变化。
3. `moneyflow_ind_dc` 的真实最早日期及回补行为。
4. 请求量、分页、积分、耗时、商业授权和可接受回补成本。

这一步会消耗更多请求额度，本轮按用户要求没有执行。

### P0：申万 Prod 前置数据口径已确认

以下事项不再作为待拍板项：

1. 首版分类版本固定为 `SW2021`，不接 `SW2014`。
2. Prod 新增范围固定为 `index_classify`、`index_member_all`、`sw_daily` 三个 direct-serving 数据集。
3. 不建设重复 Raw 表，服务表保留完整源字段和来源追踪字段。
4. “特钢Ⅲ”业务标准码固定为 `850412.SI`；分类接口异常源值 `850401.SI` 只作为审计字段保留。
5. `840401` 是输入笔误，不存在映射需求。

LLD 前置门禁的当前状态：

1. **已完成**：项目真实 connector 的分页行为核验；分类和成员已取得全量唯一键集合，日行情已验证不带日期会命中 4,000 行截断。
2. **已完成**：`index_classify(SW2021)` 的 511 行、三级分布、父子闭包、发布状态和“特钢Ⅲ”标准化规则验收。
3. **已完成**：`index_member_all` 当前/历史两组 7,899 行、分页、日期字段、重复键和分类代码闭包验收。
4. **已完成**：三份独立 LLD，覆盖字段端到端、主键/索引、direct-serving、事务、Ops 消费者、性能预算、迁移和发布验收。
5. **仍未完成**：用业务样本确认成员 `out_date` 的包含/排除边界，冻结目标日有效成员谓词。
6. **仍未完成**：`sw_daily` 全代码起止日期、交易日覆盖、空值、修订和历史回补请求量验收。
7. **仍未完成**：实施日 Alembic/Prod head 对齐、三张服务表迁移、最小真实同步、read-back 与幂等重放。
8. **仍未完成**：申万源端盘后到达时间和自动排程规则；当前 LLD 只声明排程能力，不创建生产 schedule。

### P1：行业层级版本策略

东财和申万都要分别定义：

1. 分类版本何时生效。
2. 回测日期如何选择当时版本。
3. 行业改名、迁移、拆分和合并如何处理。
4. 当前层级是否允许回看历史，若允许必须明确是“按当前分类重述历史”，不能包装成当时真实分类。

2. 三个申万 Prod 数据集的独立 LLD 已完成，下一步是先评审 LLD，不直接进入迁移或生产同步。
3. LLD 获批后按“共享代码契约与三表迁移 → 分类层级 → 有效期成员 → 单日日行情 → 获批历史窗口”的顺序实施并做真实五段对账；本审计不授权编码、迁移、生产同步或回补。
4. 东财路线继续使用 400 日共同窗口开展 20/60/120 日候选实验；250 日状态只作为敏感性试算。
5. 两套体系的数据门槛确认后，分别建立离线输入快照和无前视回测，再计算东财—申万成分关系、统一事实相关和共识/分歧。
6. 真实关系密度和回测结果出来后再设计正式切换与对比交互；当前不进入板块雷达前端开发。

本轮没有修改代码、数据库、配置、任务或 Lake 数据，也没有执行任何同步、回补或物化。
