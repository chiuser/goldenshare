## 2. 产品定位

板块分析首先回答“当前发生了什么”和“过去一段时间如何变化”，不承担未来预测。

五项基础分析能力是：

1. 横截面动量排名。
2. 双动量筛选。
3. 相对强弱轮动。
4. 板块成员广度。
5. 量价确认。

这些能力属于财势探查，而不是五个预测模型。它们产生的可重复基础事实，未来可以成为量化研究的输入，但不能因为未来可能用于回测，就在当前页面强加预测含义。

### 2.1 核心原则

| 原则 | 结论 | 理由 |
|---|---|---|
| 状态与预测分离 | 描述当前状态和预测未来是两类不同研究目标 | 当前事实成立，不代表已经证明其具备未来预测能力 |
| 方法独立 | 五种方法分别计算、分别展示 | 避免用户无法判断结果由哪种方法产生 |
| 禁止临时混合 | 首版不提供多选方法并自动合成公式的能力 | 任意混合会形成未经定义和验证的新方法 |
| 组合重新立项 | 将来需要组合时，必须注册为新的独立研究方法并重新回测 | 组合后的公式语义和效果均已发生变化 |
| 公式可追溯 | 同一种方法允许调整已批准参数，公式结构必须固定并版本化 | 保证不同日期和不同运行结果可以解释和复现 |
| 参数按需暴露 | 固定参数直接固化，只有真实观察需要的选项才进入页面 | 页面不是公式编辑器，不用为技术参数制造交互 |
| 不做发布 | 本轮不建设候选、审批、发布或行情信号接入流程 | 当前目标是研究观测，不是生产信号发布 |

### 2.2 当前范围

1. 当前已确认到可设计层面的对象是行业板块及其一级、二级、三级关系。
2. 页面不出现数据源品牌缩写或品牌名称，只使用“行业”“一级行业”“二级行业”“三级行业”等产品语言。
3. 申万相关产品入口和交互继续暂缓。
4. 概念、地域是否复用五种方法尚未进入当前已确认范围，不得在本轮 Figma 中自行扩展。
5. 当前使用盘后已发布事实；不设计分钟热度、实时预警或盘中预测。

## 3. 页面信息架构

```text
TopMarketBar（保持现有公共组件不变）
└── 财势探查
    ├── 成交额洞察
    └── 板块分析
        ├── 动量排名
        ├── 双动量
        ├── 相对轮动
        ├── 成员广度
        └── 量价分布
```

### 3.1 财势探查入口首页

1. 不修改现有 `TopMarketBar` 的结构、样式或导航层级。
2. 点击 `TopMarketBar` 的“财势探查”进入财势探查入口首页，而不是直接进入某一个分析模块。
3. 财势探查首页是功能分流页，不直接展开成交额洞察、板块分析或其他大型榜单和图表。
4. 面包屑为 `财势乾坤 / 财势探查`。
5. 面包屑下方使用与财势乾坤首页 `ShortcutBar / ShortcutCard` 完全一致的小型快捷入口样式；不得重新设计另一套入口卡。
6. 当前正式入口只有“成交额洞察”和“板块分析”，按从左到右顺序排列；未确认的未来能力不使用空卡或“敬请期待”占位。
7. 入口卡只表达模块名称和简短用途，不展示模块内部指标、分数、榜单、图表或预测结论。
8. 点击入口卡进入对应模块子页面；入口首页不预加载、不隐藏挂载模块内容。

### 3.2 模块子页面公共骨架

1. 财势探查首页及其模块子页面在面包屑下方复用同一组快捷入口，保证用户可直接切换模块。
2. 入口首页不高亮具体模块；模块子页面只高亮当前模块入口。
3. 成交额洞察面包屑为 `财势乾坤 / 财势探查 / 成交额洞察`，页面只承载成交额洞察内容。
4. 板块分析面包屑为 `财势乾坤 / 财势探查 / 板块分析`，页面只承载板块分析内容。
5. 模块子页面面包屑中的“财势探查”可点击返回入口首页；快捷入口可直接切换到另一个模块。
6. 各模块拥有独立、可恢复的页面地址；正式路由名称由后续技术方案确定。
7. 所有模块继续使用公共 `pageContext.tradeDate`，不得因为拆分子页面而自行计算业务日期。

### 3.3 板块分析页面骨架

1. 在板块分析快捷入口条下方增加五按钮横条：`动量排名 / 双动量 / 相对轮动 / 成员广度 / 量价分布`。
2. 默认进入“动量排名”。
3. 当前运行态已建设“动量排名”“双动量”“相对轮动”和“成员广度”四个独立工作区，点击后切换到各自可恢复路由；成员广度的趋势查看增量已完成本地代码与验收，随下一次部署进入正式环境；“量价分布”继续等待独立产品与设计收口并保持轻量“待建设”提示。
4. 后续每个方法必须单独完成产品口径、正式交互和开发验收；完成后才成为可独立恢复的页面状态，并在点击按钮后替换按钮栏下方的完整分析工作区。
5. 五种方法最终可以复用页面外壳和基础组件，但不得共用一张大而全的参数表单，也不得把五种图表纵向堆叠在一个大页面中。

### 3.4 加载与性能边界

1. 财势探查入口首页不加载成交额洞察或板块分析业务数据。
2. 模块子页面只加载当前模块的数据；板块分析内部只加载当前选中方法的数据和图表。
3. 未选中的板块分析工作区不提前请求数据、不提前挂载图表，也不得使用隐藏节点保留五套完整实例。
4. 切换模块或方法时，下方内容区使用稳定的加载骨架，页面主体不应突然坍塌或跳动。
5. 每个模块和板块分析工作区独立表达 Loading、Ready、Delayed、Empty 和 Error。

采用入口首页分流、模块子页面承载和工作区替换，是为了控制数据请求量、图表实例数量、首屏加载压力和页面信息密度。

## 4. 公共日期与历史规则

1. 页面业务日期统一遵循财势乾坤公共 `pageContext.tradeDate`，板块分析不得自行用本机时间推导“今天”。
2. 20:00 前默认展示上一完整交易日；20:00 后优先展示当日已发布数据。
3. 20:00 后当日数据延迟时，继续展示最近完整交易日事实，并明确提示“当前展示 YYYY-MM-DD 盘后数据”。
4. 历史图表范围统一提供截至当前数据日期最近 `20/30/60` 个 SSE 开市日；某日事实缺失时保留日期槽并断线，不把缺口从时间轴删除。
5. 历史不足时展示已有全部数据，不补零、不前向填充、不伪造连续历史。
6. 所有数值和图表必须明确绑定当前数据日期；切换历史日期后，榜单、详情和图表使用同一日期口径。
7. 页面保留交易日选择器，默认值为 `pageContext.tradeDate`。从当前行业行情覆盖起始日到公共目标日期之间的全部 SSE 开市日都可选择，不能只返回已有行业行情的日期交集。
8. 历史日期复盘是整块工作区的统一状态，不允许榜单使用一个日期、详情使用另一个日期。
9. 日期选择器必须区分“完整”“部分缺失”“整日缺失”：完整日正常显示；部分缺失日仍可进入并保留缺值行业；整日缺失日仍可进入并展示空状态。缺口对用户可见，便于后续补齐。
10. “部分缺失”是日期数据覆盖标记，不新增单独的页面 Partial 状态；只要当前比较池至少有一个行业可计算，页面仍使用正常内容骨架并明确缺失数量。

## 5. 横截面动量排名工作区

### 5.1 用户问题

该工作区回答：

1. 当前同级行业中，哪些行业在指定计算周期内涨幅最高或最低？
2. 某个一级行业内部，哪些直属二级行业更强或更弱？
3. 某个二级行业内部，哪些直属三级行业更强或更弱？
4. 某个行业的区间涨跌幅和排名在过去一段时间如何变化？

动量排名描述当前和历史表现，不输出预测信号、成功率或未来解释。

### 5.2 五类排名榜

| 榜单 | 比较对象 | 必要性 |
|---|---|---|
| 一级行业总榜 | 所有一级行业 | 查看一级行业整体强弱分布 |
| 二级行业总榜 | 所有二级行业 | 查看全体二级行业中的绝对位置 |
| 三级行业总榜 | 所有三级行业 | 查看全体三级行业中的绝对位置 |
| 一级行业内二级榜 | 选定一级行业的直属二级行业 | 支持从一级行业继续研究内部结构 |
| 二级行业内三级榜 | 选定二级行业的直属三级行业 | 支持从二级行业继续研究内部结构 |

同级总榜和父行业内部榜同等重要，不能把同级总榜降级为隐藏的辅助能力。

二级、三级总榜必须展示父级路径，避免用户只看到行业名称而不知道其所属关系。

五类榜单使用明确的横向选项：`一级总榜 / 二级总榜 / 三级总榜 / 一级内二级 / 二级内三级`。选择“一级内二级”或“二级内三级”后，显示对应父行业选择器；不把榜单口径拆成多组抽象配置项。

父级内榜单采用以下固定交互：

1. 选择“一级内二级”后，在比较范围同一行显示一个“一级行业”选择器；榜单只展示该一级行业的直属二级行业。
2. 选择“二级内三级”后，在同一位置显示“一级行业”和“二级行业”两个级联选择器；二级选择器只提供当前一级行业的直属二级行业，榜单只展示当前二级行业的直属三级行业。
3. 改变一级行业时，二级行业选择器重置为新一级行业下的第一项；改变任一父行业后，榜单与右侧详情同步刷新。当前选中行业仍属于新比较池时继续保留，只有退出新比较池时才选择第一条可计算行业；没有可计算行业时选择第一项。
4. 从一级行业或二级行业行的独立下钻箭头进入下一级榜单时，自动带入该行作为父行业，同时保留交易日、计算周期、排行方向和图表显示范围。
5. 三级行业没有继续下钻入口。
6. Figma 使用“信息技术 / 软件服务 / 行业应用软件”作为层级交互示例，仅用于说明选择和下钻效果，不代表生产环境固定默认行业或固定榜单数据。

### 5.3 计算周期

计算周期固定提供 `1/5/10/20/30` 个交易日：

- 1 日直接使用当前数据日期的当日涨跌幅。
- 5、10、20、30 日使用“期末收盘价 ÷ 区间开始前一个交易日的收盘价 - 1”计算累计涨跌幅。例如，5 日涨跌幅覆盖最近 5 个交易日，需要这 5 日和区间前一交易日共 6 个收盘价。
- 多日涨跌幅不使用每日涨跌幅连乘来补缺值；缺少任一必要收盘价时，该行业本次结果不可计算。

工作区默认状态为“一级行业总榜 + 1 日”。

这里的周期是区间涨跌幅计算窗口，不是图表显示范围，也不是多日上榜次数统计。

### 5.4 排名主体

1. 榜单以表格为主要载体，不单独占用大面积绘制全部行业横向柱状图。
2. 表格至少表达榜单序号、行业名称、所属行业路径、区间涨跌幅和同组百分位；榜单序号只表示当前列表中的展示顺序，不作为历史排名口径。
3. 区间涨跌幅单元格使用小型横向数据条辅助比较，同时保留准确数值。
4. 数据条以零为中心，遵循财势乾坤红涨绿跌设计语义。
5. 榜单提供明确的“涨幅榜 / 跌幅榜”切换；两种榜单都展示当前范围的全部行业，不截断为 Top N。
6. 涨幅榜按区间涨跌幅从高到低完整排序，跌幅榜从低到高完整排序。
7. “涨幅榜 / 跌幅榜”只改变列表顺序，不改变行业的同组强度排名、同组百分位或历史趋势事实。
8. 表格使用固定表头和内部纵向滚动，切换涨跌榜时复用同一稳定容器。
9. 二级、三级总榜使用独立的“所属行业”列：二级显示所属一级行业，三级显示“一级 / 二级”路径。
10. 所属行业路径过长时单行省略并通过 Tooltip 展示完整内容，不能与行业名称混成难以扫描的长文本。
11. 个别行业缺少本周期必要行情时，行业仍保留在榜单末尾，涨跌幅、同组强度排名和百分位显示 `--`；其他可计算行业继续正常排序和展示。
12. 只要当前比较池内至少有一个行业可计算，页面保持正常内容态；全部行业均不可计算时才展示空状态。不得补零、前向填充或借用相邻日期结果。
13. 同组百分位固定使用 `(n - averageRank) / (n - 1) × 100`；`n` 为当日同一比较池的可计算行业数，并列值使用平均名次。最强为 `100.0%`，最弱为 `0.0%`，只有一个可计算行业时为 `100.0%`，缺值行业为 `--`。

### 5.5 行业详情与历史趋势

选中一个行业后，详情区同时展示上下两个趋势图，不使用 Tab 在两者之间切换：

1. 上图：滚动区间涨跌幅趋势。每个历史交易日都使用当前选择的计算周期重新计算区间涨跌幅；标题明确显示当前周期，例如“10 日区间涨跌幅趋势”。
2. 下图：同一交易日、同一比较范围内的同组强度排名趋势。区间涨跌幅最高始终为第 1 名，排名定义不随“涨幅榜 / 跌幅榜”切换而改变。
3. 排名图中第一名位于顶部，避免“数值变小但视觉向下”的反直觉表达。
4. 两张图共用 `20/30/60` 个交易日日期轴、悬停位置和 Tooltip 联动，但使用独立纵轴，不把不同单位强行叠到同一纵轴。
5. 历史排名严格沿用当前比较范围：从二级总榜进入时计算全体二级行业强度排名，从一级行业内二级榜进入时计算该父行业内部强度排名。
6. 图表标题必须明确当前排名范围，例如“二级行业总榜排名趋势”或“电子行业内排名趋势”。
7. 桌面端采用左右布局：左侧为完整可滚动榜单，右侧为选中行业摘要和上下两张历史趋势图。
8. 榜单首次加载且没有选中行业时，默认选择第一条可计算行业；没有可计算行业时选择榜单第一项。
9. 切换数据日期、计算周期、涨幅榜／跌幅榜或 `20/30/60` 日图表范围时，只要当前行业仍属于当前比较范围，就必须继续保留该行业，不得自动跳到新榜单第一项。当前行业当日缺值时也继续保留，并按缺值规则展示。
10. 只有切换比较范围或父行业后，当前行业不再属于新的比较池，才重置为新榜单第一条可计算行业；没有可计算行业时选择第一项。
11. 点击表格行只负责选中行业并更新右侧详情；一级、二级行业使用独立下钻箭头进入直属下级榜单，三级行业不显示下钻入口。
12. 二级行业详情同时展示“全部二级行业同组强度排名”和“所属一级行业内部强度排名”摘要；三级行业详情同时展示“全部三级行业同组强度排名”和“所属二级行业内部强度排名”摘要。
13. 两种排名摘要用于同时说明全局位置和父级内部位置；历史排名趋势仍只绘制当前进入详情时的比较范围，避免把不同分母的排名混在一条趋势线上。
14. 历史排名 Tooltip 必须同时显示“第 N 名 / M 个可计算行业”；个别行业缺值导致当日有效比较数量变化时，不能只显示名次而隐藏分母变化。
15. “一级内二级”和“二级内三级”必须分别具有可直接评审的完整页面状态，不能只在默认页放置两个无结果状态的按钮。

数据日期是两张历史图的共同结束日期。切换数据日期后，榜单切换到该日，两张图也同时改为以该日结束并向前展示所选 `20/30/60` 个交易日；切换显示范围只改变图表长度，不改变计算周期或排名定义。

“历史排名”是指：对当前选中的同一个行业，回到历史范围内的每一个交易日，重新计算它在当日同一比较范围中的名次，再把每天的名次连成趋势。它不是历史行业分类，也不是读取当时保存的一张旧榜单快照。

例如：用户选择“一级内二级”、一级行业“信息技术”、计算周期“10 日”、行业“软件服务”、历史显示范围“20 日”。系统会在这 20 个历史交易日中的每一天，分别计算“信息技术”当前直属二级行业截至当日的 10 日累计涨跌幅，再记录“软件服务”当天在这些直属二级行业中的名次，最终形成类似 `第 8 名 → 第 6 名 → 第 4 名 → 第 2 名` 的历史排名趋势。

行业范围统一使用当前已发布的行业一级、二级、三级关系。也就是说，历史日期的排名仍按当前行业关系重新计算；首期不保存或重建过去每一天的历史行业分类版本。若未来行业关系发生变化，重新查看旧日期时的比较池也会随当前关系变化。

### 5.6 三级行业成分股明细

成分股明细是动量排名中选中三级行业后的事实下钻，不是“板块成员广度”方法，也不产生新的评分、筛选或预测。

1. 只有“三级总榜”和“二级内三级”两个比较范围展示成分股明细；其他三个范围保持既有单榜单左栏，不预加载或隐藏挂载成分股列表。
2. 左栏总高度保持不变，拆为上部三级行业榜单和下部成分股列表；两个区域各自拥有固定表头和独立纵向滚动，滚动其中一个不得带动另一个。
3. 成分股列表只展示四列：股票名称、股票代码、当前板块数据日期的收盘价、当前统计周期的区间涨跌幅；不增加操作、搜索、筛选、分页、导出或股票详情入口。
4. 成分股来源使用当前页面实际展示交易日的来源成员全集，不套用 Heat 或其他“有效 A 股池”过滤。行情缺失只表示该成员当前数值不可计算，不能据此把它从成员关系中删除。
5. 1 日区间涨跌幅使用来源当日 `pct_chg`；5/10/20/30 日使用截至当前板块数据日期最近 N 个 SSE 开市日的每日 `pct_chg` 连乘。任一必要交易日缺行或数值不可用时，本行区间涨跌幅显示 `--`，不补零、不前向填充、不借用最近有价日。
6. 成分股排序跟随当前“涨幅榜／跌幅榜”：涨幅榜按所选周期涨跌幅降序，跌幅榜按升序；空值始终位于末尾，同值按股票代码升序。
7. 个别成员缺目标日收盘价或区间历史时仍保留该行并显示 `--`。页面应能区分全部来源成员数、收盘价可用数和区间涨跌幅可计算数。
8. 选中行业、统计周期、榜单方向或页面实际展示日期变化时刷新成分股列表；只切换右侧图表的 `20/30/60` 日显示范围时不刷新成员。
9. 成分股加载、为空或失败只影响左栏下半区；上部行业榜单和右侧详情继续可用，用户仍可选择其他三级行业。
10. 完整成员列表一次返回并在页面内部滚动，不截断为 Top N。该合同以生产聚合审计证明的最大规模和响应预算为实施门禁。

## 6. 双动量筛选工作区

### 6.1 目标与边界

1. “自身表现”表示同一个行业当前值与过去值之间的比较；绝对动量使用所选周期的区间涨跌幅表达。
2. “同组表现”表示同一数据日期内，该行业与当前可比行业之间的排名；相对动量使用同组强度排名和百分位表达。
3. 双动量只筛选“自身上涨且同组领先”的当前状态，不解释为未来会继续上涨，不产生预测信号、综合评分或买卖建议。
4. 绝对动量和相对动量是两个独立条件，必须同时满足；不设置权重，不允许其中一项抵消另一项。
5. 双动量与其他四种方法保持独立，不能在页面上临时勾选并合成新公式。

### 6.2 比较范围

双动量完整支持与动量排名一致的五种比较范围：

1. 一级行业总榜。
2. 二级行业总榜。
3. 三级行业总榜。
4. 一个一级行业内部的直属二级行业。
5. 一个二级行业内部的直属三级行业。

默认范围为“一级行业总榜”。父级选择、行业层级、当前行业关系和历史日期口径沿用本文公共规则，不另建第二套行业池。

### 6.3 观察周期

1. 支持 `5/10/20/30` 个交易日，默认 `20日`。
2. 不提供 `1日`，因为单日涨跌只代表当日表现，不作为双动量的周期状态。
3. 绝对动量和相对动量必须使用同一个周期，页面不允许分别选择快周期和慢周期。
4. 区间涨跌幅沿用动量排名已确认的完整 `N+1` 个 SSE 开市日事实和计算公式；缺少任一必要日期时不可计算，不用两个端点冒充完整窗口。

### 6.4 绝对动量

1. 所选周期区间涨跌幅 `> 0` 时，状态为“自身上涨”。
2. 区间涨跌幅 `<= 0` 时，状态为“自身未上涨”。
3. `0%` 是固定门槛，不提供页面配置。
4. 不引入无风险收益率、宽基指数、均线、历史标准化或其他替代基准。

### 6.5 相对动量

1. 相对动量使用同一日期、同一周期、同一比较池内的同组强度排名和百分位。
2. 百分位公式、并列平均名次、最强 `100.0%`、最弱 `0.0%` 及缺值规则完全沿用动量排名，不重复创造第二套排名公式。
3. 领先门槛提供 `70%/80%/90%` 三档，默认“强度百分位不低于 `80%`”。
4. 页面使用“强度百分位 >= N%”表达门槛，不使用不精确的“前 N%”文案。
5. 领先门槛是已批准的可调观察参数；公式结构和百分位计算方式不可由用户修改。

### 6.6 入选规则与四类状态

只有同时满足以下两个条件的行业，才进入“符合条件”结果：

```text
区间涨跌幅 > 0
并且
同组强度百分位 >= 当前领先门槛
```

“全部行业”视图必须透明展示四类当前状态：

1. 自身上涨、同组领先：符合双动量。
2. 自身上涨、同组不领先。
3. 自身未上涨、同组领先。
4. 自身未上涨、同组不领先。

页面不得把两个条件合成为综合分，也不得用“信号已触发”“预测成功”等预测语言。

### 6.7 小组与缺失数据

1. 同组至少有 `3` 个可计算行业，才能判断“同组领先”。
2. 可计算行业少于 `3` 个时，区间涨跌幅、同组排名和同组强度百分位仍作为客观事实正常计算并展示，同时标记“同组样本不足”。
3. “同组样本不足”时不作“同组领先”判断，不进入“符合条件”结果，二维图也不得使用符合条件高亮。
4. 只要区间涨跌幅和百分位均可计算，该行业仍可按客观坐标显示在二维图中；页面必须明确“样本不足，不作符合条件判断”。
5. 区间涨跌幅或百分位缺失的行业仍保留，缺失数值显示 `--`，并明确“区间数据不足”或“同组数据不足”。
6. 缺少任一二维图坐标的行业只保留在“全部行业”列表，不伪造图中位置；该行业仍可被选中，详情摘要展示已有事实、缺失值和缺失原因，二维图提示“当前行业坐标不可计算”。
7. 坐标缺失不阻断独立层级下钻；只要行业层级关系存在，一级和二级行业仍可进入其直属子行业比较范围。
8. 缺失行业不进入“符合条件”结果；不得补零、前向填充、借用上一交易日或直接删除。
9. 页面必须同时展示比较池总数、可计算行业数、符合条件行业数和数据不足行业数。

### 6.8 页面结构与二维分布图

双动量使用“筛选结果列表 + 二维分布图”的单一工作区：

1. 工作区顶部放置比较范围、必要父级选择器、分析日期、观察周期和领先门槛。
2. 结果列表提供“符合条件 / 全部行业”两个视图，默认“符合条件”。
3. 二维图横轴为所选周期区间涨跌幅，纵轴为同组强度百分位。
4. 图中使用 `0%` 竖线和当前百分位门槛横线；右上区域表示符合双动量。
5. 全部可展示行业均作为圆点出现，符合条件的行业使用明确高亮；缺少任一坐标的行业只保留在列表，不伪造图中位置。
6. 行业名称不全部常驻，避免重叠；悬停时显示名称、路径、区间涨跌幅、同组排名和百分位，只有当前选中行业常驻显示名称。
7. 列表与图中圆点双向联动，选中任一侧时另一侧同步高亮并显示同一行业事实。
8. “同组样本不足”的行业可以显示客观坐标，但不能使用符合条件区域的入选语义或高亮样式。

### 6.9 结果列表

列表至少展示：

1. 行业名称。
2. 所属行业路径。
3. 区间涨跌幅。
4. 同组强度排名。
5. 同组强度百分位。
6. 当前状态。

默认按百分位从高到低排序；百分位相同时按区间涨跌幅从高到低，再按行业代码稳定排序。用户可以点击“区间涨跌幅”和“同组强度百分位”表头切换排序，但页面不提供综合分排序。

当“符合条件”数量为 `0`、但比较池仍有可计算行业时，页面继续保持 Ready：摘要和二维图照常展示，左侧结果区显示“当前没有符合条件的行业”，并提供切换至“全部行业”的入口。此时不得使用整页 Empty，因为页面仍有可分析的客观事实。

### 6.10 选择与下钻

1. 点击列表行或二维图圆点只选择行业，不改变比较范围。
2. 一级和二级行业使用独立下钻控件：一级下钻到其直属二级，二级下钻到其直属三级，三级不能继续下钻。
3. 下钻时保留分析日期、观察周期和领先门槛；当前行业退出新比较池后才重置选择。
4. 选中行业时，列表、二维图和当前详情摘要必须同步，不允许出现不同对象。
5. 在“符合条件”视图中，参数或筛选变化后，如果原选中行业不再符合条件，则自动选择当前结果中的第一只行业；如果当前没有符合条件的行业，则清空选择。
6. 在“全部行业”视图中，只要原选中行业仍属于当前比较池，就继续保留选择；只有行业退出比较池时才重置。
7. 切换结果视图、领先门槛、分析日期、观察周期或比较范围时，未被该操作直接改变的比较范围、父级、日期、周期和门槛必须继续保留。

### 6.11 历史日期与首版排除项

1. 保留本文公共交易日选择器，默认使用 `pageContext.tradeDate`，支持历史日期复盘。
2. 切换历史日期后，列表、二维图、摘要和统计数量必须全部使用同一日期事实。
3. 首版不增加双动量历史趋势图；历史观察只通过交易日选择器完成。
4. 首版不增加多周期同时对比、快慢周期组合、门槛穿越、持续入选天数或未来结果验证。

### 6.12 摘要、状态与恢复

1. 页面摘要只展示比较池行业总数、可计算行业数、符合条件行业数和数据不足行业数，不展示机会分数、市场强度分数或预测结论。
2. 默认状态为：一级行业总榜、20 日、强度百分位不低于 80%、符合条件视图、`pageContext.tradeDate`。
3. 比较范围、父级、分析日期、观察周期、领先门槛、结果视图和当前选中行业都必须成为可恢复页面状态；刷新、前进和后退后语义不变。
4. 工作区复用公共 Loading、Ready、Delayed、Empty 和 Error 骨架；部分缺失继续使用 Ready 骨架并明确缺失数量。只有当前比较池没有任何可计算行业时才进入 Empty，“符合条件”为零不属于 Empty。
5. 双动量、相对轮动和成员广度均已使用正式工作区替换原“待建设”提示；成员广度趋势查看只允许使用本节批准的正式交互与真实 Details 事实，量价分布在产品与设计评审完成前不得接入草稿 Figma、Mock 数据或隐藏工作区。

## 7. 相对强弱轮动工作区

### 7.1 目标与方法边界

1. 每个数据日期对应一张四象限快照。
2. 横轴表达行业在当前同组中的相对强弱位置，纵轴表达该相对位置最近是在改善还是没有改善。
3. 本方法使用财势乾坤自己的“同组百分位轮动”公式，不实现传统 RRG 的 `JdK RS-Ratio / RS-Momentum`，不引入宽基指数作为共同分母，也不得在页面或文档中把本方法宣称为标准 RRG。
4. 四象限只表达当前相对位置和变化方向，不解释为未来预测、转热信号、综合评分或买卖建议。
5. 本方法与动量排名、双动量及其他板块分析方法保持独立；首版不允许临时勾选多个方法并合成新公式。

### 7.2 比较范围

完整支持与动量排名、双动量一致的五种比较范围：

1. 一级行业总榜。
2. 二级行业总榜。
3. 三级行业总榜。
4. 一个一级行业内部的直属二级行业。
5. 一个二级行业内部的直属三级行业。

默认范围为“一级行业总榜”。父级选择、当前行业关系和历史日期口径沿用本文公共规则；不同一级行业下的二级行业、不同二级行业下的三级行业只有在选择对应“总榜”范围时才进入同一比较池。

### 7.3 强度周期与轮动公式

1. 强度计算周期支持 `5/10/20/30` 个交易日，默认 `20日`。
2. 每个行业先使用动量排名已经确认的完整区间涨跌幅和同组百分位公式，得到目标日期的同组强度百分位 `P(t, N)`；最强为 `100.0%`，最弱为 `0.0%`，并列使用平均名次。
3. 横轴固定为目标日期的同组强度百分位：

```text
X(t) = P(t, N)
```

4. 纵轴固定为目标日期百分位与5个交易日前百分位之差：

```text
Y(t) = P(t, N) - P(t-5, N)
```

5. `N` 是用户选择的 `5/10/20/30` 日强度周期；前后两个百分位必须使用同一个 `N`、同一个比较范围和同一个父级比较池。
6. “5个交易日前”是固定公式参数，首版不提供第二个变化周期选择器，避免与强度计算周期混淆。将来若改变该参数，必须形成可追溯的新公式版本。
7. 页面在列表和 Tooltip 中同时展示所选周期的实际区间涨跌幅，不允许只展示百分位而隐藏真实涨跌幅大小。

### 7.4 四象限边界与状态

横轴以 `50%` 为相对强弱分界，纵轴以 `0` 为改善分界：

| 条件 | 当前状态 |
|---|---|
| `X >= 50%` 且 `Y > 0` | 领先且增强 |
| `X < 50%` 且 `Y > 0` | 偏弱但改善 |
| `X >= 50%` 且 `Y <= 0` | 较强但未增强 |
| `X < 50%` 且 `Y <= 0` | 偏弱且未改善 |

纵轴等于 `0` 只表示相对位置没有改善，不能表述为已经减弱；因此首版不使用“较强但减弱”“偏弱且继续走弱”描述零变化。

### 7.5 名称、选择与行业列表

1. 默认圆点不常驻显示全部行业名称，避免密集重叠。
2. 右侧提供“全部”和四象限快捷筛选、行业名称搜索及完整可滚动行业列表，不截断为 Top N。
3. 列表默认按横轴百分位降序、纵轴变化降序、行业代码升序稳定排列。
4. 列表与 Tooltip 至少展示行业名称、所属路径、所选周期区间涨跌幅、当前同组百分位、5日百分位变化和当前象限。
5. 点击列表或图中圆点均可选中行业；筛选列表只改变列表可见范围，不重新计算坐标，也不删除图中其他行业圆点。
6. 鼠标经过圆点时，Tooltip 临时显示同一行业事实。
7. 只有当前选中行业的名称常驻显示，其圆点放大并增加选中描边。

### 7.6 历史轨迹与坐标轴

1. 只为当前选中行业展示历史移动轨迹；其他行业保留为当前数据日期的浅色快照圆点。
2. 历史轨迹长度支持最近 `20/30/60` 个 SSE 开市日，默认 `20日`。
3. 每个轨迹点都按该点自身日期、当前强度周期、当前比较范围和当前父级比较池独立计算 `X/Y`；切换数据日期后，所选日期成为轨迹终点。
4. 历史轨迹点由浅到深，终点显示方向；不把历史轨迹解释为必然顺时针轮动或未来方向。
5. 横轴固定为 `0–100%`，并固定展示 `50%` 分界线。
6. 纵轴以 `0` 为中心，综合当前快照全部可绘制圆点和当前选中行业轨迹自动生成上下对称范围；必须显示清晰刻度，普通图和放大图使用相同坐标范围。
7. 图表提供放大查看能力，但放大后也不默认显示全部行业名称或全部行业轨迹。

### 7.7 小组与缺失数据

1. 当前比较池至少有 `3` 个可计算行业时，才赋予正式四象限状态。
2. 少于 `3` 个可计算行业时，已有区间涨跌幅、百分位及变化值仍作为客观事实展示；坐标可计算时使用灰色圆点并标记“同组样本不足”，不赋予四象限语义。
3. 当前百分位缺失时，行业继续保留在完整列表，横轴与纵轴显示 `--`，图中不伪造点位。
4. 当前百分位可用但5个交易日前百分位缺失时，横轴和区间涨跌幅继续展示，纵轴显示 `--`，图中不伪造完整二维坐标。
5. 历史轨迹中的单日坐标缺失时保留日期槽并断线，不补零、不前向填充、不借用最近可用点连接成连续轨迹。
6. 个别行业缺失只影响该行业；当前比较池至少有一个行业可计算时继续使用 Ready 骨架并明确缺失数量，全部不可计算时才进入 Empty。

### 7.8 日期、状态与恢复

1. 分析日期使用本文公共交易日选择器，默认 `pageContext.tradeDate`，支持完整、部分缺失和整日缺失交易日复盘。
2. 比较范围、父级、分析日期、强度周期、轨迹长度、行业列表象限筛选、搜索条件和当前选中行业均属于可恢复页面状态；刷新、前进和后退后语义不变。
3. 参数或日期变化后，只要当前行业仍属于新比较池就保留选择；退出新比较池时才选择新列表第一项或清空。
4. 工作区复用 Loading、Ready、Delayed、Empty 和 Error 稳定骨架；数据延迟时继续展示最近完整交易日事实并明确实际数据日期。
5. 未选中相对轮动方法时不得请求轮动数据或挂载图表；当前正式运行页已完成该方法，不再显示“待建设”。

## 8. 板块成员广度工作区

### 8.1 用户问题与方向

成员广度用于观察板块上涨或下跌是由少数股票推动，还是多数成分股共同参与。

1. 工作区提供“上涨广度 / 下跌广度”方向切换，默认“上涨广度”。
2. 上涨广度包括上涨成分股占比、上涨成交额占比、站上指定均线的成分股占比。
3. 下跌广度包括下跌成分股占比、下跌成交额占比、跌破指定均线的成分股占比。
4. 平盘或等于均线的成分股属于中性组成，保留在对应指标的可计算分母和组成展示中，但不计入上涨、下跌、站上或跌破的分子。
5. 三项指标分别描述参与股票数量、成交额参与程度和价格位置，不合成为综合广度分，也不解释为预测、信号或买卖建议。

### 8.2 比较范围与日期成员关系

完整支持与其他已完成方法一致的五种比较范围：

1. 一级行业总榜。
2. 二级行业总榜。
3. 三级行业总榜。
4. 一个一级行业内部的直属二级行业。
5. 一个二级行业内部的直属三级行业。

默认范围为“一级行业总榜”。父级选择、交易日选择器、完整／部分缺失／整日缺失标记和 `pageContext.tradeDate` 口径沿用本文公共规则。

行业的比较层级使用当前已发布的行业三级关系；每个数据日期的广度事实必须使用该日期实际发布的行业成分关系。历史日期不得借用最新成员关系，也不得默认把所有下级行业成分股合并后冒充该级行业的来源成员。

### 8.3 三项广度事实

每项指标独立确定可计算分母：

1. 上涨成分股占比：当日涨跌幅大于 `0` 的成分股数量，占当日涨跌幅可计算成分股数量的比例。
2. 下跌成分股占比：当日涨跌幅小于 `0` 的成分股数量，占当日涨跌幅可计算成分股数量的比例。
3. 上涨成交额占比：当日上涨且成交额可计算的成分股成交额之和，占当日涨跌幅和成交额均可计算的全部成分股成交额之和的比例。
4. 下跌成交额占比：当日下跌且成交额可计算的成分股成交额之和，占同一成交额分母的比例。
5. 站上均线占比：分析日收盘价高于所选均线的成分股数量，占均线关系可计算成分股数量的比例。
6. 跌破均线占比：分析日收盘价低于所选均线的成分股数量，占均线关系可计算成分股数量的比例。

当日涨跌幅等于 `0` 计为平盘；收盘价等于均线计为均线中性。成交额占比使用当日成交额，不使用市值加权，也不把多个交易日成交额累加后再比较。

### 8.4 均线周期与价格口径

1. 均线周期固定支持 `5/10/15/20/30/60` 个交易日，默认 `20日`。
2. 同一时刻只选择一个均线周期，不在主榜中同时混合多个均线结果。
3. 均线使用完整窗口；缺少窗口内任一交易日价格时，该成分股不纳入均线关系指标，不补零、不前向填充。
4. 均线使用经过复权处理的价格序列，避免分红送转等除权行为制造虚假的站上或跌破；页面不额外暴露复权方式选择器。
5. 调整均线周期只改变均线位置指标及依赖该指标的排序和明细，不改变当日涨跌成员占比或当日成交额占比。

### 8.5 可计算成分股与榜单资格

1. 产品统一使用“可计算成分股”，不使用容易被理解为股票本身失效的“有效成分股”。
2. 页面按三项指标分别展示“可计算数量 / 全部来源成分股数量”，不能悄悄改变分母。
3. 数据不足的成分股标记为“未纳入本指标计算”，不按零值、下跌或前一日结果处理。
4. 单项指标至少有 `5` 只可计算成分股，且可计算覆盖率达到 `80%`，该行业才参与该指标排名。
5. 不满足门槛的行业仍保留在完整榜单中，展示来源成员数、可计算数和“样本不足”；该指标比例显示 `--`，不赋予名次。
6. 后续技术阶段必须使用生产只读数据核验覆盖率分布；若门槛会把大量正常行业排除，必须回到产品评审，不得在代码中私自改变门槛。

### 8.6 排名与默认状态

1. 排名指标支持“成分股占比 / 成交额占比 / 均线位置占比”，默认“成分股占比”。
2. “上涨广度”按上涨、上涨成交额或站上均线占比由高到低排名；“下跌广度”按下跌、下跌成交额或跌破均线占比由高到低排名。
3. 榜单完整展示当前比较池全部行业，在固定高度容器内滚动，不截断为 Top N。
4. 相同指标值共享名次；行业代码只用于结果稳定排序，不打破并列名次。
5. 默认状态为一级行业总榜、上涨广度、成分股占比、20日均线、20日历史范围、`pageContext.tradeDate` 和第一只有资格排名的行业。
6. 比较范围、父级、分析日期、上涨／下跌方向、排名指标、均线周期、历史范围和当前选中行业均属于可恢复页面状态；刷新、前进和后退后语义不变。

### 8.7 工作区布局与交互

1. 左侧是完整行业广度榜单，展示行业、所属路径、当前排名指标、名次、可计算数量和覆盖情况。
2. 右侧顶部是当前选中行业摘要，并并列展示三条组成条：上涨／平盘／下跌成分股组成、上涨／平盘／下跌成交额组成、站上／等于／跌破所选均线组成。
3. 右侧中部是当前选中行业的历史广度趋势；历史范围支持最近 `20/30/60` 个 SSE 开市日，默认 `20日`。
4. 趋势图同时展示当前方向下的成分股占比、成交额占比和均线位置占比，三条线共用 `0–100%` 纵轴。
5. 历史每个点使用该日成员关系和当日事实独立计算；某日某条指标不可计算时保留日期槽并断线，不补零、不前向填充。
6. 下部展示当前选中行业的完整成分股明细，列包括股票名称、代码、当日涨跌幅、当日成交额、成交额贡献占比和相对所选均线的位置。
7. 成分股明细只加载当前选中行业，在固定高度容器内部滚动；选中行业、方向、排名指标或均线周期变化时，摘要、图表和明细同步更新。
8. 趋势图初始保持普通阅读状态；用户在有效绘图区单击后进入趋势查看状态，并吸附到距离单击位置最近的真实交易日，不停在两个交易日之间，也不插值业务数值。
9. 趋势查看状态同时显示日期纵线、跟随鼠标高度的百分比横线、三条折线在同一日期上的有效交点，以及包含完整日期和三项同日数值的 Tooltip。某项当日无值时不绘制伪交点，Tooltip 对应项显示 `--`。
10. 鼠标左右移动切换最近交易日；上下移动只帮助读取纵轴百分比，不改变已吸附日期。鼠标离开图表后保留最后读数，避免用户移向 Tooltip 或其他内容时信息突然消失。
11. 再次单击图内有效绘图区之外的空白或坐标轴区域，或图表获得焦点时按 `Esc`，退出趋势查看并恢复普通状态。
12. 切换行业、业务日期、上涨／下跌方向、均线周期、历史范围，或详情不再处于可展示状态时，清除旧趋势查看；只切换左侧排名指标时保留当前查看结果，因为趋势详情事实没有变化。
13. Tooltip 默认放在当前日期的右侧；当前日期位于图表右侧约62%以后时放到左侧，并始终限制在图表范围内，不能遮挡当前交点或溢出。
14. 趋势查看只读取页面已经加载的三条趋势事实，不产生新请求，不改变 URL，也不重新计算占比。

### 8.8 状态与加载边界

1. 工作区复用 Loading、Ready、Delayed、Empty 和 Error 稳定骨架；数据延迟时继续展示最近完整交易日事实并明确实际数据日期。
2. 个别行业或个别指标缺失时继续使用 Ready 骨架，保留行业并显示 `--`、缺失原因和可计算数量；当前比较池全部行业均不可计算时才进入 Empty。
3. 未选中“成员广度”方法时，不请求成员广度数据、不加载成分股明细、不挂载趋势图。
4. 成员广度按钮已经进入正式运行页面；M16I 已完成本地代码与验收，部署前不得把本地结果冒充生产交付。开发只能引用第10节正式节点，不得接入旧草稿或 Mock 数据。
