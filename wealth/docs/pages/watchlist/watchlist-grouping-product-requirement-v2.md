## 0. 文档目的与版本关系

本文汇总用户对“我的自选”分组能力、展示态、编辑态、批量操作、置顶、排序、颜色和股票详情页分组选择的最终产品决策，为后续交互设计、技术方案、低层设计、开发和验收提供统一输入。

v1 与 v2 的关系如下：

1. v1 保留为当前单列表实现及其历史验收的事实记录。
2. v2 定义下一版本目标，不修改 v1 的历史开发证据。
3. v1 中“本期不覆盖分组、手工置顶、涨跌排序、批量操作”的范围限制不适用于 v2。
4. v1 的右侧固定“操作”列、行内“移除”、股票详情页直接添加和 `id ASC` 单一排序口径，由本文定义的目标行为替代。
5. 编码前必须另行完成与本文一致的交互设计、技术实施方案和 LLD；不得直接依据本文猜测 API、表结构或分页算法。

## 1. 背景与目标

当前“我的自选”只能维护一个用户—股票列表，不能表达用户对不同观察主题的分类需求。

v2 的目标是把自选升级为用户私有的分组观察能力，使用户可以：

1. 使用系统默认的“我的自选”分组。
2. 创建多个自定义分组，并为自定义分组设置颜色。
3. 在不同分组中保存同一只股票。
4. 在分组之间移动、复制或移除股票。
5. 通过展示态浏览行情，通过编辑态集中管理成员关系和置顶状态。
6. 在股票详情页一次选择该股票所属的一个或多个分组。
7. 对行情数值列进行临时升降序排序。
8. 保留首页“我的自选”入口和默认组股票数量语义。

## 2. 用户范围与产品边界

### 2.1 本期覆盖

1. 默认分组和自定义分组。
2. 分组创建、查询、改色和删除。
3. 分组成员的添加、移动、复制式添加、移除、置顶和取消置顶。
4. 分组 Tab 与当前分组行情列表。
5. 展示态和编辑态两套列表交互。
6. 股票详情页的多分组选择面板。
7. 自选股票左侧多分组颜色条。
8. 行情数值列升降序排序。
9. 首页默认分组数量和默认进入行为。
10. 现有用户自选数据无损进入默认分组。

### 2.2 本期不覆盖

1. 分组重命名。
2. 分组拖动排序或手工调整 Tab 顺序。
3. 自选股票拖动排序或任意手工位置编辑。
4. 表头全选、跨未加载数据全选或一键选择整组。
5. 排序条件持久化；以后也不规划保存排序状态。
6. 颜色唯一性；不同分组允许使用相同颜色。
7. 自动把股票加入“我的自选”。
8. 在股票详情页把股票从全部分组中移除。
9. 标签、备注、价格提醒、交易计划、导入导出。
10. 扩展当前证券准入范围；仍沿用 v1 的当前上市 A 股边界。
11. 盘中实时行情改造；行情日期和缺失语义继续沿用 v1 已冻结合同。

## 3. 术语与业务对象

### 3.1 默认分组

“我的自选”是系统默认分组：

1. 每个用户必须且只能有一个。
2. 永远排在所有分组第一位。
3. 不能删除。
4. 不能重命名。
5. 没有分组颜色。
6. 是用户从首页或无分组参数进入自选页时展示的分组。
7. “默认分组”只表示默认进入和首页统计归属，不表示股票详情页默认勾选。

### 3.2 自定义分组

用户主动创建的分组：

1. 每个用户最多创建 9 个。
2. 加上“我的自选”，每个用户最多拥有 10 个分组。
3. 按创建顺序排列在“我的自选”之后。
4. 创建后不允许重命名。
5. 允许修改颜色。
6. 允许删除。

### 3.3 分组成员关系

一只股票属于一个分组，表示该股票与该分组之间存在一条成员关系：

1. 同一只股票在同一分组中只能存在一次。
2. 同一只股票可以同时属于多个不同分组。
3. 从一个分组移除，不影响它在其他分组中的关系。
4. 置顶状态属于具体的“分组—股票”关系，不是股票的用户级全局状态。

### 3.4 展示态与编辑态

1. 展示态用于查看行情、切换分组、进入股票详情和排序。
2. 编辑态用于选择当前分组中的股票并执行批量管理。
3. 编辑态锁定当前分组，不允许切换其他分组。

## 4. 分组通用规则

### 4.1 分组名称

1. 提交前必须移除名称前后的空格。
2. trim 后必须包含 1～6 个用户可见字符。
3. 允许正常可见文字、英文、数字、普通标点及合理混排，不新增字母数字白名单；例如“AI-组”合法。
4. 同一用户的分组名称不允许重复。
5. 自定义分组不能命名为“我的自选”。
6. 空字符串、纯空格和超过 6 个用户可见字符均不能提交。
7. 分组创建后不提供改名能力。

“可见字符”按扩展字素簇计算，不按编码单元或码点数计算。前后端统一 NFC 规范化、首尾空白处理与计数口径；规范化后仍包含换行、控制字符或纯不可见内容的名称不能提交。技术算法和共同测试向量见 LLD 第 7.2 节。

### 4.2 分组颜色

1. “我的自选”没有颜色，也不能设置颜色。
2. 创建自定义分组时，从固定色板中单选一个颜色。
3. 自定义分组创建后允许修改颜色。
4. 不同分组可以选择相同颜色，不做唯一性限制。
5. 颜色使用受控色板，不允许用户输入任意颜色值。
6. 固定色板已在[我的自选分组能力交互设计 v2](./watchlist-grouping-interaction-design-v2.md)中冻结为 8 个色值及固定顺序；开发不得自行增删或调整。

### 4.3 分组数量

1. 分组总数上限为 10，包含“我的自选”。
2. 自定义分组上限为 9。
3. 达到上限后不能继续创建，并向用户明确提示“最多创建 9 个自定义分组”。
4. 删除一个自定义分组后，用户可以再次创建，直到重新达到上限。

## 5. 页面入口与整体结构

### 5.1 首页入口

1. 首页“我的自选”快捷入口继续进入 `/wealth/market/watchlist`。
2. 不携带具体分组时，页面必须展示“我的自选”。
3. 首页徽标只统计“我的自选”中的股票数量。
4. 自定义分组的数量和成员数不计入首页徽标。

### 5.2 自选页结构

页面继续复用当前顶部行情栏、面包屑、Panel、行情颜色和数字格式。

目标结构：

```text
TopMarketBar
财势乾坤 / 乾坤行情 / 我的自选

[我的自选] [自定义组1] [自定义组2] ... [+ 新建分组]

┌─ 当前分组 ───── 当前组数量 ── 数据日期 ── [添加自选] [操作] ┐
│ 展示态：行情表                                                    │
│ 编辑态：批量操作栏 + 勾选列 + 行情表                              │
└───────────────────────────────────────────────────────────────┘
```

### 5.3 分组 Tab

1. Tab 导航位于面包屑下方、行情面板上方。
2. “我的自选”永远是第一个 Tab。
3. 自定义分组按创建先后排列；不因时间戳相同或显示格式变化而换序。
4. “+ 新建分组”位于最后一个分组 Tab 右侧。
5. 点击“+ 新建分组”打开创建分组弹窗。
6. 创建成功后关闭弹窗，并自动切换到新分组。
7. 达到 10 个分组后，创建入口不可继续提交新分组。
8. 展示态可以切换分组；切换后展示目标分组股票，并恢复默认排序。
9. 编辑态下，除当前分组外的所有 Tab 均为不可点击状态。

## 6. 创建、改色与删除分组

### 6.1 创建分组

创建弹窗包含：

1. 分组名称输入框。
2. 固定色板，以可单选圆形色块展示。
3. 取消按钮。
4. 确认按钮。

确认时必须同时满足名称和颜色规则。明确未写入的创建失败保留输入和颜色选择，允许修正或重试；提交结果未知时先读取当前分组，不直接重试创建。具体反馈遵循第 12.3 节。

### 6.2 修改颜色

1. 只有自定义分组允许修改颜色。
2. 改色入口属于当前分组的组级操作，不依赖是否勾选股票。
3. 改色入口位于编辑态操作栏，排在“取消置顶”之后、“删除分组”之前；默认组下不可用。
4. 修改成功后，该分组在所有股票颜色条中的颜色同步更新。
5. 改色不改变分组顺序、成员顺序或置顶状态。

### 6.3 删除分组

1. “删除分组”只出现在点击“操作”进入编辑态后的批量操作栏中。
2. 它删除当前分组，不是删除选中的股票。
3. 当前分组为“我的自选”时，“删除分组”不可用。
4. 删除自定义分组不要求先选择股票。
5. 点击后必须弹出确认弹窗，显示分组名称和组内股票数量。
6. 确认后，先删除该组中的全部成员关系，再删除分组；两步必须形成不可分割的结果。
7. 删除一个分组不能删除相同股票在其他分组中的关系。
8. 删除成功后退出编辑态并清空选择。
9. 如果被删除分组右侧还有分组，切换到右侧相邻分组。
10. 如果被删除分组是最右侧分组，直接切换到“我的自选”，不切换到左侧相邻自定义分组。
11. 取消删除不改变分组、成员、当前 Tab 或编辑态。

## 7. 展示态

### 7.1 页面头部

展示态头部保留当前组股票数量和数据日期，并在右侧展示：

1. “添加自选”。
2. “操作”。

展示态不显示“删除分组”独立按钮。

### 7.2 行情表格

1. 行情字段、格式、统一交易日和缺失值语义沿用 v1。
2. 删除当前表格最右侧“操作”列。
3. 展示态不提供行内移除、置顶或取消置顶按钮。
4. 股票代码、股票名称、行情、估值、活跃度、资金流和所属板块继续沿用当前列及样式。
5. 点击股票行或股票代码进入对应股票详情页。
6. 数值列可以通过表头进行升降序排序。

### 7.3 向当前组添加股票

1. “添加自选”只向当前激活分组添加股票。
2. 候选状态只判断股票是否已经属于当前分组。
3. 股票已经属于其他分组但尚未属于当前组时，仍可添加到当前组。
4. 重复添加到当前组按幂等成功处理，不生成重复关系。
5. 当前没有数值排序时，新成员进入当前组的基础顺序末尾。
6. 当前存在数值排序时，新成员按当前排序规则进入正确位置，不承诺出现在列表末尾。

## 8. 股票颜色条

1. 每个股票行最左侧预留分组颜色展示区。
2. “我的自选”无颜色，不占用颜色条区段。
3. 股票只属于“我的自选”时，不显示颜色条。
4. 股票属于一个或多个自定义分组时，显示这些自定义分组的颜色。
5. 多个颜色条共享同一高度，每个区段高度占比为 `1 / 有颜色的所属分组数`。
6. 颜色条按自定义分组创建顺序排列，不随当前 Tab 改变顺序。
7. 相同颜色允许相邻出现，不自动合并为一个分组语义。
8. 悬停每个颜色区段时，显示对应分组名称。
9. 编辑态增加复选框列后，颜色展示仍位于整行最左侧，不能被横向滚动隐藏。
10. 颜色只是辅助识别手段，不能作为唯一的分组信息来源。

## 9. 编辑态

### 9.1 进入与退出

1. 点击展示态头部“操作”进入编辑态。
2. 编辑态只作用于进入时的当前分组。
3. 其他分组 Tab 全部不可点击。
4. 编辑态退出的正常入口是操作栏右侧“完成”。
5. 点击“完成”清空选择、隐藏操作栏和勾选列，回到当前分组展示态。
6. “完成”只退出编辑态，不是批量操作的统一保存按钮，也不撤销已经成功的操作。
7. 删除当前分组成功时，系统自动退出编辑态并按分组删除规则切换 Tab。
8. 进入编辑态保留原面板头部和组名、数量、日期；“添加自选”禁用，“操作”显示为“编辑中”，操作栏追加在头部下方。

### 9.2 勾选列与行行为

1. 编辑态在表格最左侧增加复选框列。
2. 每个内容行有一个复选框。
3. 表头不提供全选复选框，也不提供整组全选能力。
4. 用户只能逐行选择已经加载并展示的股票。
5. 点击复选框或整行都切换该行的选中/未选中状态。
6. 编辑态点击整行不能进入股票详情页。
7. 选择以当前分组成员身份为准，不能误操作其他分组中的同代码关系。
8. 单次最多选择 200 只，具体上限由分组接口规则返回。达到上限后只阻止新增勾选，仍可取消勾选、浏览和加载更多。
9. 加载更多后保留当前组已选成员；不提供未加载数据选择。

### 9.3 操作栏

操作栏位于表头上方，包含：

1. 移动分组。
2. 添加到分组。
3. 移出本组。
4. 置顶。
5. 取消置顶。
6. 修改颜色，仅自定义分组可用。
7. 删除分组，仅自定义分组可用。
8. 右侧“完成”。

其中：

1. 前五项是股票级操作；未选择股票时不可用。
2. 修改颜色和删除分组是组级操作，不依赖股票选择。
3. 所有写操作各自即时提交；“完成”不再次提交。
4. 操作执行期间必须阻止同一批对象重复提交。

### 9.4 移动分组

1. 用户选择一只或多只当前组股票后点击“移动分组”。
2. 目标分组使用单选，只能选择一个。
3. 当前分组不能作为目标分组。
4. 目标列表按“我的自选”在前、自定义分组创建顺序在后展示。
5. 确认后，把选中股票加入目标分组，并从当前分组移除。
6. 加入目标和移除当前组必须作为一个不可分割的业务操作；任一步失败都不能留下半移动状态。
7. 目标分组已经包含某只选中股票时，不重复创建，但仍从当前组移除该股票。
8. 成功后清空选择，继续停留在当前组编辑态。

### 9.5 添加到分组

1. 用户选择一只或多只当前组股票后点击“添加到分组”。
2. 目标分组使用多选，可以一次选择一个或多个目标组。
3. 当前分组不作为目标选项。
4. 目标列表按“我的自选”在前、自定义分组创建顺序在后展示。
5. 未选择目标分组时，确认按钮不可用。
6. 确认后，把选中股票加入全部目标组，同时保留当前组关系。
7. 目标组已存在的成员按幂等成功处理，不生成重复关系。
8. 整批操作必须形成完整结果，不能只成功部分股票或部分目标组。
9. 目标选择面板中的确认就是提交动作，不增加第二个确认弹窗。
10. 成功后清空选择，继续停留在当前组编辑态。

### 9.6 移出本组

1. 用户选择一只或多只股票后点击“移出本组”。
2. 必须弹出二次确认，文案明确显示“将 N 只股票移出「分组名」”。
3. 确认后只删除选中股票与当前组的关系。
4. 不能删除这些股票在其他分组中的关系。
5. “我的自选”也允许通过该操作移除成员，但默认分组本身继续存在。
6. 取消不产生任何写入。
7. 成功后清空选择，继续停留在当前组编辑态。

### 9.7 置顶与取消置顶

1. “置顶”把选中成员标记为当前组置顶。
2. “取消置顶”只取消选中成员在当前组中的置顶状态。
3. 同一股票在其他分组中的置顶状态不受影响。
4. 对已经置顶的成员再次置顶、对未置顶成员取消置顶，均按幂等结果处理。
5. 成功后清空选择，继续停留在当前组编辑态。

## 10. 排序与置顶顺序

### 10.1 基础顺序

1. 每个分组保留稳定的成员加入顺序。
2. 未置顶成员在默认状态下按加入当前分组的先后排列。
3. 移动或添加到目标分组时，新建关系排在该组既有关系之后；目标组已包含该股票时保留原有位置和置顶状态。
4. 取消置顶不修改基础顺序，因此默认状态下可以回到原本位置。

加入先后采用成员关系的稳定 ID 顺序表达：普通区 ID 升序，默认置顶区 ID 降序；时间戳只用于展示与审计，不承担排序键。迁移保留原有 ID 和顺序。

### 10.2 默认置顶顺序

1. 置顶成员永远位于未置顶成员之前。
2. 没有数值排序时，置顶成员按加入当前分组的先后逆序排列，即后加入当前组的在前。
3. 未置顶区仍按基础加入顺序从早到晚排列。

### 10.3 数值列排序

以下列支持排序：

1. 最新价。
2. 涨跌幅。
3. 成交量。
4. 市盈率（PE TTM）。
5. 市净率（PB）。
6. 量比。
7. 换手率。
8. 资金净流入。

排序规则：

1. 股票代码是证券标识符，不属于本期数值排序列。
2. 第一次点击可排序表头时按降序排列。
3. 再次点击同一表头时切换为升序；后续继续在升降序之间切换。
4. 切换到另一个数值列时，该列从降序开始。
5. 缺失值 `--` 无论升序还是降序都位于对应区域最后。
6. 相同数值必须保持稳定顺序：置顶区按成员 ID 降序，未置顶区按成员 ID 升序。
7. 置顶优先级高于数值排序。
8. 启用数值排序后，置顶区和未置顶区分别按当前数值排序。
9. 此时“后加入当前组的在前”不再控制置顶区内部顺序，只作为无数值排序时的默认规则。
10. 数值排序中取消置顶后，股票进入未置顶区的正确数值位置；只有默认顺序下才严格回到原基础位置。

### 10.4 排序状态生命周期

分页边界：成员、置顶和排序行情值不变时，连续加载完整且无重复遗漏。本页写成功后按当前排序从首批重载；其它会话修改或同日行情更新可能改变旧游标前后的顺序，用户刷新后读取当前结果。本期不提供跨请求快照或实时跨端同步，列表去重不能保证补回外部变化造成的遗漏。

1. 排序状态只存在于当前页面、当前分组的本次查看过程中。
2. 切换分组时，目标分组恢复默认顺序。
3. 刷新页面、离开后返回或重新登录时恢复默认顺序。
4. 不写数据库、本地存储、用户设置或其他持久化位置。
5. 后续版本也不规划排序偏好持久化。

## 11. 股票详情页分组选择

### 11.1 按钮状态

1. 股票不属于任何分组时，按钮显示“+自选”。
2. 股票属于任意一个分组时，按钮显示“已添加”。
3. “已添加”不再置灰，仍然可以点击。
4. 两种状态点击后都在按钮下方打开分组选择面板。

### 11.2 分组选择面板

1. 面板位于按钮下方。
2. 每行两列：第一列复选框，第二列分组名称。
3. “我的自选”排第一，自定义分组按创建顺序排列。
4. 面板按当前实际分组数量展示：有两组就展示两行，有十组就展示十行。
5. 面板不使用固定六行高度，也不提供内部滚动。
6. 每次打开都重新读取最新分组及该股票的归属，读取成功后才建立预选；不能直接使用详情页首次加载时的旧缓存。
7. 股票尚未加入任何分组时，不默认勾选任何分组，包括“我的自选”。
8. 勾选变化只保存在面板本地，不在点击时立即写入。
9. 底部提供“确认”和“取消”。
10. 读取中和读取失败时不可勾选、不可确认；失败时提供读取重试。关闭后迟到的响应不能重新打开面板或覆盖下一次选择。

### 11.3 确认与取消

1. 用户勾选一个或多个分组后，确认按钮可用。
2. 未选择任何分组时，确认按钮置灰。
3. 点击确认后，以最终勾选集合为准：新勾选的分组加入，取消勾选的已有分组移除。
4. 整体变更必须一次完成，不能出现部分分组成功、部分失败。
5. 成功后关闭面板，并重新计算按钮是“+自选”还是“已添加”。
6. 明确回滚的失败保留面板和当前选择，显示错误并允许重试；结果未知时先读取实际归属再恢复编辑，不能直接重交旧选择。
7. 点击取消时丢弃本次全部临时选择，即使用户已经修改过勾选也不写入。
8. 点击面板外、按 `Escape` 或其他取消式关闭均等同于点击“取消”。
9. 如果股票当前只属于一个分组，用户取消该分组后会形成零选择，此时确认按钮不可用。
10. 因此股票详情页不能移除最后一个分组关系；用户必须到自选页编辑态执行“移出本组”。

## 12. 页面状态与反馈

### 12.1 分组状态

1. 分组列表加载中时，不展示伪造分组。
2. 分组读取失败时，保留页面壳并提供重试。
3. 当前分组不存在、已被删除或不属于当前用户时，不能展示其成员。
4. 无有效自定义组落点时，回到“我的自选”。

### 12.2 当前组列表状态

每个分组独立处理：

1. loading：加载当前组成员及行情。
2. ready：展示当前组行情。
3. empty：提示当前分组没有股票，并提供“添加自选”。
4. delayed：保留列表，展示最近可用交易日提示。
5. partial：保留成员，缺失字段显示 `--`。
6. error：展示当前组加载失败和重试，不伪装为空组。

### 12.3 写操作反馈

1. 操作执行期间禁用重复提交。
2. 成功反馈必须对应真实完成的分组和股票数量。
3. 明确未写入或已回滚的失败不能乐观删除或伪造成功；保留输入，允许修正或重试。
4. 批量操作必须完整提交或完整回滚，不能保留部分业务结果。
5. 写入已确认成功但列表刷新失败时，显示“操作已完成，列表刷新失败”，只重试读取，不重新执行写入。
6. 网络中断或提交阶段连接异常导致结果未知时，明确提示“提交结果待确认”，先读取当前分组和成员事实；不自动重放，也不提供直接重试同一写操作的按钮。
7. 读取当前事实不等于证明原请求成功；读回后恢复基于当前事实的操作，由用户重新确认新的变更。读取失败期间保留待确认状态。

## 13. 用户与安全边界

1. 分组和成员关系都是登录用户私有数据。
2. 所有读取和写入必须要求登录。
3. 用户只能读取、创建、修改或删除自己的分组和成员关系。
4. 请求不能通过传入其他 `userId` 访问他人数据。
5. 分组 ID、成员 ID 和目标组都必须验证归属，不能只相信前端状态。
6. 单股添加、移动、添加到分组和详情页调整归属时，仅对实际需要新增分组关系的股票执行当前上市 A 股资格校验；任一不合格则整批不变，移动源关系保留。已存在关系可以保留或移除，不因后续退市而禁止管理；重复添加已有关系按幂等成功处理。
7. 删除分组只删除用户关系数据，不删除证券、行情、估值或资金流事实。

## 14. 现有数据迁移要求

1. 上线 v2 时，现有每个用户的全部自选股票必须进入该用户的“我的自选”。
2. 迁移前后，首页徽标的默认组股票数量必须一致。
3. 必须同时保留现有成员 ID、添加时间和完整基础顺序，并逐用户核对有序成员清单。
4. 迁移不能把现有股票自动复制到任何自定义分组。
5. 迁移不能丢失、重复或跨用户混合现有自选关系。
6. 新用户也必须拥有唯一的“我的自选”，在用户创建事务中一并初始化，具体职责见技术方案和 LLD。

## 15. 验收标准

### 15.1 分组

1. 新用户进入自选页时存在且只存在一个“我的自选”。
2. 默认组不能删除、不能改名、没有颜色，并固定第一。
3. 最多创建 9 个自定义组，总分组不超过 10。
4. 名称 trim、1～6 个用户可见字符、不可重名、不能使用“我的自选”。
5. 自定义组不能改名，但可以改色和删除。
6. 相同颜色可以被多个自定义组使用。
7. 创建成功后自动进入新组。

### 15.2 展示态与编辑态

1. 展示态只有“添加自选”和“操作”，表格没有操作列。
2. 点击“操作”后出现操作栏和逐行复选框列。
3. 表头没有全选，编辑态整行只切换选择，不进入详情。
4. 编辑态其他 Tab 不可点击。
5. 各股票级操作在未选择股票时不可用。
6. 操作成功后清空选择并停留编辑态。
7. 点击“完成”退出编辑态，不撤销已成功操作。

### 15.3 批量操作

1. 移动只能选择一个目标组，并原子完成“加入目标 + 移出当前”。
2. 添加可以选择多个目标组，并保留当前组。
3. 移出本组必须二次确认，只影响当前组。
4. 置顶和取消置顶只影响当前组成员关系。
5. 已存在目标关系不重复创建，整批仍按成功处理。
6. 任何批量操作都不能只完成部分股票或部分目标组。

### 15.4 删除分组

1. 删除入口只存在于编辑态操作栏，并删除当前自定义组。
2. 默认组下删除操作不可用。
3. 确认弹窗显示分组名和成员数。
4. 确认后完整删除组内关系和分组，不影响其他组。
5. 右侧有分组时进入右侧相邻组；删除最右侧组时进入“我的自选”。

### 15.5 颜色条

1. 默认组不产生颜色区段。
2. 多个自定义组颜色等分行高，并按创建顺序排列。
3. 相同颜色不合并业务语义。
4. 每个区段都能通过悬停识别对应分组。

### 15.6 排序与置顶

1. 八个行情数值列支持首次降序、再次升序。
2. 缺失值在升降序中都排最后。
3. 置顶区始终位于普通区之前。
4. 默认状态下置顶区后加入当前组的在前。
5. 数值排序时两个区域分别排序。
6. 取消置顶不破坏基础顺序。
7. 切换分组、刷新和重新进入后恢复默认顺序。

### 15.7 股票详情页

1. 未加入任何组显示“+自选”，已加入任意组显示“已添加”，两者均可点击。
2. 面板展示全部实际分组行，不固定六行、不内部滚动。
3. 已有关系预选，新股票不自动选择“我的自选”。
4. 取消不写入，确认按最终选择集合原子更新。
5. 零选择时确认不可用，不能从详情页移除最后一个关系。

### 15.8 首页与迁移

1. 首页继续进入默认组。
2. 首页徽标只统计默认组。
3. 现有自选数据迁移到默认组后数量、用户归属和基础顺序不丢失。
