## 1. 目标与定位

“我的自选”是登录用户维护和查看关注股票的核心页面，不是全市场榜单，也不是运营配置页。

本期目标：

1. 用户从市场总览首页“我的自选”入口进入独立页面。
2. 用户可以添加或移除自己关注的股票。
3. 用户可以在一张可连续滚动的高密度列表中快速查看自选股票的最近可用交易日行情。
4. 用户点击股票行进入现有股票详情页，默认展示日线 K 线。
5. 首页“我的自选”徽标展示当前登录用户的真实自选数量，不继续使用固定占位数字。

## 2. 本期范围

### 2.1 本期覆盖

1. 首页“我的自选”入口真实导航。
2. 自选列表、真实数量、纵向连续滚动和横向滚动。
3. “添加自选”对话框与股票搜索结果状态。
4. 单只股票幂等添加。
5. 单只股票轻量确认后移除。
6. 股票详情页现有“+自选”按钮接入相同添加能力。
7. 股票行进入 `/wealth/market/stock/{tsCode}`，沿用详情页默认日 K。
8. 当前上市 A 股准入：`EQUITY + L + CNY + SSE/SZSE/BSE`。

### 2.2 本期不覆盖

1. 自选分组、标签、备注。
2. 拖动排序、手工置顶、涨跌排序或多条件筛选。
3. 价格提醒、资金提醒、交易计划。
4. 批量添加、批量删除、导入导出。
5. B 股、退市股票、指数、ETF、基金、港股、美股。
6. 盘中实时行情；本期展示统一交易日的最近可用盘后快照。
7. 自动删除后来停牌或退市的历史自选关系。

## 3. 页面结构

页面复用当前 Wealth 的 `TopMarketBar`、面包屑、Panel、数字字体与颜色语义，不新增侧边栏。

```text
TopMarketBar
财势乾坤 / 乾坤行情 / 我的自选

┌─ 我的自选 ─────────── N只 ─── 数据日期 YYYY-MM-DD ── [ + 添加自选 ] ┐
│ 股票代码 │ 股票名称 │ 最新价（元） │ 涨跌幅（%） │ 成交量（万手） │
│ 市盈率（PE TTM） │ 市净率（PB） │ 量比 │ 换手率（%） │ 资金净流入（万） │
│ 所属板块 │ 操作                                                  │
│          纵向滚动；中部行情内容过宽时横向滚动                  │
└─────────────────────────────────────────────────────────────────┘
```

### 3.1 列表列定义

| 列 | 单元格内容 | 业务口径 |
|---|---|---|
| 股票代码 | `tsCode` | 自选关系主体；固定在左侧第一列 |
| 股票名称 | 股票名称 | 固定在左侧第二列，不与代码或板块合并 |
| 最新价（元） | 收盘价数值 | 最近可用统一交易日；字色跟随涨跌幅的结构化方向，红涨绿跌；缺值 `--` 为中性色 |
| 涨跌幅（%） | 涨跌幅数值 | 红涨绿跌；显示正负号，单元格不重复 `%` |
| 成交量（万手） | 成交量数值 | 源单位手，前端除以 10000 后展示；不在本列混入成交额 |
| 市盈率（PE TTM） | `peTtm` 数值 | 独立列，单元格不加字段前缀；非正值或缺失显示 `--` |
| 市净率（PB） | `pb` 数值 | 独立列，不与 PE 合并；非正值或缺失显示 `--` |
| 量比 | 量比数值 | 独立列，不再归入“活跃度”组合列 |
| 换手率（%） | 换手率数值 | 独立列；单元格不重复 `%` |
| 资金净流入（万） | 净流入额数值 | `net_mf_amount` 源单位万元，前端不缩放，保留两位小数；正负号表达流入/流出 |
| 所属板块 | A 金色细边标签 | 可滑动区最后一列，不冻结；轻金底、细金框、金色字，24px 高 / 12px 字号；文字与表头左对齐，行内垂直居中；长名称单行省略，悬停可看全名；缺失用无装饰 `--` |
| 操作 | 移除按钮 | 固定在最右侧，不触发行跳转；按钮与文字均水平、垂直居中 |

数据列表头与对应单元格内容统一左对齐，并使用相同列内左边界；数值列不因使用等宽数字字体改为右对齐。操作列及搜索结果的状态列按本次指令居中，按钮内文字/加号也居中；不再用单侧 padding 对齐按钮文案。

### 3.2 滚动规则

1. 表头固定，列表正文纵向滚动直到最后一只股票。
2. 页面不显示传统分页器；后端可以有界分批返回，前端滚动接近底部时自动加载下一批。
3. 表格宽度超过可视区时允许横向滚动，不压缩或隐藏已确认字段。
4. 股票代码、股票名称固定在左侧；最新价至所属板块均属于横向滑动区，其中所属板块是该滑动区最后一列；只有操作列固定在右侧。
5. 行 hover 只轻微提亮，不使用跳动或大面积遮罩。

## 4. 添加自选对话框

点击“+ 添加自选”后打开居中对话框。对话框结构固定为上方搜索栏、下方搜索结果展示区。

### 4.1 搜索栏

1. hint 文案固定为：`输入名称首字母或代码`。
2. 支持股票代码、完整 `tsCode`、股票名称拼音首字母前缀。
3. 输入 trim 后为空时不发请求。
4. 停止输入 500ms 后发起查询；继续输入重置计时并取消旧请求。
5. 该控件属于“添加自选”业务选择器，不把首页股票搜索框挂载到自选页，也不改变首页搜索只出现于首页的既有约束。

### 4.2 固定结果区

1. 结果区高度固定，不因零条或多条结果改变对话框高度。
2. 列头固定为：`代码 / 名称 / 状态`。
3. 初次打开且没有搜索词时，结果正文保持空白；不展示热门股票、历史搜索或推荐。
4. 有搜索词但没有匹配项时，结果正文显示“未找到匹配的当前上市 A 股”。
5. 结果超过可视行数时只在结果区内部纵向滚动。
6. 状态列的表头、`+` 按钮和“已添加”文本居中；按钮为原生 button，复用当前暗底、边框、金色强调及禁用态规范，加号在按钮内部水平/垂直居中。

### 4.3 搜索结果 item

| 列 | 未添加 | 已添加 |
|---|---|---|
| 代码 | `600000.SH` | `600000.SH` |
| 名称 | 浦发银行 | 浦发银行 |
| 状态 | `+` 按钮 | `已添加` 文案 |

交互规则：

1. 点击 `+` 后按钮进入处理中状态，防止重复提交。
2. 服务端成功后当前结果行原位变为“已添加”，对话框保持打开，允许继续添加其它股票。
3. 新股票追加到自选列表最后；不移动已有股票。
4. 重复添加返回幂等成功，结果行仍变为“已添加”，不产生第二条关系。
5. 结果行本身不导航；只有 `+` 按钮执行添加。
6. 对话框支持关闭按钮、遮罩和 `Escape` 关闭，关闭时取消未完成搜索请求。

## 5. 删除交互

1. 点击列表行“移除”后，在页面正中打开轻量确认弹窗，不锚定行内按钮。
2. 文案为：`确认移除「{股票名称}」？`。
3. 操作为“取消”和“确认移除”。
4. 确认期间当前行保留，按钮进入处理中状态。
5. 成功后只移除该行并更新总数；失败时保留该行并显示轻量错误提示。
6. 删除不存在的关系按幂等成功处理，不向用户暴露竞争窗口。

## 6. 排序与实体导航

1. 默认顺序固定为添加顺序升序。
2. 新添加股票始终位于列表最后。
3. 排序使用持久化自增主键作为稳定游标和最终顺序，不依赖数据库隐式顺序。
4. 股票行整行可点击，页面统一使用 `buildStockDetailPath(tsCode)` 进入股票详情。
5. 行内“移除”必须停止事件冒泡；确认弹窗的遮罩、取消和确认操作不得触发行导航。
6. 股票详情页继续沿用 `day + forward` 默认 K 线合同。

## 7. 股票详情页联动

1. 详情页现有“+自选”按钮接入本模块的幂等添加接口。
2. 未添加时显示“+自选”；添加成功或已经添加时显示“已自选”。
3. 本期不从详情页移除自选；删除入口保持在“我的自选”列表。
4. “+提醒”和“+交易计划”继续保持未开通，不因本功能改变。

## 8. 数据时效与缺失规则

1. `MarketPageContext.tradeDate` 是页面期望交易日。
2. 列表行情的 `observedTradeDate` 取不晚于期望交易日的最新 `equity_daily_bar` 市场日期。
3. 日行情、每日指标和资金流只能按同一个 `observedTradeDate` 精确关联，禁止每张表各取自己的最新日期。
4. 某只股票在统一日期缺少个别数据时保留自选行，缺失字段显示 `--`。
5. 全部行情落后于期望日时显示 delayed；部分行或部分字段缺失时显示 partial。
6. 自选为空是正常 empty，不是错误。
7. 停牌、后续退市或源数据缺失都不能自动删除用户自选关系。
8. 后续分页或添加后的尾部补读发生行情日期变化时，丢弃该批次，整表重新加载并回到顶部，避免同一张列表混用日期（用户已拍板）。

## 9. 状态与反馈

| 状态 | 用户可见表现 |
|---|---|
| loading | 列表局部 skeleton；不展示 mock 行情 |
| ready | 展示自选和统一日期行情 |
| empty | “还没有自选股”及“添加第一只股票”按钮 |
| delayed | 展示真实数据并明确实际数据日期 |
| partial | 保留所有自选行，缺失字段为 `--` |
| error | 页面错误区与重试；不回退 mock |

搜索、添加和删除具有各自局部状态，不用整页 loading 覆盖已经可用的列表。

## 10. 用户与安全边界

1. 自选是用户私有数据，所有读写必须要求登录。
2. 服务端只使用认证上下文中的 `AuthenticatedUser.id`，请求体或 URL 不接受 `userId`。
3. 用户只能读取和修改自己的自选关系。
4. 添加前必须在服务端再次校验当前上市 A 股候选合同，不能信任前端搜索结果。
5. 首页公开行情接口的可选鉴权不适用于自选读写；自选统一使用强制登录依赖。

## 11. 验收标准

1. 首页“我的自选”点击进入 `/wealth/market/watchlist`，徽标为当前用户真实数量。
2. 对话框默认结果正文为空，hint、三列表头与固定结果区符合本基准。
3. 搜索只返回当前上市 A 股；B 股、退市股和非股票不得出现或被添加。
4. 未添加结果显示 `+`；点击后原位变为“已添加”，列表末尾出现该股票。
5. 重复点击、重复请求或并发添加只产生一条用户—股票关系。
6. 移除前在页面正中显示轻量确认弹窗；取消不变，确认成功后删除并更新数量。
7. 列表可纵向滚动至最后一项，并可横向查看全部已确认列；横向滚动时所属板块随行情列移动，股票代码、股票名称和操作保持固定。
8. 数据列表头与其下方内容均左对齐，所属板块标签文字也左对齐且在行内垂直居中；操作/搜索状态列居中。
9. 行点击进入正确股票详情页，首个 K 线请求仍为日线。
10. 行情、估值、量比、换手率和资金流使用同一 `observedTradeDate`，缺值不串日回填。
11. loading/ready/empty/delayed/partial/error 均有真实可验证表现。
