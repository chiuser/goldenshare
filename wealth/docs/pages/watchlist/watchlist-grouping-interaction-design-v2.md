## 2. 页面结构与量测基线

### 2.1 桌面评审画布

1. 主页面画板使用 `1600 × 980`，与当前自选页 V1 Figma 基线一致。
2. 顶部行情栏高度沿用 `56px`。
3. 页面左右边距沿用 `18px`。
4. 当前分组面板头部沿用 `66px`。
5. 表头沿用 `42px`，股票行沿用 `60px`。
6. 表格继续使用横向滚动；固定身份列与最左颜色条/勾选区不随横向滚动消失。
7. 本轮不增加移动端或窄屏新形态，后续开发不能据此自行创造另一套移动端交互。

### 2.2 Tab 导航

1. Tab 位于面包屑下方、当前分组面板上方，单行展示。
2. “我的自选”固定第一，自定义分组按创建顺序排列，“+ 新建分组”文字按钮固定在最后。
3. 激活 Tab 以品牌色边框、文字和分组色圆点共同表示；默认组不显示颜色圆点。
4. 展示态可切换 Tab；编辑态仅当前 Tab 保持可识别，其余 Tab 与“+ 新建分组”统一降为不可点击状态。
5. 切换 Tab 后重置数值排序，目标组恢复默认顺序。

## 3. 展示态

### 3.1 头部

当前分组头部按从左到右排列：

```text
分组色圆点 / 分组名 / 当前组股票数  ……  数据日期 / 添加自选 / 操作
```

1. 默认组没有分组色圆点。
2. “添加自选”只向当前组添加股票。
3. “操作”进入当前组编辑态。
4. 删除原有表格最右侧“操作”列，展示态不提供行内移除或置顶。
5. 点击股票行仍进入股票详情页。

### 3.2 数值排序

1. 八个可排序数值列在表头显示排序提示。
2. 未排序时显示双向提示；首次点击变为降序，第二次点击变为升序。
3. 切换排序列时，新列从降序开始。
4. 置顶区优先于未置顶区，两个区域内部再分别执行当前数值排序。
5. 缺失值始终位于所在区域最后。

## 4. 编辑态

### 4.1 进入与退出

1. 点击“操作”后，当前分组面板原位进入编辑态，不跳转新页面。
2. 保留原 `66px` 面板头部、组名、数量和日期；“添加自选”降为不可操作，“操作”显示为“编辑中”。
3. 在原头部下方、表头上方插入 `52px` 高操作栏，表格整体下移；不能用操作栏替换原头部。
4. 点击操作栏右侧“完成”后，清空选择并恢复展示态。

### 4.2 勾选与行行为

1. 表格最左侧增加“选择”列，每个内容行显示独立复选框。
2. 表头不显示全选复选框。
3. 点击复选框或整行都只切换该行选择状态，不进入详情页。
4. 选中行在固定身份列和横向指标区使用一致的选中底色。
5. 操作成功后清空当前选择，继续停留编辑态。
6. 单次选择上限消费 `rules.maxBatchMemberships`（本版为 200）。达到上限后，未选行的复选框和整行点击都不能新增选择，提示“单次最多选择 200 只”；已选行仍可取消，浏览和加载更多不受影响。
7. 只选择已加载成员，加载更多保留当前选择；不支持表头全选或选择未加载成员。

### 4.3 操作栏排布

操作栏从左到右为：

```text
已选择 N 只｜移动分组｜添加到分组｜移出本组｜置顶｜取消置顶｜修改颜色｜删除分组 …… 完成
```

1. “移动分组、添加到分组、移出本组、置顶、取消置顶”是股票级操作，没有选择股票时不可用。
2. “修改颜色、删除分组”是当前组级操作，不依赖股票选择。
3. 默认组下不提供“修改颜色”和“删除分组”的可执行状态。
4. “移出本组”和“删除分组”使用危险色；“完成”使用品牌色。
5. 每项写操作即时提交，“完成”不承担统一保存或撤销。

## 5. 分组创建与组级操作

### 5.1 新建分组

创建弹窗包含名称输入、固定色板、取消和创建按钮：

1. 名称统一 NFC、trim，按扩展字素簇校验 1～6 个可见字符，用户内唯一且不能为“我的自选”。允许普通标点，不增加字母数字白名单；准确算法及反例以 LLD 第 7.2 节为准。
2. 颜色必须从八个固定色值中单选。
3. 创建成功后关闭弹窗并切换到新组。
4. 达到 9 个自定义组时，创建动作不可提交，并显示上限提示。

固定色板按下列顺序展示：

| 顺序 | 色值 | 语义 |
|---|---|---|
| 1 | `#F7C76B` | 金色 |
| 2 | `#5AA7FF` | 蓝色 |
| 3 | `#A78BFA` | 紫色 |
| 4 | `#2DD4BF` | 青绿色 |
| 5 | `#FB923C` | 橙色 |
| 6 | `#F472B6` | 粉色 |
| 7 | `#A3E635` | 青柠色 |
| 8 | `#22D3EE` | 青色 |

色值允许重复使用；选中态使用高对比外描边，不依赖颜色本身表示是否选中。

### 5.2 修改颜色

1. 入口位于编辑态操作栏，排在“取消置顶”之后、“删除分组”之前。
2. 只对当前自定义分组生效。
3. 弹层复用新建分组的同一固定色板。
4. 确认后只更新颜色，不改变分组、成员、置顶或排序。

### 5.3 删除当前分组

1. 入口位于编辑态操作栏，只删除当前自定义分组。
2. 弹窗明确显示分组名称和组内股票数。
3. 确认后先移除组内全部成员关系，再删除分组，且不影响其他分组关系。
4. 删除后右侧有相邻组时进入右侧组；当前组是最右侧时回到“我的自选”。

## 6. 批量目标选择与确认

### 6.1 移动分组

1. 目标列表使用单选，当前组不显示。
2. “我的自选”排第一，自定义分组按创建顺序排列。
3. 目标选择弹层中的确认即提交，不增加第二次确认。
4. 成功后清空选择并停留当前组编辑态。

### 6.2 添加到分组

1. 目标列表使用多选，当前组不显示。
2. 至少选择一个目标组后确认按钮才可用。
3. 确认后加入全部目标组，同时保留当前组关系。
4. 目标选择弹层中的确认即提交，不增加第二次确认。

### 6.3 移出本组

1. 必须二次确认，正文使用“将 N 只股票移出「分组名」？”。
2. 补充说明明确“只影响当前组，其他分组归属保持不变”。
3. 确认后清空选择，取消则不产生变更。

## 7. 股票详情页分组选择器

### 7.1 入口

1. 股票不属于任何组时显示“+自选”。
2. 股票属于任意组时显示“已添加”。
3. 两种状态都保持可点击，并在按钮下方打开选择器。

### 7.2 列表与高度

1. 每行由复选框、可选颜色点和分组名组成。
2. “我的自选”始终第一，但系统不自动勾选它。
3. 自定义分组按创建顺序排列。
4. 选择器高度跟随实际分组行数：两组显示两行，十组显示十行。
5. 不保留六行空位，也不提供内部滚动。

### 7.3 确认语义

1. 每次打开先读取最新分组及归属，成功后才建立预选；已有归属选中，无归属时全部未选。初始按钮缓存不能直接作为下一次打开的草稿。
2. 勾选变化只存在于弹层本地，点击确认才提交最终集合。
3. 新勾选加入，取消已有勾选移除。
4. 零选择时确认按钮立即置灰，因此不能在详情页移除最后一个归属。
5. 点击取消、面板外或 `Escape` 都丢弃本次临时变化。
6. 读取中和读取失败时不能勾选、不能确认；错误态提供读取重试，不提交旧缓存。关闭后取消旧读取并屏蔽迟到响应。
7. 草稿建立后不再由后台读取覆盖用户勾选；不增加实时同步或多端集合自动合并。

## 8. 股票颜色条

1. 颜色条占据股票行最左侧，编辑态复选框位于其右侧。
2. 默认组无颜色，不生成颜色区段。
3. 属于多个自定义组时按分组创建顺序纵向等分行高。
4. 相同颜色不合并，仍保留多个可悬停区段。
5. 悬停提示对应分组名，颜色只做辅助识别，不作为唯一信息来源。

## 9. 页面状态与反馈

1. 读取失败、空组、延迟行情和字段部分缺失继续沿用 V1 的页面状态语义。
2. 写操作期间禁用重复提交。
3. 明确未写入或已回滚的失败保留当前弹层、输入和选择，不伪造成功，也不留下部分结果。
4. 创建、移动、添加、移出、删除、改色成功后都要反馈真实分组和股票数量。
5. 首页入口和徽标不变：仍进入“我的自选”，徽标只统计默认组。
6. 写入已成功但随后列表刷新失败时，提示“操作已完成，列表刷新失败”，只重试读取，不恢复原选择或重试写操作。
7. 提交结果未知时，提示“提交结果待确认”，暂停当前写入口并读取实际状态；读取失败只允许重试读取。不能自动重放或一键重交旧请求；读回后按当前事实恢复操作，不把 GET 成功提示成原写入成功。

## 10. 评审门禁与下一步

交互稿评审应至少确认：

1. 展示态、编辑态和详情页三类入口是否符合预期。
2. 操作栏的动作分组、顺序和危险级别是否清楚。
3. 移动单选、添加多选、移出和删除二次确认是否没有歧义。
4. 详情页零选择禁用是否能够解释“不能移出最后一个归属”。
5. 固定色板、重复颜色和多段颜色条是否可接受。
