## 1. 目标与当前实现

股票和指数详情页的普通日线图表请求统一显式传500根，包括日K、日线九转和日线趋势通道。股票本步只改这三处请求量，股票分页和空状态归股票专项。按剩100根预取历史、缓存和图层接续只在上证普通日K启用。分钟线相关请求当前已是500根。后端指标接入仅限上证日K，从原行情行生成价格和量额，只把MA、BOLL、MACD、KDJ的16个字段换成内核结果。上证历史页的九转和趋势通道按当页实际日期取数。

| 环节 | 已核实的当前实现 | 本方案的接入位置 |
|---|---|---|
| 普通日K首屏 | 先请求 `page-init`，取 `asOfTradeDate`，再请求 `kline`。股票页面传300，指数页面传1000。 | 普通页面显式请求500，沿用原路由和K线字段。上证新分支在 `meta` 补续页日期，边界见第8节。 |
| 日K数据和随附指标 | 上证日K新分支已实现。DG 和 Prod 均复用当页行情，只补读更早的预热数据，再用内核结果填回原指标字段。 | 前端沿用原行情和指标字段，并使用 `meta.nextEndDate` 续页。 |
| 九转与趋势 | 九转已有起止日期参数。上证趋势通道接口已补可选起始日期。 | 首屏沿用原触发时机，只改请求量为500。上证历史日K成功后，用实际首末日期请求同页图层。 |
| 图表 | 数据数组改变会重新创建日K、MACD、成交量和KDJ四张图。当前拖动到最早位置后，可见范围会被固定在边界。 | 历史左插在原图实例上更新，按交易日期保持可见范围。重试取自用户真实拖动，即使已经拖不动。 |
| 计算内核 | 现有服务通过 `PriceSource` 接收输入，现有 Lake 读取实现没有指数日线。 | 增加上证指数日线输入，直接复用当页K线。需要预热时，内核只向本环境补读缺少的前置K线。 |

代码依据见 [首屏控制器](../../../src/features/index-detail/controller/useIndexDetailController.ts#L63)、[指数日K路由](../../../../src/biz/api/wealth/market/index_detail.py#L132)、[日K两条读取分支](../../../../src/biz/queries/wealth/market/index_detail/index_detail_kline_query_service.py#L86)、[图表更新](../../../src/shared/charts/detail-workspace/DetailChartWorkspace.tsx#L654)和[内核当前取数规则](../../../../src/foundation/clients/local_lake/technical_indicator_contracts.py#L51)。

## 2. 产品交互

### 2.1 首屏与继续查看历史

1. 点进上证指数详情页后，沿用当前日期选择逻辑。通常由 `page-init` 给出最新有行情的交易日。从指定日期进入时，仍使用该入口确定的 `asOfTradeDate`。从这天往前最多取500根。若 `page-init` 已明确无行情，则直接沿用首屏空状态。
2. 用户向右拖动图表，查看更早的行情。以最左侧可见的交易日为准，从这根数到缓存最早一根，两端都计入。**剩100根或更少时**，提前请求下一页。缓存有500根时，最新为第1根，第401根是首次触发位置；接成1000根后，对应第901根。一次快速拖动跨过阈值，也只请求当前下一页。
3. 下一页只取更早日期，例如首屏第1～500根、下一页第501～1000根。已加载的数据继续保留。用户在缓存覆盖范围内查看时，直接使用缓存；仍有更早历史时，只有用户拖入新的预取范围才发起下一页。图表因接入新数据而调整自身位置，也只更新显示。
4. 旧页在请求途中，用户若已拖回较新的日期，回包只存进缓存，画面保持原样。再次向历史拖动，进入当前图表左端剩100根的范围时，先用已有缓存补图。比如缓存已有第1～1000根，图上仍只有第1～500根，拖回第401根时只从缓存补图，拖到第901根才请求下一页。用户若还在历史一侧，接上旧页时保持回包当下正在看的交易日期和缩放，让同一次拖动可以继续。

### 2.2 左端与异常

| 情况 | 用户看到什么 | 页面动作 |
|---|---|---|
| 下一页在后台加载，用户还未拖到最早一根 | 图表照常 | 等待当前请求。 |
| 下一页尚未回来，已拖到最早一根 | 最早K线左侧显示「加载中」 | 停在当前左端。数据到达时撤下提示，接入左侧。 |
| 历史页失败 | 到左端时显示「加载失败」。若已拖回较新日期，保留当时的视图；当前请求的后端日期或四价错误仍弹出具体提示。 | 保留原图和缓存。下一次继续向右拖、试图越过左端时，用原日期重试；每次新手势最多触发一次，无回弹动效。 |
| 历史页成功，返回1～499根 | 接上本页已有数据 | 标记已到最早，后续拖动使用本地数据。 |
| 历史页成功，返回0根 | 原图照常 | 撤下等待提示，标记已到最早，原图无需重绘。 |
| 首屏成功，返回0根 | 使用现有「暂无指数日线数据」页面状态 | 结束加载。首屏查询失败则走现有页面错误状态，后端报告日期或四价异常时同时提示具体原因。 |
| 切换指数、日期，或离开页面 | 以当前页面状态为准 | 取消旧请求；迟到的成功、失败和收尾回调均丢弃。 |

首屏和历史页成功返回不足500根即到头。判断依据是后端成功返回的 `bars` 根数。恰好500根且后端给出下一页截止交易日时，下一次用户拖到阈值才正常请求更早一页。如果下一页返回0根，就结束加载。

## 3. 请求与上下游合同

### 3.1 普通日K

| 请求 | 参数 | 回包和衔接 |
|---|---|---|
| 首屏 | 现有 `GET /api/v1/wealth/market/index-detail/kline`，带 `tsCode=000001.SH`、`period=day`、`endDate=page-init.asOfTradeDate`、`limit=500` | 日期从早到晚。实际首末日期取自 `bars`，`meta.endDate` 仍表示本次请求的截止日期。 |
| 更早一页 | 同一指数和周期，`limit=500`；把上一成功页的 `meta.nextEndDate` 原样传为 `endDate` | 后端用同环境交易日历，给出本页最早一根之前的上一交易日。最早一根若是周一且上周五开市，下一页直接传周五。 |
| 重试 | 沿用失败请求的指数、周期、截止日和上限 | 仍是当前最早日期之前的同一页。成功后才推进缓存边界。 |

上证普通日K同时只发一个历史页请求，预取阈值为剩100根。股票和指数的普通日线三路请求共用500根页大小。指标计算分支由标准化的指数代码和内核单次容量确定，见第8节。股票三路请求沿用各自的触发条件和时机，分页和空状态按股票专项安排。 [股票接入方案 §9.3](../../../../docs/architecture/technical-indicator-kernel-stock-daily-api-integration-plan-v1.html#stock-daily-frontend)

回包入缓存前核对指数代码和日线周期，并与发请求时记录的页面编号、首屏截止日、当前请求编号和本页截止日对应。历史页的 `meta.endDate` 对应的是该历史请求。用户从上证切到沪深300再切回上证，第一次打开上证时发出的回包也属于旧页面。页面取消是为了尽早停止请求，编号检查用于挡住已经在路上的旧回包。

### 3.2 后端负责日期和四价完整性

- 上证日K新分支在返回成功前核对日期范围、日期唯一性和顺序，以及开盘、最高、最低、收盘是否为可用的有限数值。发现异常时整页失败，错误信息带指数代码、出错交易日期和具体原因，例如「000001.SH 2026-10-15 收盘价缺失」。沿用现有 `ID_QUERY_FAILED` 和错误消息传递方式，页面直接弹出消息。后端记录同一请求的诊断信息，供按错误日期追查。
- 日期核对要覆盖整根缺失。例如周三应有行情，但数据漏了，查询又用更早一天补满500根，后端仍要指出周三缺失。优先复用当前请求已有的交易日和行情信息，区分休市、确实没有更早历史和行情缺失。LLD 写明日期依据和检查位置。
- 上证普通页面使用交易日作为截止日。仍传入休市日的直接调用，按截止日及之前最近的交易日判断数据状态，原请求日期保留在 `meta.endDate`。分页所需的上一交易日与 `pageContext.prevTradeDate` 分开，字段及短页规则见 LLD §27.2。
- 成功回包保持当前 `bars` 及指标字段，合法的指标空值保留。前端只做回包归属检查并处理成功或错误，行情日期和四价的完整性由后端承担。历史回包只补图表缓存，首屏的行情日期、右栏摘要和页面状态仍来自首屏。

参考 [上证日K合同 §5.5](index-detail-api-contract-v1.md#sse-daily-kline-api)、[错误码登记](../../system/exception-code-registry.md)、[前端错误读取](../../../src/features/index-detail/api/indexDetailApiClient.ts#L85)和[当前指数API回归样本](../../../../tests/web/test_wealth_index_detail_api.py#L40)。

### 3.3 九转与趋势通道

首屏沿用现有时机。趋势在 `page-init` 后照常发起，九转按当前页面逻辑触发，两路只把请求上限改为500。趋势先回来时暂存在首屏状态，日K回来后按实际K线日期绘制。首屏结果由主图和右栏共用。

历史日K成功且有K线后，两路图层以该页 `bars` 的实际首末日期并行请求。比如最后一页有200根，两路仍传500作为上限，日期范围覆盖实际的200根。

| 图层 | 查询规则 | 页面使用 |
|---|---|---|
| 九转 | 现有 `GET /api/v1/wealth/market/index-detail/nine-turn`。首屏只改 `limit=500`，历史页传同页 `startDate`、`endDate` 及 `limit=500`。 | 按日期放置标记，只有出现计数的交易日才有标记。首屏最新九转摘要复用首屏响应，旧页标记只补图。 |
| 趋势通道 | 现有 `GET /api/v1/quote/detail/trend-channel` 增加可选 `start_date`。首屏只改 `limit=500`，历史页用包含首末日期的范围和 `limit=500` 截取现有计算结果。显式起始日晚于显式截止日返回 HTTP 400 / `INVALID_DATE_RANGE`。省略起始日期时沿用现有调用行为。见[趋势接口合同 §5.1](../../../../docs/architecture/sse-daily-trend-channel-realtime-computation-low-level-design-v1.md#trend-history-range-api)。 | 按日期接入趋势点，缺点的日期留空。追加历史趋势时保留用户选择的叠加项和首屏趋势摘要。 |

日K的成功回包用于判断到头。历史空页不触发图层。历史图层按页面、日期范围和图层登记，在途和成功的请求由对应显示位置复用。九转或趋势单独失败时，在对应图层提示并重试原请求，已成功的日K和图层继续显示。

参考 [九转查询](../../../../src/biz/queries/wealth/market/index_nine_turn/index_nine_turn_query.py#L23)、[趋势通道接口](../../../../src/biz/api/quote.py#L123)和[趋势通道计算与截取](../../../../src/biz/services/quote_trend_channel_query_service.py#L181)。

## 4. 缓存和图表如何衔接

- 同一次打开只保留一份业务缓存，以交易日期存日K、随附指标和辅助图层。图表记录当前显示区间、缩放和正在拖动的位置。旧页回包时若用户已拖回较新位置，只更新缓存；之后拖回历史侧时才更新图表。
- 左插时保留原四张图实例，在已有数据序列上调用 `setData`。以更新前实际可见的交易日期和缩放恢复四图的共同范围。左插会改变数组下标，所以正在进行的拖动也要按更新后的日期位置接续。用户选定 MA、BOLL 或趋势后，首屏迟到回包和历史回包均保留该选择。用户已拖回较新位置时，历史图层也只写缓存。
- 早期 K 线照常显示。MA、BOLL 各条线从自身首个有效值对应的交易日开始绘制，之前的 `null` 留空。MACD 可见范围内没有有效指标值时，保留面板和坐标，留空柱和线。从各自首个有效值所在日开始画 MACD 柱、DIF 和 DEA。数值 `0` 是有效值。
- 浏览器在上证页面分别验收用户仍在向历史拖动时回包和已经拖回较新日期后回包，观察可见交易日、缩放、十字线和拖动是否跳变。
- 当前图表在到达边界后会固定可见范围。左端失败重试应读取新的真实拖动手势，以识别继续向右拖的意图。单次手势内即使收到多次移动事件，也只重试一次。

参考 [拖动边界](../../../src/shared/charts/detail-workspace/DetailChartWorkspace.tsx#L552)、[四图更新](../../../src/shared/charts/detail-workspace/DetailChartWorkspace.tsx#L654)和[主图叠加项](../../../src/features/index-detail/chart/IndexChartWorkspace.tsx#L41)。

## 5. 上证日线接入计算内核

1. **当页直接复用。** `IndexDetailKlineQueryService.build_kline()` 复用原行情读取并校验。合法空页直接返回。有行情时，App 为本请求创建 `PriceSource`，把现成的交易日、最高、最低和收盘交给内核。同一页一次提交MA5、10、20、30、60、90、250，以及BOLL、MACD、KDJ。用不复权的指数点位计算，结果只覆盖当页日期。
2. **预热由内核按日期独立补读。** 内核确定预热根数后，`PriceSource` 按当页首日之前的交易日期取数，本地读DG，生产读Prod PostgreSQL，只取交易日和高、低、收。DG 用交易日历确定这段预热日期，直接读取对应文件。当页查询与预热之间只交接已取得的当页K线和日期边界。达到同源历史起点时按已有初始化规则计算，缺数据或读取失败按错误处理。
3. **回填后用本次数据检查并按原方式组包。** 先逐日核对内核结果和 `rows`，再把16个结果写回原行中对应的指标字段。MACD的 `hist` 写入 `macd_bfq`，KDJ的 `j` 写入 `kdj_bfq`。有效根数是实际交给内核的预热根数，加上当页从首根到当前这根的已校验根数。MA 和 BOLL 窗口尚未满时保留合法空值。上证新分支使用本次交易日核对结果确定数据状态，旧分支沿用原查询。价格、量额、涨跌等字段继续从原行组包。内核原有 `price` 输出能力保留，本次业务只使用四组指标结果。日期对不上、结果字段不齐或计算失败时，整页报错。
4. **正常两页的指标数值验收采用新旧对照。** 每个环境各用本环境原路径的16个指标值和内核结果逐日、逐字段对照。非空原值的绝对差不超过 `0.0005`，即小数点后第三位的半个单位。日期、字段、根数及空值位置必须一致。该上限只用于验收，发现超限记录交易日、指标、原始新旧值和绝对差。各环境最早三根的短页另核指标初始化，见 §7.1。

参考 [日K取数与缺项检查](../../../../src/biz/queries/wealth/market/index_detail/index_detail_kline_query_service.py#L86)、[内核确定预热需求](../../../../src/foundation/technical_indicators/service.py#L135)、[数据交接接口](../../../../src/foundation/technical_indicators/sources/contracts.py#L138)和[日K字段映射](../../../../src/biz/services/wealth/market/index_detail/index_detail_field_mapper.py#L113)。

### 7.1 历史起点、固定样本与读取上限

2026-11-05 只读核实。**DG 上证日K从 `2000-01-04` 开始，Prod 从 `2010-01-04` 开始。** DG 的正式因子目录最早分区就是 `2000-01-04`，读取最早三份文件均有上证行情。Prod 在 `core_serving.index_factor_pro` 按上证代码用索引取最早三行，首行为 `2010-01-04`。两边的上交所日历都确认了各自起点开市。实际读取位置、查询范围和抽样结果见[LLD §27.5.1](index-detail-low-level-design-v1.md#sse-daily-kline-acceptance-samples)。

| 正常对照样本 | 请求 `endDate` | 应返回的交易日（含首末日） | 前置预热（含首末日） |
|---|---|---|---|
| 首屏 | `2026-10-20` | `2024-09-23`～`2026-10-20`，500根 | `2022-08-30`～`2024-09-20`，500根 |

两边使用同一日期安排，各自与自己的旧指标对照。首屏最早一根是 `2024-09-23` 周一，回包给出 `2024-09-20` 周五，续页正好从周五接上。每个环境一次固定对照覆盖1000个日期、16000个指标值。复核发现 DG 的1500个所需日分区文件均存在，Prod 同范围的1500个上证行情日期和交易日历完全对应。两边另各抽查了6个边界日期，16个旧指标字段均有值。指标数值是否一致在后端接入后实际比较。

**历史起点按现有内核规则初始化。** 两边第一天的旧 MA20、MA250 已有值，而新内核从本环境实际首根开始计算。MA、BOLL 窗口未满时返回 `null`，前端按第4节保留日期并留空指标。正常两页仍按第5节核对全部16个字段的原值绝对差和空值位置。另取各环境最早三根检查短页、指标初始化和到头，再请求起点前的一个开市日检查成功空页。图表的指标留空与首次出值用受控回包验证。

每个正常页只读500根当页和500根预热。原定验收安排包括一次旧值参考、两环境各两次新日K、起点短页与空页，以及 DG 本地浏览器连走两页。原定上限含每个环境最多一个获准的失败节点续跑，**DG 上证行情最多6003根，Prod 最多4003根**。失败尝试按实际读取量计费。Prod 暂缓项见 §7，接下来的浏览器验收只用 DG。图层请求和故障场景用受控样本核对，具体数量及停止规则见[LLD §27.5.2](index-detail-low-level-design-v1.md#sse-daily-kline-acceptance-budget)。

## 8. 页面页大小和接口边界

股票及指数普通日线页面显式传 `limit=500`。股票日K API 仍按现行默认500、范围1～500处理。指数日K API 仍按现行默认300、范围1～2000处理。标准化后的 `tsCode=000001.SH` 且 `period=day`、`limit≤500` 时，非空日K页一次调用内核。直接请求上证501～2000根或请求其它指数时，从入口按现有查询处理。已经进入内核计算的请求如遇失败，按原错误合同返回。
