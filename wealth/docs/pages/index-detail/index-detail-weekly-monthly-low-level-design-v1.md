## 2. 页面契约补充

**`GET /page-init`。** `chartDefaults.defaultPeriod` 仍为 `day`。当前环境的指数周、月两种算子位置均已启用、应用装配有可执行的周月线处理且指数在现有主要名单内时，`availablePeriods` 在 `day` 后增加 `week`、`month`，`supportsWeeklyMonthly=true`。其它情况下按原能力返回。能力判断复用算子运行配置，验收确认两端现有 `max_output_rows` 能满足 500 根页大小。分钟能力的环境规则及 `nineTurnPeriods` 沿用现有合同。其余 `page-init` 字段、右栏查询与日期沿用现有口径。

**`GET /kline`。** 使用现有鉴权、参数名称和错误处理。省略 `period` 为 `day`。周、月响应复用已有行情和 `factors` 结构，`period` 回显请求周期。周月 `meta` 必带 `nextEndDate`，包括空页。上证现有日线分页响应与其余日线响应的字段形状沿用原合同。

| 字段 | 周、月规则 |
| --- | --- |
| `tsCode` | 现有 `majorIndices/CN_A` 名单。未知或未开放的代码沿用原 404。 |
| `period`、`limit` | `week` / `month`，`limit` 默认 300，允许 1–500。页面显式传 500。能力未开启、非法周期或超出上限走原 `ID_REQUEST_INVALID`。 |
| `startDate`、`endDate` | 若提供下界，所选 K 线实际截止日在上下界内，含首尾。页面首批显式传 `page-init.asOfTradeDate`，续页显式传上次 `meta.nextEndDate`，二者均不传下界。省略 `endDate` 时复用初始化的市场日期和最近实际日行情日期查询，取实际日行情日期。无法取得该日期时按查询失败处理。 |
| `bars[].tradeDate` | 周／月线实际截止交易日，唯一、正序。后端用 `source_as_of` 生成。日期同时用于 K 线、横轴、鼠标提示和各指标。 |
| `meta.count/limit/startDate/endDate` | `count=bars.length`；`limit` 为归一后的上限；`startDate` 为请求下界或 `null`；`endDate` 为本次有效查询上界。行情更新较晚时末根实际日期可早于查询上界。 |
| `meta.nextEndDate` | 按同一指数、同一周期向前多找一根，使用它的实际截止日，且早于本页首根。没有更早符合范围的 K 线时为 `null`，即使本页恰好 500 根。 |
| `dataStatus`、`debugInfo` | 状态沿用 `EMPTY > PARTIAL > DELAYED > READY`，观测日为实际末根，普通响应 `debugInfo=null`。核验路由使用相同数据与游标，复用调试 DTO，提示按实际周期生成。 |

例如页面以 `endDate=2026-11-20&limit=500` 请求上证周 K，返回 `period="week"`、实际首根 `2017-02-17`、实际末根 `2026-11-20`，`meta.nextEndDate="2017-02-10"`。下一次请求直接使用这个截止日。DG 和 Prod 已对照正式来源核对这三个日期，阶段二再经实际接口验证。

## 3. 后端读取、计算和组包

1. **先选页面要显示的周期。** 两端只查一个代码和一个频率，按周期倒序取本次需要的最新 `limit+1` 根。按自然周期界限缩小物理日期范围，同时用源 `trade_date` 判断是否在请求的实际日期上下界内。仅取 `ts_code`、`period_start_date`、`trade_date`、`pre_close`、`change_amount`、`pct_chg`，按日期保留有界结果。额外一根只提供游标，请求范围内没有额外一根就返回 `nextEndDate=null`。
2. **选页和计算分别读取。** 选页及补充字段一次取出。Prod 选页使用现有短期只读会话，取完即归还，算子按原方式建立和关闭自己的事务。DG 两步打开同一正式路径，算子沿用阶段一在单次计算内部的文件检查。两步之间允许读到不同版本，日期能对齐就按本次所读数据返回。接口无需跨步骤固定文件版本或共享数据库事务，也无需因此自动重试。
3. **单次计算并逐根对齐。** 以选中首根所属自然周期起始日和末根实际截止日构造计算范围，一次请求 `price`、MA(5/10/20/30/60/90/250)、BOLL(20,2)、MACD(12,26,9)、KDJ(9,3,3)。算子按所需窗口读前置历史，并按阶段一规则核对已发布范围内的周期。逐根核对 `times[i]` 对应选中的自然周／月，`source_as_of[i]` 等于同一行 `trade_date`。错期、重复、应有历史缺根、四价非法或算子结果无法对齐都按现有查询失败处理。
4. **组回日线形状。** 四价与量额取 `price`，七条 MA、三条 BOLL、MACD 的 `dif/dea/hist` 和 KDJ 的 `k/d/j` 映射至原 `factors` 字段，其中 `hist` 映射到 `factors.macd.macd`。源 `pre_close` 为周期第一交易日的前收，映射 `preClose`；`change_amount` 映射 `change`。DG `pct_chg` 已是百分数，Prod 的 `pct_chg` 乘 100。两端算子结果已统一为股、元，分别除 100、1,000 得到手、千元，`volDisplay` 用原 formatter。振幅仍由后端按 `(high-low)/preClose*100` 填充，前收为零或所需字段缺失时为 `null`。量额和原行情辅助字段缺项可返回 `PARTIAL`。MA、BOLL 因真实历史不够留空，值 `0` 按正常数值处理。
5. **完成或退出。** App 在现有[请求执行入口](../../../../src/app/runtime/technical_indicators/execution.py)内完成选页、计算和编码。Prod 选页复用[现有只读会话](../../../../src/app/dependencies/stock_daily_technical_indicators.py#L49)的语句时限和退出清理。DG 批次间沿用运行状态检查。请求断开或到期后停止后续工作，各阶段各自释放资源。读取、计算或结果对齐失败沿用 `ID_QUERY_FAILED`；重试以原参数重新读数。

**空页和更新延迟。** 复用[市场日期查询](../../../../src/biz/queries/wealth/market/context/market_page_context_query.py#L39)得到响应所需的 `pageContext`。有显式上界时，用该日的开市标志和前一开市日得到截至上界最近的开市日。省略上界时，使用按 §2 得到的实际日行情日期。这个日期在请求范围内时写入 `expectedTradeDate`。合法空页若没有适用的开市日，`expectedTradeDate` 取有效查询上界，`observedTradeDate=null`。

| 情况 | 判断和响应 |
| --- | --- |
| 正常翻到历史尽头 | 当前页仍返回已有 K 线。多取的一根不存在时 `nextEndDate=null`，页面停止再查。历史不足导致 MA250 等为空时照常返回。 |
| 没有选到任何一根 | 查询上界早于该指数在正式周月线来源的最早周期，或交易日历确认查询范围内没有应取的开市日时，返回 `EMPTY`、`bars=[]`、`nextEndDate=null`，直接结束，无需调用算子。只有需要判断历史起点时才补查来源首根。日历或行情读取失败，以及应有行情却读不到，均按查询失败处理。 |
| 已有 K 线，最后一根早于 `expectedTradeDate` | 用正式来源最新一根的实际截止日区分。如果来源最新实际截止日也早于预期日，保留现有行情，按既有状态优先级处理 `DELAYED`。若预期日已在来源发布范围内而缺少对应行情，按查询失败处理。正常首批或翻页最后一根已到预期日时无需额外补查来源末根。 |
| 普通和核验接口 | 共享行情、游标、预期日期和状态，沿用 `EMPTY > PARTIAL > DELAYED > READY`。核验提示根据 `response.period` 生成，周月线有 `nextEndDate` 字段时仍报告已确认的延迟。现有日线提示及判断沿用原行为。 |

## 4. 前端请求与绘图

1. **注册周期。** API 请求的周期类型扩展为 `day | week | month`。周月响应类型要求 `meta.nextEndDate`。`supportsPeriod` 以两个初始化能力字段共同决定按钮是否可点，保留分钟能力分支。页面选择 `day` 时使用现有日图，`week/month` 使用周期图，其余已启用分钟周期进入现在的分钟图。后端能力未启用时沿用当前禁用状态。
2. **管理当前图表。** 周月首批、历史和重试由指数图表控制层管，按指数、所选周期、首批 `asOfTradeDate` 和打开次数识别请求。切换周期重置到最近一批；切指数回日 K。离开或切换结束旧请求并丢弃迟到结果。周月首批的 `loading/empty/error` 仅替换图表区，`PARTIAL/DELAYED` 保留可画内容和现有反馈形式。更新 `page-init` 日期后，新结果以新截止日替换相同周期的最新一根。没有独立的定时刷新。
3. **加载历史。** 直接使用 `DetailChartWorkspace.onHistoryViewport`。确认用户向历史方向移动、左侧已加载剩余不超过 `SSE_DAILY_PREFETCH_REMAINING` 的 100 根、有游标并且当前无旧页待显示或在途时，发一批请求。检查响应指数、周期、`meta.endDate`、根数、实际日期正序和游标。续页整体早于现有首根，验证通过才更新游标。左插时按日期保留可见范围及缩放；较新视口下只缓存当前页。错误保持原游标，在新手势尝试越过左端时只重试一次；`nextEndDate=null` 结束加载。
4. **复用展示。** `toCandlePoint` 用 `tradeDate` 同时填图表 `time` 和完整提示日期，各主副图使用同一日期键。图表身份包含指数、周期和首批日期，历史追加保持身份。周月主图初始显示均线，BOLL、成交量、MACD、KDJ 使用现有显示控件、格式和色值。成交额继续随行情用于现有提示。九转、趋势通道和顶底识别不进入周月图，也无周月版独立请求。日线和分钟已有内容的来源和标注保持原样。

## 5. 成本与恢复

| 项目 | 单次与验收预算 |
| --- | --- |
| 请求与根数 | 每次首次切换或历史触发一个 `/kline`，带 `limit=500`。服务端最多保留 501 条选页记录，再调用一次算子。完整页最多读入 1,000 根行情并返回 500 根。选页记录与计算输入有重合，分别记数。前端每个周期只保留一个在途历史请求，取消或失败不自动重发。 |
| DG | 额外读取正式指数周线或月线文件中的六个选页字段。2026-11-22 只读页脚核对，这些列从文件展开后的大小为周线 284,854 字节、月线 67,621 字节。加上[算子库读取预算](../../../../docs/architecture/technical-indicator-index-period-low-level-design-v1.md#5-性能预算与中断恢复)，行情选页与计算两步的文件列展开大小估算为周线 `284,854+767,859=1,052,713` 字节、月线 `67,621+224,785=292,406` 字节。 |
| Prod | 一次按 `(ts_code, period_start_date)` 约束的选页查询，最多交付 501 条。核对真实执行计划、索引和扫描范围。算子内部读取仍走阶段一预算。 |
| 日期和状态 | 接口复用一次现有市场日期上下文读取；省略截止日时才额外查询一次日行情日期锚点。空页或疑似更新延迟时才补查该指数、该频率的来源首根或末根。Prod 对需要的一端按周期索引取一条；DG 最多额外读一次代码和两个日期列，按阶段一同列测量估算周线 71,401 字节、月线 17,086 字节。市场上下文和日行情日期锚点的实际读取开销，阶段二单独记录。 |
| 时间 | 复用现有请求预算。默认从服务端收到请求起总目标 8 秒，其中读取计算的工作截止为 6 秒，留 2 秒清理。选页、算子和接口编码同属该请求。阶段二记录接口用时和回包字节数，阶段三记录图表更新时间。 |
| 实测与重试 | DG、Prod 各对上证跑两次周 K，首批 500 根和前 500 根。每端共 1,000 根页面记录、2,000 根算子输入、至多 1,002 条选页记录；DG 两次行情选页与计算的文件列展开估算为 `2×1,052,713=2,105,426` 字节，市场上下文另计。另用上证和中证 A500 各一次月 K，按实际返回和送算根数记录。核验接口对照已验证的普通接口样本，每次按对应页的同一预算计。失败后重试增加最多一次当页预算，已成功的页面和对照样本可复用。受控错误和旧响应测试使用隔离环境。 |
