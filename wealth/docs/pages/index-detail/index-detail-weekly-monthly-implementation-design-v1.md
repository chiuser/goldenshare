# 指数详情页周线、月线实施方案 v1

2026-11-22｜阶段一算子库已验收并提交（`9f77940c5`），阶段二接口已通过 DG、Prod 正式数据只读验收（`bd71f1591`）。阶段三前端已通过连接 DG 的本机真实页面验收。数据来源、日期和指标算法见[算子库专项方案](../../../../docs/architecture/technical-indicator-index-period-plan-v1.md)。[阶段二验收](index-detail-weekly-monthly-low-level-design-v1.md#7-阶段二验收记录) · [阶段三验收](index-detail-weekly-monthly-low-level-design-v1.md#8-阶段三验收记录)

## 1. 用户看到什么

- 现有主要指数详情页都可点击「周K」「月K」。名单沿用当前 `majorIndices/CN_A` 配置，包含北证 50。打开新指数时默认日 K，周期按钮、布局及 K 线交互沿用现有页面。
- 一周、一月各一根。历史 K 线的日期是该周期最后一个交易日，最新一根用该周期行情实际更新到的交易日。K 线、横轴、鼠标提示和 MA、BOLL、MACD、KDJ 一起对齐到这个日期。节后仅两个开市日的上证周 K，若行情截至 10 月 9 日，图上就显示 10 月 9 日。
- 点击周期时取最近最多 500 根。向左看更早行情时，按后端给出的上一批截止日期继续取，直到历史起点。刚发布的指数也能看已有 K 线，MA250 等指标历史不足时留空。
- 周、月使用日 K 已有的四组指标和行情展示格式。九转、趋势通道、顶底识别等独立图层首期不支持周、月。右栏的基本行情、权重和原有按日线或分钟周期标注的内容仍使用自己的数据。股票周月线另行实施。

视觉和交互以[现有指数详情标杆](index-detail-benchmark-requirement-v1.md)、[周期工具栏](../../../src/features/index-detail/layout/IndexChartToolbar.tsx)、[现有日线图表](../../../src/features/index-detail/chart/IndexChartWorkspace.tsx)和[上证日线左拖规则](index-detail-daily-kline-integration-implementation-design-v1.md)为依据。本次在原布局启用已有按钮，因此直接验收原图表和新增周期的状态变化。

## 2. 接口和数据从哪来

沿用 `GET /api/v1/wealth/market/index-detail/kline`，增加 `period=week/month`。默认 `day` 及既有日线路径保持原行为。分钟线继续走 `/minutes` 和 `/minute-indicators`。`/page-init` 用已有的 `chartDefaults.availablePeriods` 和 `capabilities.supportsWeeklyMonthly` 告诉页面能否切换周、月，两个字段与后端路由依据同一运行能力判断。

| 环节 | 约定 |
| --- | --- |
| 首次打开周期 | 用 `page-init.asOfTradeDate` 作 `/kline` 的 `endDate`。休市时页面初始化本来就提供最近有行情的交易日。切换周期无需重做页面初始化。 |
| 更早一批 | 接口以实际截止日正序返回 `bars`。`meta.nextEndDate` 是本页首根之前、同一指数同一周期实际可用的上一根截止日，到头时为空。前端原样传回该字段作为下一批的 `endDate`。 |
| 行情与指标 | 本地由 DG 指数周、月线 Silver 提供，Prod 由 PostgreSQL 指数周、月线 Serving 提供。后端同次调用算子库读取行情并计算 MA、BOLL、MACD、KDJ，再把同一根 K 线的四价、量额与指标一起组包。 |
| 日期与单位 | 用算子结果中的实际截止日 `source_as_of` 填 `bars[].tradeDate`。后端沿用日线接口的成交量（手）、成交额（千元）、涨跌幅（百分数）和显示格式。前端直接消费这些字段。 |

选页和算指标可以分别读取正式周月线。行情更新时，两步偶尔读到不同版本，同一根 K 线的补充字段可能与四价不同步，影响限于当次只读响应。下一次请求重新读数，更新完成后会读到更新后的数据。组包仍逐根核对所属周期和实际截止日，保证指标贴在正确的 K 线上。

具体请求、响应和后端读取预算见[专项 LLD](index-detail-weekly-monthly-low-level-design-v1.md)。阶段二同步[指数详情 API 合同](index-detail-api-contract-v1.md)，接口验收通过后进入阶段三。

## 3. 加载和翻页

周月线只切换图表内容。等待时用现有图表加载状态，空结果显示当前周期无数据，首批失败允许重试当前周期。历史请求失败时，保留已显示的图和原截止日期，下一次向左端外拖时重试。旧页接到左侧时保持当前可见日期和缩放。

历史到头时，最后一批的下一批日期为空。最新周 K 或月 K 尚未更新到本次应有的交易日时，有旧行情就继续返回，并标记更新延迟。新指数因历史短而无法算出的 MA250 等指标照常留空。读源失败或已发布历史确实缺根时，沿用现有查询错误。

承接上证日线的加载节奏。用户向左看历史且离已有起点只剩 100 根时，可以预取一批。一个周期同时只取一批，用户拖回较新日期时，已返回的旧页先留在本次看图的内存里。切指数、周期、行情日期或离开时取消旧请求，并忽略已经发出的旧响应。新周期从最近一批开始，右侧行情日期保持页面初始化所给的日期。

## 4. 性能与通过标准

- 一次周期切换或一次历史加载只新增一次 `/kline` 请求，后端最多算一次。满页且历史充足时，算子读取 500 根目标和 500 根前置历史，只向页面返回 500 根。用于下一页日期和行情补充字段的读取另计。请求的现有服务端时间及内存限制继续适用。
- **阶段二，后端接口。** DG、Prod 各用真实普通接口跑上证周线首批 500 根和用游标取更早的 500 根，检查日期衔接、MA250、接口耗时和回包大小。用上证月 K 核对当月实际截止日，用中证 A500 月 K 核对短历史和翻页停止。核验接口对照普通接口，并回归现有日线和分钟线。
- **阶段三，前端页面。** 接上已验收的接口，用浏览器验证切周期、向左拖、视口和缩放、横轴、鼠标提示及指标日期，记录图表更新时间。若需回退，按已交付的阶段回退本次周月线接入，按钮恢复原能力。

| 项目 | 本模块做法 | 验证 |
| --- | --- | --- |
| 事实源单一 | 每个环境各用正式周、月线数据集，后端按实际截止日组包 | 核对两端真实来源、行情和指标日期 |
| 契约先行与冻结 | 在现有 `/page-init`、`/kline` 扩充周期，沿用原行情字段 | 校验周月 DTO、旧日线形状与页面消费 |

| 排序与筛选确定性 | 后端按实际截点翻页并校验周期唯一 | 两批 500 根无重复、无遗漏，旧响应丢弃 |

| 用户可见结果 | 通过真实 API 驱动周、月图表 | 检查图表日期、量额、指标、重试和保留视口 |
