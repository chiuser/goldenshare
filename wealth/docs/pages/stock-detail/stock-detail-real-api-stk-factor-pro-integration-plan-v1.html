股票详情页真实 API 对接方案 v1

本方案用于把财势乾坤股票详情页从首版 mock UI 过渡到真实数据。首期只接入 core_serving.equity_factor_pro 与 core_serving.security_serving，覆盖日 K、日频技术指标和右侧盘口摘要中的基础信息。

页面：股票详情页 周期：首期仅 day 主源：equity_factor_pro 身份源：security_serving 不做：分钟线 / 周月线 / 资金 / 板块 / 用户动作

1. 当前代码事实核验

1.1 quote.py 与 quote_query_service.py 不是“无人使用”

当前 src/biz/api/quote.py 和 src/biz/queries/quote_query_service.py 仍有真实引用，不能在本轮直接删除。 它们更准确的状态是：旧 quote 详情链路仍在线，但不应作为财势乾坤股票详情页新 API 的主设计口径。

引用方 当前用途 处理建议
src/app/api/v1/router.py 仍挂载 biz_quote.router，暴露 /api/v1/quote/detail/*。 本轮不删；后续单独做 quote legacy 下线计划。
src/biz/api/market.py 仍复用 QuoteQueryService().build_trade_calendar()。 若下线 quote service，需先迁出该 calendar 能力。
tests/web/test_quote_api.py 覆盖 quote detail 的 page-init、kline、related-info、announcements。 测试还在，说明旧 API 当前不是死代码。
tests/integration/test_quote_qfq_parity_with_pro_bar.py 直接实例化 QuoteQueryService 做复权一致性校验。 需要迁移或重写后才能删旧 query service。
docs/platform/* 与 docs/product/* 仍记录旧 quote detail API。 后续文档清理时标记 legacy，避免污染新财富系统 API。

结论：股票详情新 API 应放在 /api/v1/wealth/market/stock-detail/* 命名空间， 不继续扩展旧 /api/v1/quote/detail/*；但 quote 旧链路是否删除，需要单独审计和替换引用。

1.2 market context 是页面级日期锚点

市场总览页已有统一 context：GET /api/v1/wealth/market/context。股票详情页也应复用这个页面级结构， 其中 pageContext.tradeDate 是“页面默认查询哪个交易日”的锚点。

字段 含义 股票详情页使用方式
market 当前固定 CN_A。 股票详情页首期只支持 A 股股票。
tradeDate 页面级期望交易日；默认由交易日历和 20:00 盘后切换规则得到。 page-init 默认取该日期或该日期之前最近可用的个股数据。
prevTradeDate 上一交易日。 首期可用于调试与数据状态，不要求前端展示。
sessionStatus PRE_OPEN / TRADING / BREAK / CLOSED。 用于说明页面是盘中还是盘后口径；不代表实时行情。
source explicit 或 default。 说明日期来自用户传参还是系统默认。

设计口径：新股票详情 API 返回 pageContext，并在模块级 dataStatus 中说明个股实际观测日期。 这样既复用页面级 tradeDate，又不会把个股缺数伪装成“已具备该交易日数据”。

2. 设计边界与性能原则

首期必须做

  • 股票身份：代码、名称、行业、上市状态、交易所。
  • 日 K：只支持 period=day。
  • 默认前复权日 K：产品含义为前复权，底层字段后缀为 qfq。
  • 右侧盘口摘要：今开、昨收、最高、最低、换手率、量比、成交量、成交额。
  • 指标：MA、BOLL、MACD、KDJ，全部只使用源表已有字段，不做自研计算。

首期明确不做

  • 不接分钟线、分时、周 K、月 K。
  • 不接关联板块、个股资金结构、自选、提醒、交易计划。
  • 不为了 UI 完整性伪造 MA15、MA120、大单净量等字段。
  • 不复用旧 /api/v1/quote/detail/* 作为新页面 API。
  • 不设计大而全的整页一次性响应，只按必要性和性能拆为 page-init 与 kline。

4. 接口设计

4.1 page-init

GET /api/v1/wealth/market/stock-detail/page-init?tsCode=603806.SH&tradeDate=2026-05-29
参数 必填 说明
tsCode 是 股票代码，例如 603806.SH。首期只支持 A 股股票。
tradeDate 否 页面期望交易日；不传时由 MarketPageContextQuery 解析默认交易日。
debug 否 开发调试用，返回源表、观测日期、缺失说明；生产 UI 默认不展示。

性能口径：该接口只查 1 条 security_serving 和 1 条 equity_factor_pro 最新可用日频记录，不加载 K 线数组。

4.2 kline

GET /api/v1/wealth/market/stock-detail/kline?tsCode=603806.SH&period=day&adjustment=forward&limit=300
参数 必填 说明
tsCode 是 股票代码。
period 否 首期只允许 day；其他周期返回明确错误，不伪造。
adjustment 否 首期只允许 forward；对应底层 *_qfq 字段。
startDate / endDate 否 用于限定日期范围；不传时按 limit 取最近 N 根。
limit 否 默认 300，最大 2000。用于控制响应体大小和查询成本。

性能口径：只查询图表所需字段，不做 select *；依赖 equity_factor_pro(ts_code, trade_date) 主键 / 索引。

5.4 StockChartDefaultsDto

为什么需要：前端图表工具栏必须由后端告诉“首期能用什么”，避免 UI 暴露未接入能力。

来源：首期固定规则，不读数据库。

性能与必要性：对象极小；用于前端禁用非首期能力和初始化图表。

字段 首期值 说明
defaultPeriod"day"首期默认日 K。
defaultAdjustment "forward" API 外部契约统一使用 forward 表示前复权；底层字段后缀是 qfq。 这等价于“默认前复权 / qfq 字段”，但不把源字段后缀直接暴露成 UI 枚举。
sourceAdjustment"qfq"仅用于 debug / 字段映射说明，表示读取 *_qfq 字段。
availablePeriods["day"]首期只有日 K 可点。
availableAdjustments["forward"]首期只支持前复权。
availableMainOverlays["MA", "BOLL"]主图可选覆盖线。
availableIndicatorTabs["VOL", "amount", "MA", "MACD", "KDJ", "BOLL"]首期接入真实数据的指标 tab。
 
{
  "defaultPeriod": "day",
  "defaultAdjustment": "forward",
  "sourceAdjustment": "qfq",
  "availablePeriods": ["day"],
  "availableAdjustments": ["forward"],
  "availableMainOverlays": ["MA", "BOLL"],
  "availableIndicatorTabs": ["VOL", "amount", "MA", "MACD", "KDJ", "BOLL"]

说明：用户拍板的 qfq 是底层字段口径；为了和已有工程枚举 forward 以及 availableAdjustments ["forward"] 保持一致，本方案把外部 API 值定为 forward，并用 sourceAdjustment="qfq" 显式记录字段映射。

9. 风险与决策记录

9.1 defaultAdjustment 的命名口径

用户拍板的业务默认是 qfq / 前复权。但 availableAdjustments 拍板值是 ["forward"]，且现有 quote 代码也使用 forward -> qfq 的映射。

因此本方案统一 API 外部值为 forward，同时返回 sourceAdjustment="qfq" 说明底层字段。 这样不会出现 defaultAdjustment="qfq" 但 availableAdjustments=["forward"] 的前端枚举不一致。

9.2 旧 quote 链路

旧 quote 链路当前仍被使用，不能作为本轮“顺手删除”对象。后续若要废弃，应先做专门计划：

  1. 迁出 src/biz/api/market.py 对 QuoteQueryService 的 calendar 复用。
  2. 确认没有前端、测试、脚本、文档继续依赖 /api/v1/quote/detail/*。
  3. 删除 router include、API、schema、query service 和对应测试。
  4. 更新 docs，把旧 quote detail API 标记为已下线。

9.3 不做自研指标计算

首期只使用 stk_factor_pro 已有字段。源表没有的 MA15、MA120 不返回。 这会让 UI 上的均线选项与 mock 期略有差异，但这是正确的：真实 API 不能为了贴 mock 去临时造字段。
