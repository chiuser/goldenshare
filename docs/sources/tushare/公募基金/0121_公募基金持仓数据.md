# 公募基金持仓数据

- 分类：公募基金
- 原始链接：[https://tushare.pro/document/2?doc_id=121](https://tushare.pro/document/2?doc_id=121)

- 接口：fund_portfolio
- 描述：获取公募基金持仓数据，季度更新
- 积分：5000积分以上每分钟请求200次，8000积分以上每分钟请求500次，具体请参阅[积分获取办法](https://tushare.pro/document/1?doc_id=13)

## 输入参数

| 名称 | 类型 | 必选 | 描述 |
| --- | --- | --- | --- |
| ts_code | str | N | 基金代码 (ts_code,ann_date,period至少输入一个参数) |
| symbol | str | N | 股票代码 |
| ann_date | str | N | 公告日期（YYYYMMDD格式） |
| period | str | N | 季度（每个季度最后一天的日期，比如20131231表示2013年年报） |
| start_date | str | N | 官方描述为报告期开始日期（YYYYMMDD格式）；见下方实测边界。 |
| end_date | str | N | 官方描述为报告期结束日期（YYYYMMDD格式）；见下方实测边界。 |

## 输出参数

| 名称 | 类型 | 默认显示 | 描述 |
| --- | --- | --- | --- |
| ts_code | str | Y | TS基金代码 |
| ann_date | str | Y | 公告日期 |
| end_date | str | Y | 截止日期 |
| symbol | str | Y | 股票代码 |
| mkv | float | Y | 持有股票市值(元) |
| amount | float | Y | 持有股票数量（股） |
| stk_mkv_ratio | float | Y | 占股票市值比 |
| stk_float_ratio | float | Y | 占流通股本比例 |

### 实测补充（2026-08-05）

官方页面未列出分页参数；当前 `tushareMcp` 与 Goldenshare 的 `TushareHttpClient` 均实测接受 `limit`、`offset`。`period=20250630`、全部 8 个字段、`limit=2000` 已连续取得 offset `0..660000` 的 662,000 行，且该已连续实测区段的 `(ts_code, ann_date, end_date, symbol)` 无重复；offset 660,000 仍是满 2,000 行。随后以 `limit=8000` 做只读边界定位，得到该请求在 2026-08-05 的总数为 **1,312,798** 行（末段 `offset=1307500` 返回 5,298 行），所有抽取行的 `end_date` 均为 `20250630`。按 2,000 行折算，该快照至少需要 657 页。未分页的 8,000 行只是一页，不是全量。

当前页面列出的输入参数和 `tushareMcp` 参数签名均未提供 snapshot ID、游标或 `as_of` 版本参数；同一 `period` 的多页读取没有可用于固定源端快照的标识。

同次实测中，`ts_code=015477.OF,000001.OF` 加 `period=20250630` 返回空集，两个代码单独请求均有数据；页面也未定义代码列表语法。`period=20250630` 的首个 8,000 行均为 `ann_date=20250831`，因此 `ann_date` 的存在本身不代表该公告日结果较小。

日期语义的样本验证如下（均显式请求 `ts_code,ann_date,end_date,symbol`）：

1. `000001.OF` 的无日期历史有 6,317 行、98 个 `end_date`，从 `20020331` 连续到 `20260630`；`001753.OF`、`015477.OF`、`510300.SH` 的样本 `end_date` 也都仅为季度末日期。
2. `period=20250630` 分别返回：`000001.OF` 187 行（`ann_date=20250721,20250830`）、`015477.OF` 274 行（`20250721,20250831`）、`510300.SH` 340 行（`20250721,20250830`）；每个结果的 `end_date` 均只有 `20250630`。
3. 只传 `ann_date=20250721` 分别得到 10、13、15 行；与 `period=20250630` 合传时结果不变。这说明 `ann_date` 是披露批次过滤，不能替代 period。
4. 对上述 O、E 样本传 `start_date=20250101,end_date=20251231`，结果均包含 `end_date=20241231,20250331,20250630,20250930`，且所有返回的 `ann_date` 都在 2025 年；这与“报告期范围”的官方字段说明不一致，当前实测行为更符合公告日期窗口。

### 实测补充（2026-08-08）

本轮为 B7-M0 复审，先固定最多 120 次源请求，实际执行 119 次，没有重拉 2026-08-05 已取得的 1,312,798 行季度全量基线。

1. `ts_code=000001.OF,period=20250630` 的默认字段与显式请求全部 8 字段均返回 187 行；字段集合相同，完整行多重集相等，`end_date` 只有 `20250630`，`ann_date` 为 `20250721/20250830`，候选身份 `(ts_code,ann_date,end_date,symbol)` 无重复。
2. 当前会话的 `tushareMcp` 工具签名没有暴露 `limit/offset`，因此不能把本轮 MCP 调用表述成分页复验。Goldenshare `TushareHttpClient` 以 `period + limit=1 + offset=0` 请求 114 个候选季度末均成功，证明当前源接口仍接受分页参数；完整多页、递增 offset 和 short-page 终止继续使用 2026-08-05 的项目 connector 实测证据。
3. 候选范围为 `19980331..20260630` 共 114 个季度末。`19980331` 为空，从 `19980630` 到 `20260630` 的 113 个季度末连续非空；每个非空样本的返回 `end_date` 都与请求 `period` 相同。该盘点只验证报告期是否存在，不声称取得每期精确总行数。

## 接口用法

```python
pro = ts.pro_api()

df = pro.fund_portfolio(ts_code='001753.OF')
```
