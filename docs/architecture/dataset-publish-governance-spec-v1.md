# 多源映射与发布规则

更新时间：2026-09-08。由原“数据集发布治理规范”收窄为多源专题；保留文件路径，不变更既有字段、发布策略或运行链路。

## 1. 适用范围

本文件补充 Prod 数据集**多源字段对齐、融合与发布**的设计要求，适用于新增多源能力及既有多源能力的来源、字段、发布规则变更。

单源接入不套用本专题，也不为形式完整增加 Std 表、规则对象或双写。通用分层遵守 [Foundation 研发基线](/Users/congming/github/goldenshare/docs/architecture/foundation-current-standards.md)；具体方案、字段字典、测试与分阶段验收填写[数据集开发模板](/Users/congming/github/goldenshare/docs/templates/dataset-development-template.md)，不另填第二套 PR/验收清单。

本文的标准字段指统一语义，不强制独立物理 Std 层。实际 `layer_plan/write_path`、物理表或视图依照获准的数据集设计，不将 `Raw -> Std -> Serving` 写成所有数据集必经路径。DG/Lake 不套用本专题。

## 2. 多源字段对齐

在数据集设计中，为每个目标字段维护一份映射；已在模板字段对账表说明的内容直接引用。

| 必须说明 | 内容 |
| --- | --- |
| 标准语义 | 字段名、业务含义、类型/精度、单位、空值和默认值 |
| 各源输入 | 实际接入来源的字段、缺失情况；不固定为 Tushare/BIYING 两家 |
| 转换规则 | 日期格式与时区、枚举/交易所码表、字符串、单位和数值归一 |
| 异常与重复 | 非法值、空主键、重复识别键、拒绝或去重规则 |
| 可比性 | 哪些字段语义相同，哪些不可比，以及依据 |
| 缺失与冲突 | 保留空值、明确的回填/回退，双源不同值的处理 |

只有双方都具备可比语义的字段才能参与差异判定。某源独有字段不能直接计作双源不一致；没有定义单位不能混用“元/万元”“股/手”等值。

Source 负责取数，不做业务语义决策；Raw 保留来源事实，允许最小格式归一，禁止业务推断填充。清洗与字段对齐放在获准的归一化实现中，须声明、可复用且有测试，不能散落在业务查询或页面临时修补。多源标准结果保留来源身份（如 `source_key`）；存在物理标准表时，说明其完整业务键、冲突键、批内去重和允许更新的列，不用示例键代替实际身份。

## 3. 融合发布策略

每个适用数据集必须明确：

1. 发布结果一行代表什么，使用什么唯一业务键。
2. 来源优先级；是整行选源还是字段级选源。
3. 主源缺失时是否回退、回退到哪里；不允许页面自行补源。
4. 同键冲突与重复如何处理，允许覆盖哪些字段。
5. 来源、策略版本和发布时间如何追溯到发布结果；写清现有字段及证据位置，不凭示例给既有表加列。
6. 删除、截断等不可逆行为的处理与审批边界。

多源发布必须能追溯“来自哪个来源、使用哪个策略版本”。规则变更须更新策略版本并记录影响范围；新增来源先补映射与清洗设计，新增字段同步受影响的标准语义、Serving 定义和 API 契约。既有消费者的迁移与空值/版本说明在原数据集方案中一次写清，不新增双轨兼容实现。

## 4. 专题测试与验收

将下列适用场景加入原数据集模板的测试计划与追溯账本：

- 可比/不可比字段、缺字段、单位差异和归一化异常。
- 完整业务键、批内重复、upsert 冲突及允许更新的列。
- 来源优先级、主源缺失回退、整行/字段级覆盖，以及结果来源与策略版本追溯。
- 按实际获准数据路径做集成验证；不为测试补造 Raw/Std/Serving 层。
- 验证 Ops 可观测性，并覆盖同域既有数据集不受影响。

设计阶段完成规则与测试计划，实现后补测试证据，正式执行另获授权；本专题不要求提前写正式库，也不代表具体数据集已实现或已验收。

## 5. 说明性示例

假设某基础信息数据集经设计确认以 `ts_code` 标识对象，并采用“主源优先、次源补缺”：可对两源均有的名称与交易所先归一后比较；只有一源提供的行业或英文名不参与双源差异统计。

这只是规则表达示例，不声明当前 `stock_basic` 的实际主键、启用来源或生产发布策略；具体事实以该数据集定义、实现和获准方案为准。
