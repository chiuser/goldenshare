事实口径

这份文档区分“代码目录已登记的数据集”和“磁盘真实存在的物理资产”。这点很重要，不然会漏账。

统一数据集口径
  • 事实源：lake_console/backend/app/catalog/datasets
  • 扫描器：filesystem_scanner.py
  • 当前登记 54 个数据集，全部来源标记为 Tushare 口径。
  • 用于 Dataset 页面、后续 Storage / Cost 页面和数据集详情。
物理文件口径
  • 事实源：`/Volumes/datasource/goldenshare-tushare-lake` 的真实目录。
  • 包含 `raw_tushare`、`derived`、`research`、`manifest`、`_tmp`、`_recovery`。
  • 当前物理占用约 233.7GB，明显大于 catalog 可统计的 81.5GB。
  • 差异不是误差，是部分资产尚未被统一模型完整接管。

架构链路

Lake Console 是本地移动盘工具，不挂生产 Ops，不写远程业务库。生产库只在白名单导出场景中只读访问。

源站 / 生产只读

Tushare 直连、prod-raw-db、少数 prod-core-db 例外。

源站事实层

`raw_tushare` 保存源接口或已批准事实源的原始字段口径。

研究基准层

`research/stk_mins_by_date_clean_next` 是分钟线正式 clean 基准。

本地派生层

`derived` 保存 90/120 分钟线和分钟指标等本地计算结果。

研究重排层

`research` 保存按股票月份分桶等查询友好布局。

查询与管理

DuckDB 研究查询、Lake Console 页面、Kopia 备份恢复。

来源与同步方式

“来源”指业务事实口径，“同步方式”指 Lake 从哪里拿数据写 Parquet。

Tushare 直连

直接请求源接口，适合本地股票池、交易日历、分钟线等必须按本地规则拉取的场景。

stock_basictrade_calstk_mins
prod-raw-db 只读导出

从生产 `raw_tushare` 白名单表只读导出，适合大批量补湖和日频/快照数据。

dailymoneyflowboard
prod-core-db 只读例外

只在 serving 层更完整、更可靠且已写入方案时使用。

index_dailyindex_weeklyindex_monthly
`prod-raw-db` 和 `prod-core-db` 都是只读来源，不允许把生产 Ops 状态、TaskRun、调度状态或远程数据库状态混进本地 Lake 文件事实。

物理差异与待收口

这些不是新需求，是当前总览必须如实展示的差异。后续要不要代码清扫，需要另起任务。

物理资产当前事实为什么没完整进入 catalog建议归属
research/stk_mins_by_date_clean_next 约 63G，21045 个 Parquet，频率 `1/5/15/30/60`，日期 `2009-01-05 ~ 2026-05-07`。 当前 catalog 的 `stk_mins` research 层只登记了 by-symbol-month，不包含 by-date clean 基准。 应作为 `stk_mins` 的正式 clean 基准层进入统一模型。
derived/stk_mins_indicators_by_date 约 75G，102576 个 Parquet，当前指标 `macd`，参数 `12_26_9`，频率 `1/30`。 分钟指标系统已形成物理资产，但 catalog 还没有独立指标数据集或 `stk_mins` 指标层。 建议后续定义为分钟指标资产，避免 Storage / Cost 和详情页漏掉最大派生资产。
research/stk_mins_indicators_by_symbol_month 约 28M，32 个 Parquet，当前只覆盖 `2026-04`、`freq=30`、32 个 bucket。 指标 research 层还未进入 catalog。 应和 by-date 指标层绑定为同一个指标资产的两种存储形态。
_tmp 约 3.3G，包含多轮历史同步、修复和恢复临时目录。 `_tmp` 不是数据集，不应进入数据集清单，但 Storage / Cost 页面必须展示。 进入存储治理和清理建议，不进入研究查询。

常用命令

这里只放理解 Lake 所需的骨架命令；具体每个数据集的命令以 catalog command examples 为准。

# 查看 Lake root 状态
lake-console status

# 扫描 catalog 已登记数据集
lake-console list-datasets

# 预览单个数据集同步计划
lake-console plan-sync daily --from prod-raw-db --trade-date 2026-04-30

# 执行单个数据集同步
lake-console sync-dataset daily --from prod-raw-db --trade-date 2026-04-30
# 股票分钟线全市场区间同步
lake-console sync-stk-mins-range \
  --all-market \
  --freqs 1,5,15,30,60 \
  --start-date 2026-04-01 \
  --end-date 2026-04-30

# 90/120 分钟线由 Dagster orchestrator 统一生成；backend 不再提供派生命令
