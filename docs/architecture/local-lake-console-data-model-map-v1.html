先把结论放在最前面，避免后面继续把目标态当成现状。

当前应该被视为统一核心模型的是 LakeDatasetSummary -> LakeLayerSummary -> LakePartitionSummary。`Recovery` 属于 Kopia 备份点管理领域，不能硬套数据集模型。

1.1 本文档统一用词

当前代码名 文档与页面说法 说明 后续处理
primary_layout 主存储形态 数据集默认查看和扫描时采用的主要文件组织方式，不代表业务主模型。 后续代码清扫时改名
layout 存储形态 某一层文件在 Lake 中的实际组织方式。 后续统一枚举命名
current_file 当前版本单文件 主数据类数据集只有一个当前版本文件，例如 current/part-000.parquet。 避免叫“快照”
manifest_file 辅助清单文件 跟随某个数据集存在的辅助清单，不应被描述成独立数据集。 页面说中文
by_date 按交易日期分区 以 trade_date=YYYY-MM-DD 为核心分区，分钟数据前面还可能带 freq。 后续改为更明确枚举
by_symbol_month 按月份分桶 research 层使用的查询优化形态，路径核心是 trade_month 和 bucket。 后续改为更明确枚举
partition_key 分区定位符 用于定位某个分区的稳定字符串，不是数据库主键，也不是展示文案。 需改造成结构化字段
Kopia 原始备份对象 备份点 Kopia 原始字段沿用外部工具命名；在管理台中统一叫备份点，避免让人误解为临时文件。 API 字段后续另评审

对象 职责 来源文件 当前状态

字段类型含义状态

5.2 LakeLayerSummary

字段类型含义状态
layerstr内部枚举包括 raw_tushare / manifest / derived / research。页面应展示为“原始层 / 辅助清单层 / 派生层 / 研究层”。已落地
layer_name / purposestr层级展示名与用途说明。已落地
source_layerstr | null来源层，当前 schema 有字段但未填。空壳字段
layoutstr内部枚举包括 current_file / manifest_file / by_date / by_symbol_month。页面应展示为“当前版本单文件 / 辅助清单文件 / 按交易日期分区 / 按月份分桶”。已落地
pathstr层级路径或单文件路径。已落地
partition_count / file_count / total_bytesint该层扫描得到的物理规模。已落地
freqs / trade_date range / trade_month rangelist / str从分区扫描聚合出来的覆盖范围。已落地
row_countint | null当前通用 scanner 不计算。预留

5.3 LakePartitionSummary

字段类型含义状态
dataset_key / layer / layoutstr分区归属。layout 在页面上按“存储形态”解释。已落地
freq / trade_date / trade_month / bucketint | str | null当前支持的结构化分区字段。已落地
pathstr分区路径或单文件路径。已落地
file_count / total_bytes / modified_atint / int / datetime分区物理事实。已落地
partition_keystr旧目标态叫法不准确。后续不应继续作为唯一字段使用。目标态需改造
partition_valuesdict目标态结构化分区字段，例如 {"freq": 30, "trade_date": "2026-04-24"}。目标态
partition_locatorstr目标态稳定分区定位符，例如 freq=30/trade_date=2026-04-24。目标态
partition_labelstr目标态页面展示文案，例如 30min · 2026-04-24。目标态
replace_scope / can_replace_safelystr / bool写入安全字段，当前未实现。目标态

6. API 架构

当前实现和目标态 API 需要分开展示。

当前已实现

API返回对象用途
GET /api/lake/statusLakeStatusResponseLake 根目录与磁盘状态。
GET /api/datasetsLakeDatasetListResponse数据集列表，含 layer summaries。
GET /api/partitionsLakePartitionListResponse独立分区列表，可按 dataset/layer/layout 过滤。
GET /api/recovery/*LakeRecovery*Kopia 备份点管理视图。
GET /api/lake/command-examplesLakeCommandExamplesResponse命令示例与前置条件。

目标态候选

API状态说明
GET /api/lake/datasets/{dataset_key}未实现单 dataset 详情，是否需要取代前端拼接需另评审。
GET /api/lake/datasets/{dataset_key}/partitions未实现更规整的 dataset 子资源形式。
GET /api/lake/datasets/{dataset_key}/files未实现依赖 LakeFileSummary 落地。
GET /api/storage/*未实现Storage 页薄投影，必须复用 dataset/layer 核心模型。

目标态 API 不能继续写得像现状。任何新 API 进入实现前，都必须先说明它是在复用核心模型，还是新增独立领域对象。

9. 后续开发规则

在模型梳理完成前，新页面开发应暂停。

必须遵守

Storage / Health / Activity 只能在 LakeDatasetSummary -> LakeLayerSummary -> LakePartitionSummary 上做页面投影。需要新字段时，先改模型与 API 设计，再开发页面。

必须避免

不要让每个页面自己解析 path、自己发明 layer 结构、自己计算事实字段。前端只做展示 view model，不做事实推断。

9.1 推荐推进顺序

顺序工作产物
1收正当前模型文档现状字段和目标态字段分开
2评审 API 架构统一 dataset/detail/partition API 边界
3补必要 schema只补被业务需要证明过的字段
4恢复页面开发Storage 先做，Health / Activity 后置
