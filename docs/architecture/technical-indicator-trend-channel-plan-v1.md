## 1. 目标与已确认范围

扩充算子库时，每个算子必须完整计算并输出相应技术指标，不能只登记名称、读取预计算结果或提供部分公式。本次先完成趋势通道算子，再沿股票、上证已经接入 MACD、KDJ 的流程接入趋势通道；页面不再使用的旧通道代码在阶段4清理；方向专项清理后续单独做。

| 编号 | 已确认口径 | 实施与验收含义 |
| --- | --- | --- |
| R1 | 先开发趋势通道算子，再接入业务 | 算子独立完成计算、注册、历史需求、跨批续算和数值验收后，再推进股票和上证接入。 |
| R2 | 算子只输出四条轨道 | 短期上轨、短期下轨、长期上轨、长期下轨；公共日期时间继续由 `times` 提供。 |
| R3 | 不计算历史方向与组合状态 | 不迁入“在通道内部保留上次突破方向”的标签，也不增加通道升降方向等替代功能。 |
| R4 | 本期取消 JSON 说明字段 | 不新增 `info` 字段，不返回说明空串，不增加 `output_info()` 或相关协议、校验和编码。未来需要时另议。 |
| R5 | 页面按每批最多 500 根接入 | 本地继续使用当前日 K 首批、续页和 `nextEndDate`；Prod 沿原加载与回包方式增加四轨，不在本次新增生产分页；不要求算子库一次返回 2,000 根。 |
| R6 | 业务提交截止日期与期望根数 | 既有证券、周期、复权及分页参数照常提交。沿当前装配转换为计算指令，不由业务计算 EMA 或提供种子。 |
| R7 | 趋势通道固定前置预热 500 根 | 这是管理员确定的设计值，返回根数另计；不使用 MACD 的 100 万范围假设求根。 |

| R11 | 保持现有通道画法与着色 | 继续使用四轨和收盘价，不新增方向展示，也不因接入而改画法。 |
| R12 | 四轨随现有日 K 接口返回 | 页面切换后不再请求旧独立通道接口；上证使用算子库返回结果，原专用计算器退出页面调用链。 |
| R13 | 页面入口不再依赖旧通道目录 | 股票页面按已接入的股票日线能力声明支持，不再用旧接口开关、旧结果目录或续算状态目录控制入口；不新增 DG 任务状态或数据集就绪查询。 |
| R14 | 区分计算输入与旧通道成品 | 新算子继续使用基础行情和股票复权因子数据，不读取旧通道结果或续算状态文件；本需求不处理 DG 数据集及其生产、字段、停产、迁移或清退。 |
| R15 | 每个指标有独立、含义明确的 build 函数 | MA、BOLL、MACD、KDJ、趋势通道分别组装；不使用 `build_stock_daily_special_factors()` 等笼统名称汇集专属指标。 |
| R16 | 公共组装复用，业务组装显式组合 | 公共函数只调用共用指标的 build 函数；日线、周月线由各自 `assemble()` 选择专属指标并合成响应。公共函数不堆叠周期判断，不复制一套公共映射到每个周期。 |
| R17 | 指标组装架构修改在第三阶段实施 | 阶段二先接通股票四轨并隔离日线计算范围；阶段三再整理公共模块、逐指标函数和全部调用方，之后完成上证接入。 |
| R18 | 分清算子结果、指标字段与完整接口响应 | 业务后端决定请求哪些算法；算子库返回现有 `CalculationResult`。各指标 build 只读取、映射字段，业务 `assemble()` 合成完整响应；首批与续页复用同一组装路径，不重复计算。 |
| R19 | 本需求不新增没有必要的重复读写 | 趋势通道与同次请求的其他指标共用行情和复权结果，各 build 只读取已经返回的计算结果，不另查表或读 DG 文件；股票、上证页面切换后不再请求旧通道。固定预热、跨请求重叠及验收边界见[专项 LLD §11](technical-indicator-trend-channel-low-level-design-v1.md#trend-channel-read-scope)。不以本规则扩展为通用读取优化或其他周期整改。 |

测试边界同时明确：删除仅为证明“不调用旧实现”而导入、替换旧计算器、缓存、读取器或旧能力函数的检查；保留新算子数值、回包、失败重试和资源释放断言。固定历史行情文件仅作为测试输入，用于检查代码修改前后计算是否仍正确；股票、上证两个页面共用的通道画图实现是正在使用的产品代码，两者分别保留，具体文件、调用方和用途见LLD §5.2。

此前“必须把方向状态一起迁入”“必须从历史起点计算被测结果”“用 829 根作为本次预算”“新增通用 JSON 说明字段并返回空串”等讨论均已退出本期需求。500 根预热、0.01 绝对误差不需要重新拍板。

### 2.1 接入后的接口和数据关系

目标调用顺序为“页面 → 现有股票或上证日 K 接口 → 算子库 → 本环境已接入的行情及必要复权数据 → 返回同批 K 线和四轨”。四轨由新算子计算，不通过旧通道接口转发，不读通道成品，也不在新算子失败时回到旧计算器或旧文件。

| 对象 | 接入后的处理 |
| --- | --- |
| 现有股票、指数日 K 接口 | 保留现有入口、行情及其他指标，增加目标日线四轨；沿本批日期和现有游标返回。 |
| 股票独立接口 `/api/v1/wealth/market/stock-detail/trend-channel` | 阶段四已删除旧路由、专用查询、schema、读取器及能力检查；隔离应用请求返回404。新四轨继续随现有日K接口返回。 |
| 上证独立接口 `/api/v1/quote/detail/trend-channel` | 阶段四已删除旧路由、专用查询、计算器、缓存、schema及前端请求；隔离应用请求返回404。`quote.py`其他四个接口保持。 |
| 股票日线趋势通道结果数据集、股票日线趋势通道续算状态数据集 | 新页面与新算子不读取，也不依靠目录存在来开放入口；本次不处理这两个 DG 数据集及其生产、检查和正式文件。 |
| 股票、指数基础行情及股票复权因子数据 | 继续作为日 K 和算子库的输入，不能因清理旧通道业务而删除。 |

### 2.2 股票页面入口判断

旧判断是为本地读取预计算文件而设：依次检查本地/开发环境和旧开关、正式 Lake 根目录、DuckDB 可用性、结果和续算状态目录是否可读。它不读取某只股票的行情记录，不查询 Dagster 任务或资产状态，也不证明目标日期的数据齐备。旧读取器实际只读取结果文件，不读取续算状态文件。

股票阶段二接入时，页面初始化中的 `supportsTrendChannel` 和 `availableMainOverlays` 同步按已接入的股票日线能力返回，不再调用旧能力判断，也不继承旧接口的仅本地限制和专用开关。不增加新的趋势通道开关或读取前检查；本环境行情来源、复权和错误处理继续沿现有日 K 合同。某次行情为空或读取失败按现有日 K 流程返回，不把它当成页面不支持该功能。

验收必须覆盖：旧开关关闭、旧通道两个目录均不存在时，已接入的股票日线页面仍有入口且可随日 K 取得四轨；基础行情读取失败时仍按既有错误流程处理。这里移除的是旧通道依赖，DG 行情读取本身需要的目录、读取组件和配置仍沿原日 K 装配使用。

### 2.3 管理员确认的组装职责及阶段归属

管理员确认：公共技术指标的读取和字段拼接应最大程度复用，专属指标由所属业务显式组合；每个指标使用所见即所得的 build 名称。实现采用函数组合，不把所有指标塞进一个按周期分支的组装函数，也不在日、周、月分别复制公共指标代码。

重构前，`build_kline_factors()` 只映射 MA、BOLL、MACD、KDJ，既被股票日线 `assemble()` 调用，也被周月线 `assemble()` 调用，但位于日线服务文件中。第三阶段已将其公共职责迁入 `stock_kline_factor_mapper.py`，拆为 `build_stock_ma_factors()`、`build_stock_boll_factors()`、`build_stock_macd_factors()`、`build_stock_kdj_factors()`；`build_stock_common_factors()` 组合这四组。趋势通道使用独立的 `build_stock_trend_channel_factors()`，由日线 `assemble()` 明确调用。周月线本次不增加趋势通道计算，也不提前创建没有实际用途的专属空函数。

这里的 `results` 是讨论中的示意名称，使用现有 `CalculationResult.calculations` 即可。后端将结果按算子 ID 和实际参数整理一次，各 build 读取同一份结果；不读行情、不计算算法、不修改算子库通用合同。指标字段组装是 `assemble()` 的子步骤；“把四轨组进日 K 回包”就是这同一个业务组装过程，不另加一次相同组装。

阶段二开发前，上游计算清单也存在共用：周月线当时调用 `stock_daily_calculations()`。阶段二已将原有共用清单命名为 `STOCK_COMMON_CALCULATIONS`，由 `stock_common_calculations()` 提供原指标；日线 `stock_daily_calculations()` 在其上明确增加趋势通道，周月线改用公共清单。该计算范围隔离是阶段二接入的必要修改，不能直接改一份共用清单而让周月线自动多算；它不提前执行第三阶段的逐指标组装重构。

### 2.4 阶段二补齐的接口与页面交接

按管理员授权，确定 `bars[].factors.trendChannel` 为日线必有对象，包含 `shortUpper/shortLower/longUpper/longLower` 四个必有数值，单位为元。日线使用明确的日线字段、K 线和响应类型；周月线保留原字段集合，不追加空轨道。具体类型、构造和消费点见专项 LLD §4.2。

首批与本地续页分别从同一次日 K 回包取得 K 线和四轨。页面保存首批通道点，历史页保存自己的通道点；图表按日期拼接，开关只切绘制，不再发独立通道请求。新一页会按自身目标与 500 根预热计算，不复用首屏作为新一页的计算结果；同一页开关不重新计算。旧通道文件由 DG 后台提前生产，并不是首屏请求缓存，新页面接入后不再读它。

失败沿日 K 流程处理。续页先完整整理本批 K 线、四轨和九转等返回数据，成功后才更新游标与页数组；任何一步失败都保留原图和原游标，重试同一批。保留当前切证券、切日期、离开日线时的取消和迟到响应处理。原股票页面方案和 LLD 已同步记录后续切换决定，旧执行记录保持历史语义。

### 2.5 第三阶段的具体实施边界

第三阶段先完成股票组装整理并独立审计，再接上证。股票计算清单由阶段二决定，第三阶段只整理结果读取和字段组装；MA/BOLL/MACD/KDJ/趋势通道各有独立 build，公共组合只维护一份，各业务 `assemble()` 显式调用自己的指标。阶段二验收是执行前置，不是尚待管理员决定的设计问题。

## 3. 计算、预热与返回

短期周期固定 25，长期周期固定 90：

| 字段 | 完整含义 |
| --- | --- |
| `short_upper` | 最高价的 25 周期 EMA，即短期上轨 |
| `short_lower` | 最低价的 25 周期 EMA，即短期下轨 |
| `long_upper` | 最高价的 90 周期 EMA，即长期上轨 |
| `long_lower` | 最低价的 90 周期 EMA，即长期下轨 |

EMA 使用 `α=2/(周期+1)`。首次读取时用该根最高价、最低价初始化，后续逐根递推，不逐根量化，不在每个批次重新初始化。无方向判断后，算子计算只需要最高价与最低价。

历史充足、单算趋势通道时，输入为 `500 + R` 根，R 为本批实际目标根数；本次业务每批最多 500 根，所以该场景最多 1,000 根计算输入，只返回目标批次。实际到达行情起点而前置不足 500 时按现有合同使用已有历史，不补造行情，也不把读取失败当成历史不足。

多个指标同算时，读取层取各算子所需历史的最大值，不相加，不逐指标查源或复权。其他指标确需更长历史时，整次输入可能多于 `500 + R`，趋势通道自身仍申报 500。这些数量是交付给计算的 K 线根数，不是物理读量或耗时保证。

## 4. 误差标准与已有证据

正确的比较方法是：先对同一份行情，从已确认的完整历史起点生成参考；再按各目标窗口前置 500 根重新开始被测计算；将同日期四轨逐项与参考比较，绝对误差均不超过 0.01。两种计算的初始化位置应不同；要求两者从同一位置初始化，会漏掉要验证的历史截取误差。此前 LLD 的这句要求写错，本次已纠正；已有样本测算本来就使用不同起点，数值不受文字纠正影响。

已有[上证指数固定样本](../../tests/fixtures/quote_trend_channel/000001_sh_daily_input.json)为 2020-01-02 至 2026-08-07 的 1,599 根快照；参考从样本首根开始，不冒充覆盖上证全部历史。独立 70 位十进制参考与逐窗口双精度计算的结果：

| 前置根数 | 四轨最大绝对误差（点） | 说明 |
| --- | --- | --- |
| 485 | 0.01006734 | 该样本仍有窗口超出 0.01 |
| 486 | 0.00984608 | 该样本满足，不作为全库统一根数 |
| 500 | 0.00721347 | 该样本满足；管理员最终决定采用固定 500 根 |

细节见 [LLD §7](technical-indicator-trend-channel-low-level-design-v1.md#7-已有测算证据及其范围)。实际目标场景仍做必要的有界验收；发现超过 0.01 时保留证据回到方案，不自行增加预热、放宽误差或回退到全历史读取。
