# 趋势通道算子与通用 JSON 说明字段方案 v1

2026-11-25｜需求口径已由管理员确认；本轮只落方案与 [LLD](technical-indicator-trend-channel-low-level-design-v1.md)，尚未开发、迁移、清理代码或部署。

本文承接[算子库整体设计](technical-indicator-operator-library-low-level-design-v1.md)、[实施 LLD](technical-indicator-operator-library-implementation-lld-v1.md)和[上证日线趋势通道维护说明](sse-daily-trend-channel-realtime-computation-low-level-design-v1.md)。原文中的运行事实和历史验收保留；本次目标与当前实现分开说明。

## 1. 要实现什么

扩充算子库时，每个算子都要具备相应技术指标的完整计算与输出能力，不能只登记名称、读取预计算结果或提供部分公式。趋势通道是本次新增对象：从算子库准备的行情计算短期、长期四条 EMA 轨道，经统一入口返回结果。现有业务中无实际页面用途的历史方向状态与组合状态，作为独立步骤审计和清理。

同时给每项算子结果增加一个通用说明字段，保存 JSON 文本。JSON 内部字段由各算子按自己的业务定义。趋势通道本次没有需要填入的说明，字段留空。

### 1.1 已确认的约束

| 编号 | 已确认口径 | 实施与验收含义 |
| --- | --- | --- |
| R1 | 算子必须完整计算并输出指标 | 趋势通道实现、注册、历史需求、跨批递推、输出与测试一并交付。 |
| R2 | 趋势通道本次只输出四条轨道数值 | 短期上轨、短期下轨、长期上轨、长期下轨；公共日期时间仍由 `times` 提供。 |
| R3 | 删除历史方向状态与组合状态，不迁入算子库 | 不计算“通道内部保留上次突破方向”的标签，也不新增按通道升降判断方向的替代规则。 |
| R4 | 保留通用 JSON 说明字段的设计和实现 | 数值字段继续用数值类型；每项算子另有一个字符串字段，非空时承载 JSON 文本，内部结构归该算子定义。 |
| R5 | 趋势通道的说明字段留空 | 不为了使用说明字段而重新塞入位置、方向或组合状态。 |
| R6 | 业务提交截止日期和期望返回根数 | 连同既有证券、周期、复权口径和算子标识提交；业务不计算预热量、不提供初始 EMA、不自行拼历史区间。 |
| R7 | 趋势通道固定前置预热 500 根 | 此值是管理员的设计决定；返回根数另计。它不是从 100 万价格假设推导出的数学上界。 |
| R8 | 每条轨道的绝对误差不超过 0.01 | 与同一行情、同一复权基准、同一历史起点的完整计算比较；单位沿输入价格单位，股票为元、指数为点。不是要求显示为两位小数后逐位相同。 |
| R9 | 清理旧业务也是本次需求的一步 | 先审计 API、页面、数据集与检查的全部消费者，再同步清理方向与组合状态的字段、计算、引用及测试；不能只完成新算子就把整个需求结案。 |
| R10 | MACD 维持现状 | 保留 `PRICE_ABSOLUTE_BOUND = 1_000_000.0`、既有精度要求、最低预热及动态预热算法。本次不整改 MACD。 |
| R11 | 不改现有页面的通道画法和颜色 | 页面按当根收盘价相对当根下轨的位置着色；无需上述历史方向标签。 |

这些是本次最终决定。此前提出的“完整输出必须包括方向状态”“因此必须从历史起点计算”“按 100 万假设统一预热 829 根”均不作为本次实施要求。

## 3. 四条轨道与历史读取

短期周期固定 25，长期周期固定 90，沿现有业务公式：

| 数值字段 | 完整含义 |
| --- | --- |
| `short_upper` | 最高价的 25 周期 EMA，即短期上轨 |
| `short_lower` | 最低价的 25 周期 EMA，即短期下轨 |
| `long_upper` | 最高价的 90 周期 EMA，即长期上轨 |
| `long_lower` | 最低价的 90 周期 EMA，即长期下轨 |

EMA 使用 `α = 2 / (周期 + 1)`，首个已读取的最高价、最低价分别初始化对应轨道，后续逐根递推。中间不逐根量化或重新播种；只在真正首次输入时初始化，跨批继续使用上一批末尾的四个 EMA 数值。业务未要求开放可调周期，本期不增加周期参数。

业务请求 `end` 和 `latest_rows=R`。算子申报 500 根前置需求，读取模块在截止时间之前定位最近的 R 根实际 K 线，再补所需前置行情；只返回目标 R 根。起点历史不足时，按已确认的实际行情起点及现有读取合同处理，不补造行情，也不把读取失败当成“历史不足”。周期、环境和复权支持仍取现行已启用组合，不因注册算子自动开放新来源。

单独计算趋势通道且历史充足时，计算输入为 `500 + R` 根。R 为 500 时是 1,000 根。这是交给算子的 K 线数量，不是磁盘读取行数、文件数或耗时保证。同算 MACD、KDJ 等指标时，读取模块取各算子历史需求的最大值，不相加；其他算子确需更长历史时，整次读取可能多于 `500 + R`，趋势通道自身的声明仍为 500。

固定窗口会改变起点 EMA，与完整历史的结果可能存在小差异；验收按 R8 检查每次请求，不继续沿用旧实现“任意窗口得到逐位相同值”的要求。发现真实场景超过 0.01 时保留证据并回到方案，不自行增加预热、放宽误差或改成全历史读取。

## 4. 本次测算能证明什么

本次只使用已有[上证指数固定样本](../../tests/fixtures/quote_trend_channel/000001_sh_daily_input.json)，共 1,599 根，2020-01-02 至 2026-08-07。参照计算从样本首根开始，不能称为覆盖上证全部上市历史。用 70 位十进制递推作独立参考，再逐个窗口重算双精度四轨。细节及边界见 [LLD §7](technical-indicator-trend-channel-low-level-design-v1.md#7-已有测算证据及其范围)。

| 前置根数 | 四轨中的最大绝对误差（点） | 结果 |
| --- | --- | --- |
| 485 | 0.01006734 | 该样本仍有窗口不满足 0.01 |
| 486 | 0.00984608 | 该样本满足；不是全库统一根数的证明 |
| 500 | 0.00721347 | 该样本满足；管理员最终采用固定 500 根 |

829 根是曾将“初始差值不超过 100 万”代入 90 周期 EMA 衰减公式得到的条件推导，管理员未采用，不进入本次读取预算。100 万在现有 MACD 中是价格范围假设，不是实测误差；其取值理由未在此次核对的原设计中找到充分说明。管理员最终决定保留该常量和 MACD 现状，本次不再给它替换数值。

## 5. 分步完成与验收

| 步骤 | 目标、实施范围 | 如何判断完成 |
| --- | --- | --- |
| 一、通用 JSON 说明字段 | 补齐每项算子结果的说明字符串、算子提供说明的接口、校验和编码；现有算子默认留空 | 两种不同结构的合法 JSON 文本均能经统一链路原样返回；空串可返回；非法 JSON 失败；原数值与日期合同继续通过。 |
| 二、趋势通道算子 | 在共享包实现四轨、固定 500 根预热、跨批续算和标准输出；说明留空 | 独立金样本、同批共享、目标范围、真实起点、取消清理，以及有界来源核验通过；四轨误差逐项不超过 0.01。 |
| 三、现有业务清理与接入 | 审计并清理旧方向、组合状态的业务代码、API 字段、前端类型、预计算数据合同和检查；规划服务接入 | 各实现方和消费者同步切换，活动链路旧方向引用清零；四条轨道、日期和现有绘图仍正确；不能只删显示字段而保留无用计算。 |

每一步先完成该步代码、合同、预算和测试审计，再进入获准开发。步骤三涉及股票趋势通道正式文件时，还须在[原 DG 方案](../../lake_console/docs/design/dagster-stock-daily-trend-channel-dataset-onboarding-plan-v1.md)和[原 DG LLD](../../lake_console/docs/design/dagster-stock-daily-trend-channel-dataset-onboarding-low-level-design-v1.md)补齐该步的字段迁移与执行设计；清理已纳入总范围，不等于物理迁移已经设计完成或获准执行。

## 6. 边界与交付

本轮只编写文档。后续共享包开发仍不读写正式数据集；本地只读 DG、生产只读 Prod PostgreSQL 的环境边界沿用原设计。没有新增数据库表、环境配置、数据集或自动任务的需求。共享包发布、业务部署、正式 Lake 字段迁移与数据重写分别按阶段执行，不能用本次文档授权代替。

清理时必须保留真正用于递推的四个 EMA 数值；股票趋势通道续算数据还包含日期、存续与停牌延续事实，不能因文件名带 `state` 就整份删除。具体保留和删除清单、读写边界、恢复、性能预算和验收见专项 LLD，未补齐的正式迁移项明确作为开工门禁。
