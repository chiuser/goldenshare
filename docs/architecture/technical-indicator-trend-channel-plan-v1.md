# 趋势通道算子及股票、上证接入方案 v1

2026-11-25｜需求口径已确认，尚未开发或部署。本次修订取消通用 JSON 说明字段，纠正预热验收的参考起点，补齐接口、数据集和页面入口判断的处理，并将算子开发、股票接入、上证接入和旧业务清理分阶段推进。[专项 LLD](technical-indicator-trend-channel-low-level-design-v1.md)

本文承接[算子库整体设计](technical-indicator-operator-library-low-level-design-v1.md)、[实施 LLD](technical-indicator-operator-library-implementation-lld-v1.md)和[原上证趋势通道说明](sse-daily-trend-channel-realtime-computation-low-level-design-v1.md)。历史决定和测算保留来源，当前实施以本次最终口径为准。

## 1. 目标与已确认范围

扩充算子库时，每个算子必须完整计算并输出相应技术指标，不能只登记名称、读取预计算结果或提供部分公式。本次先完成趋势通道算子，再沿股票、上证已经接入 MACD、KDJ 的流程接入趋势通道；现有业务中无用的历史方向与组合状态，另列步骤清理。

| 编号 | 已确认口径 | 实施与验收含义 |
| --- | --- | --- |
| R1 | 先开发趋势通道算子，再接入业务 | 算子独立完成计算、注册、历史需求、跨批续算和数值验收后，再推进股票和上证接入。 |
| R2 | 算子只输出四条轨道 | 短期上轨、短期下轨、长期上轨、长期下轨；公共日期时间继续由 `times` 提供。 |
| R3 | 不计算历史方向与组合状态 | 不迁入“在通道内部保留上次突破方向”的标签，也不增加通道升降方向等替代功能。 |
| R4 | 本期取消 JSON 说明字段 | 不新增 `info` 字段，不返回说明空串，不增加 `output_info()` 或相关协议、校验和编码。未来需要时另议。 |
| R5 | 页面按每批最多 500 根接入 | 继续使用当前日 K 的首批、续页和 `nextEndDate`，更多历史由下一批提供；不要求算子库一次返回 2,000 根。 |
| R6 | 业务提交截止日期与期望根数 | 既有证券、周期、复权及分页参数照常提交。沿当前装配转换为计算指令，不由业务计算 EMA 或提供种子。 |
| R7 | 趋势通道固定前置预热 500 根 | 这是管理员确定的设计值，返回根数另计；不使用 MACD 的 100 万范围假设求根。 |
| R8 | 每轨绝对误差不超过 0.01 | 参考从已确认的完整历史起点计算，被测从目标前 500 根开始计算；使用同一份行情、相同复权基准，比较相同目标日期。股票单位为元，指数单位为点。 |
| R9 | 清理旧业务是本次需求的一步 | 审计并清理旧方向、组合状态的字段、计算、引用及测试；新算子通过不能代替清理完成。 |
| R10 | MACD 保持现状 | 保留其 100 万常量、精度要求、最低及动态预热；趋势通道的 0.01 不改变其他指标的容差。 |
| R11 | 保持现有通道画法与着色 | 继续使用四轨和收盘价，不新增方向展示，也不因接入而改画法。 |
| R12 | 四轨随现有日 K 接口返回 | 页面切换后不再请求旧独立通道接口；上证使用算子库返回结果，原专用计算器退出页面调用链。 |
| R13 | 页面入口不再依赖旧通道目录 | 股票页面按已接入的股票日线能力声明支持，不再用旧接口开关、旧结果目录或续算状态目录控制入口；不新增 DG 任务状态或数据集就绪查询。 |
| R14 | 区分计算输入与旧通道成品 | 新算子继续使用基础行情和股票复权因子数据，不读取旧通道结果或续算状态文件；整个旧数据集是否停产、清退另按全部消费者审计确定。 |

此前“必须把方向状态一起迁入”“必须从历史起点计算被测结果”“用 829 根作为本次预算”“新增通用 JSON 说明字段并返回空串”等讨论均已退出本期需求。500 根预热、0.01 绝对误差不需要重新拍板。

## 2. 当前实现与要复用的接入方式

| 对象 | 当前代码事实 | 本次处理 |
| --- | --- | --- |
| 共享算子库 | [注册入口](../../packages/technical_indicators/src/goldenshare_technical_indicators/calculation/indicators/__init__.py)有价格、MA、BOLL、MACD、KDJ、九转，没有趋势通道 | 增加实际计算算子，沿现有 DOUBLE 数值输出；不改通用请求、结果结构和算子协议，不增加说明字段。 |
| 股票日线 | [计算指令](../../src/biz/services/wealth/market/stock_detail/stock_daily_kline_calculations.py)集中列算子，[服务](../../src/biz/services/wealth/market/stock_detail/stock_daily_kline_service.py)把结果组装为日 K 指标，[App 装配](../../src/app/dependencies/stock_daily_technical_indicators.py)处理环境和调用 | 在既有指令加入趋势通道，按本批日期将四轨加入日 K 结果并供图层使用。沿本地 DG 和 Prod 现有的调用方式接入，不重新设计整个旧 HTTP 接口。 |
| 上证日线 | [App 装配](../../src/app/dependencies/index_daily_technical_indicators.py)已经调用共享库，[查询服务](../../src/biz/queries/wealth/market/index_detail/index_detail_kline_query_service.py)负责结果映射和游标 | 沿相同入口加入趋势通道；保持本次每批不超过 500 根，按现有游标续页。 |
| 页面翻页 | [股票历史控制](../../wealth/src/features/stock-detail/controller/useStockDailyHistory.ts)与[指数历史控制](../../wealth/src/features/index-detail/controller/useIndexDailyHistory.ts)已经按日 K 批次加载、使用 `nextEndDate` | 趋势通道跟随同一批行情返回和绘制。目标日线接入后，清理该页面已无消费者的独立趋势请求，不新增另一套分页。 |
| 股票页面入口 | [页面初始化](../../src/biz/queries/wealth/market/stock_detail/stock_detail_query_service.py)通过[旧能力判断](../../src/foundation/config/stock_daily_trend_channel_capability.py)决定是否显示入口，当前要求本地环境、旧配置和两个通道目录 | 股票接入阶段同步移除页面对旧判断的调用；新入口随已接入的股票日线能力返回，不能只改取数而保留旧目录依赖。 |
| 旧通道业务 | 上证有独立全历史计算器，股票读取正式预计算文件；旧通道端点声明上限 2,000 | 这些是后续清理和消费者审计对象，不是新算子一次必须支持 2,000 根的要求，也不以直接替换其整个 HTTP 合同作为接入前提。 |

当前 DG 日线已有 `end/latest_rows` 调用；Prod 日线已有先确定本批目标日期、再把日期范围交给共享库的调用。接入沿各自已经使用的路径，不为本次趋势通道强制新增 Prod 按根数读取能力。外层业务仍按截止日、每批数量和现有游标使用，算子内部决定历史需求。

### 2.1 接入后的接口和数据关系

目标调用顺序为“页面 → 现有股票或上证日 K 接口 → 算子库 → 本环境已接入的行情及必要复权数据 → 返回同批 K 线和四轨”。四轨由新算子计算，不通过旧通道接口转发，不读通道成品，也不在新算子失败时回到旧计算器或旧文件。

| 对象 | 接入后的处理 |
| --- | --- |
| 现有股票、指数日 K 接口 | 保留现有入口、行情及其他指标，增加目标日线四轨；沿本批日期和现有游标返回。 |
| 股票独立接口 `/api/v1/wealth/market/stock-detail/trend-channel` | 股票页面切换后停止调用；接口仍存在期间沿原合同读取旧结果文件，阶段四审计全部调用方，删除无消费者的路由、读取器和专用代码，不改造成另一套算子库入口。 |
| 上证独立接口 `/api/v1/quote/detail/trend-channel` | 上证页面切换后停止调用；四轨改用现有日 K 流程中算子库的结果，旧专用全历史计算器及缓存退出该页面调用链；阶段四按全部引用清理旧接口和专用代码。 |
| 股票日线趋势通道结果数据集、股票日线趋势通道续算状态数据集 | 新页面与新算子不读取，也不依靠目录存在来开放入口。页面切换不等于整个数据集停产或正式文件获准删除。 |
| 股票、指数基础行情及股票复权因子数据 | 继续作为日 K 和算子库的输入，不能因清理旧通道业务而删除。 |

### 2.2 股票页面入口判断

旧判断是为本地读取预计算文件而设：依次检查本地/开发环境和旧开关、正式 Lake 根目录、DuckDB 可用性、结果和续算状态目录是否可读。它不读取某只股票的行情记录，不查询 Dagster 任务或资产状态，也不证明目标日期的数据齐备。旧读取器实际只读取结果文件，不读取续算状态文件。

股票阶段二接入时，页面初始化中的 `supportsTrendChannel` 和 `availableMainOverlays` 同步按已接入的股票日线能力返回，不再调用旧能力判断，也不继承旧接口的仅本地限制和专用开关。不增加新的趋势通道开关或读取前检查；本环境行情来源、复权和错误处理继续沿现有日 K 合同。某次行情为空或读取失败按现有日 K 流程返回，不把它当成页面不支持该功能。

验收必须覆盖：旧开关关闭、旧通道两个目录均不存在时，已接入的股票日线页面仍有入口且可随日 K 取得四轨；基础行情读取失败时仍按既有错误流程处理。这里移除的是旧通道依赖，DG 行情读取本身需要的目录、读取组件和配置仍沿原日 K 装配使用。

## 3. 计算、预热与返回

短期周期固定 25，长期周期固定 90：

| 字段 | 完整含义 |
| --- | --- |
| `short_upper` | 最高价的 25 周期 EMA，即短期上轨 |
| `short_lower` | 最低价的 25 周期 EMA，即短期下轨 |
| `long_upper` | 最高价的 90 周期 EMA，即长期上轨 |
| `long_lower` | 最低价的 90 周期 EMA，即长期下轨 |

EMA 使用 `α=2/(周期+1)`。首次读取时用该根最高价、最低价初始化，后续逐根递推，不逐根量化，不在每个批次重新初始化。无方向判断后，算子计算只需要最高价与最低价。

历史充足、单算趋势通道时，输入为 `500 + R` 根，R 为本批实际目标根数；本次业务每批最多 500 根，所以该场景最多 1,000 根计算输入，只返回目标批次。实际到达行情起点而前置不足 500 时按现有合同使用已有历史，不补造行情，也不把读取失败当成历史不足。

多个指标同算时，读取层取各算子所需历史的最大值，不相加，不逐指标查源或复权。其他指标确需更长历史时，整次输入可能多于 `500 + R`，趋势通道自身仍申报 500。这些数量是交付给计算的 K 线根数，不是物理读量或耗时保证。

## 4. 误差标准与已有证据

正确的比较方法是：先对同一份行情，从已确认的完整历史起点生成参考；再按各目标窗口前置 500 根重新开始被测计算；将同日期四轨逐项与参考比较，绝对误差均不超过 0.01。两种计算的初始化位置应不同；要求两者从同一位置初始化，会漏掉要验证的历史截取误差。此前 LLD 的这句要求写错，本次已纠正；已有样本测算本来就使用不同起点，数值不受文字纠正影响。

已有[上证指数固定样本](../../tests/fixtures/quote_trend_channel/000001_sh_daily_input.json)为 2020-01-02 至 2026-08-07 的 1,599 根快照；参考从样本首根开始，不冒充覆盖上证全部历史。独立 70 位十进制参考与逐窗口双精度计算的结果：

| 前置根数 | 四轨最大绝对误差（点） | 说明 |
| --- | --- | --- |
| 485 | 0.01006734 | 该样本仍有窗口超出 0.01 |
| 486 | 0.00984608 | 该样本满足，不作为全库统一根数 |
| 500 | 0.00721347 | 该样本满足；管理员最终决定采用固定 500 根 |

细节见 [LLD §7](technical-indicator-trend-channel-low-level-design-v1.md#7-已有测算证据及其范围)。实际目标场景仍做必要的有界验收；发现超过 0.01 时保留证据回到方案，不自行增加预热、放宽误差或回退到全历史读取。

## 5. 分阶段推进，逐阶段 review

| 阶段 | 做什么 | 完成标准 |
| --- | --- | --- |
| 一、趋势通道算子 | 在共享包实现、注册四轨，固定预热 500 根；复用读取、引擎、批次与数值输出，不做 JSON，不改业务页面 | 算子独立请求、独立金样本、误差、跨批、同批共享、真实起点与取消清理验收通过。完成后独立 review。 |
| 二、股票日线接入 | 沿现有股票日 K 算子指令、结果组装和前端分页接入四轨；复权价格与其他指标共用，同步移除页面入口对旧通道目录和开关的依赖 | 首批及下一批均为最多 500 根；旧通道目录不存在、旧开关关闭时仍可展示和取四轨，页面不再请求旧接口；日期、游标、盘口及现有指标不受影响。完成后独立 review。 |
| 三、上证日线接入 | 沿上证现有算子调用、结果组装和历史加载接入四轨，页面停止独立通道请求，专用计算器退出该调用链 | 首批、续页、图层开关、日期与失败重试通过；不调用旧计算器、旧通道缓存和独立接口；本地/生产沿各自现有装配与已启用来源验收。完成后独立 review。 |
| 四、旧业务清理与总验收 | 按消费者清单清理无用方向、组合字段、旧接口、计算器、读取器、配置、类型、请求、测试和数据集相关检查；正式文件迁移独立安排 | 无消费者的旧接口和专用代码删除，活动消费者同步迁移、旧方向引用清零；保留基础行情、复权因子数据及仍在使用的 EMA 续算数值；原方案、LLD、代码和验收一致。不能只完成新算子就结案。 |

阶段二、三的具体 DTO 映射、代码与测试清单在各阶段开工前按 LLD 补齐并复审；不把阶段一通过当成后续阶段自动获准。部署与正式数据迁移按对应阶段执行。

## 6. 清理与执行边界

清理已纳入本次需求，包括 API、页面、数据集与检查的消费者审计。真正用于递推的四个 EMA 数值和股票续算数据中的源日期、观察标志不能因文件名带 `state` 被整份删除。移除方向标签不等于退休整个股票日线趋势通道数据集。

上述“保留 EMA 数值”适用于仍在运行的旧数据生产和新算子本请求内的递推；不要求新算子读取旧续算文件。整个旧结果及续算数据集是否停产、清退，阶段四根据全部消费者确定并补回原 DG 方案和 LLD，不作为阶段一算子开发或阶段二、三页面切换的前置条件。旧接口尚未删除期间的环境和目录检查只服务旧接口，不能再控制新页面入口。

正式股票文件如需字段迁移，先在[原 DG 方案](../../lake_console/docs/design/dagster-stock-daily-trend-channel-dataset-onboarding-plan-v1.md)与[原 DG LLD](../../lake_console/docs/design/dagster-stock-daily-trend-channel-dataset-onboarding-low-level-design-v1.md)补齐字段、目标范围、候选校验、逐文件提升、checkpoint、恢复和性能预算。尚未补齐的正式迁移项不能直接编码或执行。

本轮只修订文档；未开发算子、未修改接口、未清理文件或部署。本地只读 DG、生产只读 Prod PostgreSQL 的环境边界沿用现有工程。MACD 的 100 万常量与既有预热算法保留，本次不再讨论或调整。
