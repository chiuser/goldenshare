决定

500根是内核能力，不是前端请求规则

每个请求默认返回最近500个符合条件的K线时间位置，最多500个；适用于所有支持周期和调用方。请求可显式指定1～500。max_output_rows配置保留，但只能在1～500内进一步收紧；配置不能把能力提高到501或10000。请求超过500或超过当前更低配置，在排队、创建连接和读取前以既有ResourceLimitError拒绝；不自动缩小、不分成多次计算后拼接。

500只限制返回的K线时间位置，不限制MA周期、递推预热或实际读取量。一根K线对应多个指标列仍是一个时间位置；一请求可以计算多个指标和同指标的不同参数。参数条件、150万输入等已有资源限制各自生效，不能拿500根截掉必需历史。

返回0根也是合法结果，但仅限请求合法、来源支持、定位及处理正常完成、目标确无K线且输出和清理成功。保留请求的参数、版本和字段说明，times及各值序列为空、range.count=0、实际起止为null，msg始终为空串。任何读取、计算、取消、超限、合同或清理错误仍报错，不能转换为空成功。

before只表示排他的时间上界。内核不额外取第501根来判断调用方是否还应请求，不输出“已经加载全部数据了”“暂无行情信息”等产品文案；这些属于后置产品设计。

01

目标与范围

设计一个对象化、组件化、模块化的通用技术指标计算内核。分钟、日、周、月只是输入K线周期不同，使用同一套对象、调度和SQL计算方式；具体可用来源由读取实现声明，不把数学支持误写成所有来源已经可交付。

提供的能力职责与边界
输入与读取从配置来源取得标准K线、必要因子及说明，准备本次唯一目标复权价格；当前实现读数据湖，未来接口来源由独立适配实现。
计算指标对象内聚参数、历史需要、依赖、SQL、状态与输出字段；业务不提供算法或SQL。
输出最多500个目标位置、实际参数和版本、来源与复权说明、统计；结果不依赖关闭后的连接。
配置和发现统一Settings提供基础配置；list_calculations/describe_calculation说明已注册能力与来源支持，不读行情。
通用隔离App在业务进程内组织有限FIFO等待、工作线程、取消、截止、发送和资源归还，不定义产品页面。

不新增跨请求缓存、计算进程池、Python指标公式、自动来源切换、湖或数据库指标写入、历史版本服务、完整性审计、SQL注入入口或前端请求编排。已有外部数据质量责任不以新增“已审计”标记、日历或证明文件为前提。

03

组件与外部职责

数据质量和完整性由外部负责，包括数值、字段内容、重复、缺口、停牌和退市。内核只校验请求、指标参数、必要来源说明、内部执行/结果合同及实际资源限制；不逐根复核源数值，不生成“应有时间点”。校验章节集中解释职责，代码检查放在最了解该合同的所属模块，不建一个包揽全部工作的质量模块。

读取模块管理本请求的数据生命周期，并组织复权对象；纯计算核心只使用已经准备的目标价格，不关心数据从Lake还是未来网络接口来。来源适配与复权计算仍是内部独立对象，不能因为同属读取模块就混成一个巨大类。

05

计算对象与依赖复用

已有对象负责什么
CalculationRequest / CalculationInstance调用方提交证券、周期、时间条件、唯一目标复权，以及所需指标和参数。一次条目例如MACD默认参数；instance_id区分请求中各项。
CalculationDefinition / Calculation定义元信息、输入字段、参数/历史/输出合同、版本和依赖；实现执行已登记SQL，持有自己的状态。
CalculationRegistry / CalculationEngine冻结注册并检查依赖；相同计算、算法版本、规范参数和输入条件只算一次；按依赖顺序执行。
CalculationSession / SqlExecutor限定表归属、固定SQL、参数绑定和计量；禁止写/删借用输入与依赖结果。
OutputInstanceDescription服务在读取前生成的不可变输出说明：每项身份、实际补齐参数、版本和公开字段，不含计划、连接或状态表。
OutputCollector / CalculationResult按说明收集目标结果；不理解内部计划、不再补参数或查注册表，空结果同样完整。

MA20与BOLL20可共用相同均值；周期不同分别计算。共用的前提是来源/证券/周期/目标复权/基准、字段、窗口、初始化、公式和版本都一致，不能只因名称近似复用。引擎用已规范化依赖标识，不接受业务自定义表、列、SQL文件或表达式。内部依赖结果只读，拥有者在全部使用方结束后释放；不跨请求保存。

每个计算对象在代码中写死允许的SQL文件、固定辅助语句和表角色。数值参数通过绑定传入；受控标识符只由内部映射生成。MACD与KDJ各自更新自己的状态且每段只更新一次，不设任意字段通用更新入口。

06

输入、时间和复权合同

公开计算入口只有calculate(request)，不增加要求业务传bars的第二套入口。一次请求是一只证券、一个周期、一种目标复权，支持多个指标/多套参数。adjustment省略为qfq，明确传none/qfq/hfq按指定处理；传错或来源不支持就失败，不偷偷改为不复权或补因子1。

输入内容固定含义
时间范围start/end按既有包含规则，before为排他上界；分钟使用Asia/Shanghai有时区datetime，日/周/月使用date。周/月区间条件沿现有周期相交合同，不用标签日冒充实际截止。
周期与字段参数以K线根数计；MA20周线就是20根周K。来源提供该周期OHLC/量/额、单位、实际复权、时间标记与source_as_of。不得用日线指标平均成周线指标。
尚未收盘的当前线当前周/月K参与计算，值随截至当时的输入更新。周一与周二是同一根周K更新，不把周二当新周递推。没有历史版本不能用周五完整K线冒充周二当时结果。
历史不足返回真实已有目标数量，不补零、不复制K线；MA/BOLL未满窗口保留该时间位置及NULL。目标无K线才成功空；目标存在但源/计算处理失败仍报错。

复权基础能力归读取模块

来源明确输入复权类型，调用方选择目标。输入已是所需口径及基准，直接使用；需要转换时只走已核实路径。不复权直接用原价；日/分钟前复权OHLC(t)=原始OHLC(t)×当日因子(t)÷本来源最新基准因子；后复权沿已核实最早可用因子基准。成交量/成交额保持来源口径，不随价格因子任意缩放。

基准不能由本次读取起止、limit或before重定。同一来源状态，相同日期的复权价必须一致。业务不能任意指定基准日期/因子；已有目标口径不能重复复权。周/月只读现成、口径明确的目标K线，不在本轮重新复权、跨基准转换、还原或读日线合成；缺少对应来源明确不支持。

图中三条路径表示三种可选方式，一次请求只走一种，绝不同时返回三组复权。price能力可单独返回所选价格，也可与指标同次输出；不重复取数或转换。来源字段/日期/schema细节、适用转换及不支持组合见LLD第05/06/08/19.32节。

06续

根据参数确定预热和读取范围

指标定义决定需要多少历史，不由读取模块猜测。服务先规范参数并汇总依赖，固定SQL推导所需预热，再从时间上界向前定位目标R和实际预热H。MA(N)至少需要首个目标之前N−1根；BOLL使用完整窗口；MACD/KDJ按参数动态推导且递推指标最低预热500根，初始化误差预算沿已确认2.5e-9。多个指标取最大必要历史，不分别遍历来源。

例如只算MA20并返回500个有效目标，历史足够需要519根；默认递推组合返回500通常选1000根，前500为预热，后500为结果。自定义参数可能需要更多，不能把H固定500。安全数学段长由平滑系数确定，与8192根读取批次不同。参数无法表示或H+R超既有资源时，尝试是否已到真实来源起点；仍无法满足则明确失败，不截历史。

定位先按分区及文件/行组时间界缩小候选。元数据不能确定本证券根数时，仅投影代码/时间键定位边界；第二遍拿到必要rank立即结束，不能继续扫剩余键。只对选中范围读价格列，按正序交付。候选最老文件与“已读到证券第一根”不同；选中4000根行组的最近1000根，不代表到达真实起点，也不能把整组4000根全读入计算。

真实历史仅1600根时，首次目标是最新500根，前面足够预热；下一次用排他时间上界请求更早500，仍按本次目标和前置定位；继续请求时剩余600根则先返较近500、最后返最早100。到最早100时H=0，按真实首根初始化，而不是将上次未返回的预热当作已返回结果删除。任一非起点目标若缺必要前置，不能误标到起点来放行；错误行数和早EOF仍按合同失败。

同来源状态与参数，重叠时间的指标遵守既定误差要求，不宣称浮点逐位相等。有限预热既有公式、1600根真实起点规则、容量分支、各指标SQL推导和定位文件合同见LLD第19.32/19.33节；本轮不重跑原长样本。

能力与来源说明注册/计划核依赖、来源能力及转换支持、必要说明；不是逐根数值或时间质量审计。

08

DuckDB SQL计算与安全分段

能力固定口径
price返回读取模块准备的目标价格，不再复权。
MAROWS按根数窗口；足N根用avg(close)，不足为NULL。常用5/10/20/30/60/90/250共用参数化实现。
BOLL默认N=20、倍数2；总体标准差stddev_pop，足N根才输出。倍数有限且非负，可为0；不设无依据上限。
MACD默认12/26/9；EMA首值为首close，首DIF/DEA/柱值严格0，之后柱值2×(DIF−DEA)，减首价计算与状态接续保持。
KDJ默认9/3/3；高低窗口不足用已有输入，递推前K=D=50，首根正常更新，RSV平区间50，K/D各用1/周期平滑。

Python仅组织依赖、SQL、说明与生命周期，不做指标加减乘除，不用Python UDF冒充SQL。DuckDB没有MACD内置函数不等于不能表达；已有原生窗口/分段实现继续使用，不因本次设计升级DuckDB。仅有具体原生SQL不支持证据时才另行讨论Python例外，不自动回退。

分段解决数值范围，批次控制读入量

EMA递推式为α=2/(N+1)、β=1−α；展开加权累计涉及β的负幂。已有隔离实验使用价格恒100、周期12、20000根，未分段第4211根开始非有限，5000/20000处NaN；固定1024分段该样本误差最大2.842170943040401×10⁻¹⁴。周期2即使1024也会溢出，所以不能固定通用段长。以上是既有合成实验记录，不是正式市场数据或本轮重验。

正式实现用固定smoothing_parameters.sql按当前参数计算可表示系数及安全段长；周期1按既定边界处理。每段仅更新一次状态，下一段接续EMA/DEA/K/D；MA/BOLL/KDJ窗口带必要历史，跨批、跨日不擅自重置。任一必要系数不可表示则整次失败，不能用其它正常分量掩盖。

读取8192根不等于一次展开8192个指数幂。窗口、排序可能缓存数据，分段不意味着进程内存恒定；SQL原生查询限制、投影行组保护和有限输入各管自己的资源。首版不临时落盘。

固定SQL与共用步骤

基础数学模板为smoothing_parameters、rolling_mean、bollinger_bands、macd_first、macd_segment、kdj_window、kdj_segment七份；另有已实现的macd_warmup、kdj_warmup两份动态预热SQL，计算包共九份。所属对象登记固定辅助建表/追加/状态语句。来源模板stage_input、adjust_price、retain_history按需请求内各读一次。输出修正后只保留merge_batch和select_result两份，删除不再需要的retain_tail及其声明/负例。SQL与代码一同交付、包资源清单逐一核对；不做动态文件替换。

共用只读未渲染模板正文；表名、绑定参数和指标状态仍各属本请求/对象。源模板通过SourceReadContext按实际用到的文件共享，算法模板由本次prepare统一加载；不用的模板不预读，不加跨请求缓存。

输出和能力发现

每个目标日期保留数值列及合法NULL；日期/数量/字段须完整。MA20从真实首根开始前19根NULL，第20根产生首个均值；若第21根整行没有生成则是漏算，报错，不能以空串代替DOUBLE或用关联补NULL。输出数量取真实目标R≤请求limit≤500，输入还含H预热，不要求输入输出一样多。

服务读取前生成OutputInstanceDescription，空结果不依赖任何批次说明也能返回完整指标身份、实际参数、algorithm_version和字段。同参数两项可共算，输出仍保留各自instance_id。输出不查询注册表、不理解内部计划。

Collector只保存当前批与目标范围交集，首交集建表、之后追加；不保存预热、不复制已有结果、不再截尾/最终COUNT。最终按周期只读必要时间/值列，读取到真正空批才结束，并核实际取回数量为R。缺行/列、错类型、数量不符或读失败整次失败，结果必须脱离连接独立存在。

CalculationResult保留series/requested/source/price_adjustment/times/source_as_of/calculations/range/statistics/kernel_version/msg等现有字段。range只有实际起止与count；所有成功msg=""。周/月source_as_of按日期对齐，空为[]；日/分钟为null。read_start/read_end包含预热的真实读取，不从返回日期推测。

公开库measure自己的最终库格式一次，块即弃；通用HTTP跳过库格式计量，只编码实际发送格式一次。UTF-8字节恰等于5000000允许，超过整次失败，不截断。不得附存第二份完整JSON，或先计量中间格式又计量最终格式；非法JSON数值按既有OutputEncodingError处理。

发现接口list_calculations、describe_calculation只返回已注册定义、参数/字段/算法版本和SourceCapability，不读文件、不执行SQL。本次500是通用请求合同，不增加各指标可单独放宽的字段或第二套发现API。

一次请求的顺序

  1. 构造冻结请求，服务一次准备规范参数、依赖计划和不可变输出说明；明显非法参数和容量在排队/读取前拒绝。
  2. 通用App申请名额，获准后进入已有工作线程；服务创建本请求唯一DuckDB连接。公开库不另建App队列。
  3. 固定SQL求动态预热；来源定位目标R及实际H，取得必要说明。R=0不打开价格流/因子/基准或预热。
  4. 读取所需列，跨文件合成8192根新输入或范围末批；本批必要复权一次，所有指标按依赖复用同一批目标价格。
  5. 指标状态更新，收集目标结果；有后续输入才保留必要窗口，再释放本批计算临时表和读取资源，然后读下一批。
  6. 正常EOF与已交付数量必须一致；完整取回R，按各自归属清理，服务关闭连接；库测最终库格式或HTTP编码发送最终body。
  7. 失败或取消停止后续操作，等待实际工作退出、清引用、清理，最后由通用App唯一出口归还名额；不返回半成品。

公开calculate只_prepare→_calculate_library；App库队前_prepare后直接同一_calculate_library；通用HTTP队前_prepare后直接同一_calculate_result，worker编码一次。prepared不公开、不缓存、仅本请求一个worker消费，不能让调用方跳过校验。股票backend迁移另属后置专项。
