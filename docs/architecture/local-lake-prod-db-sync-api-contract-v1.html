Local Lake / Sync Center / API Contract v1

Sync Center API 接口与字段契约

本文定义 Local Lake Sync Center 的后端 API、字段、枚举、错误模型与前端消费边界。 API 统一使用 /api/lake/sync/* 前缀，沿用当前 Lake Console 的 /api/lake/** 命名风格。

版本：v1 状态：待评审 更新时间：2026-05-14 本期范围：Profile 1~4 禁止 SQL UI

0. 结论

  • 通用 Profile Runner API 覆盖 prod_db_daily、prod_db_snapshot_refresh、prod_db_manual_backfill、lake_reference_refresh。
  • stk_mins_sync 已有专项 plan/run/continue/abort 分支，不走普通 Profile Runner；index_mins_sync、indicator_compute 仍只在 profile 列表中展示为后续专项，不提供启动。
  • 所有写入任务启动前必须先经过 plan，run API 默认要求 plan_token，避免页面绕过计划预览直接写盘。
  • 所有请求 schema 必须禁止额外字段。任何 sql、table、fields、where 等字段出现时都应该被拒绝。
  • 单任务门禁超时口径为 6 小时，字段为 stale_after_seconds=21600。
  • prewrite snapshot 默认不 pin，字段为 pin_policy=manual_only 或 pinned=false。

1. 设计原则

接口只暴露意图

前端只能传 profile、dataset、日期、执行模式。不能传 SQL、表名、字段名或任意 where 条件。

先 plan，再 run

写入任务必须先生成计划和备份范围。启动任务时使用 plan_token，确保用户看到的计划就是要执行的计划。

Kopia 是硬门禁

run 进入写入前必须完成 prewrite snapshot。备份失败，run 状态必须变成 backup_failed 或 blocked。

小接口原则

Sync Center API 不做“大而全”的接口。每个接口只服务一个页面动作： profile 列表只返回入口摘要，plan 只返回计划预览，run 只负责启动，detail 只返回任务详情， events 只返回增量事件，lock 只返回门禁状态。

如果前端需要更多详情，应该通过详情接口或分页/筛选接口读取，不允许为了省请求数把所有字段塞进一个大响应。 这能避免页面误用字段，也能让后端状态文件更容易维护。

2. API 调用流程

GET profiles页面加载可用入口，未开放专项 planned/disabled。
GET current lock判断是否已有任务运行。
POST plan生成计划、备份范围、warnings。
POST runs用 plan_token 启动任务。
GET current/run轮询整体进度与结果。
GET events轮询事件流，更新时间线。

3. 接口清单

接口 方法 用途 是否写入 备注
/api/lake/sync/profiles GET 列出 Sync Center 能力入口。 否 未开放专项也返回，但 profile_status=planned 或 disabled；stk_mins_sync 返回 enabled 并走专项流水线。
/api/lake/sync/lock GET 读取当前任务锁。 否 页面顶部门禁状态使用。
/api/lake/sync/profiles/{profile_key}/plan POST 生成计划与备份范围。 否 返回 plan_token，用于启动 run。后端必须先校验 profile_status=enabled，未开放 profile 返回 PROFILE_DISABLED。
/api/lake/sync/runs POST 启动写入任务。 是 必须持有有效 plan_token；进入写入前先做 Kopia backup。
/api/lake/sync/runs/current GET 读取当前运行任务。 否 无任务时返回 active_run=null。
/api/lake/sync/runs/{run_id} GET 读取任务详情。 否 用于详情抽屉。
/api/lake/sync/runs/{run_id}/events GET 读取任务事件流。 否 支持 cursor 增量读取。
/api/lake/sync/lock/release-stale POST 释放 stale lock。 是，仅锁文件 必须传确认原因；只允许 stale 状态。

4. 状态文件

当前已有的状态文件只有 manifest/sync_runs.jsonl，由 ManifestService.append_sync_run 写入。 它是历史同步摘要流水，不足以支撑 Sync Center 的任务锁、计划 token、事件流和 Kopia 备份映射。 因此本功能需要新增一组更细的本地状态文件，全部位于 manifest/lake_jobs/。

文件 职责 写入时机 API 消费方
manifest/lake_jobs/active_task.lock 全局单任务门禁锁。 run 启动时原子创建；run 结束或失败收尾时删除。 GET /api/lake/sync/lock
manifest/lake_jobs/current.json 当前任务轻量摘要。 任务状态变化时覆盖写。 GET /api/lake/sync/runs/current
manifest/lake_jobs/plans/<plan_token>.json plan 结果缓存，用于 run 校验。 plan API 成功后写入，设置短 TTL。 POST /api/lake/sync/runs
manifest/lake_jobs/runs/<run_id>.json 单次任务详情与最终结果。 run 启动后创建，执行过程中小步更新。 GET /api/lake/sync/runs/{run_id}
manifest/lake_jobs/events/<run_id>.jsonl 任务事件流。 锁、备份、数据集开始/完成、错误等事件 append 写入。 GET /api/lake/sync/runs/{run_id}/events
manifest/lake_jobs/backups/<run_id>-kopia.json Kopia prewrite snapshot 映射。 Kopia 备份完成后写入。 run detail / Recovery 页面跳转。
状态文件边界

这些状态文件只服务 Sync Center 的本地任务观测，不是数据集事实源。 数据集文件事实仍以 Parquet 目录和 manifest 中的数据集账本为准。 状态文件写入失败不得污染已完成的 Parquet 写入；但若发生在任务启动前或 Kopia 前置备份前，应阻断任务继续。

5. 枚举定义

枚举 取值 说明
profile_key prod_db_daily, prod_db_snapshot_refresh, prod_db_manual_backfill, lake_reference_refresh, stk_mins_sync, index_mins_sync, indicator_compute 前四个走通用 Profile Runner；stk_mins_sync 走专项流水线；其余后续专项不可启动。
profile_status enabled, planned, disabled enabled 表示该 profile 可由页面启动；其中通用 profile 进入普通 Profile Runner，stk_mins_sync 进入专项流水线。planned 表示计划中，当前用于 index_mins_sync、indicator_compute 等尚未开放入口。
date_mode target_date, date_range, snapshot, reference_range, none 描述本次请求的日期输入形态。
source prod-raw-db, prod-core-db, tushare, local UI 不允许任意 source；由 profile/dataset 决定。
dataset_plan_status will_run, skipped, blocked, planned_only 计划阶段的数据集行状态。
run_status planned, lock_acquired, backup_running, backup_failed, running, success, failed, partial_failed, blocked, stale 任务状态。
lock_status idle, running, stale 单任务门禁状态。6 小时无心跳进入 stale。
backup_status not_required, pending, running, success, failed 本期写入任务不得出现 not_required。
event_type run_started, lock_acquired, backup_started, backup_completed, dataset_started, partition_written, dataset_completed, run_completed, run_failed 事件流类型。

Plan 只生成计划，不写数据，不创建 Kopia snapshot。

11. 错误模型

所有 Sync Center API 错误统一返回以下结构。

{
  "error": {
    "code": "KOPIA_BACKUP_FAILED",
    "message": "Kopia prewrite snapshot 创建失败，未执行任何写入。",
    "request_id": "req_01HY...",
    "details": {
      "profile_key": "prod_db_daily",
      "run_id": "20260514T210000Z-prod-db-daily"
    }
  }
}
错误码 HTTP 含义 前端处理
LOCK_BUSY409已有任务运行。展示当前任务链接，禁用启动按钮。
LOCK_STALE_REVIEW_REQUIRED409锁已 stale，但需要人工确认释放。展示 stale lock 面板。
PLAN_TOKEN_EXPIRED400计划已过期。提示重新生成计划。
PROFILE_DISABLED400该 profile 当前未开放执行入口。展示 planned/disabled 状态说明；前端应禁用生成计划和启动任务；后端在 plan/run 前仍必须统一校验。
DATASET_NOT_ALLOWED400数据集不在 profile 白名单。提示重新选择。
SQL_FIELD_FORBIDDEN400请求含 SQL/表/字段类禁止字段。这是开发错误，页面不应产生。
KOPIA_BACKUP_FAILED503备份失败。阻断写入，展示 Kopia 错误。
REMOTE_DB_UNAVAILABLE503远程 DB 不可用。展示连接错误，不重试写入。
LAKE_ROOT_NOT_WRITABLE500本地 Lake 不可写。展示本地路径修复建议。

12. 前端消费规则

页面可以做的事

  • 展示 profile 列表和 disabled/planned 状态，未开放 profile 不允许生成计划。
  • 提交白名单参数生成 plan。
  • 使用 plan 响应渲染计划预览、备份范围、warnings。
  • 使用 run/detail/events 响应渲染进度和详情抽屉。
  • 根据后端 lock 状态禁用启动按钮。

页面禁止做的事

  • 禁止拼 SQL。
  • 禁止自行推导远程表名和字段。
  • 禁止自行判断备份是否可以跳过。
  • 禁止自行合成任务进度百分比，除非后端明确返回计算口径。
  • 禁止绕过 plan 直接启动 run。
