01目标、范围与不能改变的规则

交付一个Foundation库组件：调用方提交一只证券、一个周期、一种目标复权、一个输出范围和一组计算实例，服务完成共享读取、必要复权、原生SQL指标计算、独立结果输出和资源清理。算法按K线根数定义，同样用于分钟、日、周、月；来源支持单独声明。

硬约束 具体实现位置 必须抓住的反例
唯一计算入口 calculate(request) service.TechnicalIndicatorService.calculate 不公开bars、SQL、算法、文件路径、第二个按来源计算入口
业务省略目标复权即前复权 contracts.CalculationRequest → service._normalize_request 显式错误不回退；一次不输出三种复权
相关主要区域一起提交，区域可独立请求 请求的 calculations 列表；接入适配器 不要求整页只能一次；单实例请求仍合法；不加区域ID
公式及系数全部DuckDB原生SQL calculation/sql、sources/sql 无Python/NumPy/Pandas/UDF公式或自动回退
外部保证数值与完整性 来源合同；内核不另做质量扫描 不加日历、停牌、退市、去重、预期时点、isfinite扫描、审计凭证
读取模块管理输入和复权，指标模块管理状态 sources.PriceInputSession、calculation.CalculationEngine 指标不读文件、不复权、不删除共享输入
同一服务创建并关闭连接 service.calculate 的单一finally出口 各指标不另建连接；不同请求不共享可变连接
分批与数学分段分别定义 8192新输入；平滑段长由SQL参数推导 不以fetchmany冒充分批；不整段物化历史；不固定1024套任意参数
输出范围不截断递推历史 calculation.history → sources.ReadRequirement 翻页、换起止不能重置EMA/K/D
当前未结束K线参与 来源提供同一周期记录及实际截止 不把周一/周二同周更新当两根，不用周五数据回算周二
周/月只读已有目标口径 stock_period_price_source 不由日线合成、不重算复权、不换基准
无缓存、预取、池、临时落盘 服务/读取/执行及装配 不持久化指标/状态，不新增线程池/进程池/外部服务
只一种成功空结果 §14 不把错误、取消或10根MA20的NULL序列返回为0根成功
一次组合任一实例失败则本请求失败 service、errors 不返回部分指标；不误停另一独立区域请求

本轮不修改旧Reader，不迁移页面或XXM，不停止DG任务，不改变现行HTTP、DTO、默认500根及Gold指标身份。HTTP装配与消费者章节定义下一步接入必须遵循的具体边界，不构成本轮修改现行API的授权。

SqlStep为内部不可变对象：name: str、sql: str、bindings: tuple、input_tables: tuple[str,...]、output_tables: tuple[str,...]、processed_rows: int。只有受控代码生成它；业务不能直接构造可执行SQL提交给公开入口。SQL步骤统计用于资源计量，不逐点核验数值。

CalculationSession记录executor引用、内部表清单、已处理新输入数、状态表名与初始化标记。不在Python保存EMA/DEA/K/D值；段末只通过SQL更新状态。服务负责连接，读取负责输入，engine负责指标状态，collector负责返回结果，各方只清自己资源。

Definition另有静态public: bool：五项业务能力为true，共用window_mean/window_range定义为false。它们同样由registry维护，resolve只供合法业务计算ID，内部resolve_dependency才可取非公开定义；list/describe业务能力不发布这些内部步骤。该标记不来自业务参数或env，不增加任意调用内部SQL的入口，避免把“声明依赖”写成实际找不到的对象。moving_average.py管理window_mean定义，kdj.py管理window_range定义，BOLL只引用同版本均值，不复制均值算法。

TechnicalIndicatorService.__init__(*, source: PriceSource, registry: CalculationRegistry, config: KernelConfig, control: ExecutionControl | None=None)只接收已解析依赖，不读全局env。没有注入control的同步库调用，在calculate进入时新建本次control并按配置启动必要中断控制；App注入的control保留最早到达时间，不重新计时。普通服务可复用其不可变定义/来源工厂，每次调用的connection/session/control都必须新建；绑定特定control的服务对象只用于该次请求。SourceDescription/SourceStream不得放进共享单例的可变字段。

ExecutionStats固定包含step_name、elapsed_ms、logical_input_rows、output_rows及是否失败；它不保存价格值。结果的sql_processed_rows定义为各SqlStep实际传入表/段的逻辑输入行数之和，同一批被多个步骤使用分别计量；不是DuckDB内部所有operator的行数。开发profiling另记累计operator处理量/报告扫描行，不能用逻辑计数冒充物理I/O或优化器实际工作。source_rows只计新交付目标K线一次，文件数/物理大小/重复读取单独记；不可可靠取得的实际物理读取字节保持未知，不填写伪数字。

04.1 依赖、结果表及实际调用方法的完整合同

1. 注册和每请求实例

  • CalculationRegistry.register(definition: CalculationDefinition, factory: Callable[[Parameters], Calculation]) -> None。
  • resolve(calculation_id: str) -> CalculationDefinition只解析公开定义；resolve_dependency(calculation_id: str, algorithm_version: str) -> CalculationDefinition解析内部依赖。
  • 定义负责validate_parameters(mapping) -> Parameters；Parameters按原LLD为补齐默认值、按定义顺序排列的不可变tuple[tuple[str, int | float], ...]。
  • 展开时先resolve Definition并校验归一参数，再形成当前请求复用键。键若仍在本次递归路径中则报循环错误；已完成的相同键直接复用。首次出现时调用一次factory(normalized_parameters)，再读取该对象dependencies并递归处理；所有循环检查及拓扑安排完成后才允许prepare/SQL。返回Calculation只持有只读定义和只读参数，不保存connection/session/当前批次/可变状态；这些只在本请求的CalculationSession中保存。注册表和factory可跨请求共享，Calculation节点每请求新建；不得跨请求共享CalculationSession。

3. 计算对象方法

使用factory绑定后的只读参数，避免对象已持参数但方法又收到另一套参数：

  • input_requirement(self) -> HistoryRequirement
  • dependencies(self) -> tuple[Dependency,...]
  • prepare(self, session:CalculationSession) -> None：只准备请求级参数/状态表。
  • consume(self, batch:PriceBatch, session:CalculationSession) -> CalculationOutput：准备本批输出表，执行本批SQL，按数学段更新状态；返回当前新位置结果的说明。
  • release_batch(self, session:CalculationSession) -> None：只删除自己登记的本批表，不删依赖/共享价格/状态表。
  • release(self, session:CalculationSession) -> None：清理本节点剩余本批表和请求级状态/参数表；重复调用幂等，具体失败仍上抛供service统一收集。

父节点只读session.dependencies[role]取得依赖表与字段；不得猜依赖内部表名，或另调依赖consume导致重复计算。MA与BOLL同窗共用window_mean，KDJ共用window_range，engine不按指标名称分支。

price的CalculationOutput可直接说明读取模块的共享目标价格表；它不把这张表登记进自身batch_tables，release_batch不得删除借用价格。其他指标也不能登记/删除其依赖表。

4. Engine和输入/输出方法完整签名

  • CalculationEngine.prepare() -> None：按固定依赖顺序创建节点session并调用prepare。
  • CalculationEngine.consume(batch:PriceBatch) -> None：按拓扑顺序构造每节点当批role→output映射，consume每个唯一节点恰好一次；保存当批CalculationOutput说明供output_for使用。
  • CalculationEngine.output_for(batch:PriceBatch) -> BatchCalculationOutputs：不再计算，只按请求实例映射当批节点结果。无当批结果/错批是内部调用错误。
  • CalculationEngine.release_batch_tables() -> None：collector已保存独立尾部后，按反向依赖顺序release_batch；清空当批输出映射。价格仍由inputs.finish_batch释放。
  • CalculationEngine.finish() -> None：正常EOF时结束；不重新递推、不输出额外位置。可核对无尚未结束批次等结构状态，不扫描数值。
  • CalculationEngine.close() -> None：按反向依赖顺序清理全部节点资源，即使某个失败也继续，按现有清理合同汇总异常。
  • PriceInputSession.prepare() -> None、resolved_description() -> SourceDescription、next_batch() -> PriceBatch | None、retain_required_history() -> None、finish_batch() -> None、close() -> None。
  • retain_required_history只在全指标consume及collector完成后，按已声明字段及W−1保存目标口径历史，不保留来源Arrow批或未复权原价，不提前读取下一批。
  • OutputCollector.append_new_rows(batch_outputs:BatchCalculationOutputs) -> None：在SQL按price_batch新seq为主表关联实例结果，按原输出范围选位置并保留limit+1；字段NULL不能导致丢位置。
  • OutputCollector.build_result(description:SourceDescription, statistics:CalculationStatistics) -> CalculationResult：关闭连接前复制为独立结果；之后表可删除。
  • OutputCollector.discard() -> None按现有清理合同释放输出表/结果引用。

CalculationPlan由dependencies.py定义：nodes为按固定依赖顺序排列的只读节点说明（node_index、Definition、归一参数、Calculation、role到上游node_index映射）；instances为按请求顺序排列的instance_id到node_index映射。registry.expand_dependencies只委托该模块；每个节点先按Definition校验参数，再创建本请求Calculation并读取其dependencies，循环检查完成后才能执行SQL。复用键仍按§07约定，同参数不同实例身份不丢；combine_history_and_fields(plan)从这些对象的input_requirement汇总，不复制指标公式。

CalculationSession是每节点每请求对象；engine另持节点session映射和当前批结果映射，不用一个可变session覆盖所有节点。prepare只建请求级状态/参数，consume每批建立并登记自己的输出/中间表，分段SQL内完成状态更新；不再提供第二个批末save_states方法。release_batch按反向依赖顺序删除本批表。price只借用输入表，不登记为自己的可删除资源。

最后一批在取下一批之前不能预知EOF，因此首版每个非空批均按同一顺序保存必要尾部；正常EOF后统一清理。不能为了省最后一次小历史表而预取。new_row_count来自来源本批新行数计量，不含历史，不进行数值质量审计。

start/end为闭区间；before为本页排他上界。分钟只接受带明确时区的datetime并归一到Asia/Shanghai；日/周/月只接受date，拒绝把datetime隐式截断。start/end省略不限定该边；end省略使用来源本次实际可用截止，不把当前系统时间冒充数据已更新。end与before同时存在时取其交集，不因合法翻页参数彼此重叠而新增拒绝。先选择符合输出范围的时间位置，再保留最近limit个，最终升序返回。before用于读取更早页，下一页参数为当前最早时间位置；没有跨请求缓存，下一页完整递推到其实际上界。跨请求不承诺来源版本固定。

周/月按周期所属区间与请求日历区间有交集选择位置；例如周二查询当周，包含当前周那根记录，输出位置为周一起日或月份首日。来源trade_date只是其bar标记，end_date是实际来源截止，不是周五/月末。按适配器明确生成period_start/period_end后处理，不能按Friday标签把本周排除。若请求历史截至周二而来源只有周五最终版本，必须来源不支持该历史截止；不得当无数据成功，不建立历史版本服务。

日线period_start=period_end=trade_date；周线period_start=该trade_date所在周一，period_end=该周五；月线period_start=月首，period_end=自然月末，均在适配层SQL按日历表达式生成，不查询交易日历。它们是周期标签，不保证周五或月末一定开市，不补造交易日。只对period_start≤请求end<period_end的未结束目标周期核对该条来源实际截止能否满足请求；若仅有后来版本则明确不支持。已结束周期不因文件后来重发就错误拒绝普通历史查询；这不是提供任意历史输入版本的能力。相应检查在正常投影/请求语义处理完成，不新增完整性扫描。

05.3 历史范围

MA(N)、BOLL(N)：输出首位置之前需要N−1根，KDJ窗口需N−1根但K/D仍需从来源起点递推。MACD/KDJ任一个出现时，都从来源约定完整历史起点推进至输出上界；不得把最新1000当初始化范围。只含有限窗口指标时，从来源倒序找到输出limit位置及前置max(N−1)位置，然后正序计算；首版为避免重复遍历，可仍从来源起点读一轮并只保留必要尾部，记录真实处理量和截止预算，不能因此声称只读M+N−1。算法声明不因读法变化。

源历史不足时，返回实际可用位置；MA250不足的前249位置为NULL。假设首个输出之前已有249根，则这些前置行不返回，也不把展示月首249位置置NULL。§18中分别测试两种情况。

06.2 读取步骤

  1. 解析配置的正式Lake根，拒绝旧湖、staging、符号链接越界及业务路径输入；只读，不自动mkdir。文件清单按证券/周期/截止有界枚举，跳过临时文件只依据既有正式路径合同；不对照日历或检查缺口。
  2. 按路径日期或股票年份升序选文件；读取元数据/模式及物理大小，只统计资源和选择投影，不核对逐行数值。元数据足以判断超文件数或选中列row group初始保护值时读前拒绝，后续实际发现超限也整次失败。物理文件大小只统计，不设合计1GiB拒绝条件。

  4. 保留当前Scanner/Reader，不与DuckDB连接上的未读完查询结果交错。来源交付一批后保留位置，等本批finish_batch才取下一批；没有匹配行继续后续文件，只有全源正常结束才返回None。
  5. 当前RecordBatch通过connection.register(internal_name, batch)交给同一连接；立即执行stage_input.sql，只把本批所需字段和目标证券记录物化为SQL标准表。注册引用只有在物化SQL完成后注销，随后释放Python列批次引用；数据数值运算仍在SQL中。
  6. 来源合同保证目标证券跨文件和批次按时间有序；来源表物化后按时间排序是算法步骤，不检查是否有重复或乱序。年文件生产者已有ORDER BY ts_code, trade_time；日/周/月分区的目标证券最多该周期一条。未能保证跨批有序的新来源不得直接接入，不在内核全历史排序或临时去重补救。
  7. 一次请求的所有指标复用同一个源遍历和本批目标价格；每个正式文件的数据流只前进一遍，schema/footer读取单列统计，不把多次读元数据说成多次价格遍历。源Scanner过滤仍可能解压含其它证券的row group：这是物理读取成本，不把目标股票的1行等同只读了1行文件。

来源时间过滤固定分周期实现。 分钟价格用trade_time和有效end/before上界；日线用trade_date；二者不得加start来截掉递推前缀。周/月候选分区必须包含与目标输出区间相交的那个周期，有限end扩到所属周五/自然月末仅用于选候选分区；period_start仍须不晚于请求end。before只在输出位置上按period_start做排他比较：before为周三时，当周周一位置仍在其前；before恰为周一起日时排除整根当周。不能在Arrow把源trade_date直接与周二end比较而提前丢当周。

周/月先读取受控候选分区，在stage SQL由源标签生成period_start/end、解析source_as_of，再处理输出相交关系；递推仍保留所有必需前置周期。只有请求end落在未结束目标周期内且该条source_as_of晚于end时，拒绝该历史截止，不得把它过滤为0根成功。例：源trade_date为周五，source_as_of为周二，周二end应包含当前周；同样标签但source_as_of为周五则不能回算周二。对普通已结束周期沿用§05.1，不因后来重发而错误拒绝。

含递推指标时Scanner的时间过滤只有有效输出上界，不应用start或最近N作为来源下界；从来源约定最早正式分区开始正序推进。服务通过SQL row_number() OVER(ORDER BY time_key)+already_delivered为新目标行分配连续seq，already_delivered仅是已交付行数计量，不计算指标。来源历史起点说明为该来源合同的最早可用历史，实际首行时间另记；不能把旧Reader默认近3年移植为来源起点。

官方依据：Arrow Scanner23.0.1 的批次、过滤及readahead参数；DuckDB Python连接 的register/unregister。实现时只使用已确认版本签名，库不存在即明确能力不可用，不自动安装或换数据源。

06.4 因子读取

价格主流通过PyArrow保留进度；当前日线因子/基准用读取模块在同一DuckDB连接中执行有界目标证券查询，并立即物化为当前因子/基准SQL小表，不跨计算步骤保存未取完的因子查询结果。这样仍只有一个Arrow价格Reader和一个DuckDB连接；因子SQL不会破坏Arrow位置。因子也不按指标重复读取，唯一文件数计入同一预算，物理字节只统计，不设合计大小上限。

只有日线由none转qfq/hfq才启用。按价格分区日期读取该股票当日因子，来源负责覆盖；不逐日期审计，不补值。最新/最早基准在来源准备时按配置已知的因子日期清单倒序/正序找到第一条该股票记录，固定整次请求；该查找是确定公式输入，不是检查因子完整性。最多受同一文件数/截止预算约束，物理字节只统计，不能无上界扫全市场。因子基准文件与同日文件重复使用时只保留当前已取行或当前批小表，不形成跨请求缓存。

06.6 SourceStream字段、推进和关闭

SourceStream每请求独立，普通方法仅在本次工作线程调用；配置/来源工厂可以共用，此对象不能共用。至少保存：

字段 类型/初值与职责
file_iterator / current_path 已有受控文件清单的迭代器 / None；路径已按时间排序，不每批重新枚举
fragment / scanner / reader None或当前文件对应Arrow对象；每次只打开一个文件
current_batch None或当前RecordBatch；SourceStream与PriceInputSession交接期引用，物化后释放
exhausted / closed / failed 初始False；正常全文件结束、显式关闭、读取失败分别记录，不能混为同一EOF
source_rows / source_files / source_file_bytes 已交付目标行及已打开唯一文件计量；不冒充物理读取字节或磁盘遍数
control / read_requirement 本次停止控制及不可变输入需求；时间过滤只有有效输出上界，不截掉递推前缀

方法next_batch(max_rows)的max_rows由PriceInputSession固定传入config.batch_rows；本请求过程中不改成别的值。若current_batch尚未release，不允许再取下一批。第一次调用打开第一个文件，后续调用延续同一个reader；不得每次重新Scanner、重新发起DuckDB读文件查询或read_all/to_table。

推进算法：检查停止→必要时创建当前文件fragment/Scanner/reader→read_next_batch→再次检查停止→若num_rows为0则释放该空批继续取本文件→交付非空SourceBatch。只有捕获StopIteration才结束当前文件：关闭reader，清空fragment/scanner引用，再推进下一个文件；全部文件都正常结束后才设exhausted并返回None。其他异常保留cause并抛SourceReadError，不转为StopIteration/None；close失败按ResourceCleanupError处理并整次失败，不打开下一文件掩盖问题。

SourceStream内部协议release_current_batch() -> None：幂等清空current_batch引用，不关闭reader、不重置读取进度。close()只由工作线程调用，先释放当前批，再尝试reader.close，最后清空scanner/fragment/file_iterator等引用并标closed；即使某项清理失败也尝试其余释放并报告错误。关闭或failed后的next_batch是内部调用错误，不返回正常EOF。正常exhausted后的next_batch可继续返回None；重复close不操作已经释放的对象。

若read_next_batch返回后已停止，不交付该批给指标；释放该批并抛取消/截止错误。不得从控制线程调用Arrow close去抢断正在运行的原生文件操作。单一批次8192是交付行数上限，不是原生解压内存硬上限；选中列row group的元数据估算及实际内存继续遵守§16～17。

06.7 交给DuckDB及两层批次的释放点

读取所得SourceBatch由PriceInputSession按以下固定顺序接收，不能把整个Reader注册给每个指标：

  1. 检查停止和实际输入计量，把当前RecordBatch注册为受控内部名称；成功后立即登记注册名。
  2. 在本请求唯一连接执行stage_input.sql，完成本批投影、类型/单位转换与受控排序；各指标只看后续准备好的目标价格临时表。
  3. stage_input物化成功后unregister本批Arrow注册名，再release_current_batch并清空接收方对SourceBatch/RecordBatch的引用。之后需要复权时，在同一连接执行读取模块的复权SQL。最终目标价格是独立SQL表，继续供所有指标复用；此时尚不读取下一批。
  4. engine计算、输出收集、SQL状态和必要历史窗口独立保存完毕后，PriceInputSession.finish_batch才删除本批SQL价格/输入表，允许下一次next_batch。Arrow批次的释放早于SQL价格表；二者不能使用同一个模糊的“批次结束”。
  5. 注册或物化失败时整次失败；待SQL实际退出并结束中断监控后，由统一finally尝试unregister、释放Arrow引用、关闭reader、清理SQL表及最终close连接。unregister失败要记清理错误；不能声称引用已经释放，最终连接关闭仍必须尝试。

没有预取、跨请求缓存或通用引用计数；不是让DuckDB和PyArrow各读一遍。一次源推进服务同批全部指标，来源数值和完整性仍由外部负责，不新增质量扫描或日历/停牌检查。

07.1 固定定义与顺序

registry.py注册 price@1.0.0 / ma@1.0.0 / boll@1.0.0 / macd@1.0.0 / kdj@1.0.0。独立复权对象的实现版本为price_adjustment@1.0.0，其说明由price能力引用并结合配置来源给出可用目标口径；不再发布一个业务不能直接调用的第六个计算ID，也不在指标引擎重复实现复权。业务单独提交price和目标复权即可取得价格，多指标中的price实例也走同一已准备价格，不触发第二轮读取。发现列出的每个计算ID必须能通过同一calculate入口解析；来源不支持与未知能力分开返回。

09.2 安全段长全部由SQL计算

WITH p AS (
  SELECT CAST(? AS BIGINT) n, CAST(? AS VARCHAR) kind
), a AS (
  SELECT *, CASE WHEN kind='ema' THEN 2.0/(CAST(n AS DOUBLE)+1.0) ELSE 1.0/CAST(n AS DOUBLE) END alpha
  FROM p
)
SELECT n, alpha, 1.0-alpha AS beta,
       CASE WHEN n=1 THEN 1024
            WHEN alpha<=0 OR NOT isfinite(alpha) OR NOT (1.0-alpha>0 AND 1.0-alpha<1) THEN NULL
            ELSE least(1024, greatest(1,
                 floor(256.0/(-ln(1.0-alpha)))))::INTEGER END AS safe_rows
FROM a;

n的BIGINT转换溢出按自然类型错误失败；先转DOUBLE再加1，避免先发生整数n+1溢出。SQL返回safe_rows=NULL表示平滑系数在当前数值类型中不能表达，executor须据这个单行参数结果报参数错误，不能交付NULL指标假成功。这里只检查参数产生的单行系数，不扫描源价格质量。

n=1走恒等结果，不计算ln(0)、0负幂；此时1024只是内部单步行数上限，不是指数幂段长，也不让恒等分量把其它平滑强制变成逐根SQL。复合平滑步骤须先逐个检查各递推分量safe_rows均非NULL，任一NULL则整次拒绝；不能直接用会忽略NULL的MIN掩盖无效分量。全部有效后，段长取其各递推分量safe_rows最小值，再与当前新输入剩余行数取小；Python只安排已经由SQL确定的S，不求α/β/对数或指标值。

约束 S×(−lnβ)≤256，因此负幂至多约e^256=1.5114×10^111；另有S≤1024。若精度验证的价格尺度M=10^6，允许MACD中间输入绝对尺度2M，负幂乘输入与累计和的保守界为1024×2×10^6×e^256 < 3.10×10^120，显著低于DOUBLE最大约1.7977×10^308。K/D输入在正常价格合同下RSV0..100，边界更小。该推导同时覆盖乘输入/求和，不能只证明幂有限。该M用于限定数值验收结论，不增加逐根输入范围检查，也不保证任意接近DOUBLE极限的异常源数值仍可计算。

本机1.5.5核验的段长：EMA2=233、EMA9/12/26/65/69/10000=1024；K/D2=369、K/D3=631、K/D10000=1024。默认MACD取1024、默认KDJ取631；读批8192分别含多个数学段。自定义参数的任一分量若要求更短段，必须共同服从；不能只按快/慢EMA忽略DEA。256既留出超过180位十进制的数值余量，又避免把默认平滑无必要地切成很短的小SQL；不为省语句采用超过公式上限的段长。

09.3 分段模板及首条处理

-- 对当前段，j为从1开始的段内序号；seed为上一段末值
-- SQL参数表提供alpha、beta，所有普通运算仍在DuckDB
CASE WHEN n=1 THEN x
     ELSE power(beta,j)*seed
        + alpha*power(beta,j)*
          fsum(x*power(beta,-j)) OVER (
            ORDER BY j ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
END AS smooth_value

EMA的第一根数学上两条EMA均为首个close，DIF=DEA=hist=0；内部按下段等价变换保存origin_price=close、两offset=0，输出直接字面SQL赋0，避免首条展开产生约1e−14的假负号。后续从第二根调用模板，段首seed取内部状态表，j=seq-last_seq。快慢EMA各算减首价后的值并相减形成DIF，再以旧DEA为seed对当前段DIF平滑；柱值2*(dif-dea)；段末更新两offset与DEA，origin_price不变。后续段不是重新以首个close初始化。

**最终编码必须采用的数值处理：**原价首根为c0，令x=close−c0后在SQL计算两EMA；初始两状态均0，额外保存固定c0。因为EMA线性、两条EMA都减去相同c0，EMA_fast(close)−EMA_slow(close)=EMA_fast(x)−EMA_slow(x)，DIF/DEA/柱的数学定义不变。不需要把c0加回后再相减；那会重新引入大数相减。状态表字段明确改为origin_price,ema_fast_offset,ema_slow_offset,dea,last_seq，其中offset只表示已减c0的内部状态，不是改变目标复权或另一个业务指标。首根原始EMA数学上仍等于close，内部状态为0。此方法不读取更多数据，不新增Python数值运算，也不改变首条严格0要求。高价/大周期的原写法已在有限样本中超出§10门槛，不能继续作为正式模板或放宽容差。

KDJ先对ti_price_window生成各新行window条高低：max(high)/min(low) OVER (ORDER BY seq ROWS BETWEEN window−1 PRECEDING AND CURRENT ROW)；CASE WHEN highest=lowest THEN 50.0 ELSE (close-lowest)/(highest-lowest)*100.0 END。K再平滑RSV，D再平滑当前K，J=3*K−2*D；K/D首根也要从50更新，不能直接输出50。k_period或d_period=1时对应平滑是恒等，不能把整个KDJ统一短路。

MA/BOLL用完整窗口输入计算后，外层只选新行。均值和总体标准差均按ROWS，count(*) OVER w < N时输出NULL。BOLL上下轨在窗口足够时mean ± multiplier*stddev_pop(close)，不用样本标准差、不补0、不四舍五入。共享均值只算一次，BOLL仅增加标准差及上下轨。

11完整调用步骤与异常收尾

def calculate(self, request):
    # 以下是编码顺序，不是已实现代码；所有数值步骤调用SQL对象
    control = self.control or ExecutionControl(arrived_at=monotonic(), config=self.config)
    normalized = normalize_request_and_validate_all_instances(request)
    plan = self.registry.expand_dependencies(normalized)
    requirement = combine_history_and_fields(plan)
    control.check_active()
    description = self.source.describe(normalized, requirement, control=control)
    ensure_supported_request_and_declarations(description, normalized)
    connection = executor = inputs = engine = output = None
    cleanup_errors = []
    primary_error = None
    result = None
    try:
        control.check_active()
        connection = connect_private_memory_instance(self.config)
        executor = DuckDBExecutor(connection, control)
        control.start_monitor(connection.interrupt)  # 绑定并启动唯一中断控制
        control.check_active()
        inputs = PriceInputSession(executor, self.source, description, requirement)
        engine = CalculationEngine(executor, plan)
        output = OutputCollector(executor, normalized)
        inputs.prepare()
        engine.prepare()
        while True:
            control.check_active()
            batch = inputs.next_batch()
            if batch is None:
                break
            if batch.new_row_count == 0:
                inputs.finish_batch()
                continue
            engine.consume(batch)
            output.append_new_rows(engine.output_for(batch))
            inputs.retain_required_history()
            engine.release_batch_tables()
            inputs.finish_batch()
            control.check_active()
        engine.finish()
        result = output.build_result(inputs.resolved_description(), actual_statistics())
        measure_result_utf8(result, control=control, max_bytes=self.config.max_output_bytes)
        control.check_active()
    except BaseException as exc:
        primary_error = exc
    finally:
        # 从这里开始不能再执行普通计算；在工作线程确认SQL已经退出后清理
        cleanup_errors.extend(control.stop_monitor())
        cleanup_errors.extend(attempt_cleanup_in_order(engine, inputs, output))
        cleanup_errors.extend(attempt_close_owned_connection_once(connection))
        # 正常路径任何清理失败提升为失败；有原错误则保留原错误并附清理问题
    raise_primary_or_cleanup_error_if_any(primary_error, cleanup_errors)
    control.check_active()
    return result

所有可能部分初始化的局部对象先设None并在创建后登记。三个清理调用在service.py内实现并返回tuple[BaseException,...]，对None无操作、实际异常逐项收集而不在中途抛出跳过后续项；stop_monitor仅在真实结束监控后返回。无原错误且任一清理失败不得返回成功。describe若产生文件句柄由source在自身try/finally关闭；不得因在连接创建前就漏清。错误后不再调用engine.finish，不返回其它指标半成品。BaseException用于保证SystemExit/KeyboardInterrupt仍清理，最终保留原异常，不改写为普通成功或空结果。

正常：结果先独立→停止并解绑中断控制→指标状态/中间表清理→读取输入/因子/文件句柄清理→输出SQL表清理→同一服务关闭连接→复核取消→返回。清理模块只操作自己的表，连接关闭由service唯一负责。清理幂等：对象未创建/已释放时无操作；实际drop/close失败则记失败并继续其它清理，不无限重试、不仅改标志冒充释放。

错误/取消：SQL调用抛出或返回后，工作线程才开始删除表；不在监控线程或另一区域请求关闭连接。原计算错误优先保留，清理错误附入内部diagnostics；原本正常但清理失败则抛ResourceCleanupError。日志写失败仅记录可用fallback，不使正常结果失败；不能把资源清理当日志吞掉。

11.1 停止后的清理执行入口

executor.py另有仅内部使用的cleanup_drop(table_name)和cleanup_unregister(registration_name)，只接受该模块资源清单中已登记的内部名称；分别只能执行DROP与unregister，不能接收任意SqlStep、SELECT、复权或指标SQL。普通SQL调用已返回且stop_monitor完成解绑/join后才能进入，不再调用check_active，否则取消本身会阻止必需清理。正常执行的execute/scalar仍在调用前后检查停止。清理成功才从所属清单移除；失败保留问题并继续其余清理，连接仍由同一服务最后关闭，不能先清标记冒充已释放。

12.2 应用层一个进程一份控制

composition.py在应用lifespan启动时创建不可变config/registry/source factory；admission.py建立唯一共享容量对象，保存closing:bool=False、active_leases:dict[内部ID,AdmissionLease]、一个最多2项的FIFO等待列表及idle_event。活动数从len(active_leases)取得，不维护另一份可漂移计数。AdmissionLease只持本请求control、内部ID和released标记；idle_event明确使用anyio.Event：初始化时置位；从0个活动请求授予第1个时替换为一个新的未置位Event，不调用不存在的clear方法；最后一个Lease归还时置位当前Event。不是每请求创建计数，不在Foundation导入App。应用退出时拒绝新请求，取消等待者，对活动请求发停止，等待其真实收尾；未清理任务不伪装已释放。实际Web worker数由部署配置记录，每worker各2；部署总上限=worker数×2，并按同刻RSS核算。

admission.acquire(control)为async；同一事件循环内原子修改active/等待列表，无耗时锁。没有空位且等待已满，立即CapacityBusyError；可以等时按入队序保存Future及绝对到期时刻，最长2秒。waiter取消/到期先从列表移除，不能后来再授予。释放时核对Lease未归还，再唯一移除active_leases记录；选最早仍有效waiter并建立其Lease，若无活动请求则置idle_event。所有集合更新和Future授予在同一事件循环内完成且中间不await，不可出现一个名额同时交给两个请求。停机先closing=True，移除并唤醒所有waiter，再对active_leases快照逐个request_stop(cancel)，等待idle_event真实置位；不能仅凭计数发送停止，也不能未归还就宣布已清理。

等待对象固定字段为future、control、wait_until、assigned_lease=None及是否已移交标记。授予时先建立Lease并登记active_leases、将assigned_lease写回等待对象，再set_result；acquire只有正常返回Lease给execution时才把管理权标为已移交。若Future已获授予、调用方尚未收到返回就发生取消/异常，由acquire自己的异常出口回收这份已分配但未移交的Lease；execution没有拿到Lease，不再归还。未授予者仅移除waiter。所有归还都检查released，既防泄漏也防重复释放；测试用Event/Barrier固定这个先后，纳入原授予同时取消类。

shutdown先设closing再取得当前idle_event引用，因此之后不会授予新请求或替换该Event；取消等待、对活动control发停止后等待该引用置位。若原生工作未退出，等待不算完成，不提前改计数或宣称安全停机。

获准后也要核对正常处理截止，不因刚等到空位重置8秒。接入层使用现有anyio.to_thread.run_sync运行完整calculate，abandon_on_cancel=False；取消不会让接入层忘记实际仍在运行的工作线程。内核不在内部再次acquire。同页两个区域是两个实际请求，不能共用一个名额；单指标合法，不加区域配额。

名额从获准开始一直保留，覆盖框架线程等待、SQL运行、停止清理、独立结果转换及HTTP发送。库级计算完成不等于API发送完成：未来接入层必须在发送/断开或序列化失败的finally归还一次；不新建结果队列或把连接交给HTTP层。普通库调用由其入口在结果移交及所需编码结束后归还；本轮不新增第二个公开计算函数。

12.3 等待工作线程期间的异步取消观察

execution.py在请求体解析完成后，用同一个AnyIO task group运行请求主任务与唯一的异步断开观察任务；观察任务在admission.acquire前启动。本次HTTP链路由它独占ASGI receive并处理http.disconnect，框架或response不得另建竞争读取receive的监听；隔离测试交付等效断开事件即可。观察到断开先同步control.request_stop(cancel)，再cancel该task group；观察任务被外部取消而退出时，若request_finished仍False，也在finally先request_stop，不能等主任务从run_sync返回后才发信号。

主任务仍使用一次anyio.to_thread.run_sync(worker, abandon_on_cancel=False)，在既有工作线程完成calculate→Biz字段适配→严格JSON编码；适配前后、iterencode每块前后和完成后均按同一control.check_active核对第6秒截止，不在事件循环同步做整个5MB编码。断开观察任务是同一组内的另一异步任务，不在run_sync内部等待的取消保护之中，能先让control进入停止；唯一中断控制随后interrupt，主任务仍等待工作线程真实返回，不遗弃后台工作。若在框架线程名额等待阶段已取消，worker不得随后启动；即使临界时刻开始，calculate首个check_active也必须拒绝。

正常发送完成后先request_finished=True，再取消该组以结束断开观察；否则会将正常结束误判取消。主任务原异常仍优先保留；最终只对实际取得的Lease归还一次，且须工作线程已退出、发送调用已退出、body/result引用已释放。无Lease的取消等待者不得归还。以上只新增既有异步流程内的观察任务，不新增计算线程、线程池、进程或配置。

13取消、到期和中断控制的精确步骤

13.1 本轮确认、时间与负责方

管理员已确认本轮不升级DuckDB，采用现有1.5.5的interrupt方案。接口到达时只记录一次monotonic时刻T0；work_until=T0+(total_target_ms-cleanup_reserve_ms)/1000，初值第6秒；target_finish=T0+total_target_ms/1000，初值第8秒。前端仍从自身发出时刻起10秒失效。排队、鉴权、框架线程等待和读取均消耗本次时间，不在每条SQL或每批开始时重新计时。

每个实际运行的请求最多一个中断控制线程，由ExecutionControl创建并结束。 它只等待停止/截止/正常结束，并调用该请求连接的interrupt；普通SQL、fetch、Arrow读取和清理都在既有工作线程执行。2个活动请求至多2个控制线程；等待中的请求没有连接，也不启动控制线程。不按指标/SQL创建Timer，不增加计算线程池或进程池。

当前版本方法可用已由§21.5的小实验核实；完整内核、文件读取、清理及并发验收仍按§17～18执行。第8秒是含清理的目标，不是任意原生调用或系统文件I/O的强杀保证。停止后未实际退出/清理的请求仍占名额，不能为了接口早返回而在后台继续且归还名额。

13.3 循环、互斥与停止顺序

以下为可直接实现的内部控制顺序。_set_deadline_if_due_locked()只在原因未定且到期时调用与request_stop相同的写入逻辑；_remember_interrupt_error()只保存首个错误摘要，不吞掉本次停止状态。

# 普通计算仍在原工作线程；这里只是唯一监控线程的循环
try:
    with self.condition:
        while not self.monitor_stop:
            self._set_deadline_if_due_locked()
            if self.stop_reason is None:
                self.condition.wait(timeout=max(0.0, self.work_until-self.clock()))
                continue
            if self.interrupt_callback is not None:
                try:
                    self.interrupt_callback()  # 必须在同一短锁内调用
                    self.interrupt_count += 1
                except Exception as exc:
                    self._remember_interrupt_error(exc)
            self.condition.wait(timeout=self.config.control_poll_ms/1000)
finally:
    with self.condition:
        self.monitor_exited = True
        self.condition.notify_all()

正常时condition一直等到截止或被取消/正常结束唤醒，不每20ms检查所有运行请求；只有停止状态出现后每20ms重试interrupt。锁只包住状态和短暂interrupt，不包住耗时execute、fetch、Arrow取批、join或close。最后一次check_active与execute之间仍可能发生停止；重复中断覆盖首次interrupt先于SQL进入而落空的情况。工作线程得到停止状态后不再开启新业务SQL或新文件/新批次。

服务只在全部业务调用已经返回后调用stop_monitor。顺序不得交换：

  1. 在condition锁内把interrupt_callback设为None，monitor_stop设为True并notify_all。若一次interrupt正在同锁内执行，先等该调用结束，不能提前关闭连接。
  2. 释放锁，在工作线程join监控。先用monitor_join_target_ms=200作退出目标检查；超目标记录ResourceCleanupError及实际时间，仍等它真实结束，不能强杀、提前close或把名额归还。正常结束也必须join；未start或启动失败不得对未启动Thread调用join。
  3. 确认monitor已结束后，再逐项清理engine、inputs、output及已注册Arrow对象，最后由同一服务关闭连接。每项失败都记入cleanup_errors，并继续后续可安全进行的清理；监控错误不能让finally跳过close。原计算/取消错误优先，无原错误而清理失败则失败。
  4. 结果交付前check_active。已接受取消/已到正常处理截止的请求不得新发布成功结果；已经开始发送的响应按§14.3结束或终止发送，不能拼入另一份JSON。

stop_monitor()不再需要回调后应清空自身对回调/线程目标的可释放引用；control保留停止原因及有限计时摘要供调用方读取。任何旧请求之后收到取消，也只能修改旧对象，不能操作下一请求的连接。

后续Biz适配的HTTP响应是另一个合同格式，由encode_response_utf8独立计量并且只生成一份最终body，直接交给框架发送；不得对同一HTTP格式先model_dump_json再由框架重复编码。库格式只做流式计量、HTTP格式形成一次body，必要的两次格式遍历均纳入同一工作截止与性能报告；不宣称整个请求只做一次JSON遍历，不增加缓存、公开编码入口或计算模式参数。计量不持有额外完整副本，已有编码内存预留保持，实际用量按§17验收。

kernel_version负责执行/合同版本，algorithm_version随公式/初始化/参数语义变化，contract_version表示来源字段/单位/时间规则。现有paramsKey、indicatorVersion和indicatorSource=gold不能被新核冒用；后续接入必须同步修改全部消费者，不留双轨兜底。

14.2 唯一成功空结果条件

请求和全部能力/参数合法，来源支持本请求，必要读取正常结束，输出区间或本页确实没有K线，输出处理及清理也成功，才返回count=0、空times/各实例值序列、NULL实际输出起止；周/月source_as_of=[]，分钟/日线source_as_of=null。保留实例/参数/版本/已知来源和复权说明，已读取前置历史的实际统计不能清零。不制造NULL假K线，不推断停牌、退市、尚未上市或缺数据。

有K线但初始MA/BOLL不足窗口，返回对应时间和NULL；中途空批次不等于结束。参数/不支持/来源声明缺失、读取/复权/SQL/编码/清理错误、超限/繁忙、取消/到期均不得转为空成功。源正常无匹配与合同要求文件访问失败分开；0根不能提前跳过能力/参数/来源支持检查。

14.3 API结果持有与名额归还

未来接入时App execution.py启动异步断开观察→取得名额→一次工作线程调用内calculate关闭SQL并移交独立result、Biz字段适配、严格编码→App response持有完整body→ASGI发送完成或断开→释放body/result引用→唯一归还Lease。响应准备/发送仍服从T0+8s目标，已发送一部分后失败只能结束发送，不再拼错误JSON。前端直到完整响应体及转换结束才撤销10秒定时保护；401刷新重发使用同一绝对前端截止。该迁移另行获准后实施，本轮只用隔离ASGI适配器验证生命周期，不修改现行HTTP。

发送的第8秒截止由response.py负责。 calculate返回前中断监控已经结束，不能靠它停止发送。完整body产生且check_active通过才允许开始成功发送；开始前已到第6秒或取消则不发布成功结果。第一次发送前取remaining=control.target_finish-monotonic()；≤0直接停止，否则用anyio.CancelScope(deadline=anyio.current_time()+remaining)包围完整ASGI start/body发送，把不同计时入口转换为同一剩余时间，不每段重置。发送完成后检查scope.cancel_called和实际target_finish，未完成或超时不算成功；任何发送await须实际退出后才释放资源和归还Lease。已开始的发送只服从第8秒完成目标，不能用第6秒计算截止将已开始响应错误中止；断开观察持续到整个发送收尾。

发送超时/断开保留真实原因；如果已发送响应头或部分body，只结束发送，不追加另一份错误JSON。未开始发送的错误响应也只能在剩余第8秒内交付，不重置时限。底层不可中断阻塞仍不能保证强杀；超过目标必须记录失败且未真实结束前不归还名额。response.py不使用会另行争抢receive的StreamingResponse断开监听，本轮仅隔离ASGI验证，将来迁移须按现行框架核对。

21.1 MACD单段完整数据流

受控表名在加载模板时由engine替换；以下省略内部序号后缀，绑定参数?只传本段新输入终点。ti_macd_parameters来自§09的三组参数合并，字段fast,slow,signal,af,bf,aslow,bslow,ag,bg,segment_rows；state字段顺序last_seq,origin_price,ema_fast_offset,ema_slow_offset,dea。origin_price为固定首价，offset是内部数值表示，不能被消费者当原始EMA。仅请求级状态在prepare阶段建表：

CREATE TEMP TABLE ti_macd_state(last_seq BIGINT, origin_price DOUBLE,
    ema_fast_offset DOUBLE, ema_slow_offset DOUBLE, dea DOUBLE);
CREATE TEMP TABLE ti_kdj_state(last_seq BIGINT,k DOUBLE,d DOUBLE);
INSERT INTO ti_kdj_state VALUES(0,50.0,50.0);

-- 每批consume开始先创建本节点本批输出表；随后在资源清单登记
CREATE TEMP TABLE ti_macd_output(seq BIGINT,dif DOUBLE,dea DOUBLE,hist DOUBLE);
-- macd_first.sql，仅该实例从未见过输入时执行；只取首根新行
INSERT INTO ti_macd_state
SELECT seq,close,0.0,0.0,0.0 FROM ti_price_new ORDER BY seq LIMIT 1;
INSERT INTO ti_macd_output
SELECT last_seq AS seq,0.0 AS dif,0.0 AS dea,0.0 AS hist FROM ti_macd_state;

-- macd_segment.sql；next_end由SQL least(last_seq+segment_rows,new_last_seq)给出
CREATE TEMP TABLE ti_macd_work AS
WITH x AS (
 SELECT b.seq,b.seq-s.last_seq AS j,b.close-s.origin_price AS x,p.*,
        s.ema_fast_offset AS seed_fast,s.ema_slow_offset AS seed_slow,s.dea AS seed_dea
 FROM ti_price_new b CROSS JOIN ti_macd_state s CROSS JOIN ti_macd_parameters p
 WHERE b.seq>s.last_seq AND b.seq<=?
), e AS (
 SELECT *,
   CASE WHEN fast=1 THEN x ELSE power(bf,j)*seed_fast
     +af*power(bf,j)*fsum(x*power(bf,-j))
       OVER(ORDER BY j ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) END AS ef,
   CASE WHEN slow=1 THEN x ELSE power(bslow,j)*seed_slow
     +aslow*power(bslow,j)*fsum(x*power(bslow,-j))
       OVER(ORDER BY j ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) END AS es
 FROM x
), d AS (SELECT *,ef-es AS dif FROM e), a AS (
 SELECT *,CASE WHEN signal=1 THEN dif ELSE power(bg,j)*seed_dea
    +ag*power(bg,j)*fsum(dif*power(bg,-j))
       OVER(ORDER BY j ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) END AS next_dea
 FROM d
)
SELECT seq,ef,es,dif,next_dea AS dea,2.0*(dif-next_dea) AS hist FROM a;

INSERT INTO ti_macd_output SELECT seq,dif,dea,hist FROM ti_macd_work;
UPDATE ti_macd_state SET last_seq=w.seq,ema_fast_offset=w.ef,ema_slow_offset=w.es,dea=w.dea
FROM (SELECT * FROM ti_macd_work ORDER BY seq DESC LIMIT 1) w;
DROP TABLE ti_macd_work;

每批ti_macd_output只存新行；第一批首根只执行first一次，随后分段；以后所有批次先建空输出，再只用state继续。collector保存独立尾部后由release_batch删除本批输出，state留到下批。Python允许读取一行last_seq/next_end/segment_rows安排语句，不取EMA/DEA回来运算，不在Python拼价格常量。状态/参数表类型需按§08固定，首根空输入时不执行first插入，不因此宣称来源支持检查可省略。

21.2 KDJ单段完整数据流

ti_rsv_new(seq,rsv)先由§09高低窗口SQL输出新行；ti_kdj_parameters(k_period,d_period,ak,bk,ad,bd,segment_rows)由相同系数模板kind='kd'生成；state初始化一行(last_seq=0,k=50.0,d=50.0)。

-- 每批consume开始一次创建并登记；不是每个数学段都重建输出表
CREATE TEMP TABLE ti_kdj_output(seq BIGINT,k DOUBLE,d DOUBLE,j DOUBLE);
-- 以下work/INSERT/UPDATE/DROP每数学段执行
CREATE TEMP TABLE ti_kdj_work AS
WITH x AS (
 SELECT v.seq,v.seq-s.last_seq AS j,v.rsv,p.*,s.k AS seed_k,s.d AS seed_d
 FROM ti_rsv_new v CROSS JOIN ti_kdj_state s CROSS JOIN ti_kdj_parameters p
 WHERE v.seq>s.last_seq AND v.seq<=?
), k_values AS (
 SELECT *,CASE WHEN k_period=1 THEN rsv ELSE power(bk,j)*seed_k
   +ak*power(bk,j)*fsum(rsv*power(bk,-j))
     OVER(ORDER BY j ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) END AS next_k
 FROM x
), d_values AS (
 SELECT *,CASE WHEN d_period=1 THEN next_k ELSE power(bd,j)*seed_d
   +ad*power(bd,j)*fsum(next_k*power(bd,-j))
     OVER(ORDER BY j ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) END AS next_d
 FROM k_values
)
SELECT seq,next_k AS k,next_d AS d,3.0*next_k-2.0*next_d AS j FROM d_values;

INSERT INTO ti_kdj_output SELECT seq,k,d,j FROM ti_kdj_work;
UPDATE ti_kdj_state SET last_seq=w.seq,k=w.k,d=w.d
FROM(SELECT * FROM ti_kdj_work ORDER BY seq DESC LIMIT 1) w;
DROP TABLE ti_kdj_work;
