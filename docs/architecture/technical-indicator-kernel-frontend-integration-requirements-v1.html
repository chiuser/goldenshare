1. 范围与依据

本文是“第四批-修复开发”的外部使用约束，也是后续页面改造的输入。内核组件边界以组件方案为准，代码与SQL细节以代码级LLD为准；本文不重复定义预热公式、误差计算或资源配置。

本轮不修改前端、正式API或现行页面行为，不声称页面已经具备本文能力。后续实施前，仍须把实际API和页面代码位置补入相应页面的设计与LLD，完成现行消费者迁移核对。

约束适用于主要图表区域中使用同一证券、同一周期、同一目标复权和同一时间范围的相关指标。其他独立区域可以有自己的请求，不要求整页所有区域只能发送一次请求。不在本文件中增加任意复权基准日期、跨请求计算状态缓存或新的分页探测能力。

3. 请求内容和双方责任

  • 页面提交证券、周期、目标复权、相关指标及其参数、请求截止范围，以及本次最多返回1000根的要求。未指定目标复权时沿用内核默认前复权。
  • 同一主要图表区域的相关指标应组合为一次请求；同一批K线只读取、按需复权一次，供这些指标使用。不能为了十个指标重复发起十次相同范围的计算。
  • 前端不传预热根数，也不按“显示1000根”强制内核只能读取1000根。内核根据参数确定所需额外历史，只向页面返回目标日期的结果。
  • 向前加载时，取当前已经返回并保存的最早K线日期时间作为before。内核按严格早于这个时间选择数据，该时间对应的K线不再返回。
  • 下一次只请求更早的一页，收到后在已有结果前方合并；不要求返回累计最新2500根，也不重复替换已经加载的1000根。

limit和before在这里表达内核语义，不在本文件预先确定未来HTTP DTO的命名或新增端点。正式API的时间表示、字段映射和错误传递，须在后续接入的API合同与页面LLD中统一。

4.2 全部历史只有1600根

请求内核如何计算返回结果页面行为
首次计算1500～1；前500根预热。1000～1，共1000根。显示并保存1000根；最早时间为第1000根的实际时间。
第二次，早于第1000根可返回的更早历史共有600根，包含首次仅预热、未返回的500根，以及此前尚未读取的最早100根。从第1600根这个真实历史起点初始化，计算1600～1001。1600～1001，共600根；不能再扣500根而只返回100根。把600根加在前方，累计1600根；不足1000根本身不触发额外探测请求。

第二次从真实历史起点递推，使用指标原有初始化规则；首次有限预热结果和这次结果按同一精度门槛与完整历史参考核对。两页公开日期互不重复；不能要求页面传递或保存第一次的预热数据来保证计算正确。

新股首次只有300根时返回实际300根；窗口不足的MA等结果保留合法NULL，不补零、不复制K线。首次无可返回数据时成功空结果且msg=""，不能提示已经向前加载到底。

5. 提前加载的触发与合并

  1. 首次成功后，保存返回K线、各指标值及实际最早日期时间，并显示最近的数据。
  2. 用户向左查看，当前视图进入已加载数据最早的500根所覆盖的区间时，如果没有同范围请求在执行、没有已到头记录，就发起一次向前请求。无需等到视图已经没有数据。
  3. 首次已加载1000根时，查看到第500根附近开始准备第1001～2000根；第二页合并后，下一次阈值随新的最早边界移动。不能每次范围变化都重复请求同一页。
  4. 响应成功后，按日期时间将新页放在已有数据之前，K线与所有相关指标保持对齐。页间日期应严格早于现有最早时间；返回日期越界、重复或必要字段缺失应报告合同错误，不能靠静默删除行掩盖问题。
  5. 追加前记录当前可见的时间范围，追加后继续显示同一段日期，避免插入旧数据导致画面跳到另一个位置。不能只保留插入前的数组下标。
提前500根是为下一页争取加载时间，不是对网络或用户任意滑动速度的无等待保证。若用户滑动快于加载速度，应显示历史加载中；本文件不新增后台计算任务或跨请求状态缓存。

前端提前发起下一次请求，与读取模块“不预读下一批”是两件事：每次进入内核后仍顺序读取、计算和释放，不能借页面提前加载改变8192根合批和资源归属规则。

6. 请求切换、失败、重试与到头

情况必须行为
同一页反复触发同一证券、周期、复权、参数、截止范围和before的请求未结束时，不再发相同请求。其他独立区域不因此被禁止请求。
切换股票、周期、复权、参数或截止范围取消旧请求，清空或切换到完全匹配的已有数据；用现有取消及请求身份检查拒绝旧响应覆盖新选择，不以“已经取消网络”代替响应有效性检查。
页面离开取消未完成请求，不再将其响应写回已离开的页面。后端按自身取消和清理合同处理，不能依赖前端直接释放后端资源。
历史页读取或计算失败、繁忙、到期保留已成功加载的数据，提示本次历史加载失败，允许重试相同before；不标记历史到头，不返回或合并半份指标结果。
向前请求成功且结果为空显示已经加载全部数据了，记录这一组选择已到起点，此后不再因滚动重复请求。
成功返回少于1000根但非空完整合并实际结果；不自动追加一个探测请求，不要求服务额外读取一根。之后用户正常触发向前请求时，仍按正常空结果规则处理。
同一显示组的复权基准或来源状态已经更新不得把不同价格尺度的数据直接接在一起。需要刷新时重新加载该组已显示数据，维持一致口径；识别来源更新的方法在后续正式API及页面LLD中使用其获批来源说明定义，本文不新增业务可选基准日期或虚构来源修订字段。

缓存若沿用现有实现，其识别条件必须包含所有影响结果的选择：证券、周期、复权、指标及完整参数、截止范围、分页位置和算法版本。参数默认补齐后的含义也必须一致；不能继续只按分钟周期就复用另一只股票或另一组参数的结果。具体代码组织在后续页面LLD确定，本轮不新建通用缓存组件。

7. 对本轮计算内核的外部约束

  • 每次返回数量是输出要求，不是计算输入上限。读取模块根据本次目标日期和动态预热需求，确定额外历史。
  • 同一页中的全部相关指标使用同一批已读取、按需复权的K线。预热需求取最大值，不相加，也不对每个指标重复读文件。
  • 只读最近一段历史不能改变复权基准。前复权仍采用来源既定最新基准，后复权仍采用来源既定基准；相同来源状态下同一日期的目标复权价格必须一致。
  • 所选输入不超过8192根时，读取完成后一次交给计算模块；超过时，除最后一批外每批满8192根。1500份日线文件不能触发1500次指标计算。
  • 返回的日期和字段必须完整；窗口不足导致的NULL保留。只有正常完成且没有可返回日期时可以成功空结果，来源、参数、计算、超限或清理失败不得转换为空成功。
  • 结果必须在本请求资源关闭后仍能独立访问。对外准确说明实际参数、算法版本及实际读取范围，不再把有限预热描述成每次从全部历史起点递推。
  • 未收盘K线按请求截止时刻参与计算；周、月线继续使用来源已经提供的目标复权数据，不读取后来发生的数据回算周中。
  • 本文不授予额外的前端、正式API、XXM、DG任务退出或并发阶段开发授权。第四批-修复开发完成后再校准原D4；后续接入单独推进。
