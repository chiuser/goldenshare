# 股票周线、月线算子库需求 v1

**2026-11-23｜股票日线读取修复及股票周月线算子库已验收，详情接入待开发。** 设计见[专项方案](technical-indicator-stock-period-plan-v1.md)和[专项 LLD](technical-indicator-stock-period-low-level-design-v1.md)。

## 1. 交付范围

算子库能按股票代码、周期和日期范围返回前复权周 K 或月 K，并返回按同一批 K 线计算的 MA、BOLL、MACD、KDJ 和九转。先完成并验收算子库，再接股票详情接口和页面。股票周、月线首期范围为这五类指标，趋势通道及其他独立图层另行安排。股票日线、分钟线、指数和现有数据生产沿用各自流程。

## 2. 行情和指标

1. 本地读取 DG 正式 Silver 的股票周线、月线，Prod 读取 PostgreSQL 的 `core_serving.stk_period_bar_adj` 对应周期。使用已发布的前复权开、高、低、收、成交量和成交额。
2. 用同一批周 K 或月 K 计算指标并返回行情。运行时直接使用成品价格，按现有算子库单位换算量额。
3. 算子库提供返回 **500 根**和 **100 根**两套配置，预热精度独立设置。股票周线首批和向前翻页都选择 100 根，以及 MACD、KDJ 初值误差上限 **0.00001**。首期指标为 MA(5、10、20、30、60、90、250)、BOLL(20、2)、MACD(12、26、9)、KDJ(9、3、3) 和九转。在上述精度和首期指标参数下，在本页第一根之前最多共用 **359 根周 K**，九转需要的 16 根包含在其中。到达历史起点时从起点算，MA250 等仍按现有规则处理历史不足。[配置细节](technical-indicator-stock-period-low-level-design-v1.md#stock-period-calculation-options)
4. 股票月线使用同一组首期指标，从本环境最早可用月 K 开始计算，一次返回全部可用月 K，额外预热 0 根，共享算子库的输出与资源上限照常适用。现有调用省略新选项时沿用现有返回和预热规则。
5. 九转使用同周期前复权收盘价。股票周、月线的 `/kline` 随行情返回九转标记，图上沿用现有开关和 1–9 标记样式，无标记时返回空数组。周线首批和续页都使用该批结果，月线一次返回。

## 3. 日期和历史起点

- 一周、一月各最多一根 K 线。历史 K 线日期直接使用成品 `trade_date`，首屏最新一根显示按个股应更新日和当期成品覆盖情况确认的交易日。行情、指标、九转标记、横轴和提示框对应同一根 K 线。
- 股票周线展示、翻页和预热在 DG 和 Prod 共用 **2014-01-02** 的历史起点，包含这一周已有的 **2014-01-03 周 K 成品**。首周按成品整根使用。新股首个有成品的周期照常保留。月线按各端正式成品覆盖范围返回。
- 整个股票详情页以 `pageContext.tradeDate` 作为行情日期锚。北京时间交易日 20:00 前以此前最近开市日为准，20:00 起以当天为准。后端从该锚点统一推导目标周期和个股应更新日，结合上市、退市和已确认的全日停牌。
- 读取该股目标周期成品的 `end_date` 判断更新日期。应有行情却缺当期成品，或 `end_date` 早于该股应更新日时，保留可用行情和指标，并在图表旁标出应到日期与当前显示范围。历史翻页沿用该页的周期边界。

## 4. 通过条件

先完成[独立的股票日线读取修复](technical-indicator-stock-period-low-level-design-v1.md#stock-daily-read-repair)，核对现有功能和校验行为。算子库轮次用同一标的和截止日验证 500 根、100 根两套配置及预热精度独立生效。DG 和 Prod 分别以平安银行核对前复权四价、量额、日期、首批 100 根周 K、向前一批、最早一批及全部可用月 K，以同源完整周月线独立计算对照指标和九转计数。沿用算子库现有 6 秒工作时限、8 秒总时限。后续独立验收股票详情的接口和页面，核对周月切换、左拖、九转开关和日期对齐，以及行情日期锚共享、20:00 前后、节假日、全日停牌、当期缺记录、`end_date` 缺失或较早、数据到齐和历史回刷的表现。
