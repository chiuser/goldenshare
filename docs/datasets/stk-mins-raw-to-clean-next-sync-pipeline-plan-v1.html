stk_mins raw -> clean_next pipeline

股票分钟线 raw 同步后自动刷新 clean_next 方案 v1

目标是打通一条可靠链路：从 Tushare 拉取 `stk_mins` 写入 raw 后， 立刻基于本次受影响的 raw 分区生成并审计 `clean_next`，让后续 90/120 分钟线、 by-month research 和技术指标始终以最新 clean 基准继续工作。

1. 用人话说，这条链路要解决什么

现在 raw 和 clean_next 是两层数据。raw 负责保存源站原始事实，clean_next 负责保存可以直接用于研究和派生的干净数据。 如果每天只更新 raw，不更新 clean_next，那么后面的 90/120、by-month research、MACD 就会读到旧 clean。

这条链路要做到：每次 `stk_mins` 同步 raw 成功后，系统自动拿本次影响到的 `freq + trade_date` 分区，从 raw 重新生成 clean_next，并通过审计后发布。
这里的“同时更新”不是数据库事务里的同时提交。更准确地说，是一个严格串联的安全流程： raw 先成功落盘，clean_next 再基于 raw 审计后发布。clean_next 失败不能回滚 raw，也不能假装整体成功。

3. 关键原则

raw 不承担清洗

raw 只保存源站事实。源站返回什么字段，raw 就按源站事实保存，不能在 raw 层删除、改代码、补派生字段。

clean_next 只能从 raw 来

clean_next 不直接吃接口返回行，不从旧 clean 来，也不从 derived/research 反推。它只读受影响 raw 分区。

审计通过才发布

clean_next 候选分区必须先通过 scoped audit。失败时保留旧 clean_next，写问题账本，阻断下游。

4. 数据层职责

层 路径 职责 禁止事项
raw raw_tushare/stk_mins_by_date 保存 Tushare 源站分钟线事实，按 freq + trade_date 分区。 禁止做身份归一、退市过滤、技术指标计算。
clean_next research/stk_mins_by_date_clean_next 保存清洗后的研究事实：最新代码、剔除退市股、剔除上市日前数据、保留 exchange/vwap。 禁止新增 trade_date/identity_id/source_ts_code 物理列。
quality ledger manifest/stk_mins_quality 记录 scoped audit 的问题分区、原因码、样本、建议修复命令。 禁止用口头说明替代账本；失败原因必须可复查。
downstream derived / research by-month / indicators 只在 clean_next 通过后继续生成。 禁止绕过 clean_next 直接读 raw 做研究链路。

5. 写入顺序与失败语义

场景 raw 状态 clean_next 状态 系统应该怎么说人话
Tushare 拉取失败 不变 不变 “源站拉取失败，没有写入任何正式数据。”
raw stage 校验失败 不变 不变 “源数据候选文件不合格，正式分区未替换。”
raw 发布成功，clean 审计成功 已更新 已更新 “raw 和 clean_next 已同步推进，下游可以继续。”
raw 发布成功，clean 审计失败 已更新 保持旧分区 “raw 已更新，但 clean_next 未发布；请先处理账本问题，再生成下游。”
clean 发布失败 已更新 保持旧分区或进入待人工确认 “raw 已更新，clean_next 发布失败；不要重建 derived/research/indicator。”
绝对不要因为 clean_next 审计失败去回滚 raw。raw 是源站事实，回滚 raw 会把已经成功同步的源数据也打回去，风险比 clean 延迟更大。

6. scoped audit 要检查什么

结构门禁

  • Parquet 物理列必须是 ts_code,freq,trade_time,open,close,high,low,vol,amount,exchange,vwap。
  • 禁止出现 trade_date、identity_id、source_ts_code。
  • freq 只能是 1/5/15/30/60。

内容门禁

  • 同一 ts_code + freq + trade_time 不允许重复且值冲突。
  • 不能有退市股票。
  • 不能有上市日前数据。
  • 不能有结构性非法价格，例如 high < low。
  • 不能有负成交量或负成交额。

完备性门禁

  • 按交易日和频率检查日内 bar 数。
  • 允许正常盘后交易导致的 bar 数增加。
  • 缺 bar、异常多 bar 必须进入问题账本。

下游准入门禁

  • affected partition 的 clean_next 没通过，不能生成对应 derived。
  • clean_next 或 derived 没通过，不能重排 by-month。
  • by-month 没重排，不能继续计算指标。

7. 受影响分区怎么算

每次同步结束后，必须产出明确的 affected partitions。它是后续 clean_next 刷新的唯一输入。 

affected_partitions = [
  { dataset_key: "stk_mins", freq: 1, trade_date: "2026-05-13" },
  { dataset_key: "stk_mins", freq: 5, trade_date: "2026-05-13" }
]
同步方式 affected partitions clean_next 处理
单日全市场 本次同步的所有 freq + trade_date 逐个从 raw 完整重建 clean_next 分区。
区间全市场 区间内所有交易日与频率组合 按分区逐个重建，失败分区进入账本，不影响已通过分区。
单股票补数 该股票写入过的 freq + trade_date 仍按完整分区从 raw 重建 clean_next，不能只把一只股票行直接 patch 进 clean_next。

8. 推荐命令与模块拆分

第一版不要把逻辑散在同步命令里。先沉淀一个可以独立验证的 clean_next 刷新入口，再接入 `sync-stk-mins-range` 主链。

能力 建议入口 说明
从 raw 分区刷新 clean_next refresh-stk-mins-clean-next 输入 affected partitions，支持 --dry-run 和 --apply。
同步后自动刷新 clean_next sync-stk-mins-range raw 发布成功后自动调用 clean_next 刷新服务；最终口径应默认执行，不作为长期可选兼容分支。
查看未通过分区 list-stk-mins-clean-next-issues 显示问题分区、原因、样本和推荐修复命令。
独立命令不是临时方案。它是 repair / audit 工具，方便在 raw 已经更新但 clean_next 未通过时，针对问题分区重跑。

9. 实施里程碑

阶段 目标 验收
M1 抽出 affected partitions 模型和 sync run 输出。 同步命令能明确输出本次影响的 freq + trade_date 清单。
M2 实现独立 clean_next refresh 服务。 给定一个 raw 分区，能 dry-run 出写入行数、过滤原因、审计结果。
M3 实现 scoped audit 与问题账本。 构造缺 bar、重复 key、非法价格样本时，clean_next 不发布并写账本。
M4 接入 `sync-stk-mins-range` 主链。 同步小窗口后 raw 与 clean_next 同步推进；失败分支有清楚输出。
M5 接入下游准入保护。 clean_next 未通过的 affected partitions 不允许进入 derived / by-month / indicators。

10. 已拍板结论

  1. 同步命令最终默认强制刷新 clean_next，不留长期跳过分支。
  2. clean_next scoped audit 将完整性问题全部视为阻断，进入问题账本后人工审计修复。
  3. 单股票补数后不允许只 patch clean_next 单股票，必须按 affected partition 从 raw 重建。
  4. 下游 derived/by-month/indicator 必须读取 clean_next 通过状态，否则链路仍可能吃到旧 clean。
