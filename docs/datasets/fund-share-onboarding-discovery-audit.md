## 结论

`fund_share` 是按交易（变动）日期返回基金份额的时序接口。单日全市场样本为 1,652 行，按 SH/SZ/O 为 938/707/7 行；其中 O 不是可忽略异常，而是必须保存的场外结果。`limit=1000` 的两页为 1,000/652、无主键重叠，故单日分页已经验证。

当前安全结论是：可研究“按日期点拉取全市场”的路径，**不能把长区间或单代码全历史当成不截断数据**。是否能做连续交易日完整性审计也尚未证明。

## 源端事实与实测

| 项目 | 已核验事实 | 接入含义 |
| --- | --- | --- |
| 参数 | `ts_code`、`trade_date`、`start_date/end_date`、`market` | 日期输入可候选 point/range；对象过滤不代表可拉全历史。 |
| 无业务参数 | 2,000 行，日期跨 2026-07-31 至 2026-08-10 | 已触顶，不能用作全量基准。 |
| 单日全市场 | `trade_date=20260617` 为 1,652 行 | 单日未触顶样本；需要更多峰值日验证。 |
| 单代码 | `510300.SH` 返回 2,000 行、从 2018 起 | 明确有截断风险。 |
| 区间 | 同代码 2026-06-16..17 返回 2 行 | 短区间语义有效，不能外推到长区间。 |
| 字段差异 | 文档列 3 字段；显式请求 6 字段返回 `total_share`,`fund_type`,`market` | 6 字段均为必须保存的 source contract，源文档已校准。 |
| 分页 | `limit=1000, offset=0/1000` 返回 1,000/652、无重叠 | 单日使用 `offset_limit`；不得以 2,000 单页上限代替总量。 |

已确认、后续 Definition 必须原样使用的 `source_fields`：

```text
ts_code, trade_date, fd_share, total_share, fund_type, market
```

`(ts_code, trade_date)` 在单日分页样本中无重复；`total_share`、`fund_type`、`market` 必须显式请求和保存，不能因本地文档遗漏而丢弃。

## 建议的接入轮廓（非 LLD）

| 层次 | 当前建议 |
| --- | --- |
| 时间 / unit | 只在峰值验证通过后采用一个交易日全市场 unit；范围由 resolver 按日展开，而非宽区间请求。 |
| freshness / audit | 暂定 `not_applicable`：份额“变动日期”不等于所有基金每天必须有值；是否转为交易日 audit 要用覆盖率证明。 |
| 范围 | 不传市场过滤，保存 SH/SZ/O 的全部源端结果；O 是硬要求。 |
| 分页 | 每个交易日 `offset_limit`；不得隐藏 2,000 行截断。 |
| Ops/UI / 存储 | “公募基金”目录；手动 + 普通定时自动任务、无 probe；全字段和全部物理分区/索引落 HDD。 |

## LLD 前仍需验证或决定

1. “规模”是否要求每日连续覆盖。若要求，须先定义基金池及上市/终止生命周期，否则日期/对象完整性会产生假缺口。
2. 历史回补可逐交易日分页；单代码整段历史仍不应作为完整路径。
3. LLD 需固定 direct-serving、HDD 分区和普通定时频率，并确保自动化不暴露 probe。

## 已冻结的事实身份与修订原则（非 LLD）

1. 日度规模事实的逻辑身份采用 `(ts_code, trade_date)`；`market`、`fund_type`、`fd_share`、`total_share` 都是必须保真的源字段。LLD 必须在全市场多日样本中验证该键唯一；若发现冲突，不能静默覆盖，必须先升级身份键。
2. 维护最新事实；同一逻辑身份的源字段内容变化时保留观察版本、内容散列和首次/最后一次观察时间。这样既可服务最新规模，也可追踪接入后源端修订。
3. 市场范围固定为 SH/SZ/O；O 是源端返回事实，不得被 ETF 池或前端筛选省略。
