## 0. 当前方法与第一步：先把日线波段和极值记录清楚

**先根据已知行情整理上升/下降区间、价格高低点、DIF各峰谷、红绿柱及各自数值和发生时间，再按判别规则选择比较对象、更新状态和标记钝化/结构/消失。**原软件视频用于核对结果和纠正方法，不能先把图上的参照或标签交给程序，再把后续吻合称为程序独立推导。历史记录不能只留下已选中的峰谷，较远的峰谷和内部回调也保留，后续由规则决定是否参与比较。

**当前先研究000001.SH日线，先核对波段和极值，再核对标签。**管理员将依据输出图和逐段记录纠偏。沿用同一套已有连续DIF，不以任意10根/130根截取决定算法能看哪些参照，也不另选起点重算MACD；实际需要多少前段由能否自行重建所需记录和状态检验。将来执行前另列具体来源和读取范围，本轮不读行情或扫描全历史。

### 0.1 已确认的方向与边界

| 对象 | 本轮明确要求 |
|---|---|
| 上升/下降周期 | 依据DIF峰谷划分，并核对价格走势：上升时各次高点和低点逐步抬高，下降时各次高点和低点逐步降低。这里比较的是各次波动形成的高低点，不要求每根收盘都同向 |
| 价格边界 | 每个价格波段以其极大、极小**收盘价**所在K线为边界，包含两端K线；不用盘中high/low替代。相邻两段共享一个转折位置时，两段均包含并引用同一根K线，不复制原行情。相同极值的全部位置保留；作者最终采用哪根尚未确定，首轮按§0.4/LLD§14明示的最早位置作试验，不冒称已核实规则 |
| DIF与柱 | 每段记录DIF峰谷、最长红柱、最长绿柱及对应K线；DIF极值、价格极值、最长柱分别保存，不要求同一天。全部DIF局部峰谷保留，不只保留每段最大/最小值 |
| 时间 | 每个点保留日期、K线级别和对应收盘时点；本步级别为日线。发生位置与后来可以确认的位置分开，走到某天只能使用当时已知信息 |
| 价格与柱色不同步 | 价格已下跌仍可能红柱，价格已上涨仍可能绿柱；不强行让价格边界等于换色日，也不因没有换色就删掉价格回调 |
| 首轮颗粒度假设 | 连续同色柱期间先不拆成多个同级周期，保留内部价格回调及全部DIF峰谷；换色后先保留独立柱色记录，不自动认定较大周期结束。按§0.4/LLD§14验证，最终规则仍须看结果 |

价格波段的极值记录与此前“DIF峰/平台起至首反色前”的参照取价窗口用途不同：前者按本节新方向研究，后者作为原已采用规则保留。后续若证据要求改变参照取价或首次色段资格，须明确修改对应条款，不能因增加价格波段记录就无声替换已定钝化公式。两位DIF用于结构转折的决定，也不自动变成筛选波段的门槛。

### 0.2 建议先同时记录、再看图选择

以下组织方向已由§0.4/LLD§14具体化为首轮测试约定，仍不声称徐小明软件内部采用此法：

1. 先分别标出原始DIF峰谷、收盘价局部高低点及连续红/绿柱区间，全部保留；真实零柱另记，不当红柱或绿柱。
2. 先用连续同色柱决定本轮哪些小波动放在一起，关联其中及相邻的全部DIF峰谷，再核对价格高低点是否同向抬高/降低；不把每个DIF小峰直接变成独立周期，也不强制指标与价格边界同日或设相差天数门槛。
3. 同时保留较大的上升/下降区间及其中的回调/反弹。例如收盘100→110→105→120→112→130，大区间可作为上升候选，内部110→105和120→112的回调仍在。最终哪些点划为同一级别，先看图纠偏，不把所有小转折自动当成同级周期。
4. 每个价格候选区间列出涉及的完整红绿柱区间、其中所有DIF峰谷及各极值。既记录价格区间内部的柱极值，也保留完整柱色区间自身的极值，避免截短一段柱后丢失原峰。

### 0.3 先交付什么、还要看什么

第一份研究结果应是能让管理员直接检查的日线图和逐段表：收盘价连出的候选区间、DIF全部峰谷、柱色区间及极值都标明日期；表中列清方向依据、两端是否包含、对应数值和哪些尚未确认。管理员纠偏时，在当前页面/对话中按计算编号和波段编号核对原计算及意见，再将已核对的方法用于原软件标签匹配；试验计算结果不自动写文件。不能只给最终标签，掩盖波段/参照选择过程。

作者最终如何处理较大周期、错位、相等和短暂反色仍须具体图例核对；首轮先按LLD§14的明确测试约定生成结果，不等待这些假设全部证明后才开始设计。尚未结束的尾段持续更新，不宣布已知最终高低点。详细记录见[LLD§0](../../wealth/docs/pages/index-detail/index-detail-xxm-next-implementation-low-level-design-v0.6.md#xxm-daily-method-design)，本轮可编程测试细节见下节。

### 0.4 近三年日线测试方案

对象为上证000001.SH日线。请求范围为**2023-10-24至2026-10-21**，含两端；10月21日是上限，不是必须补齐的末日。以本次实际取得的连续行情首末日作为观察范围，显示实际日期和根数；若只到10月16日，就先算到16日，不因缺21日或23日后的尾部而阻止试验。实际范围中间缺应有开市日时指出具体日期，不用删行或补值假装连续；最左波段起点未知另记，不能与中间缺交易日混为一谈。

实际观察起日前，先取最近250个开市日建立记录；首个关联前段仍不完整时再补250个，最多500个、绝对下界2021-10-01。主范围最多800根，含前段合计最多1300根。前段不是EMA重算起点；同一套源DIF直接使用。与实际观察范围相交的色段及关联价格候选保留完整记录，范围前的真实起始K线不挪到左边界。前段仍不足时如实标未知，不无限扩展读取。

试验三步保持：

1. **基础记录。**分别计算连续同色柱、收盘局部高低点、原始DIF全部峰谷及各自日期；真实零柱中性，内部回调不丢。
2. **价格候选。**按管理员本轮确认的方法先做：红柱从前一完整绿柱首日至首根红柱之间取最低收盘，再从该低点至本红柱目前末日取最高收盘；绿柱镜像。每个色段最多一个同级候选，包含两端，相等极值保留全部日期、主图取最早。即使出现100→110→95→120这样的冲突，也不另换算法或移起点；保留原取法、95及问题，供管理员看图纠偏。具体字段和绘图约定见LLD§14.5/14.6.1。
3. **原软件对照。**管理员核对候选后，再用已有日线截图/讲稿说明相容、冲突和未知。软件答案不进入前两步计算，不把试验候选当完整钝化/结构识别结果。

红→短绿→红先保留三段及中间绿柱根数/长度，不默认合并或忽略。尚未换色的尾段只表示截至当日的结果，不能预知未来终止K线。

**本轮试验结果全部在内存。**不新建reports、CSV/JSON/SVG/HTML结果文件，不写磁盘缓存、季度文件、完成清单、恢复检查点或纠偏文件；不做导出和自动留档。计算中断/出错即丢弃本次未完成结果，下次重新读取并从头算。页面开启或重试时由后端有界读取并调用同一个计算函数，成功后返回；不再依赖提前保存结果、人工登记或文件路径配置。页面本次结果只留内存，关闭/离开后释放，拖动/缩放不重算。

原有历史研究文件和首批1、2、9的冻结资料保持原样，不删除；本节新决定仅替换当前日线试验的落盘方案。它也不自动改变首批原有保存政策，首批恢复时单独复核。已有旧快照止于10月13/16日是历史资料范围，不据此推定数据库最新范围。此前设计轮仅完善Figma与文稿；当前第一批范围以§0.6为准。

第二步的函数和独立例验收后，再接[§13](#xxm-daily-wave-page-plan)页面供核对，不要求先证明作者完整算法。方案和LLD的试验规则仍可被后续材料推翻，文档完善不等于方法已验证。

## 2. 已采用的算法规则

本节是下一阶段采用的工作规则。课程、截图和管理员决定提供的依据不同；采用决定不等于已经验证全部现代软件案例。相关演进及出处保留在研究记录第3—8类，前期明确决定可追溯至[原方案§12.94.12—13](xxm-direction-algorithm-plan-v0.1.md#xxm-fixed-reference-decision)。2026-10-23本轮批注明确采用连续反色段计数、A/B最多一段、平台第一根起价及零柱中性；旧历史固定与本次搜索范围分别说明，不把未理解的建议冒充已确认。

### 2.1 输入、完成时间与两位DIF

1. 新旧方法读取同一套连续计算好的收盘价、DIF、DEA、MACD柱及相同前段。MACD为12/26/9，柱值为2×(DIF−DEA)。不截窗重新启动EMA，不按截图修改某一方DIF，不把旧参照或旧状态直接交给新方法。
2. 只处理已经完成的K线。“周期结束”指这一根K线结束，不指一波行情结束。60分钟端点为10:30、11:30、14:00、15:00；90分钟为11:00、14:00、15:00；120分钟为11:30、15:00。分钟保留上海时区；日线按交易日收盘完成。
3. 两位取数从绝对值首个非零数字起截取两位，再恢复符号及小数位置。例如40.057取40、−8.086取−8.0、0.008086取0.0080。不是四舍五入，不等于固定1%。原始DIF、DEA和柱色不因此改变。
4. 结构转折比较相邻两根完成K线的两位DIF；两位相等不算转折。首次背离资格比较当前同色阶段的DIF极值与旧峰，不能暗中改成本根DIF。

### 2.2 首次比较的阶段、峰和价格

首次顶部必须满足“旧红柱阶段〔A、B〕→绿柱→当前红柱阶段〔C〕”；底部镜像。中间一根反色柱足以分隔，当前同色柱至少两根。真实零柱按本轮同意的中性方式处理：不充红/绿或反色，不结束阶段，不增加红绿根数。正0正仍是一阶段、有两根实际正柱；正0负到负根才换色，新负柱计一根。零根收盘仍属于首反色前的旧价窗口；开头零不借未来颜色补身份，当根零不首次建钝化。已有钝化/结构仍核原参照和两位DIF，零本身不使其形成或消失。

同一当前连续同色阶段内的小峰，不参与该阶段自身的首次钝化比较。价格101变102也不进入这种比较。局部峰仍保存，供未来反色之后的新阶段使用。旧阶段A、B即使没有反色相隔，也分别保留，供C先比较B、再比较A。这两件事不能混写成“同色只能有一个峰”。

指标用DIF峰谷，不用红绿柱最长位置替代。不同原始DIF局部峰分别保存，不合并、不加小起伏门槛、不因为两位值相同而删峰。原始值完全相等的平台保存一个峰区间；峰发生位置与后续确认时间分开，只有当时已确认的历史峰可参与比较。

旧峰价格从DIF峰区间第一根起到首次反色柱之前，顶部取最高收盘价、底部取最低收盘价；平台包含全部相等峰根，单根按区间长度一使用同一取价方法。DIF与价格极值分别记录，不能拿DIF最大那根的收盘替代整个价格区间。反色柱排除，旧区间结束后不再扩大。不同峰可以共用终点或得到相同价格，仍不合并。本轮对平台第一根的同意及“高点出现后比较到反色”的说明按上述统一方式记录，不把单独选中文字当一条额外批准。

已经结束的旧区间，原始DIF、收盘及选定窗口的极值均固定，后续只更新最新完成K线和当前阶段截至此根的极值。区间结束前若出现更高DIF或收盘，记录当时的新数据；不改写旧K线数值，也不因此删除此前已发生的不同局部峰。原始峰的发生位置和后根确认时间只是程序避免提前使用未知数据的记录，不添加额外等待根数；历史参照用于当前阶段时已经有反色分隔。

### 2.3 首次选峰与钝化成立

在允许范围内由近到远逐峰检查，首个全部成立即采用；近峰失败继续更远的允许旧峰。不只取前两个，不先删除价格失败者再重排近峰和隔峰，不在全池中另选DIF最高者。

两个旧峰A、B之间最多0或1段反色柱，约束的是A和B之间；不能改成当前C到远峰A的总间隔上限。按连续反色段计数，其内部多个局部谷不增加段数，这是本轮已同意的规则。同一连续同色阶段内的第三、第四个峰之间没有反色；不同旧同色阶段之间有一段反色时也不因序号大于2而直接排除。整次查找用哪个B划范围及停止、是否在后续日期更新查找边界，仍需与“旧数据不变”分开说明；不能从旧数值固定直接推导所有日期永远用同一个B。

| 判断 | 顶部 | 底部 |
|---|---|---|
| 首次价格资格 | 最新完成根收盘严格高于旧峰对应最高收盘 | 最新完成根收盘严格低于旧谷对应最低收盘 |
| 首次DIF资格 | 当前同色阶段两位DIF最高值严格低于旧峰两位DIF | 当前同色阶段两位DIF最低值严格高于旧谷两位DIF |
| 首次DIF相等 | 这一参照不成立，继续检查下一个允许旧峰 | 同左 |

成立时保存首次参照、阶段与反色分隔、价格区间、DIF极值、首次时点和比较依据。现r2另有首次顶部当根DIF>0条件；完整新方法是否保留尚未决定，不从旧代码自动继承，也不因重写遗漏已经确认的首次顶部修正案例。

### 2.4 已有钝化的保持、形成和消失

**同一轮固定首次成立时的原参照。**不每根重选，不用近峰给远峰钝化判断消失，也不在原参照失效后换更远峰来伪装本轮一直有效。新峰加入或原候选从列表移除，不改变已经保存的原参照；恢复缺少原记录必须拒绝，不能另选补齐。

已有顶部钝化时，两位DIF与固定原峰相等仍保持，严格高于原峰才因DIF突破消失；底部严格低于才消失。例如26.92、26.93同取26，不因原值突破取消；到27才越过。首次相等不成立与已有相等保持是不同条件。

钝化成立后，价格回落到旧峰收盘之下，本身不取消钝化，也不自动形成结构。有效钝化下，两位DIF相对上一完成根顶部向下、底部向上转折，按本根完成值确认结构；不必等DIF穿DEA或再等一次换色。钝化不是必然会形成结构。

若本根首次钝化资格与结构转折同时成立，先记钝化，再记结构，两事件同一完成时间、同一原参照，最终为结构。没有有效钝化不能只凭DIF拐头形成；换色不独立或重复补发结构。只改变确认方式的旧行为对照保留“进入本根前已有钝化”的限制，仅用于隔离差异，不能带入完整方法。

### 2.5 结构纠错、再次钝化及历史

课程给出换色前DIF转回需纠错、换色后最高或最低收盘价突破需纠错。背离仍在不等于原结构仍有效，纠错也不必然等于钝化消失；完整取价区间和各分支顺序尚需第4节补齐。

已有7/10—7/13底部材料必须保留：结构消失当时没有新钝化，后来最新根价格重新达到条件才重出。不能仅因原DIF背离仍在，或过去累计价格曾突破，就自动回到钝化。等待原参照可用与当前已有钝化分别保存，不能用普通状态NONE绕过等待条件。

新一轮同方向信号接续后，关注新一轮形成或消失，旧结构停止继续判断，但已发生历史保留。停止旧跟踪本身不补绿色字，不设置统一24根或26根到期。当前状态、曾形成的结构、历史是否仍跟踪、图中文字可见性分别处理。第10.1节已局部验证底部钝化同根结束/另起及显示候选；其余结构纠错组合未定，不凭镜像把底部单例推广成所有方向已证实。

本轮批注明确：在已讨论的顶部例中，原峰26、20→19形成结构、今天19→27且未换色，今天达到纠错并突破原参照，就在今天纠错、结束旧轮，随后允许用今天完成的K线开始新一轮判断，不额外等明天或再等反色。若最新收盘、允许旧峰、当前段DIF极值及阶段根数未满足新钝化条件，则没有新黄色；纠错不自动等于新钝化。该决定不一概覆盖尚未突破原峰的结构纠错保持/等待分支，7/10纠错当时无新黄的反例继续保留。

## 12. 首批方案：第1、2项及第9项必要集成

### 12.1 目标、范围及明确保留项

管理员已同意此范围；本轮只整理设计，不编码、不运行新算法测试或行情核验。首批实现只替换当前产品的结构形成/未换色纠错判据、取消独立换色确认，并同步已有预测与消费者。必要配套含不同条件分别精确求解及合法整数展示，按本轮确认的§12.5执行；这不改变实际标签的精确判断。对象/周期、来源和现有页面布局不变，不新增用户/运营开关，不保留两套在线算法。

首批不替换DIF峰池、整个色段取价、累计当前价/最近旧段价门槛、最强合格、原值突破、活动底钝化救援、首次顶部DIF>0、零柱切段、历史价格边界及等待去向；任务3—8明确暂缓。首批仍须进入本根前已有DULL才确认结构，首次activation和reactivation当根仅DULL，不提前引入任务4。新结构触发较早可使后续历史和参照实际不同，报告应追溯首次差异，不能误要求整段结果都与r2相同。

两位值仅用于本批的相邻转折，不用于首次背离资格、取消或历史原参照突破。真实零柱沿现行为结束原柱段，本批不形成；前根DIF为0则正常取Q(0)=0并严格比较，不继续保留旧`basis!=0`转折屏蔽。例：已有底钝化0→0.01可满足上转，原值突破和阶段条件仍先检查。完整工作规则§2与首批保留项不一致的地方，均由本节明确标明暂缓，不能混报为完整规则已实现。

### 12.2 处理和配套决定

形成只依相邻两位DIF转向。原值突破/既有救援的优先级保持；相等不转折。换色时，只有进入本根前有效DULL、原参照未被原值突破且两位DIF转折成立才形成，route统一`dif_turn`；否则不因换色形成或补画紫字。换色仍按现规则结束旧普通柱段并更新历史，不能把“未形成”强记成技术消失。详细输入、顺序和逐项预期只维护在LLD§13.2。

新识别版本固定`xxm-direction-v0.1-r3`，新预测版本固定`xxm-key-point-forecast-v0.3-r3`，仅表示首批，不表示完整逐峰方法。规则身份由完整Spec计算，前端从同一Spec生成固定值并断言，不手工猜hash。旧缓存/快照与新版本互拒，从现来源前段重新计算，不迁移r2活动状态。r2仅作为隔离离线对照，不添加产品兼容入口。

预测同时替换目标条件、中间不得提前形成的条件、候选分界、整段交集、下一根结果及展示样例校验中的1%公式；不允许只让末端调用新识别器兜底。采用两位DIF分段求解，复用现条件表达式，不增加前端计算公式或新增预测能力。所有形成route只允许`dif_turn`，该字段只表示原因类别，不是结果名称或唯一编号；向上/向下、目标柱色和每组结果必须分别保存，编号见LLD§13.3.1。新增下一根结果`SEGMENT_ENDED`表示“换色结束原柱段、没有形成结构”，不等于绿色消失事件；相关后端schema、前端校验及说明同步。其余字段、原值取消和救援结果保持；公式和完整切分见LLD§13.3。

### 12.5 五项审计的已确认结论

以下1—5指上方再次审计报告中的五个问题，不是§11的任务编号；首批开发范围仍只含任务1、2、9。第1—3点已按管理员后续确认补齐，第4—5点保留此前已确认要求。本轮只落实设计及静态审计，不制作/执行测试输入、不测性能、不改变运行配置。原审计报告保留当时记录，当前执行要求以本节及LLD§13为准。

**1．分别算全条件，再整理用户看到的结论。**价格区间只在真实判断发生变化的位置切分，例如价格突破原参照、DIF达到原峰、柱色变化、两位DIF转折阈值；不按每1点随意分组，也不是新增作者规则。每段和关键边界分别精确求解，保存对应的全部条件；不能只因参照相同便合并后拿一个中点决定整段。现r2有些中点仅用于选公式，公式仍随价格变化，不能把它们全部说成已证实的错误；首批须逐处审计其适用范围，确有错误时修正。完整实现要求见[LLD§13.3.2](../../wealth/docs/pages/index-detail/index-detail-xxm-next-implementation-low-level-design-v0.6.md#xxm-first-batch-price-conditions)。

用户只需知道某时点钝化/结构能否形成、收盘满足什么条件。同一方向、同一时点的钝化可行范围可在求并集后简化说明；不同的后续结构条件及其参照、适用范围必须在内部和原结构化结果中保留。例“超过4000且低于4020”直接说明该范围，不展示无意义的小分组。未满足首次钝化不等于已有钝化消失；已有状态继续按该批的参照/取消/结构分支计算，不用首次条件的补集代替消失条件。首批旧救援政策仍保留，不借此提前实施任务7。

**2．结果必须能够区分并说清保存位置。**采用管理员提出的日期、周期和收盘时点，并将时点统一到四位时分：`260515_60_1500`是K线位置，不是全部结果共用的唯一编号。实际形成记录须能明确DIF向上/向下、顶部/底部结构；预测同一目标根的同色/反色及不同价格条件分别编号，不互相覆盖。原`dif_turn`仅作为原因类别保留。使用已有事件id、relationId、方向、发生时间及条件表达式传递，不新增API根字段，不在前端推算方向或重新编号。完整格式、稳定性及关联规则以[LLD§13.3.1](../../wealth/docs/pages/index-detail/index-detail-xxm-next-implementation-low-level-design-v0.6.md#xxm-first-batch-result-ids)为准。

**保存位置明确。**现产品的计算中间结果、事件和预测响应缓存在服务进程内存；通过API返回，进程结束/缓存淘汰后按来源重新计算。首批沿用该方式，不新增写库或写盘服务。离线测试才将输入身份、独立观察和对照结果写入本次reports的新目录。冻结研究材料是另存的文件，不等于线上有事件落盘。审计第2点所说的是迁移时内存关联可能覆盖/连错的风险，不是已发现磁盘写入错误。

**3．内部精确，对外取合法整数。**精确条件若为收盘价＞4135.78，对外给“达到4136点及以上”；若为4000＜收盘价＜4020，对外给“4001—4019点”；若为收盘价＞4136，必须给“4137点及以上”，不能让不合法的等号混入。先按完整条件求得合法范围，再分别取最小/最大合法整数；不加小数避让量，不颠倒上下界，不把不相连的范围连成一个区间。整数只是用户参考，真实收盘4135.90仍按＞4135.78判断标签。允许至多1个指数点的展示收缩，不是内部±1点容差，更不是接受MACD来源或判别错误。

范围内无合法整数时保留精确计算结果，明确说明没有可用整数参考，不硬取非法整数，也不把显示限制当作算法无解或改选更晚时点。真实行情、DIF/DEA/柱、实际事件价格及固定持平假设不取整。原2/4位展示回退按此要求替换，Spec、后端schema和前端校验同次同步；字段及处理细节见[LLD§13.3.3](../../wealth/docs/pages/index-detail/index-detail-xxm-next-implementation-low-level-design-v0.6.md#xxm-first-batch-integer-display)。重要研究仍是软件与来源MACD差异及算法差异，不围绕无意义小数继续扩大课题。

**4．测试之前先配好每案材料。**首批清单用于开发前确认材料足够、开发后做新旧算法与软件对照、以后回归。每案必须把“原图/讲稿的独立答案、实际行情文件及身份、计算起点和检查范围、来源精度、能证明什么”配成一组；不能用旧程序输出造答案，不能把局部摘录当完整历史。具体字段、四组材料缺口及拒绝条件见[LLD§13.5.1](../../wealth/docs/pages/index-detail/index-detail-xxm-next-implementation-low-level-design-v0.6.md#xxm-first-batch-test-inputs)。本轮只写要求，清单未制作，不声称已齐备。

**5．200ms是当前工程上限，不是作者算法规则。**先估实际DIF值域内的分界、条件组数、重复计算和响应大小，再以固定输入分别测完整求解、真实API、缓存及两请求并发。离线受控计时可在独立测试进程给完整求解更长的单次上限，以了解超过200ms后的真实成本；这不是调高产品预算，也不记作产品通过。测试组数、重复次数、统计和停止条件见[LLD§13.5.2](../../wealth/docs/pages/index-detail/index-detail-xxm-next-implementation-low-level-design-v0.6.md#xxm-first-batch-cost-acceptance)。若正确且消除重复计算后仍超200ms，提交实测和具体新上限建议；经确认同步方案、唯一配置、身份及验收要求之前，运行配置保持不变。禁止删掉合法条件或靠大量正常请求报超时来冒充达标。

### 13.2 用户看到的标记和交互

- **上升区间：**起点与终点对应K线下方各一个红色实心上三角，使用现行情上涨红；**下降区间：**两端K线上方各一个绿色实心下三角，使用现行情下跌绿。三角8×6px，不因缩放变成大箭头，不加常驻起止文字或整段连线。
- 哪根是端点仍由第二步的**最高/最低收盘**决定。绘图时红三角放到该根最低价之下、绿三角放到最高价之上，只为不压住K线；不能改成按盘中high/low重新选端点。
- 同一根可兼作下降终点和上升起点，绿上、红下同时显示。同方向同根共用一个同色三角，详情保留全部波段编号及起止身份，不合并后端波段。
- 悬停对应K线时，沿用现十字线详情，列方向、编号、起止日期/15:00、收盘、DIF/柱极值及各自日期、何时才可以确认、待核对之处。MACD中的钝化/结构/消失文字继续原含义，不能把三角当作新增XXM信号。
- 底部指标栏新增“波段核对”入口，默认关闭，仅上证日线提供。本功能进入的是本次固定研究范围；首次进入及退出会按各自数据集初始化现有默认可视根数，不把两套数据的logical序号直接沿用。开启/重试重新计算；关闭/离开释放本次结果。范围内拖动/缩放不请求重算，不在每根K线上重复生成结论。显示“研究截至实际日期”，不让固定结果冒充最新行情研究。

### 13.3 不完整、未结束及冲突怎样表示

| 情况 | 必须呈现 |
|---|---|
| 三年起日处在一段中间，有限前段仍不完整 | 写明“最左侧波段不完整”；不补假起点，不因这点拒绝其余完整记录 |
| 真实起点已知，但位于观察范围/当前视野之外 | 只画真实可见端点；详情保留起点日期，不能把它画到左边界 |
| 当前段尚未结束 | 若起点有效且已可知，只画起点；候选终点/截至当日极值留在详情与表格，不用实心三角伪装已确认终点 |
| 端点价格合法，但内部价格或DIF对应有待核对 | 仍显示研究候选的真实端点，并在详情明确问题；不删掉难解释的候选来提高吻合程度 |
| 端点本身不合法/没有可确定的价格候选 | 不画正常的一对端点，列原因和数量；基础记录仍保留 |
| 与九转/可视极值文字拥挤 | 日期不动，只在原K线上方/下方竖向避让；研究查看时主图上下至少44px留白。仍放不下须显式说明，不压回K线、不把端点移到别日 |
| 结果尚未生成、读取失败、来源不一致 | 只显示本图层状态及必要重试，其余行情不被当作失败；不改用旧算法或前端临时算一套 |

**随三角标记一起实现：指数详情页日线统一请求1000根。**第四批已将此前300根改为下列确定要求，当前验收状态见§0.13.1：

- 所有现有受支持指数的普通日线主K线请求改为`limit=1000`；上证波段核对也使用1000，不再设置“只有核对时才扩大”的分支。普通模式以页面日期为截止日，核对模式以本次内存结果的实际日期范围为准；统一数量不改变各自日期含义。
- 主图MA、BOLL、MACD、KDJ随K线读取；上证趋势通道、指数日线九转同步请求1000。XXM按主图实际起止日期与实际根数请求，不能仍只覆盖最近300根。各层继续按日期对应，数据源缺失照实说明，不前端补算。
- 每屏仍45—180根，初始根数沿现自适应规则；1000是一次请求的最多数量，不是每屏数量，也不是必须凑出的行数。加载后拖动/缩放不增加请求。股票页及分钟请求不随本项改变。
- 进入核对时先请求后端内存计算，再读取其实际日期范围的真实K线，逐日核对close/DIF/DEA/柱后才画三角。OHLC仅由真实K线接口提供，不从研究收盘折线伪造蜡烛。

这项改动复杂度低，主要是统一几个取数参数及九转缓存使用的数量；现后端相关接口已允许最多2000根，不需要为1000另改接口上限或重写指标算法。请求1000不能补出数据库尚未提供的历史；不足时保留实际范围，试验先用已有连续范围，注明实际覆盖。离线试验的主范围≤800、含前段≤1300是另一项运行保护上限，继续有效，不与页面请求数量混用。具体位置、缓存处理及验收见LLD§15.4.1。

### 13.4 数据、开发边界及验收

后端计算只读`core_serving.index_factor_pro`与SSE日历，按LLD§14读取有界范围，所有中间与最终结果只在内存。API请求调用同一Biz纯函数，不读取reports、登记文件或旧算法状态；无新增Settings、磁盘缓存、导出、后台任务及跨请求恢复。失败释放本次结果，用户重试时重新读取和计算；HTTP响应不做持久缓存。

前端先取得本次结果，再按实际observationStart/end及limit=1000取真实K线，逐日核close/DIF/DEA/柱后一次显示三角及详情。计算编号只用来区分当前请求，不保证以后找回；关闭/离开释放，过期响应忽略。普通主图/右栏保持普通日期；研究九转/趋势用独立的同一hook/client实例及实际研究截止日，不覆盖右栏。

基础记录保留有限前段全部峰谷/色段；主表按色段与实际观察范围相交纳入，响应带齐所有被引用记录，但辅助前段不计入主范围数量。无价格候选时按LLD§14.6.1给空值及原因，不冒用色段极值填价格统计。已结束及开放候选分别按LLD§15.5绘图。
