## 4. 版本隔离的最小办法

只用一个本地读取子进程、两个专用计算子进程及一个离线编排过程，不新建通用加载器或算法工厂。

### 4.1 固定模块名单

历史进程按依赖顺序仅加载以下8个模块的原源码：

- 产品`index_detail_xxm`内的`types.py`、`spec.py`、`snapshot_validation.py`、`calculator.py`。
- 研究主题`xxm`内的`r4_reference_trial.py`、`r4_observation.py`、`r4_comparison_records.py`、`r4_comparison.py`。

修订后r4进程仅加载上述4个产品核心模块，调用唯一`XxmCalculator(record_decisions=True)`，保留其真实逐根判断依据；不加载预测、查询、API或缓存。

保留每个模块原来的完整导入名和源码，不改写源码。进程内先登记有限的空包及模块，再按依赖顺序执行；空包搜索路径为空，不执行仓库的包初始化文件。名单外的业务模块导入直接失败，禁止退回读取工作区文件。标准库导入仍按原Python环境提供。

使用现有解释器，以`-I -S -B`启动，忽略Python环境路径及用户站点，不导入site、不生成字节码；不依赖PYTHONPATH隔离。依据见[Python官方启动选项](https://github.com/python/cpython/blob/main/Doc/using/cmdline.rst)，已用Context7核对。

### 4.2 进程之间传什么

父进程一次取得六列源行情并校验后，经内存管道给两次计算传递完全相同的日期、原始数值和完成标志。各进程建立自己版本的XxmBar，不传pickle或跨版本类实例，不对DIF截位、不格式化价格、不补值。

JSON使用有限原数值并禁止NaN/Infinity；编码前后逐项检查日期及数值相等，不因进程传输改变float。版本身份、输入标的/范围/根数必须在返回时再次核对。

历史进程执行同版本原compare_r4，先完成其原有记录关联和比较，再只向父进程返回本次需要的逐日事实、原基准摘要和真实判断记录；不同时复制整份旧differences/idPairs和另一份旧账本。新进程返回point/events/structures/decision，不制造旧等待或旧历史字段。

父进程不改变任何组的业务结果，只负责检查关联、按日期对齐和整理报告；不重跑选择器来猜未执行条件，不为补解释重复计算整段行情。为报告活动进程峰值，仅允许在历史子进程给原比较器_memory_bytes附加只读报告：调用原函数、报告资源、原值返回，finally恢复；不改源码、原check、Spec或业务方法，详见专项LLD§4.2。

子进程不传入数据库连接、Settings、凭据或会话，不导入App及数据访问模块。源码检查和测试须证明：计算不读取行情、配置或工作区算法文件，不写文件、不访问网络/数据库，不调用正式服务、查询、API或缓存；允许调用固定版本的纯计算核心。解释器、标准库和获准新入口的必要启动读取不属于业务数据读取，固定算法源码仍只能经管道进入内存。**普通子进程仍使用本机账户，不等于获得了操作系统级文件/网络禁用权限。**本方案的保证来自固定代码范围、最小环境、无访问路径及反向测试，不夸大为系统权限隔离。

| 总时间 | 在首次读取行情或Git源码之前开始同一个20秒截止，包含编码、进程启动/通信/退出、比较、最终验收和报告准备；末尾预留0.5秒清理，不给各阶段另开20秒 |
| 总内存 | 父自身峰值加最高子峰值的保守上界≤256MiB，前提为无重叠/无后代子进程；活动worker报告峰值，Git及异常退出在wait后补核系统记录，计入管道/JSON副本；这是检查点监测及最终验收，不是OS硬内存限制 |
| 结果 | 全部必要事实及最终比较结果合计16MiB；只保留一套必要逐日事实，避免重复副本；超限整轮失败，不删日期或条件凑上限 |

本地读取进程关闭DuckDB后发送数据，父进程核完整消息、成功退出和回收，再做原输入校验，全部通过才计算。所有读取及Git/计算进程严格串行，均纳入原256MiB及20秒；不让计算进程继承连接。Parquet读取前后核文件设备、inode、大小及mtime_ns，期间变化整轮失败，不把它冒称数据库事务快照。

本轮已获准修改本专项本地读取并做一次限定真实读取验收；不调用run_historical_comparison，不启动旧/新识别或生成差异。范围仅为本表，不包含远程访问、数据库/Lake/DG写入或全局读取。

## 6. 比较内容与历史复现检查

先检查旧两组是否复现[原摘要](xxm-r4-implementation-plan-v0.1.md#161-提交与本次真实对照结果)：各DULL30、STRUCTURE17、CANCEL12、历史撤销7；逐日标签type/direction/route及根末普通状态相同。另核活动参照24天不同、events记录13天不同、任意字段差异254天及原候选表。字段计数、日期数与标签数分别统计，不能相互替代。

保留原三次无新事件的B→A：2023-04-18、2023-08-18、2024-01-22。重点核4月18/19保持钝化且无额外消失/首次事件。旧基准不复现即停止，不把当前实现结果倒写为历史expected。

旧基准通过后，主要比较“修订后r4—历史r4”；历史r2作为第三列参考。按原逐根时间顺序保留业务事实，不能拿最终锁死状态覆盖此前处于考核期的状态。

| 比较层次 | 必须呈现 |
|---|---|
| 标签及普通状态 | 日期、顶底、当根事件、每日根末状态；无事件不等于无钝化；形成并锁死不能因根末NONE而丢掉形成事件 |
| 结构后续 | 未锁死的保持/回钝化/直接消失、真实反色锁死及发生时间；旧价格撤销和新锁死单列，不能硬翻译为同一种普通CANCEL |
| 参照 | 三组实际使用的近/远参照、区间、收盘极值、DIF极值及各自发生日；无事件的切换仍记录 |
| 判断依据 | 当根收盘/DIF、历史门槛、本轮曾击穿、实际执行过的选峰及1%条件、柱色/根数；未执行就是未执行，不猜True/False |

旧参照对象只有区间/价格/DIF四字段，极值日期从该组旧观察器已输出的`referenceChecks.wave`建立对应关系并保留；新版直接读取自身六字段参照。映射必须区分组和完整参照身份，缺失或多义明确失败，不借另一组日期、不重新选峰、不补查数据库。

沿用旧比较“不跨日期强行配对”的规则：某天旧有新无、另一日新有旧无，先逐日列出，不自动认定提前/推后；只有后续人工确认同一事件才补说明。

差异原因须关联当前正式规则和当根事实，区分首次当根取价、统一回转、锁死、本轮突破记忆/参照选择、仅编号变化及暂不能解释。旧结果不是新规则的正确答案；有差异不等于bug，无差异也不证明与原软件完全一致。不能解释的差异保留并停止调规则，不为对齐旧版而修算法。
