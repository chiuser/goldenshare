## 1. 本次要完成什么

财势乾坤采用r4作为唯一正式顶底识别算法，**本轮先仅在本地开发环境支持**。本地普通页面显示钝化、结构、消失及关键高低点预判；辅助核验能力保留，但只在明确请求debug时加载和显示。生产环境暂不提供r4：日线也不显示识别标签、悬停状态、预判卡片或研究入口，不请求相关计算；生产分钟K线继续不支持。不保留r2作为生产回退。

产品化完成后，工作区不再保留r2算法、r2执行入口或可运行的r2比较副本；r2只作为设计、开发和验收文档中的历史记录存在。Git历史不重写，公共输入类型、严格安全检查和r4仍使用的工具不因原来服务过r2而删除。

P1准备及P2核心/内部调用限定验收已完成，实际证据见LLD§19.6、§20.4；原中断已经按批准方式处理。本文件和技术方案负责明确实施范围、顺序与验收条件；不把“研究通过”或“P1材料通过”当成“产品已经上线”，不提前实施代码清退。

## 3. 产品范围

1. 标的仍仅上证指数`000001.SH`；算法周期仍为日线、60、90、120分钟，分别计算。
2. 本次不扩大到股票、其他指数或其他分钟周期。本地开发支持上述四周期，分钟继续遵循已有本地分钟配置和数据条件。生产暂不提供r4日线/分钟识别、预判或核验工具，即使带`debug=1`也不开启；正常生产日线K线、MACD、九转和趋势等不受影响。沿用本地分钟的环境区分方式，不能要求日线也必须有分钟Lake才能使用。
3. 实际信号只使用已完成K线、原始收盘价及来源DIF/DEA/MACD柱。不重算实际MACD，不用假设收盘替代真实信号。
4. 保留现有关键高低点预判及其假设、适用条件和失效说明，计算同步采用r4。只更换历史识别而留下r2预测，不算完成升级。
5. 普通指数日线1000根加载能力保留，不因研究工具进入debug退回300根；其他页面和分钟数量不顺手修改。

## 4. r4规则登记

下表为本次唯一目标规则，详细处理顺序见技术方案§4。两位法不恢复，也不混入独立日线波段的另一种价格窗口。

| 判断步骤 | 固定规则 |
|---|---|
| 分红绿柱区间 | 以源柱值正负判断。真实反色才结束旧区间；零柱中性，不分段，不充当反色，不增加有色柱根数；归属已知区间时参与收盘和DIF极值 |
| 取价格和DIF | 分别取当前逻辑同色区间内累计最高/最低收盘、累计DIF峰/谷，极值可以不在同一天；历史区间取完整极值 |
| 候选参照 | 仅最近两个已结束同色区间：近B、远A，按时间确定，不按DIF强弱排序。没有B就没有首次钝化 |
| 首次资格 | 当前区间至少两根真实有色柱；先严格突破B的价格，再先查B完整价格/DIF资格，B失败才查A自身资格。最多两个。首次顶部还要求当根DIF大于0 |
| 等号 | 首次价格突破和DIF背离仍严格比较；DIF等于旧极值不满足首次背离。已有钝化只有严格突破原参照才按突破规则处理，等于不因此消失 |
| 零柱日 | 根数已够且其余条件满足，可首次钝化；已有状态照常检查结构和消失；符合原等待条件时可重新底部钝化 |
| 钝化持续 | 跟踪已选原参照，不因价格回落至首次突破价以下就宣告消失，也不每天随意重新选峰 |
| 当根B→A | 已钝化且仍在同一逻辑区间，累计DIF严格突破原B时，**同一根完成K线上、取消前**检查A。A完整合格则换A、保持原钝化，不多报“消失→钝化”；A失败才消失。不能回切B、找第三个或等下一天补做 |
| 结构及回转 | 保留相邻两根实际完成K线DIF的1%转折/回转和前值0保护；真实翻色独立确认结构。首次钝化当天只报钝化，不在同一根追加结构 |
| 结构后跟踪 | 保留当前r4-v2的顶部、底部历史退出及底部等待/重新激活规则；活动参照切换不改写原事件或历史保存的参照 |

例：昨天顶钝化对比B；今天DIF突破B，但价格和DIF仍符合A。今天继续顶钝化、活动参照变成A，不增加标签。若A今天不合格，则今天显示消失；明天才合格，不能抹去今天的消失。

当根切换仅限既有钝化；不得扩展到已有结构、底部等待、真实翻色或首次激活分支。

## 5. 普通页面与debug页面

以下显示约定**仅适用于本地开发环境**；生产不加载本功能及辅助信息。唯一debug入口沿用指数详情页URL中的`debug=1`。没有该参数即关闭；开发环境也不自动开启。不新增页面调试入口、用户设置、持久化开关或第二套算法选择。进入debug后仍须手动点击“波段核对”，不会自动计算三年研究。

| 内容 | 普通页面 | `debug=1` |
|---|---|---|
| K线、MACD、DIF/DEA/柱值、MA/BOLL、九转、趋势等既有正常行情 | 保留 | 相同 |
| 钝化、结构、消失的文字和圆点，当前顶底状态、发生时间 | 显示正式r4结果 | 相同结果，不另跑一套算法 |
| 关键高低点预判、条件、适用/失效说明、截至时间 | 显示 | 相同，并可核验详细依据 |
| 识别加载中、来源延迟、无数据、失败和重试 | 正常显示，名称改为“顶底识别” | 相同；不能把真实故障藏进debug |
| 参照A/B、区间、编号、DIF/价格极值、历史跟踪、等待记录、计算依据、来源核验信息 | 不加载辅助响应、不显示 | 随明确debug请求返回和显示 |
| 日线“波段核对”按钮、三角、图例、待核对数量、说明列表、研究专用九转/趋势 | 不加载研究模块、不请求、不创建图层 | 加载工具；仍须手动开启“波段核对”才请求三年研究计算 |
| “九转标记未找到对应K线”等核对数量 | 指数详情普通模式不显示这种诊断数量 | 显示；真实指标错误仍按上一行故障原则正常显示 |

普通悬停内容已确认：当前顶底状态、当根事件和发生时间。比较峰谷的日期、价格、DIF、编号、历史和等待记录只在debug查看；MACD本身的正常指标数值继续显示。普通悬停不再显示“徐小明V0.1·研究”“研究判断，历史寿命尚未验证”等研究文案。本地以“顶底识别·r4”描述正式功能；生产不显示该功能名称或占位卡片。

debug只决定辅助资料的请求和呈现，不改变识别、预测的规则、事件编号或结果。为了完整识别而必须计算的历史和等待状态，后端仍须内部计算、校验；不能因普通响应不展示就删掉。

移除debug、切标的/周期、离开页面时，取消辅助请求、清空辅助结果、卸载辅助图层。迟到结果不得重新出现。正常行情、右栏和正式识别不沿研究的历史日期倒退。

| r2实现、旧研究算法变体、r2/r4双组执行器及专属测试 | 已确认有用通用能力迁出、调用清零后删除；不改名封存为可执行旧算法 |
| 两位方法代码 | 已确认仅保留已有独立`quantize_dif`取数函数、必要数值校验及人工算术测试；完整两位计算器、旧r2双组入口及专属保护代码在迁移验收后清退。未执行；不恢复两位法研究或产品判断，不整文件保留其中的旧识别逻辑 |
| 研究r4复制的识别器 | 正式r4等价验收后删除；研究工具调用唯一正式r4，不保留第二份识别实现 |
| 报告目录中的旧算法脚本、动态候选加载与旧算法Notebook | 同样纳入清退，不能因为放在reports就漏掉；只用独立峰谷扫描器的Notebook保留 |

管理员现已确认“两位代码最低成本保留”的具体范围：仅保留不依赖r2的独立取数方法、必要数值校验及人工算术测试。当前`near_first_review.py`已有此函数，无须新增取数副本或一套实验；正负数、零、跨数量级及相等值的人工样本继续保留。这里只保留曾研究的算术方法，不代表该方法已被证明符合作者现行规则，也不接入r4判断。

完整两位计算器继承r2并复制其识别流程，还会检查旧Spec/源码，无法在删除r2后保持原样可运行；不能移除检查让它悄悄变成基于r4的另一项实验。完整两位计算器、r2双组执行入口及专属保护/测试随旧执行依赖清退；有用字面算术样本先迁出，旧完整实验从Git和历史设计/开发/报告追溯，不为它复制r2到工作区。

这不是清空全部研究目录或行情材料，也不重写Git历史。正式删除前必须给出逐文件及必要的函数清单，区分保留、迁移、删除及引用证据；先迁出需保留的算术能力和样本，待唯一r4及工具迁移验收后清退旧执行器。不删除本任务之外的未提交工作，本次确认不等于立即执行删除。

## 8. 必须验收的结果

1. 顶/底、先B后A、真实反色、零日、当根切换、1%、结构后跟踪均符合已批准r4-v2；对照必须含参照和历史关联，不能只数标签。
2. 四周期人工序列、连续/复制/增量/历史位置以及正式接口均有测试。真实验收分别报告日线、各分钟来源的实际可用范围；缺证据不冒充通过，不为此扩大全局读取。
3. 关键点预判在零柱、切换参照和临界价格上与唯一r4一致；不沿用“DIF最强”“零柱结束”“顶部不会换参照”的旧假设。
4. 普通/debug对同一批输入的正常标签和预测一致；debug关掉时无辅助下载和图层，打开后辅助编号、关联及日期可以核对。
5. 旧r2版本/缓存/内存进度被拒绝并从同源重算；错误进度不能污染正常对象，无磁盘恢复机制。
6. 既定性能预算不因产品化放宽。源码清退不能破坏保留的核验工具，也不能留旧算法别名、回退、动态加载或报告中的可执行副本。
7. 本地和生产能力分别验收：本地四周期依配置工作；生产日线及`debug=1`页面均无r4标签、悬停、预判卡片、研究入口及请求，直接请求相关接口也不进入计算，不以r2回退。生产正常日线能力保留。

当前判断：**P1、P2限定验收已完成，含LLD§20的退出清理修复；P3尚未开始。**已确认的本地/生产范围、普通悬停、debug入口、迁移原则及两位最小保留范围不变。P2通过只证明人工案例下核心迁移、内部调用和恢复符合设计，不证明预测、公开合同、真实来源或页面已交付；不提前清退、提交或发布中间版本。
