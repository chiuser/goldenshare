## 1. 目标与使用场景

在财势乾坤新增数据中心，将本机的数据查看和维护能力组织为可进入的业务模块。第一项为“上市公司公告”：查找需要的公告，查看本地 PDF 状态，执行经确认范围的下载、更新与维护，了解任务进展和异常原因。

此前选择的是本机运行财势乾坤和本机后端，由后端管理 datasource。后端读取本地公告元数据并管理本地下载归档；浏览器不直接接管移动磁盘。公告查看跳转到源站 URL，不由本机后端提供本地 PDF 预览。

2026-10-06 已确认：所有登录用户均可访问数据中心及部署环境提供的公告功能，暂不增加角色、权限分级或管理员专属限制。未登录沿用系统登录要求。这里的下载、核验与修复仍属于数据维护操作，但不另设权限门槛。

2026-10-06 已确认部署差异：Prod 正常显示数据中心首页，暂不显示上市公司公告卡；只有本地部署提供该入口。登录权限与部署可用性是两个条件，不用额外角色权限控制部署差异。

## 4. 已确认的页面范围与布局

以下页面职责及 R1 布局已获用户确认，实际页面细节见第 8.4 节。

**数据中心首页**：沿用财势探查等一级页面的顶栏、面包屑与紧凑板块卡片。按部署可用性呈现模块，本地第一项为上市公司公告，卡片展示用途和本地标记，不承担大范围文件统计。Prod 暂无其他卡片时显示“当前暂无可用数据模块”，不展示公告占位卡。

公告列表用于查找公告、通过源站链接查看详情、了解下载状态；本地 PDF 预览不纳入方案。创建下载仅按公告日期，采用设置日期、预览、开始的流程；页面任务行为以已确认产品规则为准，不能直接沿用 CLI 重跑来冒充精确恢复。

## 5. 已确认的一期产品规则

本节与 R1 评审清单对应的产品规则已获用户确认；仍需技术核验或设计补齐的事项单独说明。本轮不授权页面、API 或任务执行器开发。

### 5.1 部署可用性与外盘状态

由后端提供部署环境可用的模块，首页据此显示卡片，不按浏览器地址、操作系统或请求失败猜测部署方式。具体配置来源与接口待后续技术设计审计，本产品稿不新增配置项。

| 场景 | 已确认行为 |
| --- | --- |
| 本地部署，外盘正常 | 显示公告卡，进入后可查询、创建日期下载及恢复原任务 |
| 本地部署，外盘未挂载或不可用 | 保留公告卡；模块提示磁盘不可用并阻断依赖外盘的操作。可用的历史台账信息注明当前不能核验，不保证公告目录可查询 |
| Prod 部署 | 数据中心首页正常，公告卡不显示；直接访问公告地址也提示当前部署不提供该模块，相应操作不可执行 |

部署方式决定有没有模块；外盘状态决定模块当前能做什么。拔盘不隐藏本地入口，Prod 存在同名目录也不自动开启功能。直达地址和后端操作遵守相同的部署可用性限制。

### 5.2 公告列表与默认参数

已确认：默认列表是公告列表，不是本地 PDF 列表。每行代表一条源公告记录，不按标题、代码或 URL 合并不同记录；相同归档文件可以被多条记录关联和复用，不改变 Raw 的保留规则。

| 列 | 已确认展示规则 |
| --- | --- |
| 公告日期 | 展示公告业务日期 |
| 公司代码 | 展示公司代码 |
| 公司名称 | 展示当前简称；历史名称保留为搜索别名。无法关联名称时展示代码，不丢弃公告；名称来源须技术核验 |
| 标题 | 展示源公告标题 |
| URL | 有地址时只显示可点击的“公告详情”，在新标签页跳转源站 PDF；不展示地址全文 |
| 下载状态 | 只显示“已下载”或“未下载” |

已确认无 URL 时显示“—”，仍保留该公告行；有无 URL、是否已下载分别表达，不能因为文件未下载而阻断源站链接查看。

主列表不增加“失败、等待、缺失、损坏”等状态。过程状态与失败原因在下载管理区域表达，不扩展公告列表的两种下载状态。

“已下载”表示台账成功且本地文件经存在性检查可用；未完成、失败或文件已删除均显示“未下载”。不逐行重算文件哈希。外盘不可用或无法完成检查时明确提示下载状态无法核验，不将未知情况自动认定为未下载。产品状态判定已确认，实际检查与状态映射须技术审计，现有台账内部状态不能直接冒充页面口径。

查询日期初始为最近 30 个自然日：结束日期为当前业务日期，开始日期为结束日期前 29 天，两端包含。公告日期倒序、同日稳定排序，每页 50 条；用户可调整起止日期。下载状态默认“全部”，可选已下载、未下载。新应用筛选或重置时回到第 1 页。

公告记录数与归档文件数分开；不把不同来源记录合并成一行来消除同文件关联。

### 5.3 搜索规则

股票搜索先给出公司候选，显示名称与完整代码；选中后按完整代码过滤公告，配合日期及下载状态。一个股票搜索框支持以下输入；标题关键词是独立的可选输入。

| 输入 | 已确认规则 |
| --- | --- |
| 完整代码，如 000001.SZ | 精确命中 |
| 六位代码，如 000001 | 列出对应完整代码；多个市场命中时由用户选择 |
| 数字前缀 | 用于查找候选，不默默按第一家公司过滤 |
| 中文名称或部分名称 | 支持当前简称和公告中的历史名称，候选中说明名称来源；选择后查该代码全部符合日期的公告 |
| 名称首字母，如 PAYH | 按简称首字母匹配，不区分大小写；历史名称也可作为候选别名 |

多音字按确定的简称读音生成，不穷举所有读音；存在歧义时在后续技术设计中列出实际样本并确认词表。当前名称来源与别名来源仍需技术核验，不能把某份主表未经审计就当成完整事实源。

默认不强制选股票，可按日期查看全部公告。无法关联股票主表的代码仍可展示、按代码和标题查找，不因名称或首字母索引缺失而丢弃；首字母功能只覆盖可建立名称索引的对象，缺失名称时明确展示代码。

标题筛选按源公告标题包含原文匹配，与公司、日期、下载状态取交集。输入“年度报告”可以找当前日期范围内标题含该文字的公告；不选公司可查全部公司，选公司后只查该公司。留空不限制标题，不搜索 PDF 正文，也不做语义分类。使用“查询”应用筛选；“重置”清空公司和标题并恢复默认日期、全部下载状态及第 1 页。“刷新列表”按已应用条件重新读取本地数据。

当前 CLI 台账查询有 `files --title` 原文包含筛选，但它查的是台账文件记录；网页的全部公告标题筛选尚未实现，不能直接把现有台账查询当成公告目录。

搜索消费本地数据，不在用户每次输入时临时请求 Tushare。是否建立本地查询表或索引留给后续技术方案，本节不决定新数据库及存储结构。

### 5.4 下载管理详细规则

下载管理独立承载，创建下载仅按公告起止日期，不支持公司、标题、单份或勾选范围。创建区域、预览、当前任务进度、失败重试、停止续跑与历史任务规则已确认；本轮仅落档产品规则，不开发 API、执行器或页面。

#### 5.4.1 功能组织与主流程

页签内包含“创建下载”“当前任务”“历史任务”三个功能区。没有运行任务时突出创建入口；已有运行任务时展示原任务范围、突出当前进度，不允许同时新建或排队。结束后提供“新建日期下载”。

主流程：设置范围 → 预览范围与数量 → 开始下载 → 查看处理进度 → 查看结果 → 重试失败项。

下载目标是 datasource 本地归档。界面明确显示归档目录与外盘状态；源站链接跳转及浏览器自行另存不计入归档下载。

#### 5.4.2 创建下载与范围预览

**范围已拍板：仅按公告日期批量下载。**起止日期两端均包含，匹配该范围内全部公司、全部标题的公告。有有效本地文件则复用，无 URL 则单独说明不能下载；不因公司、标题或查询列表的下载状态筛选缩小任务范围。

| 项目 | 口径 |
| --- | --- |
| 公告起止日期 | 必填，初始均为空；是唯一业务范围输入，起止相同即处理一个公告日期，不默认全部历史 |
| 请求间隔 | 默认 5 秒，允许非负秒数及调试用的 0；不能用 0 绕过失败退避和源站冷却 |
| 归档位置 | 标签仅为“归档位置”；输入框置灰且不可编辑，显示 /Volumes/datasource/announcements，不展示“只读”字样；外盘状态单独呈现 |

公告查询保留公司、代码、首字母和标题搜索；这些只用于查询。下载管理不出现公司或标题下载条件、不设行内首次下载或勾选下载入口，也不提供自动带入查询条件的操作，避免将查询意图误当成下载意图。

日期为空或结束日期早于开始日期时，不能预览；日期倒置在日期控件下方显示原因。间隔须为非负秒数。点击“预览下载范围”，展示日期摘要、匹配公告记录数、对应归档文件数、无 URL 公告数，以及预计已有可复用数和需下载数。公告记录与文件分别计数，不将多个记录关联同一文件变成 Raw 去重。

预览完成、外盘与来源检查通过后再“开始下载”；无可处理文件时说明原因，不创建空下载任务。准备期间显示正在检查/统计及已扫描日期或记录量，支持停止准备；已有文件是否可复用在执行时核验，预览数量只是预计值。

任务记录本次日期范围与准备好的文件集合，运行或继续时不因查询变化、DG 后续更新自动扩大集合。若预览后的来源变化影响候选，应明确重新准备。持久化方式、批次与规模上限留给后续 LLD，不把全部候选常驻内存。

失败重试与继续未完成项是恢复原日期任务的操作，不是新增按公司、单份公告或勾选创建下载的能力。失败行“重试”只定位原任务已失败的文件，不能扩大到同公司、同日其他公告。

#### 5.4.3 当前任务与进度

当前任务展示范围、开始时间、请求间隔、归档位置，以及下列进度信息：

| 信息 | 已确认表达 |
| --- | --- |
| 阶段 | 正在准备、正在下载、等待下一次请求、等待重试、停止中或已结束；阻断时说明原因 |
| 总体进度 | “已处理 X / N 个文件（P%）”；同时显示新下载成功、已有文件复用、失败、剩余数量 |
| 当前公告 | 公告日期、公司代码/名称、标题 |
| 单文件进度 | 显示实际已接收大小；总大小可靠时显示接收比例，否则只显示已接收大小；接收完仍须校验落盘后才算成功 |
| 等待原因 | 正常请求间隔、自动重试退避或源站限流冷却；有确定期限才显示等待剩余时间 |
| 更新时间 | 展示最近业务进度时间；观察连接失联时显示状态暂不可获取，不伪装为任务失败或停止 |
| 操作 | 运行时提供“停止任务”，停止中禁止重复点击；已完成结果不受停止影响 |

可见状态至少每 5 秒刷新一次，文件处理或接收进度变化时及时更新；心跳更新时间不能代替业务完成量。准备阶段总量未知时显示已扫描量和“正在统计”，不伪造百分比。剩余总耗时没有可靠依据时显示“暂无法估算”。

总体百分比表示处理进度，失败处理完也计入已处理；不能将进度条命名为“下载成功率”。例如已处理 320/1000、成功 300、复用 10、失败 10，则处理进度 32%，结果仍含 10 个失败。总处理进度到 100% 后，有失败时显示“已结束，存在失败项”，不能显示“全部下载成功”。

文件数量按归档文件计，源公告数量另列。重试过程中不反复增加总量或把一次文件重试算作多份文件。

#### 5.4.4 文件结果与失败重试

任务详情展示文件结果，R1 以失败明细为重点，展示关联公告日期、代码、标题、失败原因和“重试”操作。任务结果可表达待处理、下载中、成功、已复用、失败，与主公告列表两种下载状态职责不同；全部文件结果列表的完整交互尚需设计细化。无 URL 公告作为单独的范围说明，不计为下载失败。

失败重试分两层：

- 临时网络异常、超时、源站限流：自动尝试最多 3 次，含首次；显示当前尝试次数、等待原因及最后错误。仍失败则记为失败，继续其他可处理文件；全局拒绝访问等阻断情况按下文处理。
- 自动尝试结束后：失败行提供“重试”，任务结果提供“重试全部失败项”。只处理本任务对应失败文件，已成功和有效复用文件不重复请求，不重新拉取整段日期的所有公告。

手工重试也遵守请求间隔及已知源站冷却，不能用连续点击绕过。原尝试结果保留，重试作为关联执行批次展示新的数量和进度；成功后更新对应公告下载状态，历史错误仍可追溯。

重试前再次检查外盘、文件及运行状态；若文件已被其他执行成功归档，复用并说明。若另有活动任务，不启动并行任务，也不偷偷排队；提示等待当前任务结束。

不同错误给出不同反馈：一般文件错误可继续处理其他文件；外盘拔出、空间不足、来源不可用、源站拒绝访问或验证码等全局阻断应停止领取新文件，保留成果并显示原因。环境恢复后的操作为“继续未完成项”；失败文件仍通过失败重试处理。

没有地址或明确的地址失效问题不承诺点击即可解决；展示实际原因，不无限自动重试，不自动找替代 URL。未来元数据更新后的公告按新的来源事实创建范围，不偷偷替换原任务地址。

#### 5.4.5 停止、继续与后台执行

同一归档位置只允许一个活动执行，不提供并行下载和任务队列。关闭网页或切换页签不停止任务，重新进入可看到同一本地后端的当前任务；所有登录用户共享其状态。

点击“停止任务”先弹出确认框，可选择“继续下载”或“确认停止”。确认后显示“停止中”，待执行器确认后显示“已停止”，保留已经归档的文件；停止中禁止重复提交。再次“继续未完成项”只处理原任务未完成集合，不扩展日期范围，不重复下载已经有效的文件；失败项单独重试。

后端重启或进程退出后，根据持久化事实显示“已中断”，让用户主动继续，不自动恢复网络请求。继续不承诺 HTTP 字节断点续传；是否可复用已有候选由现有文件恢复规则校验决定。

#### 5.4.6 历史任务与结果反馈

历史任务展示时间、公告日期范围、结果、新下载成功/复用/失败数量、补充信息与操作，点击进入任务详情。结束反馈明确区分全部成功、部分失败、已停止和已阻断/中断；无 URL 数量单独说明。已成功且有效的文件不因查看历史或恢复任务重新下载。

任务成功归档后，公告查询刷新即可展示相应“已下载”。文件后来被删除时，重新执行对应公告日期范围允许重新归档，不能因历史成功永久阻止重下，也不因此新增单份公告创建下载入口。存在性检查的实际读取与性能边界继续在技术设计中校准。

#### 5.4.7 当前实现差距

现有 CLI 支持按日期枚举、限速、有限自动尝试、文件结果统计、停止及幂等重放，但不具备网页任务管理、原任务精确失败批次重试、冻结范围内继续或页面单文件字节进度。公司、标题、单份及勾选创建下载不属于本期需求，不作为待补能力。不能以重新执行同日期 CLI 冒充“只重试失败”或“只继续未完成”。

任务和重试产品规则已确认，将涉及任务持久化、原任务恢复和观测合同的扩展；开发前须在原技术方案/LLD 做 CodeGraph 影响面审计、逐项合同对账和测试设计。维护 CLI 不承担网页后台任务主链，本轮不新增配置、API 或执行实现。

### 5.5 元数据更新（分工已确认）

R1 已呈现本地来源与不可用反馈。最新公告日期及最近更新结果的具体摘要尚未绘制，须在后续技术核验与设计细化时明确；最近更新成功时间和最新公告日期必须区分，不能把公告少的一天判定为同步失败，也不能把顶栏市场日期冒充公告同步时间。

### 5.6 公告详情查看与本地维护边界

外站如何展示、是否可访问、浏览器是否预览或提供另存，属于外站及浏览器行为，系统不管理或干预，不据此改变本地下载状态。

已确认通过日期范围重新下载缺失文件，或恢复原任务的失败/未完成项。独立的本地核验、修复维护入口不在 R1 中，不能因现有 CLI 有这些能力就视为本次已批准页面功能；如需扩展应另行讨论。删除文件、清空台账、强制覆盖不属于本期页面范围。

#### 公告查询

- 模块头显示“上市公司公告”、本地数据与外盘状态；页签为“公告查询”“下载管理”。切换页签不把查询筛选复制到下载。
- 筛选栏按公司名称/代码/首字母、标题关键词、公告开始日期、公告结束日期、下载状态组织；操作为“查询”“重置”“刷新列表”。公司和标题可留空；搜索候选同时展示简称、完整代码及匹配依据。
- 列表严格为公告日期、公司代码、公司名称、标题、URL、下载状态六列，无复选框、首次下载按钮或本地 PDF 预览入口。有 URL 时链接名称为“公告详情”，旁边可带外链图标；无 URL 为“—”。点击仅在新标签页进入源站。
- 列表头显示匹配公告记录数与分页信息，底部提供分页；数量是公告记录数，不能替换为本地 PDF 数量。缺失名称、URL 或发布时间不因此删除源公告记录。
- 无匹配结果显示“没有符合条件的公告”并提供“清除筛选”；来源异常显示“无法读取本地公告来源”与“重新读取”，不把读取失败显示成零条公告。

#### 日期下载创建与范围预览

- 创建区只出现公告开始日期、公告结束日期、请求间隔、归档位置及“预览下载范围”。日期初始为空，未填写时预览按钮不可用；日期倒置时输入框及下方原因提示明确报错。
- 归档位置标签仅为“归档位置”，路径位于置灰且不可编辑的输入框；不添加“只读”字样，不提供路径选择、编辑或切换按钮。外盘状态不通过这个输入框表达，继续单独展示。
- 预览区重述起止日期、全部公司/全部标题和请求间隔，分列匹配公告记录、对应归档文件、预计可复用、预计需下载、无 URL 公告，操作为“开始下载”“调整日期”。
- 预览估计与执行结果分开。示例 1,028 条公告、1,000 个文件、10 个预计复用、990 个预计需下载、8 条无 URL，只说明计数口径，不是当前真实数量或性能承诺。

#### 当前任务、停止与恢复

- 活动任务时创建区缩为原任务日期范围、间隔和归档位置摘要，标明已有活动任务。进度区优先展示阶段、数量、处理进度条、当前公告、实际接收量、等待原因及业务更新时间；结束后提供“新建日期下载”。
- 数量卡分别展示新下载成功、已有文件复用、失败、剩余；无 URL 数量是原日期范围的补充说明，不计入文件失败。处理总量按文件计算，单次网络尝试不新增文件数。
- 32% 示例为成功 300、复用 10、失败 10、剩余 680，合计 1,000。100% 仅表示处理结束，有 10 个失败仍显示“已结束，存在失败项”。0% 不显示完成段，准备阶段使用不定进度并显示已扫描日期/记录量。
- 单文件接收完仍须校验落盘才计成功；等待提示区分正常间隔、重试退避和源站冷却。无可靠总大小或剩余时间时不伪造百分比和 ETA。
- 停止确认说明成果保留和恢复范围，操作为“继续下载”“确认停止”；确认后按钮进入“停止中”不可重复提交，最终显示“已停止”。准备阶段“停止准备”取消准备，未形成可执行任务时不创建空下载任务。
- 已停止或中断状态提供“继续未完成项”，失败项通过独立重试恢复。外盘或源站全局阻断显示具体原因与重新检查入口，检查通过后仍由用户手动继续。

#### 失败明细、重试和历史

- 部分失败结果下方展示失败文件，列为公告日期、公司代码、标题、失败原因、操作；每行“重试”，区块提供“重试全部失败项”。没有 URL 的公告不进入失败列表。
- 单项重试展示本次总量 1；全部失败项重试只展示该原任务失败集合的数量。例如原任务 1,000 个文件中失败 10 个，批量重试总量为 10，不重新扫描或请求整段日期的全部文件。
- 重试显示当前尝试次数、退避原因和最后错误，保留原任务失败记录与关联批次。明确 HTTP 404 或地址失效的原因，不承诺重试一定解决；HTTP 403/验证码等全局问题进入阻断反馈。
- 历史列表展示开始时间、公告日期范围、结果、成功/复用/失败数、补充信息与操作，支持查看原任务详情及相应恢复操作；不同任务与重试批次不可混成一个累计成功数。
- “全部成功”说明可处理文件已全部成功归档或复用；无 URL 仍单独说明。文件被删除后，通过重新创建对应日期范围下载即可恢复，不增加主公告列表的单公告创建入口。
