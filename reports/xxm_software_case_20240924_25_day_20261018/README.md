## 3. 两条输出在当前代码中是一条连续过程

已核当前[calculator.py](../../src/biz/services/wealth/market/index_detail_xxm/calculator.py)与原结果的代码校验值一致，没有重算后迎合图片。

1. 9/24：现模型选中8/30的历史红柱段。模型参照价格2842.2142、DIF -22.237；当根收2863.1255、DIF -26.795，满足现代码“价格更高、DIF较低”的条件，首次报顶钝化。当前红柱段为第2根，现行至少2根要求已经满足。
2. 9/25：同一参照还在，DIF升至-14.515，超过-22.237，于是报钝化消失。它是前一天那次激活的后续，不是独立生成的另一次顶部判断。

所以，若要消除这组多出的输出，应先明确9/24首次钝化缺少什么条件，而不是在页面隐藏9/25的消失，或改结构形成的1%转向要求。1%并不参与这两条事件的判断。软件真正采用的历史参照仍未知，上述8/30和各数值只属于本系统。

## 4. 哪些问题仍不能由这两张图分清

既有两种解释在这两天都不输出目标事件：

- 首次顶钝化时，要求当根DIF大于0；9/24当根为负。
- 要求所比较的历史DIF大于0；现模型选中的8/30历史DIF也为负。

新图对这两种解释都相容，仍不能分出哪一种是软件真实条件，也不证明除此之外没有其他计算差异。此前“历史段至少2根”的统一过滤已被1/6日线例子反驳，不能只为符合9/24再次采用。

因此本轮可以把问题写成“当前输出与两天当日图不一致”，并将修订检查放到首次顶部钝化；不能宣布零轴公式已经明确，更不能宣布内核已修复。旧52项标签不改，不将两条缺字直接写成软件内部NONE状态。
