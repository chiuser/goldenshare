# XXM统一业务日期修正

用户已确认四周期遵循财势乾坤统一业务日期：交易日20:00前上一交易日、20:00起当日，周末节假日沿用系统规则。方案和LLD先修订，随后修改产品代码；规则与硬口径矩阵统一见[预测方案§19](../../wealth/docs/pages/index-detail/index-detail-xxm-key-point-forecast-implementation-plan-v0.1.md#19-统一业务日期与20点切换修正2026-10-15)，不复制20点参数。

本轮范围：原共享日期解析器增加内部时钟注入，XXM共享取数及两个build统一业务上限，相关测试和原方案/LLD；公共DTO、原算法、正式源、前端布局及配置不变。页面由用户手动验收，未安装、部署、重启用户服务、写正式数据、提交或推送。

影响面：CodeGraph search/explore/callers/impact覆盖共享context、source/load_entry、识别和预测build、两组hook及消费者；context_consumers_before.json逐项登记真实调用点。共享resolve_context既有调用不传新增可选时钟，默认行为保持。before_identity.json为落码前身份；reported_failure_before.json保存11:15只读源核查，60/90被误判DELAYED而120尚为READY。历史报告不改写。

## 落点与边界

- `market_page_context_query.py`：原SSE交易日历SQL及20点常量不改；新增内部可选时钟，使同一请求只使用一个时钟。20个既有导入文件、26处调用已核验，原关键字调用保持。
- `index_detail_xxm/query_service.py`：原4秒预算内取得统一业务日期；日线SQL、分钟两路签名与读取、计算前缀全部封顶至该日。识别与预测共同迁移load_entry第二项返回值，清除原盘中日期判定。
- `index_detail_xxm/forecast_query_service.py`：LATEST和REPLAY同样受业务日约束，预测仍基于真实快照推演未来端点；20点后缺少当日完整源则保留DELAYED，不输出新的条件。
- 3个对应测试文件：统一时钟、跨年、四周期盘中、20点切换、未来数据提前入库／修订、缺失／部分来源、回拨缓存、历史回放及周末节假日。分钟完整Parquet读取测试同时验证识别层。

App→Biz→Foundation及Wealth经HTTP的依赖方向不变，新增调用为Biz内部复用。公开参数、DTO字段、HTTP码、原Spec、数学域、生命周期、Gold来源、1000根批次、2槽／16序列／64MiB缓存和4s／200ms／32KiB预算不变，无新配置。8个关键算法、来源、Spec及Card文件哈希保持，见identity_comparison.json。
