# AGENTS.md — 离线研究代码组织规则

适用于 `scripts/research/` 及子目录。继承仓库根与 `scripts/AGENTS.md`；这里是离线研究工具，不是产品运行时，也不改变 QTF 的正式产品域边界。

## 1. 代码按主题集中

1. 新增研究先确定一个主题目录：`scripts/research/<topic>/`。同一研究的脚本、辅助代码和隔离测试必须放在该目录内，不在根 `tests/`、`reports/`、`docs/` 或临时目录长期散放可维护代码。
2. 指数大势、概率统计、缠论教学和买卖信号实验统一归入 `index_market/`：`statistics/` 放统计实验，`chan/` 放缠论研究，`tests/` 放本主题全部测试，`README.md` 提供入口与运行方法。
3. 不按每次日期复制一整套代码，不另建同义主题目录。按需要分实验模块，不提前创建空框架或通用层。
4. 既有其他主题（例如本目录现存 `sector_radar_*.py`）不属于指数研究迁移范围；未经该主题授权不顺手移动。后续整理按主题单独进行，不把这次授权扩大到全部研究。

## 2. 文档、结果与代码分开

1. 方案和教学主文档留在既有 `docs/` 职责目录，主题 README 只保留导航、当前运行说明与迁移记录，不复制另一份主方案。
2. 结果、图表、事件账本、数据摘要和 manifest 放在 `reports/<experiment_run>/`，不放执行脚本。输出目录必须明确且每次新建，拒绝覆盖历史结果、正式数据或宽泛目录。
3. 历史报告中的参数、成绩、输入/代码哈希不因整理目录而重写。迁移另记旧路径、新路径与前后校验值；旧运行命令保留为历史记录，当前命令只从主题 README 获取。
4. 第三方源码保持隔离，不复制为本仓主实现，不自动安装、下载或升级依赖。

## 3. 导入与测试

1. 从仓库根使用完整模块入口 `python -m scripts.research.<topic>...`。不留旧路径转发脚本、模块别名、软链接或双份实现。
2. 主题内导入只使用新路径；生产模块不得依赖离线研究脚本。迁入产品域须另行设计、审计和批准。
3. 移动文件必须同时审计包导入、`__file__` 相对层级、输入/输出路径、pytest 发现配置、文档链接、复现命令与历史来源校验。
4. 测试集中在主题的 `tests/`，并注册到仓库 pytest 的 `testpaths`，避免整理后默认测试漏跑。默认测试用合成数据、已冻结的本地研究证据或临时目录，不读真实 Lake、不调外部 API、不运行回测。
5. 组织优化不得改变实验算法、参数或筛选范围。来源校验不能直接删除或放宽；确需登记纯迁移前后的代码哈希，只接受有记录的精确旧值/新值对，其他变更仍失败。

## 4. 执行与交付

1. 先写清目标、依据、范围和验收，再编码。方案未确认不得擅自运行新实验；研究代码整理不等于批准读湖、调参或重跑回测。
2. 参数集中于实验的单一 Spec/配置来源，报告保存实际值；不得通过随手改常量绕过冻结方案。
3. 数据读取与生产操作继续服从根规则和对应技能；不得写 Lake、数据库、DG 事件或启动服务。
4. 交付至少核验：新入口可导入/显示帮助、隔离测试通过、旧活动引用清零、文档链接有效、历史结果未改。说明移动文件、验证结果、未执行项；不把工程检查称为方法有效。
