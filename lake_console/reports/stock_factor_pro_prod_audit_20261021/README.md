### 4.1 补查：普通同步下载一天，还是最近多天

结论：普通同步只下载指定的一个交易日，没有默认把最近多天的全市场数据重刷。10 月 21 日两次定时同步的目标日都是当天；同一任务内因复权变化追加的单股票历史请求另算，不能把它们解释为普通更新的滚动窗口。

| 证据 | 已核实的内容 |
| --- | --- |
| [普通请求构造](/Users/congming/github/goldenshare/src/foundation/ingestion/request_builders.py:859) | 没有单股票区间输入时只生成 `trade_date=YYYYMMDD`，不生成最近几天的 `start_date/end_date`。 |
| [日期展开](/Users/congming/github/goldenshare/src/foundation/ingestion/unit_planner.py:219) | `point_incremental` 对本数据集的日期轴返回 `[request.trade_date]`，不会展开多天；区间维护是另一分支。 |
| [本数据集规划](/Users/congming/github/goldenshare/src/foundation/ingestion/unit_planner.py:991) | 先生成普通日期请求，再追加复权变化股票历史，不把两者混成全市场多日请求。 |
| [复权历史追加](/Users/congming/github/goldenshare/src/foundation/ingestion/unit_planner.py:914) | 只对识别出的变化股票附加 `ts_code + 最早已有日期～T`；这是本次问题明确排除的历史更新。 |
| 实际节点 25501、25572 | 两者均为 `{"mode":"point","trade_date":"2026-10-21"}`，分别属于 18:30、21:02 启动的定时工作流；没有多日输入。 |
| 行数辅助证据 | 后一次 35,558 行与当天 5,567 行加历史 29,991 行吻合。总行数仅作交叉核对，不单凭它推断请求范围。 |

普通请求参数示意为 `trade_date="20261021"`，另有契约字段和分页参数；历史请求则是特定股票的 `ts_code/start_date/end_date`。这是当前仓库执行路径与实际任务输入共同支持的结论。没有取到昨晚原始 HTTP 日志，未声称逐条还原当时网络请求；也没有因此宣称审核了所有历史调度日期策略。

补查只读两个已知任务/节点的日期和 JSON 顶层键：父任务的 plan_snapshot 为空，节点 context 只有 action_key，因此没有把不存在的完整执行计划作为证据。原始结果保存在 `09_plan_keys.sql/txt`，此前明确节点日期的结果为 `05_task_summary.sql/txt`，均在原临时审计目录；本次没有增加源请求或业务表明细读取。

## 5. 读取边界、方法和限制

- Prod 仅通过 `bash scripts/psql-remote.sh`，全部使用 READ ONLY 事务；单条 SQL 15～30 秒限制、锁等待 2 秒。
- 业务表白名单：`raw_tushare.stock_basic/stk_factor_pro/suspend_d`、`core.equity_adj_factor`、`core_serving.trade_calendar/equity_daily_bar`；辅助读取 `ops.task_run/task_run_node` 的相关日期或明确 ID 汇总。Serving 因子仅查结构，没有重复导出。
- 日覆盖只读 10 月 21 日；变化判断只读 20/21 日；历史汇总只针对明确的 17 个代码；实际历史明细仅 34 个主键、显式 261 字段。没有全市场全历史明细读取。
- 源请求 38 次：1 次新股小样本，1 次当日全市场 3 字段，2 次相邻日复权因子，34 次历史单行全字段。返回数量均低于相应接口上限，无分页完整性新结论。
- 最初的复杂历史联表审计在 30 秒上限被取消，未提高限时继续扫描；随后检查执行计划，改为 17 个代码的复合索引聚合及 34 个主键点查。这不是未来 blocking checks 的耗时验收。
- 原始只读 SQL、输出和源样本保存在 `/private/tmp/stk_factor_pro_prod_audit_20261021`；仓库报告保存统计、明细范围及 34 行比较摘要，不把所有业务行复制进 Git。
- 初次审计未改 Prod/DG 数据、任务、日历分区、调度或配置，未编写本数据集 LLD。后续按管理员确认仅补查任务元数据并编写方案/LLD 草案，仍未开发资产、job、sensor，未触发补数或重跑。
