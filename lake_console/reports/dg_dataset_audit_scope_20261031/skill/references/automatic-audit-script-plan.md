## 2. 当前问题与必须保留的既有修正

1. 原`_audit_trade_date`只要分区模型名称不以`trade_date_partition`开头，就直接排除。因此漏掉七项；`catalog_classification_complete=true`只证明分类数量对得上，无法证明分类正确。
2. 周/月文件可长期存在。只查总行数会漏报更新滞后，不能用周五/月末坐标或文件mtime代替源`end_date`。
3. 原汇总把`unreadable_file`计成缺失，并把零行混入缺失数量；原年度查询还读取`ts_code`、`trade_time`做额外统计。这些并非新增七项所需。
4. 28日已保存的`audit_count_only.py.txt`和测试证明：年度文件只按指定日期`count(*)`、损坏/权限错误不算数据缺失、零行单列已有明确处理。该适配器仅用于28日，没有改回原skill。正式入口必须保留这些已确认的修正，不能重新带回旧错误，也不能继续依靠另一个临时审计入口。

第3—4项仅在审计工具内收敛：年度查询改为目标年份、目标日期计数；错误和零行由统一汇总分类。既有Serving资源、表白名单、日期过滤、只读设置和查询限额保持。历史报告、固定28日脚本及其原测试作为证据保留，不修改、不重新执行。

## 3. 七项判定口径

### 3.1 周、月线

- 从当前catalog与分区模型得到身份、层级、路径和schema，沿原`run_contracts.stock_period.period_for`确定周/月坐标。日历使用现有SSE，不要求另建SZSE。
- 所选周期内，截至指定日期最后一个开市日为应有的更新日期。整个窗口无开市日则列“不应要求本期更新”；日历缺失或不合法则列“未核实”。
- 同时报告文件行数、合法`end_date`最大值、达到应有日期的行数、旧日期行数、合法NULL数和非法日期数。部分行较旧或NULL不能被一概判错；最大值达到日期，也只证明观察到该日期数据，不证明全市场代码覆盖或所有质量检查通过。
- 有数据但没有达到应有日期，必须报告更新滞后，不能继续用“有数据”隐藏它。当前文件更晚的数据只能证明目前已覆盖，不能证明历史当天执行成功或存在那天的快照。
- 最后应有开市日的19—20点源发布窗口尚未结束且未观察到目标日数据时，报告等待窗口；周末按上一开市日窗口，不再等周末20点。20点是源说明中的窗口末端，不是人为规定的Silver完成期限。审计观察到的缺口不能自动解释成程序故障或任务超时。

### 3.2 公告

按`ann_date`自然日检查。0字节文件与可读的0行Parquet不同；后者在公告生产者合同中合法，不计作物理缺失。输出“允许零行，未检查源交付完成”，不能据此声称源同步完整。此次自动审计不为证明零行而运行原检查、扫描九日窗口或连接DG instance；需要解释源交付时另做精确只读核验。

### 3.3 日历

Raw使用`cal_date VARCHAR/YYYYMMDD`、`is_open INTEGER`；Silver使用`trade_date DATE`、`is_open BOOLEAN`。指定日记录必须唯一，开休市标志合法；`is_open=0/false`正常。周月窗口还需确认没有缺日或重复。Silver是周月日期计算依据；Raw独立出结果。两份日历都可核且在所需日有矛盾时，相关周期的日期判定为未核实，不能静默任选一份。

## 4. 自动分类和汇总

按`PARTITION_MODEL_DEFINITIONS`的模型、模型族、物理布局和已明确的审计规则分类，不再用模型名称前缀当完整业务规则。七项必须各有审计结果；未知模型、无法解释的路径或事实冲突必须保留为未分类/未核实，不能自动排除。

当前剩余13个全量快照和1个湖健康项逐项保留排除理由：不适用指定日正行数判断，不代表已废弃、当前健康或新鲜度通过。名单详见LLD§3，不形成第二套资产、路径或字段事实源。

报告版本更新为`report_schema_version=2`。原三组结果及原主要字段保留，新增周月、公告、日历三组结果与明确的更新滞后、等待、允许空、未核实和最终判定。物理存在与满足本次日期要求是两个结论：即使“有数据”很多，仍有更新滞后或未核实，就不能给出审计通过。字段、计数恒等式和退出规则见LLD§9—10。

未来日期按日历、周月、公告各自规则判断，不设“未来日期一律等待”的总规则：日历覆盖不足照实报告；周月缺少有效日历依据则未核实，只有能够确定应更新日且尚未到其源窗口末端时才等待；未来公告文件尚未生成可以等待，读取失败和明确错日不改成等待。具体顺序见LLD§4、§6、§7和§10。

## 6. 读取、性能和失败规则

新增七项的行情/公告读取只限精确周/月/公告文件及必要日期字段；不读价格、其他历史周期、股票年度明细或Tushare源。每个实际文件一次必要统计，同一文件供多个请求日期共用；schema/footer和读取前后stat可以单独读取元数据，不计算数据SHA。

性能预算按输入日期数、去重周/月和精确文件大小计算，详见LLD§11；不凭文件大小承诺磁盘实际读量或固定秒数。本次未读取正式文件测量大小。新增正式业务写入、源请求、备份、COPY、spill均为0；报告只写原输出目录。一次中断后不自动重读，下一次显式执行另计同范围上界；收尾只汇总已有结果，不再扫描。

开始时只确认一次所选Lake根存在、是目录且可读取，再建立共享DuckDB连接；任一步失败，明确报错并以非0退出。此时不继续其它后端，也不生成一套部分审计结果。不新增挂载监控、写探测文件、自动重连或降级执行。

开始审计后的单项读取失败保留“未核实”，源窗口未到保留“等待”，文件运行中改变保留“未核实”；其它已具备正常连接的查询沿原流程继续。不自动重跑、不改内存/并发/超时、不跳过检查、不删除pending。目录和只读边界遵守根AGENTS，不使用退役Lake或Kopia。
