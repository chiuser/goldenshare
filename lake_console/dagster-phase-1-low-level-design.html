Dagster 第一期 Low Level Design

本文档是《Dagster 第一期方案设计：市场广度最小闭环》的低层技术设计。 它用于指导下一步编码落地，重点写清模块结构、asset/resource/check/partition 的实现边界、DuckDB 读写口径、metadata 输出和验证门禁。

项目目录lake_console/orchestrator
Lake Root/Volumes/datasource/data_lake
第一期范围trade calendar、stock basic、stock daily、market breadth
明确不做Tushare 同步、ClickHouse serving、prod release、自动调度

1. 依据与边界

本低层设计只承接第一期已确认方案，不扩展新需求。第一期 raw 数据来自已经准备好的新湖 raw 文件；Dagster 负责登记、校验、标准化、计算和观测。
依据 用途 本文采用口径
lake_console/dagster-phase-1-design.html 第一期业务与数据资产方案 本文所有 asset、path、字段、check 只从该方案下钻，不另造资产范围。
lake_console/orchestrator/AGENTS.md Dagster 目录开发门禁 raw/silver/gold 三层、Tushare 事实核验、DuckDB hive partition 读取门禁。
Dagster 官方 assets 文档 资产定义依据 使用 @dg.asset 表达长期存在、可观测、可重跑的数据资产。
Dagster 官方 resources 文档 外部能力注入依据 使用 resource 管理 Lake Root 与 DuckDB，不把路径和连接逻辑散落到 asset 内部。
Dagster 官方 partitions / checks 文档 分区与质量检查依据 交易日使用 dynamic partitions；质量检查使用 asset checks，阻断和观察分开。

raw_tushare_trade_calendar

@dg.asset(key="raw_tushare_trade_calendar")
def raw_tushare_trade_calendar(lake_root, duckdb) -> dg.MaterializeResult:
    path = lake_root.raw_path("tushare", "trade_calendar", "full", "part-000.parquet")
    lake_root.ensure_available_for_run()
    assert_file_exists(path)
    schema = duckdb_describe(path)
    row_count = duckdb_count(path)
    return dg.MaterializeResult(metadata={
        "path": str(path),
        "row_count": row_count,
        "columns": schema.columns,
        "raw_contract": "trade_cal source mirror: cal_date/pretrade_date YYYYMMDD, is_open 0/1"
    })

silver_stock_daily

WITH raw AS (
  SELECT *
  FROM read_parquet(:raw_path, hive_partitioning=false)
),
conflicts AS (
  SELECT
    ts_code,
    trade_date,
    COUNT(DISTINCT hash(open, high, low, close, pre_close, change, pct_chg, vol, amount)) AS fact_versions
  FROM raw
  GROUP BY ts_code, trade_date
  HAVING fact_versions > 1
),
deduped AS (
  SELECT DISTINCT *
  FROM raw
)
SELECT
  ts_code,
  strptime(trade_date, '%Y%m%d')::DATE AS trade_date,
  open,
  high,
  low,
  close,
  pre_close,
  change AS change_amount,
  pct_chg,
  vol,
  amount
FROM deduped
如果 conflicts 有行，asset 必须失败，不能自动挑一条事实。 完全重复行可以 distinct，但必须输出 duplicate_removed_count、duplicate_key_count、duplicate_sample_rows。

gold_market_breadth_daily

SELECT
  trade_date,
  SUM(CASE WHEN pct_chg > 0 THEN 1 ELSE 0 END) AS up_count,
  SUM(CASE WHEN pct_chg < 0 THEN 1 ELSE 0 END) AS down_count,
  SUM(CASE WHEN pct_chg = 0 THEN 1 ELSE 0 END) AS flat_count,
  COUNT(*) AS total_count,
  CASE
    WHEN COUNT(*) = 0 THEN 0.0
    ELSE ROUND(SUM(CASE WHEN pct_chg > 0 THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2)
  END AS red_rate
FROM read_parquet(:silver_path)
WHERE trade_date = :partition_date
  AND pct_chg IS NOT NULL
GROUP BY trade_date

7. Dynamic Partitions 设计

cn_a_trade_days 是 Dagster dynamic partitions 定义。它保存 Dagster 认识的交易日 partition keys。 第一期开工时不从自然日推导，也不手写节假日；只从 silver_trade_calendar 读取 SSE is_open=true 的日期。 

cn_a_trade_days = dg.DynamicPartitionsDefinition(name="cn_a_trade_days")

手动同步 job

@dg.op
def sync_cn_a_trade_day_partitions(context, lake_root, duckdb):
    silver_path = lake_root.silver_path("calendar", "trade_calendar", "full", "part-000.parquet")
    keys = duckdb_query("""
      SELECT strftime(trade_date, '%Y-%m-%d') AS partition_key
      FROM read_parquet(?)
      WHERE exchange = 'SSE'
        AND is_open = true
        AND trade_date BETWEEN DATE '2026-04-01' AND DATE '2026-04-30'
      ORDER BY trade_date
    """, [silver_path])

    context.instance.add_dynamic_partitions("cn_a_trade_days", keys)
    context.log.info(f"registered {len(keys)} cn_a_trade_days partition keys")
这个 job 只是注册 Dagster partition keys，不产出 raw/silver/gold 数据文件，所以不定义成数据资产。

持久 instance 门禁

注册 dynamic partitions 时，必须使用正式 Dagster instance。 如果直接调用 job.execute_in_process() 且不传 instance，Dagster 会使用临时 instance； job 可能显示成功，但 partition keys 不会进入本地正式 DAGSTER_HOME 对应的持久状态。 

本地验证必须使用：
  os.environ["DAGSTER_HOME"] = "/Users/congming/.goldenshare/dagster_home"
  instance = dg.DagsterInstance.get()
  job.execute_in_process(instance=instance, resources={...})

验证注册结果必须从同一个正式 instance 读取：
  keys = instance.get_dynamic_partitions("cn_a_trade_days")

禁止：
  1. 用默认 execute_in_process() 的临时 instance 验证 dynamic partition 注册
  2. 看到 job success=True 就认定 partition keys 已持久注册
  3. 不读取正式 DAGSTER_HOME 对应 instance 就进入下游分区资产开发

8. Asset Checks 低层设计

每个 check 只验证一个属性。阻断 check 使用 blocking 语义；观察 check 不阻断下游运行，但必须在 metadata 中输出差异统计和样本。

Asset Check 实现要点 门禁
raw_tushare_trade_calendar raw_trade_calendar_required_columns 必须包含 exchange/cal_date/is_open/pretrade_date。 阻断
silver_trade_calendar silver_trade_calendar_has_open_days_in_poc_range 2026-04 范围内存在 SSE is_open=true 的交易日。 阻断
silver_stock_basic silver_stock_basic_known_list_status_values list_status 只允许 L/D/P/G。 阻断
raw_tushare_stock_daily raw_stock_daily_partition_date_matches 文件内 YYYYMMDD 与 partition key 归一化为 date 后一致。 阻断

9. 写文件与原子替换策略

silver/gold asset 会生成新的 parquet 文件。写入时使用同目录临时文件，然后原子替换正式文件。 这样可以避免 run 中途失败时留下半个正式文件。 

target = .../part-000.parquet
tmp = .../part-000.parquet.tmp

COPY (SELECT ...) TO tmp (FORMAT PARQUET)
validate tmp row count and schema
os.replace(tmp, target)
raw 文件第一期不由 Dagster 生产，只登记和校验。 silver/gold 可以由 Dagster 写入；任何写入路径必须由 LakeRootResource 生成，禁止字符串拼接到旧湖目录。

10. 测试与验证门禁

验证项 命令或方式 通过标准
Dagster definitions 加载 uv run dg check defs code location 能加载，移动盘缺失不应导致导入失败。
raw schema 核验 read_parquet(path, hive_partitioning=false) stock daily 文件内部 trade_date 是 YYYYMMDD 字符串。
交易日 partitions 运行 sync_cn_a_trade_day_partitions 使用正式 DAGSTER_HOME 对应 instance 注册，只注册 2026-04 的 SSE is_open=true 日期。
silver/gold 产出 materialize 2026-04 单日样本，再扩到全月 metadata 中可见 path、row_count、columns、重复行统计、完整性观察差异。
asset checks 回归 使用 Definitions 注册 assets 与 asset checks，再通过 asset job / selection 执行。 checks 必须来自正式 Dagster definitions，不能只靠临时脚本 import。
文档一致性 对照本文与第一期方案文档 字段、路径、check 名称、阻断口径一致。

Dagster materialize 与 asset checks 门禁

当前 Dagster 版本的 dagster.materialize() 是轻量脚本验证 API，不接受 asset_checks= 参数。 它可以用于只验证 assets 的临时运行，但不能作为完整的 asset + checks 验收模型。 

正确验收模型：
  1. 所有 assets 和 asset checks 必须注册进 Definitions
  2. 通过 Dagster asset job / asset selection / implicit global asset job 执行
  3. schedule、sensor、backfill、自动化也必须基于正式 Definitions 解析

禁止：
  1. 只在测试脚本里临时 import checks，却不让 load_from_defs_folder 自动发现
  2. 把 dagster.materialize() 当成完整的生产运行模型
  3. 用只跑 asset 的结果替代 asset checks 验收

允许：
  1. dagster.materialize() 可用于只跑 asset 的小范围冒烟验证
  2. asset checks 回归必须使用 Definitions + asset job / selection
