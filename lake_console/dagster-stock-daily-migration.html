Stock Daily 历史迁移设计

本文档单独记录 daily 从旧湖迁移到新湖的口径。它不是一个孤立数据集迁移， 必须同时依赖 stock_basic 提供股票池边界，依赖 suspend_d 修正停牌语义， 最终让 silver_stock_daily 成为后续 gold_market_breadth_daily 可稳定消费的标准事实资产。

1. 核心结论

raw

raw_tushare_stock_daily 保持源站镜像

raw_tushare_stock_daily 不做当前上市股票过滤，不做上市日过滤，不做 BJ 起始日过滤。 它继续保留旧湖中按 Tushare daily 源口径取得的全部日线记录。

silver

silver_stock_daily 才定义标准事实边界

silver_stock_daily 从 raw 中筛选出：2014-01-01 之后、当前上市股票、 股票上市日之后、BJ 自 2021-11-15 起的数据，并完成字段类型标准化。

check

停牌语义不再混淆

全日停牌仍然定义为 suspend_type='S' AND suspend_timing IS NULL。 盘中临时停牌定义为 suspend_type='S' AND suspend_timing IS NOT NULL。 旧湖中 14 条缺失 suspend_timing 的盘中停牌，必须在 silver 层修正； 旧湖缺失的长期全日停牌记录也只在 silver 层补充，不回写 raw。

boundary

日期类型原则

raw 中的 Tushare 日期字段保持源站字符串，例如 trade_date='20260515'。 silver 中具备明确日期语义的字段统一标准化为 DATE。

decision

已拍板实现边界

silver_stock_basic 正式只保留 list_status='L'； silver_stock_daily_price_sanity 作为阻断 check； 14 条 suspend_timing 修正规则先放代码常量； 全日停牌缺失补充以已审计 S 清单为依据，通过 Dagster metadata 留痕。

4. 数据资产口径

raw raw_tushare_stock_basic raw/tushare/stock_basic/full/part-000.parquet
保持 Tushare stock_basic 显式字段全集，日期字段在 raw 中保持 YYYYMMDD 字符串或 null。
↓
silver silver_stock_basic silver/basic/stock_basic/full/part-000.parquet
标准化日期字段为 DATE。本迁移口径下，silver 股票池只保留当前 list_status='L' 的股票。
↓
raw raw_tushare_stock_daily[trade_date] raw/tushare/stock_daily/trade_date=YYYY-MM-DD/part-000.parquet
保持 Tushare daily 源口径，保留旧湖该交易日全部日线记录。raw 中 trade_date 保持 YYYYMMDD 字符串，字段名仍为 change。
↓
silver silver_stock_daily[trade_date] silver/quote/stock_daily/trade_date=YYYY-MM-DD/part-000.parquet
从 raw 中筛选标准事实：trade_date >= 2014-01-01、当前上市股票、trade_date >= list_date、 .BJ 只保留 2021-11-15 及之后。字段标准化：trade_date 转 DATE，change 改为 change_amount，数值字段转统一数值类型。
↓
gold gold_market_breadth_daily[trade_date]
下游市场宽度只消费 silver_stock_daily，不直接读取 raw，不在 gold 层重复做股票池过滤。

5. 停复牌修正口径

suspend_d raw 保持源镜像，不修改源字段。旧湖和 Tushare 当前接口中存在 14 条盘中停牌记录， suspend_type='S' 但 suspend_timing 为空。它们会被误判为全日停牌， 因此必须在 silver_stock_suspend_daily 层补充 timing。这里的“修正”是实实在在写入 suspend_timing 业务字段：raw 中为空，silver 中写成确认后的盘中停牌时间。 但 silver parquet 不额外增加 is_manual_corrected、correction_reason 这类人工修正标记字段，避免污染业务数据结构。

全日停牌缺失补充口径

除 14 条盘中停牌 timing 修正外，历史 suspend_d 还存在一类问题： 某些股票在较长时间内没有 daily 记录，人工审计确认其原因是全日停牌， 但旧湖 suspend_d 没有覆盖对应 S + suspend_timing NULL 记录。 这类数据不回写 raw；raw 继续保持源镜像。补充只发生在 silver_stock_suspend_daily，作为标准事实层对停牌事实的补齐。

最新审计以旧湖最新 daily 为准，而不是以新湖是否已经跑过分区为准。 人工未标 S 的 3 条缺失已在旧湖补齐 daily； 当前剩余缺失为 29 只股票、4022 个交易日，全部被已标 S 的清单覆盖。920188.BJ 悦龙科技 2026-03-30 和 2026-03-31 旧湖已经有 daily， 不应进入全日停牌补充。 

全日停牌补充记录:
  ts_code = 审计清单中的股票代码
  trade_date = 审计清单覆盖的交易日
  suspend_type = 'S'
  suspend_timing = NULL
补充清单生成原则： 不能机械按 CSV 原始区间全量补。必须先用旧湖最新 daily 重新计算 unexplained_missing，再取 当前仍缺 daily 的记录 ∩ 人工标记 S 的区间 生成补充清单。 如果某个日期已经存在 daily，即使 CSV 区间标了 S，也不能补全日停牌。

silver_stock_suspend_daily 生成时应执行： 

silver_suspend =
  raw suspend_d 标准化结果
  + 14 条盘中停牌 timing 修正后的结果
  + 当前仍缺 daily 且人工确认 S 的全日停牌补充记录

冲突处理必须保守：若同一 ts_code + trade_date 在 raw suspend 中已有非 S + NULL 的记录，且补充规则试图再写入全日停牌，应直接失败并输出冲突样本； 若补充规则覆盖的日期在旧湖最新 daily 中已有记录，应跳过或在生成补充清单阶段剔除， 禁止制造“全日停牌但有日线”的新冲突。

已人工拍板的 raw 冲突例外只在 silver 层修正，不直接改 raw 文件： 688766.SH 普冉股份 2025-11-26 在 silver 中输出为 S + NULL，raw 中同日同股票的 R + NULL 不进入 silver； 688005.SH 容百科技 2026-01-16 在 silver 中输出为 S + NULL。这类例外必须通过 Dagster metadata 记录 raw override 数量、版本和样本。

Dagster 留痕方式

不新增 silver_suspend_d_known_timing_corrections_applied 这类 check。 Dagster 官方支持在 asset materialization 上附加 metadata，并在 Asset Details 的 Activity 中展示。 因此修正结果写入 silver parquet 的 suspend_timing 字段；修正过程的审计留痕采用 materialization metadata，而不是额外 parquet 字段或 blocking check。 14 条修正规则在实现中先放代码常量；等后续数据修补完成、全量 checks 稳定通过后，删除这段临时修正常量。 这不是长期数据模型的一部分。

6. Checks 设计

raw_tushare_stock_daily

Check 阻断 口径
raw_stock_daily_file_exists是目标分区 raw parquet 必须存在。
raw_stock_daily_row_count_positive是交易日 raw 行数必须大于 0。
raw_stock_daily_required_columns是必须包含 Tushare daily 字段：ts_code/trade_date/open/high/low/close/pre_close/change/pct_chg/vol/amount。
raw_stock_daily_partition_date_matches是raw 内部 trade_date 字符串转换后必须等于 partition key。

silver_stock_daily

Check 阻断 口径
silver_stock_daily_row_count_positive是标准事实分区必须有数据。
silver_stock_daily_unique_ts_code_trade_date是ts_code + trade_date 必须唯一。
silver_stock_daily_conflicting_duplicate_absent是同一 key 出现不同字段内容时直接失败。
silver_stock_daily_required_columns_non_null是ts_code、trade_date、pct_chg 不允许为空。
silver_stock_daily_partition_date_matches是silver 内部 trade_date 是 DATE，必须等于 partition key。
silver_stock_daily_current_listed_only是不允许出现非当前 list_status='L' 股票。
silver_stock_daily_after_list_date_only是不允许出现股票上市日前日线。
silver_stock_daily_bj_after_market_open_only是BJ 股票不允许出现 2021-11-15 前日线。
silver_stock_daily_price_sanity是阻断。价格字段不允许为负；不允许 high < low；必须满足 high >= open >= low、high >= close >= low。审计结果为 0。
silver_stock_daily_row_count_not_greater_than_raw否观测项。silver 经过筛选，行数应小于等于 raw。

silver_stock_suspend_daily

Check 阻断 口径
silver_suspend_d_known_type_values是suspend_type 只能为 S/R。
silver_suspend_d_unique_business_key是ts_code + trade_date + suspend_type + coalesce(suspend_timing,'') 不重复。
silver_suspend_d_full_day_not_conflict_with_daily否观测项。修正后全日停牌但 daily 有记录应为 0；若未来 Tushare 源再次出现歧义，先上报样本。

7. 推进顺序

  1. 先更新 Phase 2 方案文档和 LLD，把本文档确认的 daily 迁移口径同步进去。
  2. 改造 silver_stock_basic，只输出当前 list_status='L' 股票，并调整对应 checks。
  3. 改造 silver_stock_suspend_daily，增加 14 条 timing 修正常量；增加全日停牌缺失补充规则；两类修正都通过 materialization metadata 留痕，不新增修正命中 blocking check。
  4. 改造 silver_stock_daily，从 raw 中执行当前上市、上市日、BJ 起始日、2014 起始日过滤。
  5. 保留 raw_tushare_stock_daily 源镜像口径，不做业务筛选。
  6. 重写 stock daily 完整性观测口径，避免把盘中停牌误判为全日停牌。
  7. 跑 2014-01-02 至 2026-05-15 全量 bootstrap 验收。
  8. 全量迁移验收通过后，再进入 Tushare API 新数据续更新，避免历史 bootstrap 与新数据同步混在一起。

9. 不做的事

  • 本轮不把 raw 也改成当前上市股票子集，raw 必须继续保留源镜像口径。
  • 本轮不接入 Tushare API 续更新；全量 bootstrap 已完成，API 新数据更新进入下一步 Slice 2.1。
