Stock Daily 历史迁移 Low Level Design

本文档把 dagster-stock-daily-migration.html 中已经拍板的历史迁移设计落成技术实现方案。 本轮只覆盖旧湖到新湖的历史 bootstrap，不接入 Tushare API 续更新，不引入 sensor、schedule、ClickHouse 或 prod release。

1. 依据与边界

Dagster

官方依据

Dagster 官方文档说明 runtime metadata 可以通过 MaterializeResult(metadata=...) 附加到 asset materialization，用于在 UI 中展示行数、schema、处理信息等。 Asset checks 用于验证数据属性，且阻断下游需要设置 blocking=True。 历史分区补齐属于 backfill 场景。

  • Asset metadata and tags
  • Asset checks
  • Partitioning assets
  • Backfilling data
Scope

本 LLD 范围

只设计 stock_basic、suspend_d、stock_daily 三个数据资产的历史迁移落地。核心目标是让 silver_stock_daily 在新口径下稳定可用，并作为 gold_market_breadth_daily 的可信上游。

Raw

raw 不做业务过滤

raw_tushare_stock_daily 保持 Tushare/旧湖源镜像口径，保留该交易日旧湖 daily 的全部源记录。 不因为当前迁移只消费上市股票，就把 raw 裁剪成当前股票池子集。

Silver

silver 定义标准事实边界

silver_stock_daily 执行四类过滤：2014-01-01 后、当前上市、 上市日后、BJ 自 2021-11-15 起。silver 日期字段统一为 DATE。

4. SQL 实现细节

4.1 silver_stock_basic_select

SELECT
  ts_code,
  symbol,
  name,
  area,
  industry,
  market,
  exchange,
  list_status,
  CAST(strptime(list_date, '%Y%m%d') AS DATE) AS list_date,
  CASE
    WHEN delist_date IS NULL OR trim(delist_date) = '' THEN NULL
    ELSE CAST(strptime(delist_date, '%Y%m%d') AS DATE)
  END AS delist_date,
  is_hs
FROM read_parquet(raw_stock_basic_path, hive_partitioning=false)
WHERE list_status = 'L'

raw stock basic 仍保留 L/D/P/G 等全部源状态；silver basic 是本迁移阶段的当前上市股票池。

4.2 silver_stock_suspend_daily_select

WITH corrections(ts_code, trade_date, corrected_timing) AS (
  VALUES
    ('000566.SZ', DATE '2014-01-02', '13:55-15:00'),
    ...
),
normalized AS (
  SELECT
    CAST(ts_code AS VARCHAR) AS ts_code,
    CAST(strptime(trade_date, '%Y%m%d') AS DATE) AS trade_date,
    NULLIF(trim(CAST(suspend_timing AS VARCHAR)), '') AS suspend_timing,
    CAST(suspend_type AS VARCHAR) AS suspend_type
  FROM read_parquet(raw_suspend_d_path, hive_partitioning=false)
)
SELECT
  normalized.ts_code,
  normalized.trade_date,
  COALESCE(corrections.corrected_timing, normalized.suspend_timing) AS suspend_timing,
  normalized.suspend_type
FROM normalized
LEFT JOIN corrections
  ON normalized.ts_code = corrections.ts_code
 AND normalized.trade_date = corrections.trade_date

修正结果写入业务字段 suspend_timing。不增加 is_manual_corrected 这类字段。materialization metadata 记录修正数量、规则版本和样本。

4.3 silver_stock_daily_select

WITH normalized AS (
  SELECT
    ts_code,
    CAST(strptime(trade_date, '%Y%m%d') AS DATE) AS trade_date,
    CAST(open AS DOUBLE) AS open,
    CAST(high AS DOUBLE) AS high,
    CAST(low AS DOUBLE) AS low,
    CAST(close AS DOUBLE) AS close,
    CAST(pre_close AS DOUBLE) AS pre_close,
    CAST(change AS DOUBLE) AS change_amount,
    CAST(pct_chg AS DOUBLE) AS pct_chg,
    CAST(vol AS DOUBLE) AS vol,
    CAST(amount AS DOUBLE) AS amount
  FROM read_parquet(raw_stock_daily_path, hive_partitioning=false)
),
deduped AS (
  SELECT DISTINCT *
  FROM normalized
),
listed AS (
  SELECT ts_code, list_date
  FROM read_parquet(silver_stock_basic_path, hive_partitioning=false)
  WHERE list_status = 'L'
)
SELECT deduped.*
FROM deduped
INNER JOIN listed USING (ts_code)
WHERE deduped.trade_date >= DATE '2014-01-01'
  AND deduped.trade_date >= listed.list_date
  AND (
    NOT ends_with(deduped.ts_code, '.BJ')
    OR deduped.trade_date >= DATE '2021-11-15'
  )

raw_stock_daily 的冲突检查必须在写 silver 前执行，避免 SELECT DISTINCT 静默吞掉同一 key 的多版本事实。

5. Asset 实现细节

Asset 实现要点 Materialization metadata
raw_tushare_stock_basic 继续使用 bootstrap full file；不改 raw 源字段。 row_count、columns、list_status_distribution。
silver_stock_basic 使用新 SQL 只保留 list_status='L'；日期字段转 DATE。 row_count、columns、source_row_count、filtered_out_count、list_status_distribution。
raw_tushare_suspend_d[date] 继续使用 bootstrap partition；允许 0 行；raw 中 trade_date 是 YYYYMMDD 字符串。 row_count、columns、source_method、partition_key。
silver_stock_suspend_daily[date] 日期转 DATE；14 条已知盘中停牌修正写入 suspend_timing。 row_count、columns、suspend_timing_correction_count、suspend_timing_correction_version、suspend_timing_correction_sample_rows。
raw_tushare_stock_daily[date] 继续使用 bootstrap partition；保留旧湖该交易日全部 daily 源记录；不做股票池过滤。 row_count、columns、source_method、partition_key。
silver_stock_daily[date] 依赖 raw_tushare_stock_daily 和 silver_stock_basic；先做冲突检查，再写标准事实 parquet。 row_count、raw_row_count、filtered_out_count、current_listed_count、duplicate_removed_count、conflict_key_count。

6. Checks 实现细节

6.1 stock_basic checks

Check 阻断 实现要点
silver_stock_basic_unique_ts_code是当前上市股票池中 ts_code 唯一。
silver_stock_basic_required_columns_non_null是ts_code/symbol/name/list_date 非空。
silver_stock_basic_current_listed_only是所有行必须 list_status='L'，否则失败并输出样本。
silver_stock_basic_lifecycle_dates_valid是若存在 delist_date，不得早于 list_date。

6.2 suspend_d checks

Check 阻断 实现要点
raw_suspend_d_schema_matches_tushare_contract是raw 字段和类型必须符合 Tushare source mirror 契约。
silver_suspend_d_known_type_values是suspend_type 只能为 S/R。
silver_suspend_d_unique_business_key是ts_code + trade_date + suspend_type + coalesce(suspend_timing,'') 不重复。
silver_suspend_d_full_day_not_conflict_with_daily否观测型。全日停牌但 daily 有记录应为 0；失败先输出样本，不阻断本轮迁移。

6.3 stock_daily checks

Check 阻断 实现要点
raw_stock_daily_file_exists是分区 raw 文件存在。
raw_stock_daily_row_count_positive是交易日 raw 行数大于 0。
raw_stock_daily_required_columns是包含 Tushare daily raw 字段。
raw_stock_daily_partition_date_matches是raw trade_date 字符串转日期后等于 partition key。
silver_stock_daily_unique_ts_code_trade_date是silver 中 ts_code + trade_date 唯一。
silver_stock_daily_conflicting_duplicate_absent是同一 key 多版本内容直接失败，metadata 输出 key 和行样本。
silver_stock_daily_required_columns_non_null是ts_code、trade_date、pct_chg 非空。
silver_stock_daily_partition_date_matches是silver trade_date 是 DATE，等于 partition key。
silver_stock_daily_current_listed_only是不允许出现非当前 list_status='L' 股票。
silver_stock_daily_after_list_date_only是不允许出现 trade_date < list_date。
silver_stock_daily_bj_after_market_open_only是BJ 股票不允许出现 2021-11-15 前数据。
silver_stock_daily_price_sanity是价格非负，且 high >= open >= low、high >= close >= low。
silver_stock_daily_row_count_not_greater_than_raw否观测型。silver 经筛选后行数应小于等于 raw。

7. Partition 与历史回填执行

raw_tushare_stock_daily、raw_tushare_suspend_d、silver_stock_daily、 silver_stock_suspend_daily 都使用 cn_a_trade_days dynamic partitions。 历史迁移前必须确认 2014-01-02 至 2026-05-15 的 3004 个交易日 partition key 已经注册到正式 Dagster instance。

步骤 动作 风险门禁
1 读取 silver_trade_calendar 中 SSE open day，范围为 2014-01-02 到 2026-05-15。 不得用自然日生成 partition key。
2 把缺失的交易日注册到 cn_a_trade_days。 必须使用正式 DAGSTER_HOME=/Users/congming/.goldenshare/dagster_home。
3 先跑 raw_tushare_stock_basic 与 silver_stock_basic。 basic 是 daily silver 过滤前置条件，失败则停止。
4 对 3004 个交易日回填 suspend_d 与 stock_daily raw/silver。 建议先小批量，再全量；不要直接一口气跑全量。
5 检查 Dagster UI materialization、checks、metadata。 不能只看文件存在；必须看正式 instance 的运行记录。

9. 技术风险与停下条件

风险 影响 防控方式 停下条件
误把 raw 做成业务过滤结果 破坏 raw 源镜像，后续无法按新口径重算。 raw_tushare_stock_daily bootstrap select 禁止 join stock_basic。 发现 raw 行数小于旧湖源行数且无法解释时停止。
partition keys 未注册 历史分区无法 materialize，或跑到临时 instance 看不到。 所有 dynamic partition 注册和验证都使用正式 DAGSTER_HOME。 正式 instance 读不到 3004 个目标 partition key 时停止。
suspend 修正常量长期遗留 迁移补丁变成长期业务逻辑。 放在 corrections/suspend_timing.py，文档记录删除条件。 源数据修补后仍保留修正常量时必须开清理任务。
price sanity 规则过严 历史特殊交易日可能被阻断。 已审计异常为 0；小批量先跑关键日期。 任一价格 sanity 失败时停止，不临时降级。
silver basic 只保留 L 影响其他资产 未来若有资产需要退市股票生命周期，会拿不到。 本 LLD 只约束本迁移口径；未来若需要全生命周期，应另建资产而不是复用当前 silver basic。 发现现有下游依赖 D/P/G 时停止并重新拆资产边界。
SELECT DISTINCT 掩盖源数据问题 完全重复可接受，但内容冲突不能静默处理。 先跑 conflict check，再写 silver；metadata 上报 duplicate_removed_count 和样本。 conflict_key_count 大于 0 时停止。
全量回填一次性跑太大 Dagster run 数量多、DuckDB 读写压力大、移动盘 I/O 压力大。 先单日，再小批量，再按年份或月份分批回填。 出现 I/O 错误、run 大量失败、移动盘不可用时停止。
文档和实现偏离 后续继续开发时口径漂移。 实现完成后必须同步更新设计文档、LLD 和 AGENTS 中的门禁结论。 发现代码口径与本文档不一致时停止进入下一 slice。
