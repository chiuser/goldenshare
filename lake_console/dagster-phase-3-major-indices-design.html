Dagster Phase 3 指数数据生产链路设计（合并版）

本文件合并原“主要指数 Phase 3 方案”和后续“Index Daily 重构方案”的当前有效口径。 旧 active pool、旧 raw-by-trade-date、旧 history backfill、旧 repair job 已不再是可执行设计。 后续开发必须以本文件、重构设计和重构 LLD 为准。

当前准口径raw 按指数代码分区，silver 按交易日分区。
旧口径状态旧链路已从 active Definitions 退场，文档不再保留旧实现教程。
当前阶段raw-by-code 已完成历史回填，silver 历史生成正在推进。
后续重点补齐 silver_index_daily_sensor，让 silver 自动响应 raw ready。

1. 合并后的核心结论

Phase 3 指数链路只保留一套方向：指数日线 raw 以 ts_code 为分区拉取和保存， silver_index_daily 继续以 trade_date 为分区生成。 指数池不再通过本地 PostgreSQL active pool 维护，而是通过 Dagster dynamic partitions cn_a_index_ts_codes 表达可生产指数集合。
问题 当前口径
指数代码集合从哪里来 cn_a_index_ts_codes dynamic partitions。第一版由连续性审计 CSV 初始化，后续增删改查通过 Dagster partition 管理能力或受控脚本完成。
raw 如何保存 raw_tushare_index_daily_by_code[ts_code]，物理路径按 ts_code 分区，文件内保存该指数的时间序列。
silver 如何保存 silver_index_daily[trade_date]，物理路径按交易日分区，从所有注册指数代码的 raw-by-code 文件中筛选当天记录生成。
日更如何触发 index_trade_day_sensor 只注册指数交易日；index_daily_sensor 在源站 ready 后触发 raw-by-code；silver 自动触发留给 silver_index_daily_sensor。
主要指数名单如何使用 gold_market_major_indices 是首页展示名单，不再充当指数日线生产池。它只需要校验名单代码存在于 silver_index_basic 和 cn_a_index_ts_codes。

2. 当前资产图

cn_a_index_ts_codes dynamic partitions
  -> raw_tushare_index_daily_by_code[ts_code]
       path: raw/tushare/index_daily_by_code/ts_code=<TS_CODE>/part-000.parquet

cn_a_index_trade_days dynamic partitions
  -> silver_index_daily[trade_date]
       reads all registered raw_tushare_index_daily_by_code files
       path: silver/index_daily/trade_date=YYYY-MM-DD/part-000.parquet

raw_tushare_index_basic
  -> silver_index_basic
       used by index metadata checks and major index list checks

gold_market_major_indices
  -> homepage major index display list
       checked against silver_index_basic and cn_a_index_ts_codes
raw raw_tushare_index_daily_by_code 以 ts_code 为 partition key。run config 提供 start_date、end_date、write_mode=replace。
silver silver_index_daily 以 trade_date 为 partition key。日期字段标准化为 DATE，change 标准化为 change_amount。
gold gold_market_major_indices 首页主要指数展示名单。它不是日线 active pool，不驱动 index_daily 请求范围。

3. 当前 Jobs 和 Sensors

类型 名称 职责 边界
job index_daily_update_job 只 materialize raw_tushare_index_daily_by_code[ts_code] 及其 raw checks。 不生成 silver，不读取旧 active pool。
job silver_index_daily_update_job 只 materialize silver_index_daily[trade_date] 及其 silver checks。 不触发 raw；缺 raw 文件时失败。
sensor index_trade_day_sensor 从交易日历注册 cn_a_index_trade_days。 不触发 raw，不触发 silver。
sensor index_daily_sensor 判断目标交易日和 Tushare index_daily ready 后，为缺少目标日期 raw 的指数代码触发 index_daily_update_job。 单 tick 最大 500 个 run request；不触发 silver。
planned silver_index_daily_sensor 后续用于判断 raw-by-code 全部 ready 后触发 silver_index_daily_update_job[trade_date]。 未实现。Slice G 单独设计和开发。

4. 旧实现禁止复活清单

下列名称只允许出现在历史审计、退场说明或数据库清理计划中，不允许重新作为 Phase 3 的生产入口、资产依赖、job selection 或实现方案。
旧对象 当前处置 禁止事项
silver_index_daily_active_pool 已从 active Definitions 删除。 不得作为 silver_index_daily 的上游，不得作为指数日线请求池。
index_daily_active_pool_update_job 已退场。 不得恢复为指数池维护入口。
raw_tushare_index_daily[trade_date] 旧 raw-by-trade-date asset 已删除。 不得重新按交易日聚合拉取 raw。
index_daily_history_backfill_job 已退场。 历史重建使用当前 partitioned asset job / backfill 能力，不恢复旧普通 job。
index_daily_repair_by_codes_job 已退场。 按代码修复应走 index_daily_update_job[ts_code]，不恢复旧 repair job。
goldenshare_lake_meta.index_daily_active_pool* 数据库遗留对象。是否 drop 需单独备份、清单和审批。 不得继续作为生产事实源读取。
