Dagster 第一期方案设计：市场广度最小闭环

本文是下一步开发前置设计文档，只覆盖第一期闭环：旧数据湖数据进入新 <LAKE_ROOT>/raw 后， 由 Dagster 管理 trade_calendar、stock_basic、stock_daily、market_breadth_daily 的资产、分区、运行状态和质量检查。

文档状态第一期开发前设计稿
项目位置lake_console/orchestrator
数据根目录/Volumes/datasource/data_lake
第一期范围2026 年 4 月 A 股交易日

1. 第一期开工边界

第一期只解决一个问题：把旧数据湖中已存在的数据放入新 <LAKE_ROOT>/raw 后，验证 Dagster 是否能稳定管理本地 Parquet 数据湖的资产依赖、交易日分区、DuckDB 计算和小颗粒度 checks。
项目 第一期口径
数据来源 旧数据湖已有数据进入新 <LAKE_ROOT>/raw。本文不展开旧路径细节，不把旧路径写入 Dagster asset 正式 path。
数据生产 不属于第一期开发内容。第一期 asset 以新 raw 路径中的文件作为输入事实。
外部接口 第一期不实现 Tushare 拉取链路，不新增 TushareResource。
远程数据库 第一期不从 prod DB 拉取数据。
资产数量 只做 trade_calendar、stock_basic、stock_daily、market_breadth_daily 和一个手动交易日分区同步步骤。
自动化 第一期分步骤手动执行，不上 sensor 自动同步，不做 schedule。
服务层 第一期不写 ClickHouse serving，不做 prod release package，不改线上 API。

5. 分区设计

第一期使用 Dagster DynamicPartitionsDefinition，名称为 cn_a_trade_days。 partition key 来自 silver_trade_calendar，不使用自然日、工作日或手写节假日规则推导 A 股交易日。

输入事实 silver_trade_calendar 中 exchange="SSE"、is_open=true 的日期。
注册范围 只注册 2026-04-01 到 2026-04-30 范围内的开市日。
保存位置 由 Dagster instance storage 保存。当前本机 Dagster storage 使用 goldenshare_dagster。
使用方式 raw_tushare_stock_daily、silver_stock_daily、gold_market_breadth_daily 共享这组交易日 key。
不使用分区的资产 raw_tushare_stock_basic、silver_stock_basic 和交易日历完整文件不按 cn_a_trade_days 分区。

手动同步步骤

第一期定义一个手动触发的 Dagster job/op，例如 sync_cn_a_trade_day_partitions。 它读取 silver_trade_calendar，筛出 2026 年 4 月开市日，然后调用 Dagster dynamic partitions add request，把日期注册到 cn_a_trade_days。 

silver_trade_calendar
  -> filter exchange = "SSE"
  -> filter is_open = true
  -> filter 2026-04-01 <= trade_date <= 2026-04-30
  -> add partition keys to cn_a_trade_days

注册后，Dagster 执行某个分区资产时，asset 函数通过 context.partition_key 拿到日期，例如 2026-04-08， 再用这个日期拼出对应 Parquet 输入路径和输出路径。

7. 字段和计算口径

trade_calendar

层级 字段 口径
raw exchange、cal_date、is_open、pretrade_date 按 Tushare trade_cal 文档字段理解。pretrade_date 若存在则保留并标准化。
silver exchange、trade_date、is_open、pretrade_date cal_date 改为 trade_date，日期字段转为 date，is_open 转为布尔语义。

stock_basic

层级 字段 口径
raw ts_code、symbol、name、area、industry、fullname、enname、cnspell、market、exchange、curr_type、list_status、list_date、delist_date、is_hs、act_name、act_ent_type 按 Tushare stock_basic 文档字段。第一期 raw 路径使用旧湖已有 parquet 进入新 raw。
silver ts_code、symbol、name、area、industry、market、exchange、list_status、list_date、delist_date、is_hs list_date、delist_date 转 date；ts_code 唯一；保留生命周期字段用于 silver_stock_daily 完整性观察 check。

判断某个交易日理论上市股票集合时，不只依赖当前 list_status = 'L'。 第一 期使用生命周期口径： 

list_date <= trade_date
and (delist_date is null or delist_date > trade_date)

stock_daily

层级 字段 口径
raw ts_code、trade_date、open、high、low、close、pre_close、change、pct_chg、vol、amount 按 Tushare A 股日线文档字段。raw 层字段为 change，不是 change_amount。
silver ts_code、trade_date、open、high、low、close、pre_close、change_amount、pct_chg、vol、amount change 标准化为 change_amount。trade_date 转 date，数值字段转数值类型。

market_breadth_daily

当前服务代码核验结果：涨跌分布以当天 stock_daily 中 pct_chg 非空的记录作为统计母体，不额外引入股票池、上市状态、停牌状态、ST 标记或其他证券范围过滤。

输入过滤：
  trade_date = partition_key
  pct_chg is not null

计算：
  up_count = count(pct_chg > 0)
  down_count = count(pct_chg < 0)
  flat_count = count(pct_chg == 0)
  total_count = up_count + down_count + flat_count
  red_rate = round(up_count / total_count * 100, 2)，total_count 为 0 时为 0.0

历史窗口不单独建 asset。后续查询 1 个月、3 个月、其他窗口时，应从 gold_market_breadth_daily 按交易日窗口读取。

8. Resources

第一期只注册两个 Dagster resource。

Resource 职责 第一期消费者 失败边界
LakeRootResource 提供 <LAKE_ROOT>，并确保 asset 读写只落到约定的 <LAKE_ROOT>/raw|silver|gold 路径。 所有第一期 assets 和 checks。 湖根不可用时，相关 asset/check 失败；不应让 Dagster code location 在加载时崩掉。
DuckDBResource 执行 Parquet 读取、标准化、聚合和写入。 silver_trade_calendar、silver_stock_basic、silver_stock_daily、gold_market_breadth_daily 及相关 checks。 SQL 或文件访问失败时，对应 run/check 失败，并在 Dagster UI 中可见。

第一期开工时不新增 TushareResource、ClickHouse resource、业务 metadata PostgreSQL resource。Dagster 自己的 PostgreSQL instance storage 已经由 DAGSTER_HOME/dagster.yaml 管理，不在 assets 中作为业务 resource 使用。
