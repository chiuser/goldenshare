# 财势乾坤数据中心：本地 DG 每日数据审计方案 v1

状态：一期业务口径已确认，第一阶段详细设计和 DG 样本读回已完成。第二阶段为每日汇总、页面和结果复用。依据 2026-11-18《DG数据集齐备性检查盘点.csv》及后续源码、数据复核。具体判定见[逐资产规则](dagster-daily-data-audit-rules-review-v1.md)，第一阶段验收见 [LLD 收尾记录](dagster-daily-data-audit-low-level-design-v1.md#10-第一阶段收尾)。

## 1. 要达到什么结果

每天回答两件事：**当天应该更新的本地 DG 数据，哪些已经更新；这些数据中，哪些有足够证据证明齐备。** 财势乾坤页面和下游程序共用结论，不在打开页面或开始计算时各自审计。

- 在财势乾坤「数据中心」新增「数据审计」卡和详情页。复用[现有数据中心的模块列表](../../../src/biz/api/wealth/data_center/home.py#L8)和[卡片入口](../../../wealth/src/pages/data-center/DataCenterPage.tsx#L7)。只在本地后端明确启用这一能力时展示；Prod 不返回卡片，不注册本地审计的读写入口，直达地址也不能读取。浏览器地址是 `localhost` 或连接能通，都不是启用条件。
- 财势乾坤负责查询和展示；本机 DG 负责日常产出、原生检查和每日汇总。独立审计走已有本地运行环境的单独任务，不新增常驻 Web 服务，不接入 Prod Web/Ops、调度或 worker，不恢复旧湖后台。具体本地接线和权限在 LLD 评审，不能把 DG 代码挂入共享生产路由。[工程与生产边界](../../AGENTS.md#工程与生产边界)
- 每天盘点整个目录。更新考核和齐备核验按本期审计范围执行。报告覆盖本机 Lake 和本机 DG 管理的 ClickHouse 交付；Prod 发布目标仅作为「范围外」说明，不访问远端库或数据源。环境健康不算业务数据。国际指数日线 Raw 和 Silver 纳入二期，一期仍在明细中列出，两项齐备状态均显示「不适用」。
- 不做历史全扫，不更改现有同步、回补或修复，不把报表当新的交易日历、停牌或应有对象事实源，不把缺证据的资产判绿。审计失败不能回滚已经提交的业务数据。

## 2. 页面功能

| 页面功能 | 规则 |
|---|---|
| 每日总结 | 选上海时间下的业务日期，显示最后一次生成时间和四项齐备数字，即「已确认齐备」「已确认缺口」「待确认」「不适用」。点击数字保留所选日期，定位资产明细并应用对应的齐备筛选。更新筛选先回到「全部」，让明细完整呈现该数字所计的资产。 |
| 资产明细 | 按资产、层和频度展示。更新状态、齐备状态分别占一列，各自可筛选。齐备状态使用与汇总相同的四项。初次点数字进入明细后，可再叠加更新条件，列表显示组合后的匹配数量。「依据 / 原因」列显示待确认的具体原因。所选日期的汇总数字保持当天全量口径。 |
| 东方财富板块标准集 | 「东方财富板块分类」下单列「东方财富概念板块」审计项。所选交易日可查看标准集及增减的板块。运营核查 Raw 后可确认当天标准集，Silver 复用该标准集并核同版转换。缺上一交易日标准集时显示「参照标准集缺失」。[逐日规则](dagster-daily-data-audit-rules-review-v1.md#东方财富板块分类标准集) |
| 概念板块核查 Tushare | 人工确认增减前，可在名单核查弹窗点「核查 Tushare」，复查当前业务日和当前差异列表中的板块。请求期间显示进度并锁定弹窗。完成后逐条查看源端名单和成分结果，失败时可重试。源端证实本地漏采时显示「已确认缺口」，待本地补齐并重新核对后才允许生成当天标准集。[源端复核流程](dagster-daily-data-audit-rules-review-v1.md#概念板块名单的-tushare-复核) |
| 东方财富板块成分详情 | Raw、Silver 分别展示所选业务日、当前正式产出对应的现有生产 Check 结果。Check 通过即按一期口径显示「已确认齐备」，详情注明「现有生产 Check 通过」。[成分规则](dagster-daily-data-audit-rules-review-v1.md#东方财富板块成分审计规则) |
| 结论详情 | 展示实际验了哪个范围、证据类型、应有/实际/缺失/多余数量（有证据才展示）、合法例外、有限的缺口样例和 DG 记录链接。股票分钟线 Raw 的盘后交付证据和状态单独展示。待确认时展示具体原因和已验证的部分，例如同版上游对账已通过、上游有缺口或参照标准集缺失。字段缺失时显示「未记录」，缺口样例与总量分别展示。 |
| 通用指数分钟线审计结果 | 页面读取和展示 DG 独立任务留下的齐备结果、核验时间和依据。待审或无法核验时，在明细与详情显示原因。页面的人工核查入口仅用于东方财富概念板块名单核查。 |
| 本地不可用 | 本地模块可用但 DG 暂未连接时，保留卡片并提示原因；不能把所有资产写成缺失。能读到旧总结时标明其时间，不能声称已验证当前文件。没有当天总结时显示「未生成」，不借用前一日结果。 |

默认显示所选业务日的最近有效结果并标明时间。以汇总实际观察时点的交付为准，首次汇总若已看到迟到交付，直接显示「已更新」，保留实际发布时间。若已有总结在迟到或补审后变化，保留原总结的观察时点。无历史依据时显示未核实。

## 3. 审计口径

### 3.1 更新：该什么时候有，是否有对应产出

先按资产的交易日历、发布日或快照规则，判断所选日期 `D` 是否要求更新及应达到的日期或周期。**只对当天有更新要求的资产，以北京时间 `D` 的次日 00:00 为超期界线。** 例如应更新到 11 月 20 日的数据，到 11 月 21 日 00:00 还未更新到 20 日，就显示「超期未更新」。

| 状态 | 判定 |
|---|---|
| 不要求更新 | 休市、未到适用起点、快照没有当天更新要求或按批准的策略该日不产出。没有更新规则时不是此状态，而是无法确认。 |
| 尚未到期 | 当天应更新，尚未到次日 00:00，且还没有对应产出。 |
| 已更新 | 有适用日期或当期截至日对应的产出证据；按数据集合同需要实际文件或发布证据时还须满足该要求。合法空结果允许已更新。任务成功、文件存在或文件时间改变都不能单独作为依据。 |
| 超期未更新 | 当天应更新，已到次日 00:00，且证据可确认仍缺对应产出。迟到后状态改为「已更新」，详情保留实际产出时间。 |
| 无法确认 | 当天适用的更新要求、目标日期或对应的产出情况无法核实。常见原因包括运行或分区证据缺失、资源不可读、版本无法绑定或无法区分合法空与缺数据。 |

复用 DG 现有资产定义、交易日历和生产调度的判定。每个交易日都做盘点，资产是否应更新仍按各自规则。主要指数周线 Raw 在本周最后一个交易日交付，月线 Raw 在次月首个交易日交付上月数据，Silver 两项都应更新至所选交易日。不新建更新频率表。股票周月行情核对当期实际截至交易日。公告按公告自然日允许合法空日。全量快照和固定事实按其发布和有效规则展示。国际指数日线在二期按适用市场交易日历和发布窗口定更新规则。[主要指数周月线调度](../../orchestrator/src/orchestrator/defs/sensors/index_period_update_job_sensors.py#L63) · [现有指定日期审计的时间口径](../architecture/dagster-local-operations-cheatsheet.md#2-按指定日期审计并生成报告)

### 3.2 齐备：有多少是该有的，哪些确实经过验收

| 状态 | 判定 |
|---|---|
| 已确认齐备 | 按适用规则核对业务键、行数或约定范围并通过。股票分钟线 Raw 核应交易股票和截至 15:00 的总根数，通过时显示「已确认齐备（常规时段）」，计入本项。盘后交付在详情另核。下游在必需的同版上游已齐备、原有检查通过、本层应有股票覆盖且总行数匹配时确认齐备。结论可在相同范围复用。 |
| 已确认缺口 | 有独立规则和有效对账证据指出缺失或不允许的多出项。允许的空结果、停牌、新增板块等合法例外须注明依据，不作缺口。 |
| 待确认 | 当前证据还不足以判定齐备或缺口，包含原「仅与上游一致」和「未核验」。前者表示已核对本层与实际使用的同版输入，但上游齐备还未确认。后者表示当前范围缺少有效核验结果。明细和详情保留具体原因，例如「已核对上游，上游齐备待确认」「等待上游核验」「上游有缺口」「参照标准集缺失」和「需要人工核查」。 |
| 不适用 | 按业务日期或当期审计范围无需做齐备判断，例如合同确认当期不必交付、一期仅考核更新、资产只负责 Prod 发布、只检查环境健康，或已明确纳入后续阶段。仅考核更新的资产仍在更新列显示所选日期的实际结果。在本期审计范围内，尚未到发布截止时间、读取失败或规则未明确的项归「待确认」，在原因中说明。可同时显示仍有效的上一版快照及其独立核验结果。 |

所选业务日期的每项资产归入一项齐备状态。适用资产数是「已确认齐备」「已确认缺口」「待确认」三项之和。「不适用」独立计数。东方财富板块分类按资产只汇总一次，行业、地域和概念各留明细。任一项有已确认缺口时总状态为「已确认缺口」。其余情况下，有待确认项则为「待确认」，适用项全齐备则为「已确认齐备」，全部不适用才为「不适用」。

先核对是否真的应有该记录，不用待审计产物自己的实有名单当独立应有名单。股票生命周期、停复牌、市场时间及分钟位置按各自合同；允许例外必须有当日/历史事实支持。好坏例子：应有 A、B，实际 A、C，总数相等仍是缺 B、多 C；ETF 日线覆盖的非阻断告警未验证通过时，其过滤后 Raw 对账不能证明整份 ETF 名单通过。

### 3.3 复用结果的成立条件

复用键必须能核对**资产、分区/业务日、频度、适用范围、目标发布版本和所用上游或规则版本**。核对真正的检查结果及所绑定的产出，不靠 TaskRun 绿灯、同名文件或最新成功记录；证据要求同日两层时，两层都须匹配。当天文件被补回或换版、依赖事实修正、规则变化影响应有集合时，不继续沿用旧结论。若原地替换不产生可关联记录，必须先补可信版本关联或做已有合同要求的有界身份核实，不能仅凭事件 ID 判当前文件；不在每日汇总重新计算全湖文件指纹。当前尚未提供这种关联的资产，只能显示现有检查覆盖和「未核验」原因。

读取先复用 DG 已有产出、检查、发布和现成对账记录；相关代码已有[股票周月分区事件批量读取](../../orchestrator/src/orchestrator/defs/asset_guards/stock_period_silver_readiness.py#L46)、[资金流交付证据绑定](../../orchestrator/src/orchestrator/defs/asset_guards/moneyflow_delivery_readiness.py#L56)的范例。后者存在实际文件哈希路径，不直接搬来给整个目录跑。详细规则遵循[性能治理的事件与文件证据边界](dagster-data-pipeline-performance-governance.md#51-ready-的最低定义)。每日汇总或独立审计输出是检查结果，不是第二份业务数据或检查规则；不默认新增状态库、状态资产或缓存表。若现有记录无法承载历史结果，LLD 必须说明缺什么、如何查询与失效，再单独评审存储方式。

## 5. 自动汇总、独立审计与性能边界

1. **每日汇总**由本机 DG 按北京时间触发，不依赖财势乾坤页面开启。每日选一个业务日期，按对应资产合同读取有界的产出、检查、发布记录；按资产、分区与检查名批量查数据，禁止在请求里逐资产逐日翻事件历史。开始时记录观察时间；批次部分不可读，单项保留「无法确认/未核验」，没有全成功就不发布全绿结论。根据第 3.1 节统一按次日 00:00 判超期，汇总安排须覆盖跨午夜后的状态。迟到、补审或换版只更新受影响结论。
2. **日更中的新增检查**对所选交易日的实际产出核代码、行数或其他约定范围。把审计结论和依据附在现有 Check 记录，数据审计读取后提供给页面。原有生产通过与下游就绪条件继续生效。新增对账只在已明确批准的规则下阻断。审计证据晚到时显示「待确认」，依赖就绪后只执行该日的覆盖 Check。新增下游审计先复用上游当天的齐备结论、下游当天的交付和任务结果。确需核股票代码或行数时，只用当次生产已有统计或已读的数据。禁止为审计重新打开行情或指标文件、重复计算或单独重跑已有的重 Check。证据不足时保留「待确认」。Check 结果与实际产出版本关联，更新状态独立展示。
3. **独立任务**由本机 DG 在单独的运行进程中执行，每次核一个资产、一个业务日期和一个适用频度。用已知文件范围、要读的列和已有行数估算开销。文件字节数仅作性能记录参考。选择历史日期也只读该日所需范围。任务只读本地业务数据，不修改正式文件、不触发同步、补数或自动修复。运行管理沿用 DG。
   - **先上游，后下游**。需要继承上游齐备结论的资产，在提交及启动独立审计前确认实际使用的同版必需输入已齐备。等待上游核验或发现上游缺口时，跳过受影响的下游审计和数据读取，并展示原因。详见[上游先审，下游复用结果](dagster-daily-data-audit-rules-review-v1.md#11-上游先审下游复用结果)。
   - **自动触发建议，待评审**：本机 Dagster daemon 周期性评估专用审计传感器；传感器只轮询已批准资产的有界产出、依赖和审计记录，条件满足后提交独立审计任务。读取文件的是独立任务，不是传感器、网页或每日总结。详见[谁触发、谁执行、何时完成](dagster-daily-data-audit-rules-review-v1.md#1-谁触发谁执行什么时候算完成)。
4. **起停与恢复**：本机 DG 停机错过的日期保留「未生成」，不伪造当天结果。恢复后按获准范围补历史日期的**已有记录汇总**，标明实际生成时间；不能证明当时状态时写未核实。独立任务中断不得留下可用结论，重试按同一范围重新核对版本；范围/版本变了则是一次新审计。记录发布失败不影响已提交行情，页面显示审计未完成。
5. **需要预算的数据量**由目标业务日期、资产目录、匹配分区和必需检查数量推导，187 是本轮目录数量。验收记录批次查询次数、返回证据大小、日更增量、独立审计实际文件数和读取键行数、首跑和重试成本及最终读回开销。页面读取、筛选和刷新使用本地记录。选定的概念板块差异只有在运营主动点「核查 Tushare」后才调用源端。正式首次运行前先验证少量代表资产。

## 6. 按什么顺序验收

先用一个正常交易日跑通初版流程。当天生产发布数据和 Check，DG 汇总所选日结果，财势乾坤展示更新与齐备状态，页面和下游复用同一份有版本依据的结论。资产明细覆盖目录，各项按实际证据显示状态。后续按下表验收新增检查、板块人工核查和独立审计，初版使用中的问题再逐步打磨。

| 次序 | 要交付和验证什么 |
|---|---|
| 1. 完成详细设计（已完成） | 核对资产目录、每日应更范围、复用入口、结果存储、消费接口和本地及 Prod 的隔离方式。已按三个已有 DG 样本验证实际截至日及产出和 Check 的关联。 |
| 2. 跑通每日总结、页面和结果复用 | 用正常交易日验证本地入口、DG 独立生成总结、日期切换、两列状态及其筛选，以及下游读取同一份结论。点击四项齐备数字时保持日期、定位明细、回到第一页，明细数量与对应汇总一致，叠加更新筛选后显示组合结果。验收同时覆盖 Prod 直达不可用、零点超期、休市和非发布日、迟到、缺少同版证据、合法空公告、周月截至日、固定快照和 DG 离线。国际指数日线 Raw、Silver 各在一期「不适用」中显示一次。 |
| 3. 接入已定的新增生产 Check | 验证正常对账、已确认缺码或多码、总根数不符、递推状态沿用、上游或版本证据待确认。新增 Check 按对应规则处理阻断。验上游晚到后只执行当天覆盖 Check。用代表性频度核日更新增耗时和内存，记录读取的日期、列和文件数。 |
| 4. 接入东方财富板块分类核查 | 从 2026-11-19 基线按交易日接续。验 Raw 名单一致时保存副本、真实调整时人工确认、确认漏采时禁止保存及补齐后按新产出重核。联验 Silver 同版转换和依赖当日标准集的东方财富板块资金流向。 |
| 5. 验证通用指数分钟线 DG 独立任务 | 先在 DG 验一个代表资产的单日范围、同版证据、实际读量与耗时及结果读回。财势乾坤随每日汇总展示结果。自动提交和运行窗口另行评审。 |

接口字段、结果存储和验收范围见 [LLD](dagster-daily-data-audit-low-level-design-v1.md)。实际预算和正式执行清单按对应阶段核验。
