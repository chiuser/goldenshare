# 财势乾坤数据中心：本地 DG 每日数据审计方案 v1

状态：逐项评审中。依据 2026-11-18《DG数据集齐备性检查盘点.csv》及后续源码复核。股票分钟线已确认 Raw 逐根、下游复用上游证据及核对股票覆盖和总行数。通用指数分钟线 Raw、Silver 的审计口径已确认。开发与正式执行另行确认，实际运行证据待验证。

## 1. 要达到什么结果

每天回答两件事：**当天应该更新的本地 DG 数据，哪些已经更新；这些数据中，哪些有足够证据证明齐备。** 财势乾坤页面和下游程序共用结论，不在打开页面或开始计算时各自审计。

- 在财势乾坤「数据中心」新增「数据审计」卡和详情页。复用[现有数据中心的模块列表](../../../src/biz/api/wealth/data_center/home.py#L8)和[卡片入口](../../../wealth/src/pages/data-center/DataCenterPage.tsx#L7)。只在本地后端明确启用这一能力时展示；Prod 不返回卡片，不注册本地审计的读写入口，直达地址也不能读取。浏览器地址是 `localhost` 或连接能通，都不是启用条件。
- 财势乾坤负责查询和展示；本机 DG 负责日常产出、原生检查和每日汇总。独立审计走已有本地运行环境的单独任务，不新增常驻 Web 服务，不接入 Prod Web/Ops、调度或 worker，不恢复旧湖后台。具体本地接线和权限在 LLD 评审，不能把 DG 代码挂入共享生产路由。[工程与生产边界](../../AGENTS.md#工程与生产边界)
- 每天盘点整个目录，但只对当天应更新的本地资产作更新考核；齐备核验只看符合合同的版本与范围。报告覆盖本机 Lake 和本机 DG 管理的 ClickHouse 交付；Prod 发布目标仅作为「范围外」说明，不访问远端库或数据源。环境健康不算业务数据。
- 不做历史全扫，不更改现有同步、回补或修复，不把报表当新的交易日历、停牌或应有对象事实源，不把缺证据的资产判绿。审计失败不能回滚已经提交的业务数据。

## 2. 页面功能

| 页面功能 | 规则 |
|---|---|
| 每日总结 | 选上海时间下的业务日期。显示最后一次生成时间及是否出过当天的总结。「更新」和「齐备」分别统计，显示各自适用总数及不适用、未核实数；不做一张把两者揉在一起的通过率。今天仍在发布窗口的资产显示待更新，不计入超期。 |
| 资产明细 | 一行对应资产、层和频度，不把五个频度折成一个绿灯。显示所选日期、适用分区/更新截止、更新状态、齐备状态、实际产出时间和核验时间。可按日期、齐备状态筛选，更新状态是独立筛选项；结果均按同一口径分页。 |
| 结论详情 | 展示实际验了哪个范围、证据类型、应有/实际/缺失/多余数量（有证据才展示）、合法例外、有限的缺口样例和 DG 记录链接。字段不存在显示「未记录」而非零；截断样例不改变总量。区分「资源不可用」「证据无效」和「已确认缺口」。 |
| 独立审计 | 对已具备审计规则且允许执行的资产，选择资产、日期、层和频度，先展示预计读取范围，然后提交本地任务；查看排队、运行、完成、失败和取消状态。没有规则或预算的资产只展示缺失依据，不提供盲目扫描按钮。页面读取、筛选、刷新均不触发扫描；只读用户不能提交任务。 |
| 本地不可用 | 本地模块可用但 DG 暂未连接时，保留卡片并提示原因；不能把所有资产写成缺失。能读到旧总结时标明其时间，不能声称已验证当前文件。没有当天总结时显示「未生成」，不借用前一日结果。 |

默认显示所选业务日的最近有效结果并标明时间；若补审后结论变化，保留原总结的观察时点，不把后来发现或修复的事实倒填成当天已知。无历史依据时显示未核实。

## 3. 审计口径

### 3.1 更新：该什么时候有，是否有对应产出

| 状态 | 判定 |
|---|---|
| 不要求更新 | 休市、未到适用起点、快照没有当天更新要求或按批准的策略该日不产出。没有更新规则时不是此状态，而是无法确认。 |
| 尚未到期 | 当天应更新，且仍在该资产适用的发布窗口内，没有可认的产出。 |
| 已更新 | 有适用日期或当期截至日对应的产出证据；按数据集合同需要实际文件或发布证据时还须满足该要求。合法空结果允许已更新。任务成功、文件存在或文件时间改变都不能单独作为依据。 |
| 超期未更新 | 已确认应更新、已过发布窗口，并且可靠证据能确认缺少对应产出。迟到后状态改为已更新，同时保留实际产出时间，供运营辨别迟到。 |
| 无法确认 | 发布窗口未定义、运行/分区证据缺失、资源不可读、无法辨别版本、无法区分合法空结果与缺数据。任务失败可以作为原因展示，而不是直接判数据缺失。 |

按资产定义判断自然日、交易日、业务日期和物理路径。股票周月行情可能每天更新同一周/月分区；核对当期实际截至交易日，不能只看文件名。国际指数按适用市场交易日历，不套用 A 股休市规则。公告按公告自然日允许合法空日。全量快照和固定事实按其发布/有效规则展示，不拿某天没重写判异常。[现有指定日期审计的时间口径](../architecture/dagster-local-operations-cheatsheet.md#2-按指定日期审计并生成报告)

### 3.2 齐备：有多少是该有的，哪些确实经过验收

| 状态 | 判定 |
|---|---|
| 合同范围齐备 | 独立应有集合已与实际业务键对账并符合合同，或约定的一行、固定快照的完整范围已核对。股票分钟线下游采用已确认的组合规则，必需的同版上游已齐备、原有检查通过、本层应有股票覆盖且总行数匹配。结论可在相同范围复用。 |
| 仅与上游一致 | 已证明目标完整映射了指定上游、冻结交付或已接收来源，但没证明上游自己齐备。只有同一版上游也通过、两者范围和转换规则可对上，才认定继承范围内齐备。仅行数相等、合法代码白名单或覆盖率达到允许阈值，不属于这类证明。 |
| 已确认缺口 | 有独立规则和有效对账证据指出缺失或不允许的多出项。允许的空结果、停牌、新增板块等合法例外须注明依据，不作缺口。 |
| 未核验 | 缺少当前范围的有效证据时展示原因。需继承上游齐备结论的资产，按情况显示「等待上游核验」或「上游有缺口」，并指出依赖资产。 |
| 不适用 | 规则确认当期不必产出，因此没有需要核验的产物。尚未到期、资源不可读及规则不明确均不能借此隐藏。可同时显示仍有效的上一版快照及其独立核验结果。 |

先核对是否真的应有该记录，不用待审计产物自己的实有名单当独立应有名单。股票生命周期、停复牌、市场时间及分钟位置按各自合同；允许例外必须有当日/历史事实支持。好坏例子：应有 A、B，实际 A、C，总数相等仍是缺 B、多 C；ETF 日线覆盖的非阻断告警未验证通过时，其过滤后 Raw 对账不能证明整份 ETF 名单通过。

### 3.3 复用结果的成立条件

复用键必须能核对**资产、分区/业务日、频度、适用范围、目标发布版本和所用上游或规则版本**。核对真正的检查结果及所绑定的产出，不靠 TaskRun 绿灯、同名文件或最新成功记录；证据要求同日两层时，两层都须匹配。当天文件被补回或换版、依赖事实修正、规则变化影响应有集合时，不继续沿用旧结论。若原地替换不产生可关联记录，必须先补可信版本关联或做已有合同要求的有界身份核实，不能仅凭事件 ID 判当前文件；不在每日汇总重新计算全湖文件指纹。当前尚未提供这种关联的资产，只能显示现有检查覆盖和「未核验」原因。

读取先复用 DG 已有产出、检查、发布和现成对账记录；相关代码已有[股票周月分区事件批量读取](../../orchestrator/src/orchestrator/defs/asset_guards/stock_period_silver_readiness.py#L46)、[资金流交付证据绑定](../../orchestrator/src/orchestrator/defs/asset_guards/moneyflow_delivery_readiness.py#L56)的范例。后者存在实际文件哈希路径，不直接搬来给整个目录跑。详细规则遵循[性能治理的事件与文件证据边界](dagster-data-pipeline-performance-governance.md#51-ready-的最低定义)。每日汇总或独立审计输出是检查结果，不是第二份业务数据或检查规则；不默认新增状态库、状态资产或缓存表。若现有记录无法承载历史结果，LLD 必须说明缺什么、如何查询与失效，再单独评审存储方式。

### 4.2 可补到日更检查（2 个）

预算依据是物理访问步骤，不是按口径猜耗时。令 `S`、`G` 是股票日线 Silver、Gold 当日行数，`C`、`T` 是本机 ClickHouse 现有检查已读回的上游和目标当日行数：首项键对账只处理 `S + G` 行的键投影，最多两个既定日分区文件；次项在已读回的 `C + T` 行上追加键集合运算，新增数据库请求和文件读取均为零。两项合计不新增历史文件、行情字段计算、源请求或 Prod 查询。这里的行数是被核对的键记录数，不是实际磁盘字节或毫秒。现有结果若能以可靠生产证据证明等价，则优先复用，不再落第二项证据。

LLD 只补核仍会影响上线的未知：文件行组投影是否复用、日更最大输入、双向差集内存、与原任务并发及失败后重试开销。范围和上界能从合同/读取计划直接证明的，不要求逐资产另测；不能证明的先移出日更，再做必要的代表样本。实现不得因为重新使用历史重算函数，把两个当前日文件扩成历史查询。ClickHouse 单日过滤沿用现有查询，不扩大读取（`query-join-filter-before`）。

## 5. 自动汇总、独立审计与性能边界

1. **每日汇总**由本机 DG 按上海时间触发，不依赖财势乾坤页面开启。每日选一个业务日期，按对应资产合同读取有界的产出、检查、发布记录；按资产、分区与检查名批量查数据，禁止在请求里逐资产逐日翻事件历史。开始时记录观察时间；批次部分不可读，单项保留「无法确认/未核验」，没有全成功就不发布全绿结论。同日迟到、补审或换版，只更新受影响结论。具体触发时间根据现有各资产发布窗口和观察需求确认，不把同一个时间强套给所有数据集。
2. **日更中的新增检查**仅针对当天有新产出且证据未覆盖的资产，做前节有界键对账；不能证明日更总开销可控时留在独立审计。失败不覆盖业务数据，不把审计状态写入数据文件。对晚到数据、纠正参考事实或历史任务，不借本流程自动重验全历史。
3. **独立任务**默认只选一个资产、一个业务日期和一个适用频度，先用分区路径、文件大小/页脚或已知行数、所需列和预期范围估算，再决定是否运行；避免与日更重任务并发争抢磁盘。选择历史日期也只读该日所需范围，不默认展开历史。若实际读取会扩大为数据集全局明细，须单独取得管理员批准；拆成批次不改变这个限制。任务只读本地业务数据，支持取消及有限的失败重试，不修改正式文件、不触发同步、补数或自动修复。
   - **先上游，后下游**。需要继承上游齐备结论的资产，在提交及启动独立审计前确认实际使用的同版必需输入已齐备。等待上游核验或发现上游缺口时，跳过受影响的下游审计和数据读取，并展示原因。股票分钟线 Raw 的逐根结论只为该版核验一次，下游复用结论并核本层股票覆盖及总行数。更新状态独立展示。详见[上游先审，下游复用结果](dagster-daily-data-audit-rules-review-v1.md#11-上游先审下游复用结果)。
   - **自动触发建议，待评审**：本机 Dagster daemon 周期性评估专用审计传感器；传感器只轮询已批准资产的有界产出、依赖和审计记录，条件满足后提交独立审计任务。读取文件的是独立任务，不是传感器、网页或每日总结。详见[谁触发、谁执行、何时完成](dagster-daily-data-audit-rules-review-v1.md#1-谁触发谁执行什么时候算完成)。
4. **起停与恢复**：本机 DG 停机错过的日期保留「未生成」，不伪造当天结果。恢复后按获准范围补历史日期的**已有记录汇总**，标明实际生成时间；不能证明当时状态时写未核实。独立任务中断不得留下可用结论，重试按同一范围重新核对版本；范围/版本变了则是一次新审计。记录发布失败不影响已提交行情，页面显示审计未完成。
5. **需要预算的数据量**：每日汇总上界由目标业务日期、资产目录、每资产匹配分区和必需检查数量推导；187 是本轮目录数量，不是硬编码上限。LLD 记录批次查询次数、返回事件/元数据大小、日更合计增量、独立审计预计与实际文件数/读键行数/字节、首跑和中断后重试成本、最终证据读取开销。预算未知不填臆造数字，也不自动扩大读权限。页面读取不会触发行情或源端请求；正式首次运行前先验证少量代表资产，不全湖重跑。

## 6. 按什么顺序验收

| 次序 | 要交付和验证什么 |
|---|---|
| 先确认方案和 LLD | 确认「当天」窗口、独立任务权限、现成证据可读范围及历史结果保存方法。用少量已发生的本地 DG 产出/检查记录验证日期与版本关联；先查已有记录，不重跑检查。明确资产目录、复用入口、消费接口和 Prod 隔离；不把本方案视为已确认接口。 |
| 再打通每日总结与页面 | 验证只在本地后端显示、Prod 直达不可用、页面关闭不影响 DG 汇总。确认目录新增或历史版本不存在时不静默漏计；筛选一个齐备状态不影响另一列或摘要分母。验证合法空公告、休市、周/月同文件不同截止日、固定快照、待窗口、已更新但未核验、迟到与 DG 离线。 |
| 再加确定的小检查 | 先验现有两项能否复用；若需新增，隔离场景下用「总数相等但缺 A 多 B」的反例，以及正常一一对应的正例。记录同日键读取范围，证明确无历史读取、额外查询或重算；同时证实上游不齐备时不能继承绿灯。 |
| 最后开放独立审计 | 先挑有独立应有规则的代表资产，验范围预览、预算拒绝、并发避让、取消重试和版本换版。股票分钟线验上游未核验或有缺口时跳过受影响的下游读取，同版齐备后才做覆盖及总行数核对，并确认页面和下游复用同一结果。代表路径通过后按已确认规则逐组开放。 |

本方案只确定功能、口径和分流。接口字段、事件/结果存储、实际预算和正式执行清单在获准后落 LLD、逐项核验，不改业务代码、部署或正式数据。
