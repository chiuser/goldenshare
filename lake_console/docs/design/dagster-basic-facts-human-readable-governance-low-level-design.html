Dagster 基础事实资产族人类可读治理 LLD

本文是 dagster-dataset-human-readable-governance-rollout-plan.html 中 Wave 1 的代码级低阶设计。目标是让基础事实资产族在 Dagster UI、run stdout、 materialization metadata、check metadata 和 sensor cursor 中说人话。

Wave 1：基础事实与全量快照 只改表达层 不改触发逻辑 不改运行逻辑 不写湖 不写数据库

当前状态：Wave 1 已按本文完成代码实现与测试验证；实现只改表达层，不改变生产决策。

1. 目标

Wave 1 不改变任何数据生产决策。完成后，运维在 Dagster UI 里看到基础事实资产族时， 应能直接判断：这个资产是什么、为什么触发或跳过、卡在哪个基础组件、下一步该修什么。

本轮资产族：

  • trade_cal：raw_tushare_trade_calendar、silver_trade_calendar
  • stock_basic：raw_tushare_stock_basic、silver_stock_basic
  • stock_lifecycle：silver_stock_lifecycle
  • namechange：raw_tushare_namechange、silver_namechange
  • stock_identity_map：silver_stock_identity_map
  • index_basic：raw_tushare_index_basic、silver_index_basic

3. 硬边界

边界 执行口径
Definition 身份 不改 asset、job、sensor、check 名称；不新增同语义替代 check。
触发逻辑 不改 job selection、run key、run config、default status、minimum interval、窗口时间、单 tick 行为。
运行逻辑 不改 Tushare API、fields、参数、DuckDB SQL、过滤规则、生命周期口径、指数终止过滤口径。
数据湖 不改 path helper、Parquet schema、文件内容、写入方式和历史数据。
状态实体 不新增 summary asset、readiness asset、状态表、manifest、runless event 或历史清理逻辑。
Cursor 只保留本 tick 路标；不得写完整 readiness 报告、status_samples、全量路径/code/date 列表。
已有 runtime state stock_namechange_sensor 的 stage / already-submitted 去重状态必须保留，不因瘦身丢失。
验证 本轮只跑单元测试、静态门禁、文档检查和 git diff --check；不运行 dg。

6. 代码级改动方案

6.1 Asset descriptions 与 stdout

文件 改动 stdout 事件
defs/assets/calendar.py 补强 raw/silver description；materialization metadata 增加交易日历范围和用途摘要。 trade_calendar_raw_started、trade_calendar_raw_completed、trade_calendar_silver_started、trade_calendar_silver_completed
defs/assets/stock_basic.py 说明 raw 是全状态股票基础信息镜像，silver 是当前上市 CNY 股票池。 stock_basic_raw_started、stock_basic_raw_completed、stock_basic_silver_started、stock_basic_silver_completed
defs/assets/stock_lifecycle.py 说明 lifecycle 是历史 CNY 股票生命周期事实，不等于当前股票池。 stock_lifecycle_started、stock_lifecycle_completed
defs/assets/namechange.py 说明 raw 去重快照与 silver 曾用名时间线；失败时 canonicalization 冲突要提示先看 check/run metadata。 namechange_raw_started、namechange_raw_completed、namechange_silver_started、namechange_silver_validation_failed、namechange_silver_completed
defs/assets/stock_identity_map.py 说明 identity map 把历史源代码归一到当前标准代码，输入是 stock_basic、namechange 和 seed。 stock_identity_map_started、stock_identity_map_validation_failed、stock_identity_map_completed
defs/assets/index_basic.py 说明 raw 是 Tushare 指数身份镜像，silver 是截至最新 index trade day 的有效指数池。 index_basic_raw_started、index_basic_raw_completed、index_basic_silver_started、index_basic_silver_completed

stdout 统一使用 orchestrator.utils.dg_log_helper.DgStdoutLogger。 字段只允许分区/阶段/row count/filter count/seed count/ready date 等小字段；禁止输出完整 SQL、DataFrame、全量股票/指数代码列表。

6.2 Materialization metadata

在保留现有机器字段的基础上，追加 namespaced 人类可读字段：

  • summary：一句中文说明本次产物。
  • next_action：成功后等待哪些 checks/下游；失败 metadata 中说明先修哪个输入或规则。
  • result_status：written 或 failed_validation。
  • input_summary：输入文件、源资产、seed 或 ready date 的小摘要。
  • filter_summary：适用于 stock_basic、lifecycle、index_basic 的过滤计数聚合。
  • diagnostic_ref：提示完整诊断看 run stdout、blocking check metadata 或对应设计文档。

现有 dagster/uri、dagster/row_count、 goldenshare/observed_columns、分布统计和样本字段不删除。

6.3 Check metadata

文件 改动点
calendar_checks.py 给 raw/silver 聚合结果补 summary、next_action、rule_summary；缺文件结果说明先跑 calendar job。
stock_basic_checks.py 聚合 contract/key/domain metadata 增加当前上市 CNY 股票池解释；failed_rule_names 保持 list。
stock_lifecycle_checks.py 说明 lifecycle 覆盖历史 CNY 股票，不按 current-listed-only 判断；失败时指出是 schema、key、日期或域值问题。
namechange_checks.py 把 interval/domain 冲突摘要写成人话，保留冲突样本上限；不扩大样本列表。
stock_identity_map_checks.py 说明 stock_basic self mapping、seed mapping、namechange 引用域分别由哪些规则保障。
index_basic_checks.py 说明 raw index_basic 字段/日期域和 silver 有效指数池生命周期规则；不新增 active pool 检查。

本轮默认不新增 check、不改 blocking/WARN 语义、不改 check 名。已有细碎历史 check 不在本轮合并，避免破坏历史 check event 与 readiness。

6.4 Sensor cursor

Sensor 改动点 必须保留
raw_stock_basic_update_job_sensor summary 区分 raw 缺失/过期、checks failed、all ready；blocked_component 明确 raw 或交易日分区。 latest registered trade date 选择、run key 和提交规则。
silver_stock_basic_update_job_sensor summary 区分 raw 未 ready、silver/lifecycle checks failed、需要提交 silver job。 silver 与 lifecycle 同 job 更新；raw ready 前不触发。
raw_namechange_update_job_sensor evidence 只保留窗口、stage、selected_trade_date、registered count；blocked_component 使用 raw/namechange/window/partition。 runtime_state.selected_trade_date、runtime_state.namechange_run_stage、runtime_state.already_submitted_for_trade_date。
silver_namechange_update_job_sensor summary 区分 raw、stock_basic、silver current、stage 已提交；next_action 指向先修 raw/stock_basic 或 retry run。 早盘/晚盘 stage 去重语义和 storage id 新鲜度判断。
stock_identity_map_sensor summary 区分窗口未到、stock_basic/namechange 阻断、identity current、需要重建；evidence 只保留 current bool 与窗口。 17:30 窗口、上游 storage id 比较、checks failed 不自动循环提交。

calendar_update_job 和 index_basic_update_job 当前无专属 sensor。本轮不新增 sensor。

6.5 Jobs

只修改 job description，使它说明“跑这个入口会更新什么、依赖什么、失败后是否应重跑”。 defs/jobs/** 仍只保留 selection，不承接任何数据逻辑。
