Dagster 日频行情 Raw/Silver 人类可读治理 LLD

本文是 dagster-dataset-human-readable-governance-rollout-plan.html 中 Wave 2 的代码级低阶设计。目标不是改变日频行情的生产方式，而是让运维在 Dagster UI、 run stdout、materialization metadata、check metadata 和 sensor cursor 里能直接看懂： 当前触发了什么、为什么没触发、卡在哪个组件、下一步该修哪里。

Wave 2：日频行情 Raw/Silver 只改表达层 不改触发逻辑 不改数据湖 不写 Dagster DB 分资产族推进

当前状态：Wave 2A suspend_d 与 Wave 2B adj_factor 已落地到代码、测试和静态门禁；index_daily 仍待后续分步实现。

1. Wave 2 范围

Wave 2 的正式改造范围收敛到三个日频 Raw/Silver 资产族： suspend_d、adj_factor、index_daily。 daily 已作为 Wave 0 标杆完成；本轮只作为样式参考，不重复改造。

资产族 本轮资产 本轮 sensor 本轮 checks
suspend_d raw_tushare_suspend_d、silver_stock_suspend_daily raw_suspend_d_update_job_sensor、silver_suspend_d_update_job_sensor raw_suspend_d_contract_check、silver_suspend_d_key_integrity_check、silver_suspend_d_suspend_type_domain_check 等现有 checks。
adj_factor raw_tushare_adj_factor、silver_adj_factor raw_adj_factor_update_job_sensor、silver_adj_factor_update_job_sensor raw_adj_factor_business_contract_check、silver_adj_factor_business_contract_check 等现有 checks。
index_daily raw_index_daily、silver_index_daily raw_index_daily_update_job_sensor、silver_index_daily_sensor raw_index_daily_file_contract_check、raw_index_daily_code_coverage_check、silver_index_daily_contract_check、silver_index_daily_registered_code_coverage_check。

market_major_indices_daily 在 rollout 早期分类中被放在日频行情附近， 但它当前是 gold_market_major_indices_daily 下游消费者，不是 Raw/Silver 资产。 本轮只审计它和 index_daily 的依赖边界，真正的人类可读治理放到 Wave 3。

运行环境 不运行 dg、job、sensor、materialize、backfill；不写 lake、prod DB、Dagster DB。

9. Stop Conditions

  • 发现某个 cursor 字段被下游逻辑当作 runtime state 使用，且本文未列出。
  • 需要新增 source readiness probe、状态资产、runless event、summary asset 或数据库表才能表达清楚。
  • 需要修改 job selection、run key、run config、default status、运行窗口或单 tick 请求数。
  • 需要访问正式 Dagster instance、正式数据湖、Tushare、prod DB 或远程服务验证。
  • 发现 market_major_indices_daily 必须随 index_daily 同步改代码才能保持一致。
