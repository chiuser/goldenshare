状态：股票技术因子接入暂缓展开，先完成tushare数据下载组件；随后再校准并推进本方案。尚未开发、未执行 bootstrap、未启用自动更新。

编写日期：2026-10-18；2026-10-19 同步完整unit交付、配置限频及“先组件、后股票因子，旧数据集迁移暂缓”的最新顺序。本文只完成技术方案，不包含 LLD。2026-10-20再次同步组件独立对象、业务限频及取消共享协调的最新定义；组件方案/LLD待评审，股票因子整体仍暂缓。

目标数据集：Tushare `stk_factor_pro`，股票技术面因子专业版。

## 1. 目标与已确认要求

将 Prod 已有的股票技术因子历史数据导入正式 DG Lake，之后每天从 Tushare 更新；监控复权因子变化，重新获取受影响股票的历史技术因子。接入过程中复用现有能力，并把已有多个实际调用方、适合共同使用的部分抽出，减少后续数据集重复实现。

当前建设顺序为：先完整建设tushare数据下载组件的六种任务模式及通用下载能力，再推进股票技术因子集成；不能按股票因子当前需求裁剪组件。旧数据集迁移优先级降低，暂不安排，不以先抽取全部共用能力或迁移旧调用方作为前置。组件完成后再核对本方案的剩余证据和实施范围。每一步先完成对应 LLD、代码与方案审计，再开发或正式执行；本轮不提前编写这些 LLD。

已确认要求：

1. 历史 bootstrap 来源是 Prod；日常来源是 Tushare。不能把初始化改成从 Tushare 重拉全部历史。
2. 复权因子监控及受影响股票的历史更新是本次接入的组成部分，不能只有当天追加。
3. 复用现有 Tushare、DuckDB、日历、运行合同、写入和恢复能力。当前先完成下载组件，不强制抽取或迁移旧消费者；未来确实实施共享替换时，再同步相关消费者并清理重复实现。
4. 按 DG 接入模板设计 Raw、Silver、Catalog、checks、job、sensor、初始化、恢复、性能与人的排障路径。
5. 正式 Lake 只使用 `/Volumes/datasource/data_lake`；候选文件只使用 `/Volumes/datasource/data_lake_staging`。不使用旧 Lake、旧 Console、Kopia 或已经清退的一次性修复入口。
6. tushare数据下载组件每下载完整一个unit，就向业务交付一次源数据；分页不逐页回传，也不等整批结束才返回。业务按本工程规则决定正式存到哪里、怎么写入，复用现有写入与发布能力。下载完成、正式写入和数据集完成分别确认；业务校验或写入失败不进入源请求自动重试。

本轮只改技术方案，不修改 Prod/DG 运行代码、合同、schema、API、Wealth、ClickHouse 或 Redis，也不新增本地 MACD/KDJ 计算。A1当前只处理DG或财势乾坤本需求涉及的本地接口契约及副本一致性；Prod仅作参考，不统一、不迁移、不修改其DatasetDefinition、执行器或消费者，也不以Prod统一作为前置条件。长期三工程可各保留副本，不构成当前实施范围；不跨工程import契约，不借此改变股票池、业务时间和写入语义。DG 不 import Prod Ops、Web 入口或调度器。

本轮尝试读取该日 Prod 全市场代码、用于解释差异时，自动审批拒绝了请求，理由是非统计的全市场明细读取需要管理员额外明确批准。该代码明细导出没有执行。正式 bootstrap 前必须解释这项差异，并分别确认“忠实导入 Prod 已有数据”与“历史范围是否完整”；导入行数相等不能替代后者。

### 4.1 数据集说明卡

| 项目 | 方案 |
| --- | --- |
| 中文名称 | 股票技术因子 |

| 用途 | 在 DG 中保存和读取股票日频技术因子，包含源提供的不复权、前复权、后复权价格及指标。 |

| 完整性 | 按 SSE 日历确定应检查的交易日；股票行覆盖结合该日来源结果及已核实的上市、退市、停牌事实解释。不能用当前上市股票数要求每个历史日都相同。 |
| 数据含义 | 保存源端当前可取得的因子结果。历史会随复权更新，不构成“历史当时所见”的版本档案。 |

### 4.2 Raw 与 Silver

建议采用两个资产，名称在后续 LLD 和全消费者核验中冻结：

| 层 | 建议资产 | 职责及路径 |
| --- | --- | --- |
| Raw | `raw_tushare_stk_factor_pro` | 显式保存全部 261 个源业务字段；建议按 `raw/tushare/stk_factor_pro/trade_date=YYYY-MM-DD/data.parquet` 组织。`trade_date` 保留源 `YYYYMMDD` 字符串；Prod DATE 导出时按合同转换。 |
| Silver | `silver_stock_factor_pro` | 保留相同业务字段和主键，将 `trade_date` 标准化为 DATE；建议按 `silver/stock_factor_pro/trade_date=YYYY-MM-DD/data.parquet` 组织。 |

以上路径均由 `defs/paths.py` 统一提供，不在脚本、页面和 Catalog 分别拼装。具体文件名须与该目录的现行规范一起核定。数值采用 DOUBLE，保留合法 NULL；指标可负，不设统一“全部非负”或“全部非空”规则。主键、日期解析错误、重复主键和数值转换失败必须阻止发布，并给出原因及样本，不能静默丢弃。

Raw 和 Silver 均保留来源返回的业务行，包括历史退市股票；本方案不额外按“当前上市”筛掉它们。来源存在非预期证券类型时先解释合同与真实样本，不能依靠隐含过滤消除行数差异。Silver 在这里提供标准日期和可复用事实，不增加重新计算的技术指标，因此不需要新增 Gold。

建议独立使用 `cn_a_stock_factor_pro_trade_days` 分区定义，Raw、Silver 和其分区 checks 共用，避免借用分钟线历史起点或当前上市因子分区范围。初始范围建议以 Prod 实际来源 `2020-01-02` 至经确认的截止日为准；准确范围、缺日清单及截止日冻结后才能执行。不默认拉取 2020 年以前的数据。

业务进程像加载SDK一样在本进程创建下载器对象，各实例独立使用；token和请求地址优先复用所在工程已有读取入口，不预设直接读env或三个工程同一文件；DG两字段读取抽象及新组件接入已确认，过程见组件方案第4节；本轮新增方法并给新组件使用，原周月线/resource/CLI/get_settings()等旧入口不替换、不收敛，不为读取加锁。组件不共享线程/进程状态，不管理额度、不协调同token频率，不比较其它实例配置，不理解业务账户。整体限频、任务并发与合计内存由业务保证；不在组件检查DG调度前提。

原共享频率F、最多2个活动unit、共享目录/文件/锁、任务登记、配置代次、统一reload、fork处理及崩溃回收要求全部撤销。2026-10-21管理员已确认同步停止与SDK正常用法：组件不自建请求子进程/后台线程，取消在网络返回/超时后检查，不强制结束任意SDK阻塞。配置读取事实及已确认的DG新增读取方法/组件接入过程见[组件审计](/Users/congming/github/goldenshare/lake_console/docs/design/dagster-tushare-request-common-module-comparison-v1.html#design-audit)；旧配置读取入口本轮保持原样，当前只更新文档。

### 6.2 保留的完整下载能力

配置、输入、执行、输出四单元组成一个对象；六种任务模式全部建设。完整契约名定位本地完整源字段、参数、模式、分页和时间规则，业务不传fields或连接设置。一个任务只使用一个来源接口的一份完整契约，同契约分类可以不同，不能混合不同接口/契约。当前只处理获准DG或财势乾坤副本，Prod参考，不实施跨工程统一。

unit由完整契约和所选模式定义，例如某日全部股票，或某代码整个明确历史范围。内部分页/时间拆分不改unit；全部成功并按时间升序后一次交业务内存结果，不逐页回传、不等全任务结束、不预取下一unit。缺失/不可比较时间的行保留原内容和相对顺序放末尾。完整字段请求不等于组件做业务校验；实际少列但协议可对应仍交业务。

每当前unit工作空间2GiB的估算初始值保留，不预分配、不测量，不以宿主进程RSS代替；仅单实例当前数据及解析/排序副本计入。原同时2个共享限制撤销，不再有组件全机4GiB保证。超容量明确失败，不裁字段/范围或改文件输出。

普通分页按每接口契约；可拆时间范围首满继续拆，不可再分首次恰好满页保留第一页并正常offset继续，不报满页错误。namechange该专项真实验证继续[原TODO](/Users/congming/github/goldenshare/docs/governance/engineering-risk-register.md#todo-tushare-namechange-pagination)，当前LLD不展开、不作为前置。

集中数字错误和有限重试保留。每页最多4次、1/2/4秒及有效Retry-After；429仍有限退避，但不是组件主动限频。配置/输入、本地处理/容量、取消、业务保存失败不得触发来源重试。重启后未完成unit从第一页，哪些unit已保存由业务持久化事实决定。

固定代码mapping选择HTTP或具体SDK实现，业务不用选择、失败不自动切换。普通Pro优先HTTP；前稿为拦住DataFrame生成而提出、尚未实施的SDK临时改写已撤销；这不是SDK正常调用的要求。各进程正常创建自己的SDK客户端，不因此增加锁。特殊SDK须实例独立、源值保真及明确超时，具体方法未核验前不宣称支持，不擅自改DataFrame输出或纳入复权/均线业务计算。

### 6.3 业务保存边界与先后顺序

业务负责归一化、业务校验、目标选择、事务/幂等、写入、读回和发布；日级归一化业务日期标准DATE，下载仍交源表示。组件不接受数据库/表名/正式文件目标，不生成数据结果临时文件，不因业务失败重试来源或回滚以前保存的数据。同一实例在同一进程、同一调用线程创建、使用、回调和关闭；DG独立任务进程可直接调用，需要响应页面的业务另开线程。组件只提供同线程标准回调，后续线程间/进程间传递由业务负责。业务可选注册组件标准回调，成功页、安排重试及每个完整unit完成时通知，含进度/条数，时间拆分无独立通知，完整数据仍按unit交付。普通回调异常不影响下载，慢回调须由业务约束；完成回调中session.cancel()或DownloadCancelled都先交当前完整结果再停止，最后unit已交付则正常完成；该项已由管理员拍板，沿用组件方案/LLD，不在本搁置总方案另定义。正常/提前停止/取消/业务异常均明确关闭自身资源，已交付结果仍归业务。

先评审并完成下载组件四单元和全部六模式，再恢复股票技术因子总方案；旧迁移继续暂缓。A2～A5只保留前序候选方向，不要求先抽取：A2前序盘点3个源数据集/2套writer；A3为3类复权处理；A4和A5各由7个资金流向接口共用一套发布或受控Prod导出。该历史盘点不是本轮新的全仓审计或抽取授权。

技术方案与[LLD](/Users/congming/github/goldenshare/lake_console/docs/design/dagster-tushare-download-component-low-level-design-v1.html)已按原26项逐项标明保留/改写/撤销，不能把原共享要求继续列为实施验收门槛。原单次请求/锁实现盘点保留在前序审计证据中，当前不再以资金流向子进程作为必须复用的基础。具体下载组件设计以以上两份原文档为准，本文不重复定义配置或错误表。

## 7. 历史 bootstrap

### 7.1 范围与来源

只从 `raw_tushare.stk_factor_pro` 导出已批准范围内的 261 个业务字段，不读 Serving 视图补字段，不带入三列系统字段，不读生产任务状态充当 Lake 数据事实。明确登记该表为此次只读导出的来源白名单；其他表不因 A5 抽取而开放。

执行前冻结起止日期、按日计数、已知缺日及来源截止条件，并解释 §3.2 的数量差异。Prod 首尾范围内是否需要补缺、补哪些日期，须基于实际证据在本方案记录并评审；不能以 bootstrap 名义默认从 Tushare 补齐全部历史。

历史因子结果可能已经被 Prod 按较新的复权基准更新。初始化前还须核对 Prod 因子与 DG 同一截止日期的复权基准，选取发生过复权变化的股票和历史日期做有界对照；不能用单个当日价格相等证明全部历史已正确刷新。若发现未解释的不一致，先处理范围和来源结论，再执行正式初始化。

截止日期也不能阻止 Prod 在导出期间更新旧日期。正式导出须事先协调来源维护窗口，确认批准范围内没有并发历史重刷，并按窗口记录来源内容核验依据；发现来源已变就停止并重新确认受影响范围。不能通过锁住生产表或长期持有全历史事务换取一致性；续跑和最后来源复核的开销纳入预算。

### 7.2 导出、候选、发布

1. 用日期索引组织有界窗口，显式排序、字段投影、SQL 超时、单次行上限；使用“上限加一行”发现截断，不把上限内的结果冒充全部结果。窗口大小、连接次数和单窗口预算由代表性样本确定。
2. A5 流式读入，A2 做 schema 与主键验证，用 DuckDB 形成日期候选。不能在 Python 中累计整个历史后首次落盘，也不启用覆盖全部历史的数据库长事务。
3. Raw 候选与 Silver 候选分别校验。每个已完成独立文件形成可读回事实，经 A4 从 staging 同文件系统 `os.replace()` 到正式目录。
4. 逐文件记录来源范围、候选/目标指纹、校验结果和完成情况；已有目标只在内容等价或已批准更新理由下继续。意外目标变化、候选变化或来源范围改变必须停止。
5. Raw 和 Silver 的多个文件不是整体原子提交。中断后保留已完成文件，续跑识别“已提升但 checkpoint 未完成”等情况，读回核验后推进；不能因状态记录失败撤销已提交业务文件。
6. 全部物理验收完成后，再单独设计和审批 Dagster 历史事件补记。Direct Lake bootstrap 不等于逐日 Dagster backfill，事件不能代替文件验收。

正式导出属于数据集全局明细读取，必须先获得明确批准；正式 Lake 写入、事件补记分别授权。小样本或代码开发授权均不替代这些授权。

## 8. 每日更新与复权变化后的历史更新

### 8.1 复权因子的使用范围

交易日 T 的前一交易日 P 由已验证的 SSE 日历确定，不用自然日减一。新数据集建议从已有 `raw_tushare_adj_factor` 的 T/P 分区规范化读数，再与本数据集需要监控的股票范围对齐；这样不会因为当前上市 Silver 的筛选而漏掉来源仍返回的股票。先验证 Raw 的字段、日期、唯一性和范围，文件存在不足以进入比较。

A3 允许调用方明确提供已有 Raw 或 Silver 输入，返回相邻日对齐事实；原消费者保持原来源及原判断。此处不修改现有 `silver_adj_factor` 的上市筛选，不另建重复因子资产，也不直接依赖分钟线 repair job 的成功状态。

新数据集的变化判断采用源复权因子值变化，不给合法变化加未经证明的阈值。旧股票缺少 P 的值不能当作“没有变化”；生命周期能证明的新上市股票不因没有上市前因子而自动补造历史。范围内股票在 T 缺值、生命周期不足或 Raw 覆盖不明时，输出具体原因并阻止该次完整性通过。退市且来源不再提供新日因子的股票保留已有历史，不要求退市后继续每日产生记录。

本轮尚未扫描 DG 物理因子覆盖，这一范围校验及代表性真实对照是后续 LLD 前的必要证据，不能在本方案中宣称现有 Raw 全市场覆盖已经通过。

### 8.2 日常流程

1. 在源端已发布完成、T/P 因子及日历可用后，以日期T形成一个unit，下载组件取得全市场完整261字段的全部页后交业务一次，再由业务复用写入代码校验并形成当天候选；不要求先抽取A2。
2. 读取 T/P 因子并识别变化股票；将该股票集合、输入因子指纹、日历、来源日期及历史范围纳入同一可追溯批次。执行时重新核对输入，不能用已经变化的输入继续旧批次。
3. 对发生变化且本数据集已有历史的股票，从其在本数据集的最早已有日期读取到 T，由下载组件取得该代码及明确历史范围的全部261字段，完成整个unit后交业务一次。不能仅修改 `adj_factor`、按比例缩放价格或本地重算部分 MACD/KDJ。
4. 将受影响股票的新结果与对应日期原文件合并，每个受影响日期每层只生成并提升一次候选；未受影响股票的行必须保持相同。不得每处理一只股票就重写全市场全年文件。
5. T 当天候选与历史候选采用同一套 A4 发布、逐文件 checkpoint、取消和恢复规则。正式写入顺序和同日写入互斥机制由后续 LLD 明确；bootstrap、日更、历史更新不能同时写同一目标。
6. 物理读回、范围与 checks 完成后，才记录该批次完成。没有变化也要有“已检查、无需历史更新”的完成结论；0 只变化、源请求失败、空数据和因子缺失必须是不同结果。

历史范围不能用固定 30/90 日截断。新上市且没有本数据集既有历史的股票通过正常日数据接入；其他无历史对象先解释原因，不能由最早日期查询为空直接推导“无需处理”。

须核对 T 日股票因子返回的 `adj_factor` 与本批次 T 日独立因子输入一致，并对历史结果按对应日期做有界抽样核验；不能要求所有历史行的因子等于 T 日因子。源发布尚未一致时先等待或报错，不能把两个不同时点的结果拼成成功批次。历史请求过程中基准再次变化时，保留已取得证据但不继续按旧基准完成整批，先重新确认范围。

同一批次的历史源行数、归一化行数、候选和发布行数须对账。源端新结果缺少原有主键时先解释停牌、数据修正或读取不完整，不能默认按源返回删除旧行。超出已批准历史范围、缺失来源、预算不足时保留未完成状态，不静默缩短区间。

### 8.3 Job、Sensor 与日常完成条件

按“源可用性判断、日更、受影响历史更新、完成校验”划清职责。sensor 只做有界判断和请求编排，不写 Parquet、不拉全历史。具体 job 拆分在 LLD 确定，但必须能独立展示日数据和历史更新的进度、失败及重试。

日常连续性复用默认最近 10 个 expected trade dates 的有界窗口，优先推进最早可行动日期；长停机与窗口外缺洞走专项恢复，不能不断扩大 sensor 扫描范围。上一批需更新的历史没有完成时，不能把后续日期标成整个数据集已就绪。

资产 ready 需要文件有效、约定的 blocking checks 通过，且该批次所需历史更新或“无需更新”结论匹配完整范围。run SUCCESS、单条 materialization 或一段样本股票列表均不够。失败或 checks 未过时给出下一动作，不无限自动重试。

使用完整变化股票范围及其指纹核验批次，不只保存前若干只股票冒充范围；大量列表存诊断文件，cursor 只保留定位与少量状态。cursor 常态目标不超过 2 KiB，复杂情况控制在 3 KiB 内，硬上限 8 KiB。新 sensor 默认 STOPPED；源发布时间和执行窗口经实测再定，不套用分钟线 19:40 或 MACD 的自动股票数上限。

## 9. 发布安全、失败与恢复

A4 是 bootstrap、日更和历史更新共同使用的发布步骤：先校验完整候选，记录提升意图，检查正式目标仍与预期相同，再原子提升并读回完成。已有 publisher 的业务等价比较使用集合差异，因此必须先保证主键唯一，不能将集合相等误当成重复行也被验证。

| 情况 | 必须达到的行为 |
| --- | --- |
| 请求卡住、超时、取消、父进程退出 | A1按同步网络超时及安全位置停止并关闭自身资源，不创建请求worker；不可承诺强行打断任意SDK内部阻塞，详见组件方案已确认的同步停止边界。 |
| 已收到源数据，业务校验或写入失败 | 停止后续下载，保留业务错误原因；不触发源请求重试，不重做业务提交。业务依据完整unit接收、已提交结果及checkpoint处理续跑，组件不清理业务文件。 |
| 全部下载结束，正式发布或目标读回失败 | 保留下载完成事实，业务写入及整批任务仍未完成；由业务检查目标和恢复，不能把下载完成显示成数据集ready。 |
| 数据缺列、错日期、重复键、转换错误 | 阻止发布，保存原因及小样本，不跳过后继续宣称完整。 |
| 候选完成、正式文件未变 | 可继续校验与提升，不重新获取已经完成且仍有效的来源单元。 |
| 正式文件已提升、完成记录未写成 | 用候选与目标指纹及读回结果确认实际情况，再补齐本次续跑状态；不重复覆盖。 |
| 正式文件被其他任务改变 | 停止并展示冲突，不能覆盖新的合法数据。 |
| 一部分 Raw 或 Silver 已完成 | 保留已完成文件，整批继续未就绪；续跑处理未完成文件，不重新扫描并重算全部历史。 |
| 状态或事件记录失败 | 业务文件不回滚、不删除；保留明确的待核验状态，按物理事实恢复。 |

写前检查正式挂载、staging 与正式目录所在文件系统、空间、目标冲突及维护窗口。取消在请求、导出、校验、提升前后检查；已完成单元保留，取消后不领取新单元。不会宣称多文件整体原子性，也不新增文件备份或快照。

## 10. 性能测算与停止条件

### 10.1 当前规模及请求量模型

| 场景 | 当前可以测算的量 | 需要补的实测 |
| --- | --- | --- |
| 日更 | 样本 N=5,566 行、F=261 字段。假设页大小 p=1,000，尾页规则下约需 `floor(N/p)+1=6` 次请求；p 只是测算值，并非已验证或已批准的默认值。 | 可用分页参数、完整字段单页字节/RSS、源限速、重试及单日总时长。恰好满页仍需额外请求确认结束。 |
| bootstrap | R 约 832 万行；仅 259 个 DOUBLE 的未压缩数值量约 17.25 GB/层，Raw+Silver 约 34.50 GB，尚未计字符串、NULL、压缩、索引或 spill。 | 实际 Parquet 压缩率、日期数、单窗口行数/字节、连接数、读写速度与空间峰值。Prod 23.55 GB 不能直接当作 Lake 空间预算。 |
| 复权历史更新 | C 只变化股票、每只已有历史 H 行，源请求约为各股票 `floor(H/p)+1` 的总和；受影响 D 个日期的文件每层至多合并发布一次。 | 典型与最大变化数量、历史长度、源请求总量、整日旧文件读取量、候选大小。文件读写成本随受影响日期增长，不只随变化行数增长。 |
| 恢复和最终验收 | 续跑校验已完成文件与 checkpoint，最终检查所有本次发布文件、分区范围及来源对账。 | 指纹/业务比较、读回、最终聚合审计开销，以及中断后不重复下载和重算的证据。 |

历史导出不用每个日期分别新建数据库连接作为未经测量的默认方案，也不能为了减少连接改成无上限全历史事务。先按索引和样本确定有界窗口与连接复用方式，完成后及时结束只读事务。

### 10.2 开发前必须明确的资源约束与性能测量

后续 LLD 开始前补齐代表性有界测量；对应步骤开发前必须记录：对象、日期、页数、请求总数、SQL/连接数、单页/窗口行和字节上限、单次/整批时间、RSS、DuckDB 内存/线程、spill、staging 峰值、文件读取/合并/提升次数、取消响应、中断续跑和最终验收成本。

现有 moneyflow transport 的 30 秒、32 MiB、768 MiB 等限制只属于原调用方，不能当作 261 列新数据的默认值。新组件使用显式频率配置与有限重试，不继承旧策略的任务总请求数或总时长限制；记录规模和耗时用于测量与排错，不建设账户额度管理。源调用耗时不等于写湖耗时，本轮 MCP 样本没有用于宣称吞吐 SLA。

物理内存、单页字节或磁盘承载不足、执行超出已批准的数据读写范围时，停止领取新单元并保留已完成结果，输出剩余范围和原因；不得丢股票、减少字段、缩短历史或推进完成状态来规避问题。不把请求总数或整个任务耗时作为下载组件的人为截断条件。需要扩大范围时先更新本方案及对应 LLD，再申请执行。

sensor 不遍历全 Lake、不读取无界事件历史；批量检查须一次读取明确文件集合，避免包一层 Python 循环仍逐分区扫描。超过 100 个历史分区或 `分区数×blocking checks数>1000` 时，按性能治理规范做批量聚合与分层验证，不逐分区全深扫。

## 12. Checks、真实验收与人的排障

### 12.1 数据验收

| 检查 | 主要内容 |
| --- | --- |
| schema | 261 个显式业务字段、类型、日期格式和可空数值；没有系统字段混入。 |
| 主键及日期 | 主键非空、唯一、日期在执行范围并与分区一致；不把休市空结果当作成功交易日数据。 |
| 行数与拒绝 | 源行数、归一化行数、候选/发布行数及拒绝原因一致；任何拒绝都有原因和小样本。 |
| bootstrap | 与批准来源范围逐窗口/日期汇总对账，并记录缺日与覆盖限制；不能仅凭估计总行数验收。 |
| Raw→Silver | 日期转换以外业务字段及主键一致，不暗中过滤当前非上市股票。 |
| 复权更新 | 变化集合和起止范围完整、所有应更新文件读回、未变化股票保持相同；“无变化”也能证明已检查。 |
| 发布/恢复 | 文件指纹、批次、checkpoint 和最新物理结果一致；旧事件不能证明新文件仍有效。 |

计算、合并和恢复正确性主要由独立金样本及离线有界验证证明；日常生产 checks 做轻量合同与覆盖检查，不重复拉全源或重算全历史。readiness 与正式 checks 使用相同的纯判断和聚合语义，避免两套口径。

Raw/Silver 分区 checks 必须显式使用与资产相同的 `partitions_def`；隔离 instance 中核对实际产生的 check event 分区，不能只看函数返回成功。开始实现后按代码约束运行必要单元、契约、隔离集成及最小真实验收；本轮没有运行数据管道测试，也不声称接入已通过。

### 12.2 测试重点

组件和新数据集各自实施时，至少覆盖：单次请求卡住/超时/取消/父进程退出；尾页/恰好满页/完整unit交付与限频；业务重复键处理；缺列、错类型、错日期和合法 NULL/负指标；分步退出及续跑；目标冲突；发布后状态写失败；历史只更新指定股票、跨年范围、没有变化、新上市与旧股票缺前因子；股票集合相同但值变化、同样行数但主键不同；正常复权变化不会被错误拦截。

夹具来自已核对的源字段、Prod schema 和有界真实样本。预期结果用独立可人工核算样本，不能用被测函数生成 expected。真实接入验收须分别记录源返回、归一化、拒绝、目标行数，mock 通过不能代替真实边界。

tushare数据下载组件后续验收按最新方案及LLD：各实例配置/连接/结果独立；没有组件线程/子进程、共享状态、锁或SDK全局修改；一个实例串行下载完整unit，六模式全覆盖；每接口分页/全字段/协议/排序/有限错误重试/容量小样本/安全位置取消与关闭；业务保存及重启恢复边界。原共享限频、两个名额、worker/管道和统一重载测试撤销。SDK真实方法及有界源验证按具体获准登记范围执行，不能用替身宣称已接入。本轮未执行。

存储边界还须证明：相同完整契约可由不同业务调用方选择本工程允许的正式目标和写入方式，无需改变下载配置；A1不触碰正式数据库或文件。分别覆盖unit内部部分页成功但unit失败、完整unit已交付但业务未提交、全部下载结束但发布失败、提交后状态写失败和接收不明；业务失败停止后续下载而不触发源重试，已提交数据保留。合法NULL与负指标必须有可写入正例，不能只测试错误被拒绝。

### 12.3 可见信息和排障顺序

资产、check、job、sensor 均使用中文说明，讲明数据是什么、读取什么、何时可执行、会改哪些文件以及失败后如何处理。metadata 先展示 `summary`、`next_action`、结果、输入和过滤范围、诊断位置，再展示机器字段。

长任务展示阶段、当前日期/股票窗口、已完成/总量、页数、来源/目标行数、耗时和最后更新时间；运行时不连续 30 秒没有可见更新。进度随已完成工作推进，不能用心跳冒充完成量，ETA 无依据时明确暂无法估算。

| 运营看到的问题 | 首先查看及下一动作 |
| --- | --- |
| 未启动 | 查看交易日、源发布及 T/P 因子 readiness 的具体缺项，不手动反复触发。 |
| 源请求失败 | 查看 API、日期/股票、页号、重试次数、超时或配额原因，修复后续跑未完成单元。 |
| 行数/字段不一致 | 查看源/归一化/候选计数、原因和样本，不能跳过校验强行发布。 |
| 历史更新未完成 | 查看完整批次范围、已完成文件及剩余范围，继续同批次或在输入变化后重新评审。 |
| 文件冲突 | 查看预期与实际目标指纹、已有任务/维护窗口，确认范围后再执行，不覆盖未知结果。 |
| 文件完成、状态不完整 | 先按 checkpoint 和物理读回核验，再处理状态；不因 UI 不绿重跑全历史。 |
