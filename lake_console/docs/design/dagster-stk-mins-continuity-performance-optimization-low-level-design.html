Dagster 股票分钟线连续性性能优化 LLD

本 LLD 按最新只读 profiling 与 2026-06-21 追加决策修订：性能瓶颈来自 sensor 热路径逐日扫 Dagster event/check 状态库， 以及在运行窗口前执行重型 DuckDB readiness；日常 sensor 回看窗口统一收敛为最近 10 个 expected trade dates。 本轮代码设计不新增任何持久化状态实体，只改变读取方式：用 DuckDB batch 查询 lake 文件事实，并复用现有 blocking check 的真实 SQL 语义。 后续 Dagster Batch Readiness Hot Path 性能治理 LLD 已完成 P0A-P0G，补齐 qfq gold batch readiness 名不副实的专项修复和全 helper 性能回归。

状态P0-P9 已完成；后续 batch readiness hot path P0 已完成；P8B/P8C 因 P8A 真实待补数为 0 未执行。
核心方向两阶段 batch readiness：日常 10 天窗口、粗筛定位明显缺口、完整语义验证防止误判 ready；60 天只作离线审计和长停机恢复参考。
禁止项不新增 status manifest、summary asset、readiness asset、数据库表或 Dagster definition。
性能目标常态 sensor tick 小于 10 秒；明显缺口定位小于 1 秒。

2.4 000638.SZ 补充审计结论

为避免只用 60 天窗口误判，本次又按年份只读扫描了正式 lake 中 silver_stk_mins 已发现的全历史分区， 范围为 2014-2026 年、全部 1/5/15/30/60 五频度，共 15130 个 parquet 文件。该审计是一次性离线只读审计， 耗时 175.561s，不得作为 sensor 热路径实现方式。

审计项 结果 解释
旧 name_timeline 口径失败 13460 个 date-freq 行，1 个股票代码 唯一代码为 000638.SZ，覆盖 2014-01-02 至 2026-04-13，共 2692 个交易日、5 个频度。

raw_stock_basic.delist_date 是股票生命周期身份的上界，不等于最后交易日。 000638.SZ 的最后交易日是 2026-04-13，而 raw_stock_basic.delist_date 为 2026-06-03。 因此生命周期 check 只回答“这个 ts_code 在这个日期是否是一个合法历史股票身份”； “这一天是否真的应该有分钟线交易数据”继续由 silver_stk_mins_codes_exist_in_stock_daily 等交易事实 check 约束， 禁止把 delist_date 误用为实际可交易日期边界。

第一阶段只负责快，不负责最终 ready 判定；第二阶段必须覆盖正式 blocking checks 的业务语义。

日常 sensor 不再默认扫描三个月窗口。超过 10 个 expected trade dates 的停机缺口、历史缺口盘点和长期恢复， 必须走显式 audit / recovery 流程，不能把三个月窗口塞回 Dagster UI 热路径。

3.2 不新增实体的含义

本专项允许新增或调整无状态代码 helper、测试和静态门禁；不允许新增任何持久化状态事实源。

7. Stock Daily 生命周期口径

P0 已拍板：silver_stock_daily 纳入本专项。它不是 sensor 热路径的小优化， 而是股票分钟线完整性判断的上游事实口径修正；如果 stock daily 仍用 current-listed-only 的股票全集， silver 分钟线再快也会在退市历史股票上得到错误结论。

7.1 当前代码事实

  • silver_stock_daily_select(...) 当前使用 silver_stock_basic 作为股票全集过滤。
  • silver_stock_basic 当前是 current-listed-only 快照，天然不覆盖已退市历史股票。
  • silver_stock_daily_current_listed_only 当前是正式 blocking check，并进入 SILVER_STOCK_DAILY_BLOCKING_CHECKS readiness 口径。
  • 这会让 000638.SZ 这类退市历史股票在最后交易日前的合法行情无法被上游 stock daily 生命周期事实覆盖。

7.2 后续正式口径

  • silver_stock_daily_select(...) 不再用 current-listed-only 的 silver_stock_basic 作为股票全集过滤。
  • 股票生命周期事实源改为 raw_stock_basic_path(lake_root)，它包含 list_status='D' 的退市股票。
  • ts_code + trade_date 必须满足 trade_date >= list_date 且 trade_date <= delist_date OR delist_date IS NULL。
  • 保留现有 CNY、上市日期、北交所开市日期等交易规则；生命周期口径只替换股票全集来源，不放宽交易数据质量规则。
  • 新增正式 blocking check 名称固定为 silver_stock_daily_stock_lifecycle_covered。
  • 旧 silver_stock_daily_current_listed_only 从正式 blocking/readiness 口径退出；可以作为历史背景或迁移前事实出现，不能继续阻断正式链路。
  • silver_stock_basic freshness guard 保留为基础资产新鲜度保险，但它不再作为 silver_stock_daily 股票全集过滤事实源。

7.3 SQL 语义骨架

WITH stock_daily AS (
    SELECT DISTINCT
        ts_code,
        CAST(trade_date AS DATE) AS trade_dt,
        CAST(trade_date AS VARCHAR) AS trade_date
    FROM silver_stock_daily_candidate
),
raw_stock_lifecycle AS (
    SELECT
        ts_code,
        CASE
            WHEN list_date IS NULL OR list_date = '' THEN NULL
            ELSE strptime(list_date, '%Y%m%d')::DATE
        END AS list_dt,
        CASE
            WHEN delist_date IS NULL OR delist_date = '' THEN NULL
            ELSE strptime(delist_date, '%Y%m%d')::DATE
        END AS delist_dt
    FROM read_parquet(raw_stock_basic_path, hive_partitioning=False)
),
lifecycle_failures AS (
    SELECT d.ts_code, d.trade_date
    FROM stock_daily AS d
    LEFT JOIN raw_stock_lifecycle AS b
      ON d.ts_code = b.ts_code
     AND d.trade_dt >= b.list_dt
     AND (b.delist_dt IS NULL OR d.trade_dt <= b.delist_dt)
    WHERE b.ts_code IS NULL
)
SELECT count(*) AS failed_code_count
FROM lifecycle_failures;

这个 SQL 骨架只表达生命周期覆盖，不替代 stock daily 已有价格、成交量、交易日、币种、上市日期和市场规则。 P2 实现时必须把 select 与 check 使用的生命周期规则收敛为同一份语义，避免 select 放行、check 阻断或反过来漂移。

8.5 查询策略

  • 先枚举 silver_stk_mins_path(lake_root, freq, trade_date)。
  • 文件存在和 row count 只作为粗筛。
  • 完整语义必须复用或重构现有 check 背后的 SQL 规则；P3 已将 _silver_name_timeline_covered 的正式判断收敛为股票生命周期身份合法性，名称时间线解释不再作为该 check 的 blocking 条件。
  • 股票生命周期身份合法性：对 silver_stk_mins 中的 ts_code + trade_date，使用 raw_stock_basic_path(lake_root) 读取包含退市股票的历史股票生命周期事实，要求 trade_date >= list_date 且 trade_date <= delist_date OR delist_date IS NULL。
  • 名称时间线解释：silver_namechange 只解释真实名称变更，不承担股票是否合法存在的判断；没有 namechange 不等于非法。
  • current-listed-only 的 silver_stock_basic 口径不变，不能为了退市股票补进去；退市历史身份应来自包含 list_status='D' 的历史股票事实。
  • raw_stock_basic.list_date 与 raw_stock_basic.delist_date 是 YYYYMMDD 字符串，SQL 中必须显式解析为 DATE；空 delist_date 表示仍在生命周期内。
  • delist_date 不是最后交易日，不能用它判断某天是否应有分钟线；实际交易事实继续由 silver_stk_mins_codes_exist_in_stock_daily 负责。
  • 如果日常 10 天窗口内完整语义发现更早日期 check 失败，selector 必须停在这个日期，不得推进后续日期；20/60 天完整语义只作为离线审计和容量参考。

8.6 生命周期 SQL 骨架

P3 已将下列生命周期语义落入正式 check；后续 P1 batch lake readiness 接入时应复用同一语义，避免两套规则漂移。

WITH silver_mins AS (
    SELECT DISTINCT
        ts_code,
        CAST(trade_date AS DATE) AS trade_dt,
        CAST(trade_date AS VARCHAR) AS trade_date
    FROM read_parquet(silver_stk_mins_paths, union_by_name=True)
),
raw_stock_lifecycle AS (
    SELECT
        ts_code,
        name,
        list_status,
        CASE
            WHEN list_date IS NULL OR list_date = '' THEN NULL
            ELSE strptime(list_date, '%Y%m%d')::DATE
        END AS list_dt,
        CASE
            WHEN delist_date IS NULL OR delist_date = '' THEN NULL
            ELSE strptime(delist_date, '%Y%m%d')::DATE
        END AS delist_dt
    FROM read_parquet(raw_stock_basic_path, hive_partitioning=False)
),
lifecycle_failures AS (
    SELECT s.ts_code, s.trade_date
    FROM silver_mins AS s
    LEFT JOIN raw_stock_lifecycle AS b
      ON s.ts_code = b.ts_code
     AND s.trade_dt >= b.list_dt
     AND (b.delist_dt IS NULL OR s.trade_dt <= b.delist_dt)
    WHERE b.ts_code IS NULL
)
SELECT count(*) AS failed_row_count, count(DISTINCT ts_code) AS failed_code_count
FROM lifecycle_failures;

上述 SQL 只负责生命周期身份合法性，检查粒度是每个频度文件内的 DISTINCT ts_code + trade_date，不是分钟 bar 行。 batch 跨频度汇总时可以统计 ts_code + trade_date + freq 命中数，但字段名必须写成 failed_code_date_freq_count 或同等明确名称，禁止把它笼统叫成 bar row_count。 完整 silver ready 还必须继续合并 schema、freq/date、唯一键、价格成交量、 suffix/exchange、stock daily 存在性、停牌结构行等当前 SILVER_STK_MINS_CHECK_NAMES 中的其它 blocking checks。

profiling 已证明 000638.SZ 这类合法退市历史股票会被旧 name timeline 语义误报：五频度文件都有行数，且最后交易日之前的历史行情合法。 P3 已补测试证明 row count 全部大于 0 仍可能因为生命周期失败而 not ready， 也证明 list_status='D' 且交易日在生命周期内的股票不会因为缺少 silver_namechange 记录而失败。
