## 4. “非必要不重复”的执行要求

| 保留的必要工作 | 执行一次的边界 | 必须取消的重复工作 |
| --- | --- | --- |
| 计划、实现、对象/范围准入 | 新执行建立上下文一次；worker只核自身请求和计划绑定 | 每文件/每worker重建全部索引和重验完整计划 |
| 输入身份与依赖解析 | 对实际会使用的文件首次取得强证据，运行内复用 | 对已核实稳定输入反复hash、枚举正式库存、重审基准/末端 |
| 空间与预算 | 本run一次建账，输出前预留、完成后结算，结束合并一次对账 | 每秒、每片段、每次COPY前后递归全目录 |
| 候选验证 | 每个新完整文件一次原blocking语义、范围及保留行检查后封存 | 已封存文件再次跑业务SQL或用同一公式重算证明自己 |
| 完成片段/文件恢复 | 先读完成记录及所绑定输出证据，直接复用；未完成才算 | 先运行kernel再发现旧片段存在；audit再次重放完整历史 |
| 测试 | 小样本验证成本模型，固定版本集中一次必要回归和一条25股链 | 每个小修复重跑数小时链，正常/续跑两份完整计算后再全量重算audit |

完整文件包含其他股票时，保留行只做一次双向EXCEPT ALL。原blocking需要的范围外输入只读并按同一批次复用，不能转成修复目标或每个worker的全市场审计。最终audit汇总已封存证据、文件归属/完整性与覆盖事实，kernel/COPY=0。

文件提交前先把实际校验结果和输出强身份记入原record，再rename并补记完成；中断后凭这份证据完成提交，不重新COPY。同批完成记录中已持久化的业务证明可供未登记文件复用，具体顺序见LLD §7。

## 5. R3具体开发顺序与验收

1. **运行上下文和计量。** 在现有入口内统一计划索引、首次输入验证缓存、预算预留/结算；本轮不新增CLI、配置或长期账本。先用累积目录和记账中断小样本证明扫描次数不会随轮询、文件和COPY数量增长。
2. **完成成果复用。** 把片段/候选完成证据检查移到计算之前；同版已完成结果不跑kernel、COPY或业务校验，部分完成只续后缀。保留原receipt/文件归属及真实损坏拒绝。
3. **进程和批次复用。** 顺序复用每阶段worker和DuckDB连接，结果/state共享重放；同一日期/年度目标合并一次。迁移内部请求和所有直接测试消费者，不改公开CLI或业务核。
4. **固定版本隔离验收。** 先验证小样本、必要故障和成本计数，再只运行一条25股完整隔离链，在其中取消/重启/续跑，最后汇总覆盖和未修改行。独立字面金样本证明公式；不另跑第二条完整正常链或同公式全量重算。

当前工程预算沿唯一RepairBudget：plan192MiB、DuckDB2GiB、父子RSS4GiB、2线程、spill2GiB、候选10GiB、单股片段100,000行、可见真实进度≤30秒。前七项是现有实现选择，不新增更紧限制；必要调整先给实测依据，不修改旧计划。本轮不套用周/月Raw临时6GiB额度。

通过标准及正反测试详见LLD §8—§10。首先证明重复工作已经退出，再跑完整链；不以增大内存替代结构优化，不用旧通过记录冒充新实现验证。
