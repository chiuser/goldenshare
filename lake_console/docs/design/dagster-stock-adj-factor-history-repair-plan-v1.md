完整文件包含其他股票时，保留行只做一次双向EXCEPT ALL。原blocking需要的范围外输入只读并按同一批次复用，不能转成修复目标或每个worker的全市场审计。最终audit汇总已封存证据、文件归属/完整性与覆盖事实，kernel/COPY=0。

文件提交前先把实际校验结果和输出强身份记入原record，再rename并补记完成；中断后凭这份证据完成提交，不重新COPY。同批完成记录中已持久化的业务证明可供未登记文件复用，具体顺序见LLD §7。

4. **固定版本隔离验收。** 先验证小样本、必要故障和成本计数，再只运行一条25股完整隔离链，在其中取消/重启/续跑，最后汇总覆盖和未修改行。独立字面金样本证明公式；不另跑第二条完整正常链或同公式全量重算。

完整白名单、函数及测试消费者见LLD §14。不改原公式核、日常assets/jobs/checks/sensors、catalog/schema/paths、AGENTS、业务API或Prod链路；无需部署或重载Dagster定义来运行专项CLI。

### 8.4 正式数据修复的执行顺序

正式执行前先形成一次执行单：本机当前dev-interface的固定实现、命令、DAGSTER_HOME只读来源、正式Lake/staging路径、新run_id、末端、窗口结束边界、原RepairBudget及预计读写范围。已审计的范围/末端/基准证据直接引用，不重跑。

1. **准备并冻结一次。** freeze内部完成有界规划，不先另跑一次inspect。已保存的同版来源和准备片段直接复用；确实尚无可用数值来源时，只取25股批准因子区间和10月16日锚点，预计最多50个基础请求，失败不盲目扩请求。目标/输入唯一清单、footer体积、身份和窗口证据完整后原子写plan。正式数量以这份清单为准，不使用R3夹具的1,778文件和5分51秒估算。
2. **构建真实候选一次。** 沿factor→price→indicator运行，按原逐文件/片段记录取消续跑；所有目标完整后，汇总现有业务证明、目标覆盖、文件归属和预算。无新公式计算、无市场复审。
3. **预览提升清单。** 给出完整目标清单引用和按资产汇总的将替换、no-op、已完成/待完成数量及字节，确认真实候选覆盖全链及仍处批准窗口。预览只读，不写checkpoint、补证明或触发事件；同一有效证据被实际提升复用，不再计算整条链。
4. **逐文件正式提升。** 按因子→价格→指标结果→state的固定顺序；同一共享文件只提交一次。先持久化该文件提交意图，再原子替换并登记；no-op不写正式文件。已有正确成果不重算或重写。
5. **统一收尾一次。** 汇总所有目标的正式文件身份、逐文件读回结果、变更/跳过/已完成数和实际修改键范围，复用候选阶段的保留行及业务证明。输出实际修改清单和失败明细。只在文件证据齐全时标记R4文件修复完成，DG事件明确待R5。

步骤1—3只写本run正式staging，步骤4才替换正式文件；两类写入的命令和范围分别列入批准执行单。发生范围外错误、未知文件、真实冲突写者、合同/版本不符或超预算时停在当前边界，保留现场，不以改hash、降校验、升额度或操作其他服务绕过。

### 8.5 失败、取消、恢复及数据可见性

原计划、候选业务证明和旧R3现场不可改写。正式逐文件checkpoint置于本run现有checkpoints树，新增的是本专项正式提交记录，不是长期状态服务/数据库或通用恢复框架。

取消后停止领取新文件，已替换文件保留；替换发生但完成记录未写时，凭提交意图和正式文件的新hash补记；仍为旧hash则继续原提交；第三种内容、候选缺失或归属不明拒绝。no-op不生成替换动作。完整恢复状态表、fsync次序和计量迁移见LLD §18—§19。

逐文件原子性不等于31资产整体原子。提升期间会短暂存在新旧文件并存，因而必须处于已批准、没有冲突写入的窗口；本任务不启动以整链一致为前提的下游计算或发布serving，不要求关闭所有只读工具。部分完成如实报告并续完，不假装整链已完成，也不自动回滚或引入备份/快照。窗口过期后的新批准窗口记录在本run执行checkpoint，业务plan/hash不改；实际输入或实现冲突才需重新规划。

### 8.6 性能、验收和阶段终点

沿LLD §8既有预算，不新增更紧内存、批次、并发或时限，也不借用周/月Raw的6GiB额度。先修读写模型；正式容量以必要文件一次去重计量、已有小样本和实际吞吐说明，未知耗时明确未知。超原预算时先说明具体对象和原因，未获确认不自行放宽或强行执行。

R4验收重点是：25股范围不扩大；准备不枚举全市场；字段、算法、量额和保留行不变；全链候选完整才可提升；正式替换前后退出能恢复；重复执行不重新COPY/重放/替换；无写权限、路径越界、symlink、缺候选/证明、第三种hash及冲突写者均拒绝；sensor的状态/水位不变，事件/Prod操作为0。

完整正反测试矩阵和最终执行清单见LLD §21—§22。R4终点是正式文件修复及一次物理对账完成；R5事件、serving、周/月周一日常验收均不夹带推进。本轮终点仅为这两份文档补齐并交review。
