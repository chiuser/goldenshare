## 1. 决定与原 side 方案的纠偏

仅因源站现在少了小数位，不重同步历史因子。保留原来实际采集的源信息；“数位更多”不自动证明更准确，也没有证据说明源站改变精度是为了节省磁盘。周线照收源 21 字段，价格对比差异记录但不单独阻断，不用本地计算价替换源 qfq/hfq。

原 side 文档拟修 601198.SH 的 451 个日期，是沿用此前逐分相等门禁的处理。该集合仅为精度变化，本次取消其默认 DG 因子/日线/分钟线/指标重建。Prod 已完成的该股 451 日及 000668.SZ 247 日维护不回滚；两边允许这些合法采集版本的精度不同，不为数字一致强行传播。

新的有限修正集合为 25 只股票/2,489 个股票—日期因子键：源当前值与旧值差异不能由本轮观察到的三位舍入解释。23 只是其中出现剩余周线分位价差的股票，不是因子修复全集。不能因此重同步全部 5,254 只源因子有差异的股票。

本专项采用独立人工历史入口：Tushare → DG Raw/Silver 因子 → DG 自主日线/分钟 QFQ → 受影响指标和 state。普通自动 repair 比较相邻交易日，不能识别同一历史日期的新旧版本；不修改其输入、job、sensor、schema、公式、参数版本和基准默认行为，不新增历史扫描 sensor、永久版本表或普通公式 check。历史修复一次完整对账结束，日常只检查本次新增数据，reports 不作执行/恢复/验收依赖。

## 3. 数据处理与基准

Raw 只替换批准的非舍入变化键，其他历史采集值保留；不是将全部 Raw 因子按当前低精度版本规范化。Silver 应用现行 CNY 生命周期与日期规则，不改变身份、不删除退市历史。执行前若发现缺行或生命周期冲突，说明后重新确认，不能静默扩成补缺或身份修正。

每股保持当前有效 QFQ 基准，显式冻结 as_of、实际因子行日期/值及各资产端点，不能把旧因子修正日当成基准日。需要检查该股既有序列是否混基准；若基准漂移或需要全历史换基准，停止重审。价格只修真实输入影响日期，日线还包含上一实际日线因子受影响的后继记录；量额保持原值。1/5/15/30/60 从 Silver 按现有公式生成，90 从 30、120 从 60 派生。

指标/state 必须向后递推到已存在端点；不得只重算改价日、九根 K 线，或按“看起来收敛”提前停止。上游价格已正确也须审计指标/state，不能凭因子 diff 空集宣告全链无事。结果或 state 不同的文件才替换；其他股票/范围外记录逐字段保留。

### 3.1 分钟指标的完整执行要求

分钟价格候选先完成五个原始频率，再生成 90/120 分钟；七频 MACD/KDJ 及四频九转都读取这批候选覆盖后的完整价格序列。价格区间以外的现有行情仍参与后续指标计算，不再改其价格。各频率、指标结果和 state 分别冻结既有末端；不统一截到因子最后变化日，也不为了本专项补新的行情或指标覆盖。

MACD/KDJ 当前计算核按交易日接收输入。首次变化 bar 所在日从第一根已有 bar 开始重算，读取上一 expected 交易日的精确 state，另带前 8 根实际 bar 供 KDJ 的 9 根窗口使用。禁止取一个任意更早的 state 代替缺失的上一交易日状态。跨年、跨计算片段继续读取前一候选片段 state 和足够的价格窗口，不能到新年重置。七频 state 中没有新行情的交易日按现有规则沿用上一状态，并保留 last_trade_time；不能因为没有 bar 跳过受影响的状态文件。

九转从完整单股历史或等价分段输入重算，使用前 4 根实际收盘价及连续方向/计数；不把连续计数截成 9。价格变化不保证 KDJ 或九转一定变化，必须比较实际结果再决定写入。日线仅 pre_close/change/pct 变化而 OHLC 未变时，不直接认定趋势/九转输入变化，但仍核验是否有之前未完成的指标修复。

所有指标起点、计算行数、状态分区数、实际差异行数、完整候选文件字节及末端值由 R0/候选阶段逐资产汇总。恢复日更前必须核验最后 expected 日 state、下一日继续计算的 seed 以及近期 readiness；文件通过后再按批准范围补事件，不用成功事件代替计算验收。本次不改变公式、参数、indicator_version、普通 sensor 合同或 API。

源周/月 Raw 的 qfq/hfq 是接口原值，不属于此计算链，禁止本专项反写。源技术因子/九转镜像也不能被本地计算覆盖。DG 日线九转的 Prod serving 消费者只输出差异；若需发布，另列股票/日期/字段和授权，不能调用整日 DELETE/INSERT publisher 传单股数据。

## 4. 同步顺序与两条链的边界

1. 先在 Prod 调整价格诊断、隔离验收、获准部署。源基准与冻结目标等真错误继续阻断；跨接口价格差异只记录。
2. 执行前复核上表并冻结源事实；经批准，Prod 用现有 adj_factor 维护入口修 25 只限定区间，Raw/Core 一次读回。DG 原始来源仍是 Tushare，不以 Prod 因子文件冒充源返回。
3. 周线链：从 15471 原详情继续原批 → 首批一次完整对账 → 冻结独立因子补刷批 → 对账并生成真实 B0 → DG 按年捕获/合并/逐文件提升/一次对账 → 事件 → cursor 水位及获准调度。不能重开全市场因子任务，也不能为了诊断重新下载已完成 523 个 unit。
4. DG 因子链可在周线续跑期间进行只读 R0 和获准候选构建；它不依赖 B0，完成与否不阻断源周线接收。所有因子、价格、指标/state 候选先审计完成，再在独占窗口按 Raw/Silver 因子 → Gold 价格 → 指标/state 逐文件提升。
5. DG 正式文件一次完整对账通过后，独立进行事件预览/获准补录，按差异决定可选 serving 发布，最后关闭维护窗口。两个专项各自收尾，日常只验本次范围，无永久历史复查。

候选位于 /Volumes/datasource/data_lake_staging/stock_adj_factor_history_repair/run_id=<uuid>/，正式目标仅 /Volumes/datasource/data_lake。同文件系统 os.replace、逐文件 checkpoint、幂等向前续跑；不备份、不删除、不回滚已提升文件。多文件不是全链事务，失败须保持维护状态直到完成读回。CLI 不自动取得 Dagster pool 锁；运营暂停/排空全部相关 writer 和避免消费混合版本，执行前确认活动 run。

## 5. 性能和拒绝策略

本轮源 25 个单股范围、每个最多 240 行，总 2,489 行；MCP 不暴露分页，未据此宣称正式客户端 limit/offset 已验证。Prod 既有维护可能按日期 unit 规划，正式请求量须以计划预览实测，不把 MCP 请求数直接当任务执行请求数。账户配额沿管理员确认，不追加调查。

DG 只读计数扫描 3,451 个文件、压缩大小合计 739,294,573 字节，峰值 RSS 347,422,720 字节；这是范围/库存聚合，不是完整候选计算耗时、全部指标输入字节或写入量。全部分钟价库存有 175 个股票×频率组合；不能套用原 1 股/451 日的文件数和耗时。

拟预算仍为 DuckDB 512MiB、RSS 1GiB、2 threads、spill 2GiB、累计候选 10GiB、单股片段最多 100,000 行，不改变共享默认。R0 按 25 只×各自区间/端点汇总价格、指标、state、九转、最大宽文件、源读取次数及候选字节，冻结精确文件/事件上界；同一全市场目标文件合并所有批准股票后只生成一次候选，不能逐股重写同一个日文件。

单股频年/月份/递推片段顺序计算，上游必要投影复用，候选视图供下游读取；Python 不逐行处理大行情。超过 100 分区用资产/频率/月聚合审计，最终仍逐文件提升。超 RSS/行数先拆片段或子进程；超累计候选/磁盘则停止并评审分批范围，不自行增加预算或先提升半链。磁盘须满足候选+spill+20%余量，样本后给出吞吐及耗时；本轮不具备全链性能数字，不能承诺全量执行已放行。
