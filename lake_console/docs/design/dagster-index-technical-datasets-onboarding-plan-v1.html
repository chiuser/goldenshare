Dagster 指数技术数据资产接入方案 v1

同一轮规划两个独立数据产品：DG 日线主要指数池的 Tushare 日级技术因子 idx_factor_pro，以及由主要指数分钟线 Silver 同日有效池计算的分钟技术指标。 两个对象池因源数据可用性而有意分离：日级产品读取现行 seeds/market/major_indices.cn_a.csv， 分钟产品读取 effective_silver_codes_for_date(trade_date)；禁止把两者强行统一。各数据集的历史起点仍由自己的 coverage contract 定义。 本文只做设计和实施门禁，不执行 Dagster、建分区、拉全量或写 Lake。

状态：已拍板，LLD 已完成 文档日期：2026-08-08 范围：DG / Raw / Silver / Gold 源接口：idx_factor_pro

代码级实施合同：Dagster 指数技术数据资产接入 LLD v1。

0. 后续日级对象池决策（2026-08-08）

当前代码仍是科创综指历史补录前的 10 指数日级 seed；本文的后续实现目标已经更新为： 日级 seed 保留 899050.BJ 北证50，并新增 000680.SH 科创综指；分钟池继续独立，不能与日级 seed 合并。 Prod 已补齐 000680.SH 的 2020-01-02..2025-01-16 历史数据，DG 补录和 11 指数 seed 的实施合同见 科创综指指数日线历史补录 LLD。 补录实施前，运行态仍按 10 指数；补录与 seed 发布完成后，日级对象池统一按 11 指数执行。本文后续章节均按这一阶段合同表述。

1. 结论先行

数据产品 A：指数日级技术因子

建议资产：raw_tushare_idx_factor_pro + silver_index_factor_pro。

事实范围：严格读取 DG 日线主要指数 seed；补录发布后的目标 seed 包含 899050.BJ 北证50和 000680.SH 科创综指，共 11 个。

日常请求：每个交易日一次全源请求，返回后只选择当日 active seed 对象。

历史请求：按批准 seed 代码逐个执行区间分页；目标合同发布后为 11 个代码，禁止按约 8800 个交易日扇出。

数据产品 B：主要指数分钟技术指标

建议资产：每频率一组 Gold 指标资产 + Gold 递归状态资产。

上游：只读现有 silver_major_index_mins_{freq}m。

事实范围：逐日严格承接上游 Silver 的有效代码集合；当前日期排除 899050.BJ、包含 000680.SH，历史日期允许少于 10 个。

计算：DuckDB 向量化 SQL；MACD/KDJ 严格承接前一交易日 state。

物理切片：继续按 freq/trade_date，不照搬股票的“股票-年份文件”。

两个产品不能合并成一个资产。日级因子是 Tushare 已计算并提供的源事实；分钟指标是从 Silver 分钟 bar 派生的 Gold 结果。它们的来源、更新方式、历史恢复和质量门禁都不同。

停止条件：当前页行数 < 8000
禁止：日常增量按代码扇出、历史按约 8800 个交易日扇出、无分页的单代码全历史请求

4.8 历史 Bootstrap 与规模

维度预估门禁
历史范围每个批准代码从源端实际最早可用日到批准截止日，不强行共用一个起点。M0 逐代码探测并冻结 first_available_trade_date，不能沿用分钟线起点猜测。
源请求/页目标 11 个代码分别分页；总页数由每代码源端历史长度决定。直接 connector 实测后 dry-run，冻结代码、区间、页预算和计划 hash。
源行数由 11 个指数各自真实首日和分页结果决定，不把旧 10 指数估算沿用为验收值。全量前逐代码抽样并以 source count 校准，禁止把估算当验收值。
文件数Raw + Silver 合计约 17400-17800 个正式 Parquet。不得产生每指数文件。
磁盘峰值数据行只有数万级，但逐日小文件开销占主导；初始工作预算按 Raw + Silver 合计低于 1 GB。以 20 日和 1 年样本实测压缩率、文件开销和 staging 峰值；可用空间低于 2 倍峰值时拒绝执行。
理论源端耗时请求量为十几页量级，源端网络时间应为分钟级而非小时级。记录每代码页数、限流等待和总 elapsed；超出 dry-run 预算立即停止。
事件补录远大于 100 分区。必须 Direct Lake Bootstrap + 批量 Runless Event Backfill，不逐分区跑 Dagster。
  1. 冻结补录发布后的 11 指数、每代码起止日期、分页计划和请求预算，dry-run 不写正式 Lake。
  2. 选择短历史和长历史代码执行分页样本：验证 offset、短页终止、重复页防护和源端总数。
  3. 按代码写入 run-scoped source staging，并用 DuckDB 重排成逐交易日 Raw/Silver 样本，校准压缩率和小文件开销。
  4. 按代码批次拉取并写临时根目录；所有代码源端/Raw 主键对账通过后再原子提升。
  5. 全量文件审计通过后，批量登记 dynamic partitions 并补 materialization/check events。
  6. 最终对账：日期、文件、行数、主键、schema、最新日源端样本。

5.4 物理路径与写入

gold/indicator/major_index_mins_technical/
  freq={1|5|15|30|60|90|120}/trade_date=YYYY-MM-DD/part-000.parquet

gold/indicator/major_index_mins_technical_state/
  freq={1|5|15|30|60|90|120}/trade_date=YYYY-MM-DD/part-000.parquet
  • 每个频率、交易日、资产只写一个文件，文件内代码集合必须与同日 Silver 有效池完全一致；当前日期通常为 10 个，历史日期允许因源起始日少于 10 个。
  • 计算使用 DuckDB SQL；禁止把分钟行拉回 Python 循环计算。
  • 每个目标文件先写 run-scoped staging，完整校验后 os.replace。
  • 若任一 blocking check 失败，不提升指标文件或 state 文件；已有健康文件不被覆盖。
  • 状态资产是次日递推门禁：缺失或参数版本不一致时，日常增量必须停止，不能静默从默认值重启。

5.5 计算流程

  1. 加载目标日期 Silver 单频率文件，并校验其 blocking checks 已通过。
  2. 读取该频率所需的有限历史 Silver 文件：按每个代码排序，截取当前日之前最多 249 根 bar。
  3. 读取严格前一开放交易日的同频 state；仅历史首日允许按冻结种子初始化。
  4. 一次 DuckDB query 生成 MA/BOLL/MACD/KDJ replacement relation。
  5. 写指标 staging 和当日 state staging；执行 schema、key、source parity、有限值、warm-up 与 state continuity checks。
  6. 指标文件与 state 文件位于不同正式目录，不能宣称跨目录原子提交；必须按 LLD 的顺序提升、partial fail closed 与 repair rollback 协议处理半提交风险。

5.7 Job、Sensor 与恢复

  • 建议一个 gold_major_index_mins_technical_daily_update_job 选择本轮批准的全部频率指标与 state assets/checks。
  • run-status sensor 监听主要指数 Silver 更新成功；再次核验同日全部上游 checks 后，只提交目标交易日一次。
  • 日常 sensor 必须按日期顺序推进；前一日 state 未 ready 时跳过并明确写出阻塞日期。
  • 历史 bootstrap 直接扫描现有 Silver Parquet，按交易日有序批量计算，不产生 Tushare 请求。
  • 历史数据重写、算法版本升级或 90/120 合同变化时，使用显式 repair 起点向后重算；不能只修单日。
  • 大范围历史文件完成后使用批量 Runless Event Backfill；逐日 event log 扫描禁止进入热路径。

6. 明确拒绝的方案

  • 拒绝从生产 PostgreSQL 的 raw_tushare.idx_factor_pro 直接迁全历史：范围和最新日均不完整。
  • 拒绝首批保存 Tushare 当日返回的全部约 3772 个指数：日级因子只保存日线 seed 当日有效池。
  • 拒绝单代码全历史不分页：000001.SH 已实测撞到 8000 行并发生截断。
  • 拒绝批准 11 指数仍按约 8800 个交易日拉历史：请求量远高于按代码区间分页。
  • 拒绝依赖纯 start_date/end_date 拉全市场：真实请求返回 0 行。
  • 拒绝在 Silver 重算 Tushare 日级因子：会制造第二套算法事实。
  • 拒绝把指数分钟指标命名成 qfq：指数不存在股票复权语义。
  • 拒绝在 Python 中逐行计算千万级分钟指标。
  • 拒绝状态缺失时从默认值静默继续：会让后续全链指标永久漂移。
  • 拒绝一边接入数据资产一边顺手改 Wealth API、指数详情页或技术分析结论。
