股票日线 Raw/Silver 人类可读治理标杆专项

本文记录当前生产链路上的股票日线可读性治理结果。专项只改变 Dagster UI 文案、run stdout、 materialization metadata、check metadata 和 sensor cursor 的表达方式，不改变股票日线 raw/silver 的生产决策。

资产族：stock_daily 范围：raw_tushare_stock_daily / silver_stock_daily 不写湖 不改触发逻辑 不改数据 SQL

1. 当前生产事实

  • raw_stock_daily_update_job 只写 raw_tushare_stock_daily 和它的 checks，不 selection stock_basic 或 suspend_d。
  • raw_stock_daily_update_job_sensor 等 stock_basic、suspend_d 和 Tushare daily 源站 ready 后，提交 raw 全量分区 run；最近两个交易日的 missing-code repair 仍走同一个 raw job。
  • silver_stock_daily_update_job 只写 silver_stock_daily 和它的 checks。
  • silver_stock_daily_update_job_sensor 等同日 raw ready、stock_basic freshness 和 suspend_d ready 后，提交 silver run。
  • silver_stock_daily 写入前仍保留不可绕过的 assert_silver_stock_basic_fresh_for_stock_daily(...)，防止人工 run 绕过 sensor 后写出静默缺行文件。

本专项没有改变 asset 名、job 名、sensor 名、check 名、selection、run key、run config、Tushare 参数、DuckDB SQL、路径或数据湖文件内容。

2. 人看问题的顺序

股票日线现在按下面顺序给人提供线索：

入口 先回答什么 完整证据在哪里
Asset / Job / Sensor description 它是什么、写什么、依赖什么、给谁消费。 asset definition metadata、拓扑文档。
Sensor cursor 本 tick 为什么触发或为什么没触发，卡在哪个组件。 完整 readiness 诊断、asset/check metadata。
Run stdout 本 run 到了哪个阶段，写了多少行，是否进入 repair 或 validation failure。 Dagster run log、materialization metadata。
Materialization metadata 本次产物写成了什么、下一步等什么 check 或下游。 Parquet 文件事实、check metadata。
Asset check metadata 质量规则通过还是失败，失败的规则名和下一步是什么。 对应 check 的 count、sample 和文件路径。

3. 本次落地口径

Asset 与 stdout

  • raw_tushare_stock_daily 的说明改为“源镜像 + 按交易日保存 + 供 silver 标准化使用”。
  • silver_stock_daily 的说明改为“标准事实 + 生命周期/币种/北交所/停牌过滤 + 下游消费”。
  • 新增 stdout 事件：raw_stock_daily_started、raw_stock_daily_completed、raw_stock_daily_repair_started、raw_stock_daily_repair_completed、silver_stock_daily_started、silver_stock_daily_validation_failed、silver_stock_daily_completed。
  • stdout 只写分区、模式、row count、attempt 等小字段；禁止写完整 SQL、DataFrame、样本行或全量股票代码列表。

Materialization metadata

  • 追加 goldenshare/summary、goldenshare/next_action、goldenshare/result_status、goldenshare/input_summary、goldenshare/filter_summary、goldenshare/diagnostic_ref。
  • 保留原有 dagster/uri、dagster/row_count、goldenshare/observed_columns、过滤计数、重复计数和冲突样本。

Sensor cursor

  • cursor 仍使用 v1 顶层结构，继续保留 runtime_state.stock_daily_missing_code_repair，避免 repair 重复提交。
  • raw cursor 不再把完整 repair_details 放入 evidence，只保留 repair 日期数、首个 repair 日期、首个 reason、缺失数量和 attempt。
  • blocked_component 明确为 cn_a_stock_trade_days、stock_basic、suspend_d、tushare_daily_source、raw_tushare_stock_daily、raw_tushare_stock_daily_repair 或 none。
  • summary 和 next_action 使用短中文；reason_code 保持 ASCII 机器码。

Check metadata

  • 聚合 check metadata 追加 summary、next_action、rule_summary，并保留 failed_rule_names。
  • 缺文件结果直接说明缺哪个文件、下一步先补文件再重跑。
  • raw/silver tradable universe metadata 追加 tradable_universe_summary，把 expected、actual、missing、extra 和全日停牌解释数放到同一个小摘要里。

4. 性能与边界

入口 本专项新增读取 本专项新增写入 拒绝策略
asset 写入 0；仍沿用原有 Tushare/DuckDB 读写。 只追加 materialization metadata 和 stdout。 不改变原失败条件。
sensor tick 0；不新增 Dagster event scan、不新增 lake scan。 只写更短 cursor。 cursor 超过硬上限仍由通用 builder 拒绝。
asset checks 0；仍沿用原有 check SQL。 只追加 check metadata 小字段。 不改变 blocking/WARN 语义。

本专项没有进入正式 Dagster 执行、没有写 Dagster DB、没有访问真实 Tushare、没有写数据湖。 验收使用本地单元测试和静态门禁。

5. 验收门禁

  • tests.test_stock_daily_sensor：锁住 raw/silver cursor 的人类可读摘要、阻断组件、repair state 保留和 cursor 长度。
  • tests.test_stock_daily_raw_checks：锁住 check metadata 的 summary、next_action、rule_summary 和 failed_rule_names。
  • tests.test_stock_daily_human_readable_contracts：锁住 description、stdout 事件名和 materialization metadata 小字段。
  • tests.test_run_contract_static_gates：禁止 oversized cursor fragment、stdout 大字段和聚合 check metadata 回退。
  • tests.test_asset_governance_contracts：确认 catalog / definition governance 没有偏离。
