Dagster 股票分钟线高频资产族人类可读治理 LLD

本文是 dagster-dataset-human-readable-governance-rollout-plan.html 中 Wave 4 的代码级低阶设计。目标是把股票分钟线 raw/silver/qfq/MACD-KDJ/state 链路的 Dagster UI、stdout、materialization metadata、check metadata 和 sensor cursor 写得更像人看的运行路标，而不是机器报告转储。

Wave 4：分钟线高频链路 只改表达层 不改触发逻辑 不改运行逻辑 不写湖 不写数据库 不运行正式 Dagster

当前状态：LLD 已补齐，代码实现尚未开始。后续实现必须按本文分子波推进并单独提交。

1. 目标

Wave 4 不改变任何数据生产决策。完成后，运维打开分钟线相关 run、asset 或 sensor 时， 应能直接判断：这是什么频度、读了哪些上游大类、写出了什么粒度、为什么触发或跳过、 卡在哪个组件、下一步该修哪里。

高频链路体量最大，因此“更可读”只能来自复用已有结果摘要，不能新增热路径扫描、 不能扩大 cursor、不能把 code/path/file 明细塞进 Dagster DB。

3. 硬边界

边界 执行口径
Definition 身份 不改 asset、job、sensor、check 名称；不新增同语义 check；不新增 summary/readiness asset。
触发逻辑 不改 job selection、run key、run config、partition、default status、运行窗口、单 tick 最大提交数、run-status sensor 触发条件。
运行逻辑 不改 prod DB SQL、Tushare fallback、DuckDB SQL、复权公式、MACD/KDJ 参数、state 递推、repair 范围和连续性口径。
数据湖 不改 path helper、物理布局、Parquet schema、文件内容、写入方式、bootstrap 或历史 runless event。
Cursor cursor 是调度路标，只放目标日期、阻断组件、原因、下一步和小证据；禁止 status_samples、完整 batch status、全量 code/path/file 列表、报告型 to_cursor_details()。
Runtime state 凡用于已提交目标去重、repair attempt、upstream batch、backoff 或 completion 判断的字段必须保留；只能改展示字段。
Checks 只增强现有聚合 check metadata；不拆分 check，不扩大 Dagster DB 状态量，不新增逐 code/逐文件 check。
验证 只运行本地单元测试、静态门禁、文档检查和 git diff --check；不运行 dg、job、sensor、materialize、backfill。

5. 性能门禁表

入口 现有规模 本治理允许增加 拒绝策略
raw asset 单分区五个源频度；prod DB 或 Tushare fallback 读取已经由现有写入逻辑控制。 只从 StkMinsRawWriteResult 已有字段生成 summary/next_action/stdout；不新增 source 查询、不新增文件扫描。 若可读 metadata 需要额外扫描明细行，停止并改为使用现有计数字段。
silver asset 单分区五个 silver 频度；写入逻辑已读取 raw、identity map、stock daily、suspend、price correction seed。 只复用 SilverStkMinsWriteResult 已有计数和路径存在性；stdout 只打阶段和聚合数量。 禁止为了生成说明重新读取 raw/silver parquet 或枚举全量股票。
qfq asset 七频度，物理按股票年份文件写入；原生频度读取 silver + adj_factor，派生频度读取 qfq source。 只复用现有 write result / diagnostics 中的 row count、file count、source freq、factor coverage 计数。 禁止把每个股票年份文件路径、每个 code 或每个 mismatch 样本扩进 metadata。
MACD/KDJ asset 七频度 indicator + 七频度 state；依赖上一 expected state 和 qfq source。 只用现有 write result 的 source/output file count、row count、previous state 信息生成摘要。 禁止把 state 文件内容、每个 code 的递推状态或全量 path 列表写入 Dagster event。
普通 sensors raw/silver/qfq daily/factor repair sensors 已有 continuity + batch readiness，窗口固定为最近 10 个 expected dates。 只重写 cursor 文案和小 evidence；不新增 readiness 调用，不改变 fast path runtime state。 普通 request/skip 目标小于 3KB，硬上限 8KB；超过即删字段而不是扩大 cursor。
run-status sensors MACD/KDJ daily/repair 由上游 run success 触发，读取必要的 qfq、repair、state readiness。 只优化 SkipReason 文案和必要 stdout/log 说明；不新增 cursor，也不新增 instance 查询。 禁止为了“更清楚”扩大 recent run 查询、扫描 event history 或改 completion gate。
checks raw/silver/qfq/MACD-KDJ checks 已经是聚合 check，内部有现有 SQL 和 sample limit。 只把已有计数组合成 summary、next_action、rule_summary。 禁止新增 SQL、禁止新增 check、禁止扩大 sample limit。

7. Cursor 标准

Wave 4 普通 sensor 仍使用现有 v1 顶层 contract：

  • schema_version、evaluated_at、decision、target_date、selected_count、blocked_count、sample_keys、details 保持不变。
  • details.summary 必须是一句短中文，直接说明本 tick 发生了什么。
  • details.next_action 必须告诉运维下一步看哪里或等什么。
  • details.blocked_component 只能写稳定组件名，例如 stock_basic、raw_stk_mins、silver_stk_mins、adj_factor、gold_stk_mins_qfq、qfq_factor_repair、run_window、none。
  • frontier 只保留窗口起止、ready through、first not ready、selected date 等小摘要。
  • evidence 只保留 registered count、freq count、run window、首个失败样本等小字段。

禁止项：status_samples、*_batch_status.to_cursor_details()、 全量 file_paths、全量 stock_codes、完整 schema/type map、 每个频度/每个日期/每个 code 的明细状态。

10. 不做事项

  • 不写数据湖、不访问 prod DB、不写 Dagster DB。
  • 不清理历史 event/run/cursor，不做 runless event 补录。
  • 不启用或停止任何 sensor。
  • 不改分钟线连续性、expected calendar、previous state、repair upstream batch、completion gate。
  • 不把 Wave 4 做成一次性全仓库重构；必须按 4A/4B/4C/4D 分子波提交。
