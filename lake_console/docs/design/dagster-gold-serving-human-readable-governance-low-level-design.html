Dagster Gold / Serving 人类可读治理 LLD

本文是 dagster-dataset-human-readable-governance-rollout-plan.html 中 Wave 3 的代码级低阶设计。目标不是改变 Gold 或 Serving 的生产方式，而是让运维在 Dagster UI、run stdout、materialization metadata、check metadata 和 sensor cursor 中能直接看懂： 指标是什么、输入口径是什么、写到了哪里、失败后先修哪里。

Wave 3：业务 Gold 与 Serving 只改表达层 不改触发逻辑 不改 lake / DB 数据 不运行正式 Dagster 分子波推进

当前状态：LLD 已建立；Wave 3A market_major_indices_daily 已落地到代码、测试和静态门禁。后续按 Wave 3B/3C/3D 分步提交。

1. 硬边界

类型 口径 代码落点
必须保留 asset/job/sensor/check 名称、partition、run key、run config、job selection、default status、触发顺序和 readiness 语义。 defs/assets/**、defs/jobs/**、defs/sensors/**、defs/checks/**
禁止 写 lake、写 ClickHouse、写 prod PostgreSQL、写 Dagster DB、运行 dg / job / sensor / materialize / backfill。 本 LLD 的实现轮只跑本地单元、静态门禁、git diff --check 和 docs integrity。
禁止 把完整 row、完整路径列表、完整 code list、完整 ClickHouse partition map、完整 to_cursor_details() 报告写入 cursor。 Wave 3 sensors：market breadth、return distribution、wealth turnover、ClickHouse serving。
允许 追加 summary、next_action、result_status、input_summary、metric_summary、serving_summary、diagnostic_ref 等小型 metadata。 只追加，不删除现有诊断字段，避免破坏已有测试和运维习惯。
允许 增强 stdout 里程碑日志，但只记录阶段、日期、分区数、行数、目标表，不打印 SQL、DataFrame、完整样本、完整 code/path 列表。 DgStdoutLogger(...)，或现有 logger 入口。

2. 性能门禁

入口 本轮新增读取 本轮新增写入 拒绝策略
Gold asset materialization 0。复用现有计算后已经拿到的 row count、metric row、audit。 0 个额外文件；只追加小型 metadata/stdout。 若必须新增 DuckDB/ClickHouse 查询才能说明清楚，停止并重新设计。
Serving asset materialization 0。复用现有 read-back / audit / target table 信息。 0 个额外 DB 写入；不改 delete/insert/transaction 语义。 若要查询 prod 或 ClickHouse 做额外审计，另起只读审批，不放进本轮。
Sensor cursor 0。只复用当前已计算的 batch readiness、frontier、gate status。 cursor 小字段，普通 request/skip 目标小于 3KB，硬上限 8KB。 禁止把 batch status、row map、path list 写入 cursor。
Check metadata 0。只用现有 check 结果聚合摘要。 只写 check event metadata 的小型摘要。 不新增细碎 check；不改变 blocking/WARN 语义。

5. 代码级改动模式

5.1 Asset Description 与 Materialization Metadata

  • 每个 Wave 3 asset description 必须回答：这是什么业务指标/serving 表、输入是谁、给谁消费。
  • 追加 summary、next_action、result_status、input_summary、metric_summary 或 serving_summary。
  • 保留现有 breadth_row、distribution_row、partition_metadata、hash、read-back 诊断字段，但它们不应是 UI 第一眼唯一信息。
  • stdout 只记录 *_started / *_completed 和小型计数，不打印完整 rows、SQL、path list 或 code list。

5.2 Check Metadata

  • 不新增、不删除、不改名 checks。
  • 聚合 checks 追加 summary、next_action、rule_summary 和 list 类型 failed_rule_names。
  • ClickHouse / prod sync checks 的 metadata 先说明是本机 serving、prod serving 还是 gold 对账失败，再保留目标表、分区和少量样本。
  • 不把历史全量对账或完整 ClickHouse row map 塞回 Dagster check metadata。

5.3 Sensor Cursor

  • cursor 顶层继续使用 v1 contract：decision、target_date、selected_count、blocked_count、details。
  • summary 必须说清：触发了什么，或为什么没触发。
  • blocked_component 必须是具体组件，例如 silver_stock_daily、gold_market_breadth_daily、gold_stock_return_distribution、ch_share_fact_market_breadth_daily、prod_clickhouse。
  • next_action 必须告诉运维先修哪个上游或哪个 check。
  • 禁止把 batch_status.to_cursor_details()、status_samples、路径列表、完整 serving row、ClickHouse partition map 写入 cursor。

6. Wave 3A 初始计划

  1. 审计 market_major_indices_daily asset/check/sensor 当前实现和 tests。
  2. 补 description、stdout、materialization metadata：说明主要指数展示表、seed row、active seed row、输出行数和下游消费。
  3. 补 check metadata：缺 seed code、schema、row count、排名/展示字段等失败必须有 summary 和 next_action。
  4. 补 sensor cursor：raw/silver/input readiness 阻断时用中文说明卡在 seed、index basic、silver index daily 还是目标 gold。
  5. 新增或更新测试与静态门禁；只跑本地单元、git diff --check 和 docs integrity。
