Dagster Sensor Cursor 治理专项 LLD

本文是 Dagster Sensor Cursor 治理专项方案 的代码级落地设计。目标不是让 cursor 更“漂亮”，而是让它回到正确职责： 只作为本次 sensor tick 的调度路标，清楚说明触发或跳过的原因、阻断组件、目标日期和最少证据。

状态：设计口径已确认 schema_version=1 不改触发逻辑 不写 lake 不写 Dagster DB 不运行 dg

0. 依据与边界

本 LLD 已按当前代码和规则重新审计，依据如下：

  1. 仓库根 AGENTS.md：要求先审计代码，不用命名、印象或文档替代当前实现。
  2. lake_console/AGENTS.md：sensor 只做编排，不直接塞业务探测细节。
  3. lake_console/orchestrator/AGENTS.md：任何 sensor / cursor 改动必须先完成设计确认，不得运行正式 Dagster 动作。
  4. lake_console/orchestrator/CODING_STANDARDS.md：不改 run key、run config、job/sensor 名称；sensor hot path 必须轻量。
  5. dagster-data-pipeline-performance-governance.md：cursor 只允许存 schema、时间、selected date、frontier、小型摘要和有限样本，禁止长 metadata payload。
  6. dagster-sensor-cursor-governance-plan.html：已拍板统一模板、短中文、长度预算、禁止报告型 to_cursor_details()、一次性治理 active sensor。
  7. Dagster basic sensor 文档：cursor 是跨 tick 的小状态，常用 JSON，必须保持小，不能当报告存储。

本文只写设计，不改代码、不跑 sensor、不访问正式 Dagster instance、不访问正式 DB、不写数据湖。 后续编码时若发现本文与当前代码事实冲突，必须先回到本文修正设计，再继续实现。

1. 硬口径

口径 代码级要求 不允许发生的事
顶层 contract 不变 build_sensor_cursor(...) 继续输出 schema_version/evaluated_at/decision/target_date/selected_count/blocked_count/sample_keys/details。 不得改 schema_version 为 2；不得删除 load_sensor_cursor(...) 对 v1 的兼容。
details 统一模板 所有写 cursor 的 active sensor 都必须提供 reason_code、blocked_component、summary、next_action。 不得继续每个 sensor 自造字段方言，只写 reason_code 不写人话。
短中文允许 summary、next_action 可写短中文；json.dumps 应改为 ensure_ascii=False 并补 UTF-8 roundtrip 测试。 reason、reason_code 继续必须是 ASCII 机器码。
cursor 是路标 完整诊断移到 asset/check metadata、readiness helper 输出或只读审计报告；cursor 只留最少证据。 不得写 status_samples、完整路径列表、sample rows、完整 schema/type、完整 SQL 结果。
一次性治理 20 个写 cursor 的 sensor 文件同一轮完成，不保留新旧两套 active cursor 方言。 不得只改最近出问题的两个 sensor，然后让其它 sensor 继续写大 cursor。
不改运行机制 run key、run config、job selection、ready 判断顺序、上游门禁、单 tick run 数量均保持不变。 不得借 cursor 治理重写 sensor 选择逻辑或改 readiness 语义。
行为依赖保留兼容 凡当前代码会读取上一轮 cursor 的字段，必须先加兼容读取，再改写入结构。 不得直接删 already_submitted_for_trade_date、namechange_run_stage、stock_daily_missing_code_repair。
长度预算 普通 cursor 小于 2KB，复杂阻断小于 3KB，硬上限 8KB；超过 3KB 必须有针对性测试解释。 不得用“这是给机器看的”解释 10KB 以上 cursor。

  • MAX_CURSOR_SAMPLE_KEYS = 20。

  • details 没有标准结构，导致各 sensor 方言化。

字段 规则 代码落点
sensor_name 必须。写 Dagster definition 函数名，例如 silver_stock_daily_update_job_sensor。 每个 _cursor_payload(...) 固定写入。
job_name 有 job 的 sensor 必须；partition registration 或通知类可为 null。 使用现有 job 常量，不新增 job。
asset_family 必须。稳定资产族名，例如 stock_daily、stock_mins_qfq、wealth_market_turnover。 不从 catalog 动态推导，sensor 本地常量写入。
partition_set 有 partition 的 sensor 必须；多个 partition set 时写主目标 partition set。 使用现有 DynamicPartitionsDefinition.name。
reason_code 必须。ASCII 机器码，稳定、可测试。 build_sensor_cursor(...) 继续递归禁止非 ASCII。
blocked_component 必须。无阻断写 none；运行窗口未到写 run_window；分区缺口写 partition set 名；源未 ready 写源系统名。 每个 sensor 的 _blocked_component... helper 输出规范化。
summary 必须。短中文，说明本 tick 结论。 新增统一 builder 校验存在；测试验证 UTF-8 显示。
next_action 必须。短中文，告诉人下一步等什么或修什么。 每个主要分支测试断言。
frontier 窗口型 sensor 使用。只存 ready through、first not ready、first missing、selected date，不存每个日期完整 status。 新增 compact helper，替代 ContinuityBatchReadiness.to_cursor_details()。
gate_statuses 链式门禁使用。每个 gate 只存 ready、reason_code、failed/missing check 计数或少量名字。 替代 readiness_details、*_status 的报告型 payload。
evidence 只存最少证据，样本固定为 count + 前 3 个样本。超过 3 个只能看诊断报告，不能塞进 cursor。 新增 limit_cursor_samples(...)。
runtime_state 只给代码下一 tick 消费用。普通 sensor 为空。行为依赖必须列入第 6 节。 新增兼容读取 helper，先读新位置，再兼容旧 details root。
performance_ms 按需启用。只存聚合耗时，例如 batch readiness elapsed，不存 SQL 明细。 已有 raw index / ClickHouse 口径可迁入统一字段。
diagnostic_ref 按需启用。告诉人去哪里看完整诊断，不复制诊断。 asset/check metadata、readiness helper 名、审计报告路径。

禁止字段： status_samples、sample_rows、missing_file_paths、 raw_batch_status、silver_batch_status、gold_batch_status、 serving_batch_status、upstream_batch_statuses、 readiness_details、完整 schema map、完整路径列表、完整 code list、完整 SQL 结果。

已落地口径

  • 统一 builder 已落地到 build_sensor_cursor(...)：details 非空时必须包含 summary 和 next_action。
  • 中文显示口径已确认：cursor JSON 使用 ensure_ascii=False；summary / next_action 可写短中文，reason / reason_code 仍必须是 ASCII。
  • 长度硬门禁已落地：典型目标 2KB，复杂目标 3KB，builder 硬上限 8KB，超过直接失败。
  • active sensor 已统一迁入 frontier、gate_statuses、evidence、runtime_state、performance_ms；旧 continuity_status、readiness_details、*_batch_status 不再作为 cursor 字段写出。
  • 行为依赖状态只允许放入 runtime_state，并保留旧 cursor fallback 读取，避免部署后第一次 tick 因旧 cursor 断掉。
  • 静态门禁已覆盖：sensor cursor 不得直接调用报告型 to_cursor_details()，不得写 status_samples、sample_rows、完整路径列表或完整 batch status。

6. 行为依赖处理口径

这些字段不是“展示字段”，它们影响下一次 sensor 是否提交 run 或怎样选择 repair。 处理口径已确认：统一迁入 runtime_state，同时保留旧 root 字段 fallback，确保部署后的第一轮 tick 能读懂旧 cursor。 修改格式时必须同步更新读取逻辑和测试。

依赖 当前代码 风险 LLD 处理方案
股票日线 raw missing-code repair 状态 stock_daily_sensor.py 写 details[STOCK_DAILY_REPAIR_STATE_KEY]； stock_daily_raw_repair.stock_daily_repair_state_from_details(...) 从上一轮 cursor 读取。 直接删除会让 repair attempt、manual/waiting/exhausted 状态丢失，可能导致重复 repair 或绕过等待。 新写入放 details.runtime_state.stock_daily_missing_code_repair； 读取 helper 先读新位置，再 fallback 旧 root key。 本轮不新增状态表，不把 repair state 移出 cursor。若未来要彻底移出，需要单独设计状态实体。
股票曾用名分阶段 already-submitted stock_namechange_sensor._already_submitted_for_stage(...) 读取 selected_trade_date、namechange_run_stage、already_submitted_for_trade_date。 字段位置变更但 reader 不改，会导致同一阶段重复提交 run。 新写入放 runtime_state.namechange_run_stage、 runtime_state.already_submitted_for_trade_date； reader 使用 cursor_runtime_state(...) 并兼容旧 root 字段。

qfq factor repair already-submitted fast path stock_mins_qfq_factor_repair_sensor._already_submitted_for_target_date(...) 与 qfq daily 同构。 同一 repair target 可能重复提交。 同 qfq daily；新增测试证明 legacy cursor 仍能被识别。

11. 已确认口径

口径 1： 引入统一 cursor 模板，但继续使用 schema_version=1。本轮是 v1 contract 收紧，不做 v2 迁移。

口径 2： 允许 cursor 写短中文 summary / next_action，并把 JSON 输出改为可直接显示中文；reason / reason_code 仍保持 ASCII 机器码。

口径 3： 长度预算固定为：普通 cursor 小于 2KB，复杂阻断小于 3KB，硬上限 8KB。超过 3KB 必须有测试解释；超过 8KB 直接失败。

口径 4： 禁止 sensor cursor 直接调用报告型 to_cursor_details()。完整 readiness 报告、路径列表、样本行和 schema/type 明细只能留在 metadata、helper 输出或只读审计报告里。

口径 5： 所有 active cursor writer 一次性改完，不分批保留新旧两种 cursor 口径。无 cursor 的 run-status / Feishu 通知 sensor 不强行新增 cursor。

口径 6： 每个写 cursor 的 sensor 必须有 summary 和 next_action。它们是 cursor “说人话”的核心字段，不能只写机器码。

补充执行口径： 确实会被代码消费的状态统一放入 runtime_state，并保留旧 root 字段 fallback；stock_daily_missing_code_repair 仍保留在 cursor 内，本轮不新增状态表，也不把 repair state 移出 Dagster cursor。
