# DG 周线、月线主数据集收敛与 Raw 修订方案 v1

更新：2026-10-15。管理员已确认本方案目标；本轮仅整理文档。代码、正式文件、sensor、cursor和事件均未变更。原文件名沿用以保持引用，本文是周/月线本轮工作的唯一总方案。

## 1. 本轮目标与任务顺序

1. DG只保留复权周线、复权月线两套主Raw。两表均含未复权/前复权/后复权三套OHLC，无需再维护独立未复权数据集。
2. 修正保留Raw的已确认缺陷、补齐仍上市股票确实缺失的键。先核真实源与对象身份，不用日线自行合成已有源行情。
3. 物理删除DG旧未复权主源和备用weekly数据文件，清退其asset/job/check、写入口和调度分支。不是只隐藏或停止采集。共享能力不得连带删除。
4. 本轮完成并独立验收后，下一步再恢复25股因子及下游修复；当前保持暂停，不因本轮修订自动放行。两套Silver另行确认，不增加为25股修复的新前置。

当前代码仍是两套周主源加备用weekly、两套月主源。下文“保留/删除/调整”均为目标，不代表已实施。代码与数据删除必须按LLD分阶段执行，不能以文档更新冒充上线。

## 3. 已核实的来源与字段

Tushare doc365的stk_week_month_adj(freq=week/month)包含21列：身份/日期/频率4列，未复权OHLC4列、前复权OHLC4列、后复权OHLC4列，及pre_close/vol/amount/change/pct_chg5列。

- 未复权价格是open/high/low/close；复权价格是对应_qfq/_hfq字段，不能自行重算后覆盖源值。
- pre_close和pct_chg按复权源的除权参考口径解释，不能把pre_close称为三套价格各自的前收。样本pct_chg=0.77表示0.77%，不再乘100。
- Raw保留YYYYMMDD、freq、原始代码、Decimal、NULL和源单位；不混入Prod采集信息。end_date是源计算截至版本，允许晚于所属周期，不能当采集时间或改成请求结束日。
- 月线2020-02唯一准入日期仍为20200228，排除20200229，不改日期、不拼接版本。
- 周线继续Tushare→Prod闭合批→DG；月线日常继续直接请求源。收敛不夹带改供数拓扑或重建全历史。

本地依据：[doc365](../../../docs/sources/tushare/股票数据/行情数据/0365_股票周_月线行情(复权--每日更新).md)、[doc336](../../../docs/sources/tushare/股票数据/行情数据/0336_股票周_月线行情(每日更新).md)、[北交所映射doc375](../../../docs/sources/tushare/股票数据/基础数据/0375_北交所新旧代码对照表.md)。实现以run_contracts、paths、catalog和实际文件为准。

2026-10-15只读审计按Silver基础表中5,576只仍上市股票、confirmed身份及合法日期区间统计：

| 原未复权主源独有的上市归一键 | 0；保留源还多61,199键 | 0；两源均693,272个上市归一键 |
| 保留源三套OHLC缺值 | 0 | 0 |
| 本地实际日线独立覆盖参照 | 2014年起2,501,426股票周键，保留源缺0 | 2014年起589,322股票月键，保留源缺0 |

2010—2013年没有本地日线参照，仅证明保留源不丢旧主源已存在的上市键，不能宣称两源同时缺失的历史也完整。退市缺口不补、不因缺口扩大修复对象。此前148项北交所未复权缺口在保留复权Raw中已有全部未复权字段，不再补写即将删除的数据集。

### 4.1 必修：2026年8月月线旧版本

DG两套8月Raw每源5,551行，trade_date全部20260831。未复权end_date为25日1只、27日1只、28日1,235只、31日4,314只；复权为25日1只、27日3只、28日5,547只。Prod只读聚合和样本与DG一致。

对照8月实际日线，复权有6只股票的较早截止已覆盖当月最后实际交易；其余5,545只还在31日交易。平安银行旧复权close=11.65/截至28日；当前MCP和31日日线为11.72。000711.SZ旧close=6.25/截至27日，当前源为5.89。002274.SZ和301139.SZ月底没有后续交易，较早截止不等于价格错。

原因：DG bootstrap原样接收Prod，历史验收只证明运输无损，漏做每股完整月份截至校验；后续sensor只推进新月，没有纠正8月。最初Prod写入任务/采集时间未定位，不能由end_date推断。

已确认修订范围是20260831/freq=month：Prod两个现有月线数据集按现行Raw→Serving链路定向upsert；DG仅修保留的复权月文件，不刷新随后就要删除的未复权月文件。重新接收完整源行，不手改end_date或拼接两个版本。其他健康月份、week行及其他股票范围保持不变；源未返回的旧行不删除且单列未刷新，不能当成功修订。

### 4.2 待核实：其他月份的截止字段异常

4月等月份存在end_date早于该股实际日线、但close相同的记录。先核源及字段差异，只把证实错误的对象/月列入追加修订清单；未确认的新范围不覆盖。未解决项必须阻断“Raw全部问题已修好”的结论，不能只修8月就关单，也不能无依据重拉201个月。

### 4.3 新旧代码的请求与版本

有已确认新代码的股票，因子及复权历史对象请求只用新代码，历史日期不变；不再请求旧代码，不用旧码空缺兜底。全市场回包必须识别新旧码，按确认映射选择本次有效的新码记录，不以旧码滞后版本覆盖新码。Raw已有旧码历史保持原始身份；不得先全表改码。

例：安徽凤凰832000.BJ→920000.BJ。MCP当前旧码20201225周线仍截至20250910，未复权close=7.16、qfq=5.58；新码同周截至20261014，close=7.16、qfq=5.51。基准因子1.399与1.4173解释了样本差异。日期是计算版本，不是固定历史版本ID或确切换码日期。

归一后周/月分别39,503/3,431组多行字段不完全相同，属于源版本共存；不把它们全部当Raw损坏。Silver的择版要求见LLD，不能改码后随意drop_duplicates。

## 5. 调度与代码清退

现有raw_stock_weekly_update_job_sensor和raw_stock_monthly_update_job_sensor均是共享sensor，没有独立“未复权sensor”可整项删除。保留两个sensor及RUNNING意图，移除其中未复权分支、已停用job、旧双源ready和互相等待逻辑；保留复权分支、19:30窗口、取消恢复及准确检查绑定。不新增第二套sensor，不自行启停服务。

删除三个旧asset定义、三个写job、九项对应check和active catalog登记；同步移除手动/CLI新写入入口、schema/config/path的无剩余消费者部分。不能只改sensor或中文名称，也不能按文件名整块删除共用实现。历史事件可保留以供追溯，不删Dagster表。

周线保留adjusted_delivery_revision/pending_adjusted，按下一闭合批顺序接收，包含历史修正；空批核实后仅推进水位。2026-10-15实例快照revision=1785、周末端2026-10-09、月末端2026-09、无相关在途任务；执行前重新确认，不把审计快照当未来删除许可。

## 6. 实施阶段与关闭条件

| 阶段 | 工作 | 关闭条件 |
| --- | --- | --- |
| C0 | 源/代码/库存预检、精确修订与删除清单 | 上市集合、新码、必要历史参照、异常/未知项和真实写入窗口清楚 |
| C1 | 开发月线有界覆盖入口及三旧数据集清退，隔离测试 | 原公共能力保留；旧入口不可再写；正反测试和取消恢复通过 |
| C2 | 获准后刷新Prod8月，再修DG保留月Raw；按清单处理追加问题 | 源→Prod Raw/Serving→DG完整行一致，其他月份/week键值不变；未刷新有明确原因 |
| C3 | 部署清退并精确物理删除三个旧DG目录 | 无在途写者，无剩余active/手工写入口；白名单全删，保留目录指纹不变，共享sensor可正常运行 |
| C4 | 一次保留Raw与删除范围收尾对账 | 覆盖/版本/剩余缺陷逐项有结论，后续新周期仅两主链；不重算整套公式 |

本轮文档完成不等于C1—C4通过。正式操作前必须提供具体命令/读写对象/恢复边界；不以删数据作为“测试”。删除后的恢复是重建已批准数据集，不自动备份、不承诺撤销。

## 7. 性能与验收

源验证一次，候选逐文件完成并持久化，恢复只接未完成部分，最终聚合对账一次。公式由独立金样本验证；运行检查真实输入、范围、输出和持久化事实，不默认同公式第二次全量重算。允许有失效机制的缓存、增量计量和批量验证，不再沿用“不缓存/不降频”的旧实现禁令。

本轮审计实测：年度分批公共字段及覆盖核对51.8秒；未作正式写入性能验收。保留Raw总计1,060文件/203,280,734字节，删除约113.7MiB。8月源请求按单月全市场分页，正常两个Prod数据集各约1页，触顶须取终空页；以实际源行数/重试记账，不逐股×月全历史请求。既有单月/周闭合批局部预算先作基线，参数、来源、消费者及生效见LLD；超出时按实测重评，不新增任意紧的限制。

正向：两主源三套价格、上市键不丢、完整月截至、2020例外、新码请求、已完成复用、逐文件原子替换、共享sensor继续推进及物理删除精确命中。
反向：旧码请求/旧入口新写、缺源/页尾未闭合、身份未确认、错误精度、目标漂移、月底交易遗漏、版本冲突、删错目录、删除shared分区或保留文件、取消后续写和旧check误绑定均拒绝。

## 8. 后续Silver与25股任务

Silver不是本轮已授权实施项：拟各建一套silver_stock_weekly/silver_stock_monthly，来源仅保留的21列Raw，标准日期/Decimal、确认身份、择版、三套价格；本轮完整性只要求确认仍上市股票，退市缺口不补，不引入历史删除。周线同批被修订的历史周必须全部传递，不能只处理anchor；月线缺历史修订通道不能冒充已有自动能力。

本轮C4通过后，25股修复作为下一步任务另行恢复。Silver详细合同及执行范围单独确认，不把Silver开发变成恢复25股的新前置。25股R1/R2已验收提交，R3未最终通过且已安全暂停，详见[暂停方案](dagster-stock-adj-factor-history-repair-plan-v1.md)和[暂停LLD](dagster-stock-adj-factor-history-repair-low-level-design-v1.md)。
