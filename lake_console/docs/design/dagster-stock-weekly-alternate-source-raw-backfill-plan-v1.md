更新：2026-10-16。**第8步此前完成周线5,577股源记录的COPY，随后因多片段接收代码bug安全停止。本轮已按§5.12完成修复及隔离验收：148项唯一用例通过；此前RSS修正一并纳入本次提交范围。未再次正式续跑，月线仍未开始，两套正式Raw、事件及handoff均未完成，不能视为ready。** 本轮未改动正式现场、原计划/hash或源片段，未启停sensor或重置水位。正式停点见共享LLD §5.10—5.11，修复对账及小样本成本见§5.12；Silver与R3继续不推进。

## 1. 目标与边界

DG只保留raw_tushare_stk_period_bar_adj_week和raw_tushare_stk_period_bar_adj_month。两者参考Prod的HTTP POST请求格式与分页语义，在DG自身实现直接访问Tushare doc365的stk_week_month_adj，完整保留未复权、前复权、后复权三套价格及其他源字段。新程序先通过隔离验收，再物理删除这两个旧Raw根，随后从Tushare重新bootstrap。新基线只由新下载结果构建，不读取、合并旧行情，不保留源未返回的旧键，不用旧数据兜底；不再逐月修补或先做旧DG/Prod全量逐行比较。

对象使用当前确认仍上市股票清单；北交所请求一律使用确认的新代码。每股按week、month分别获取完整历史，不传时间参数，不以旧DG目录起点截断源返回。**周/月Raw不再保留退市股票行情：退市对象不规划、不请求、不重试或兜底；全市场回包中的退市行不入湖；首次通过删除整个旧Raw根移除旧存量，不另做逐行清理。不能从旧文件带回退市数据。** 上市集合、身份和北交所映射在一次运行内共用；换码不等于退市，必须先按确认身份区分，禁止按代码前缀或缺少映射猜退市。

执行顺序为：DG周/月Raw直接源重建及每日更新→DG周/月Silver生成及日常变更传递。与本主线无依赖的Prod和R3后置维护，不混入当前开发、执行或验收清单，R3继续暂停。第1—7步程序开发和隔离验收仅使用临时根；第8步正式执行边界见第4节，当前停点及待开发修复见共享LLD §5.11—5.12。

| 项目 | 周线 | 月线 |

| asset key | raw_tushare_stk_period_bar_adj_week | raw_tushare_stk_period_bar_adj_month |
| freq | week | month |
| 周期坐标trade_date | 自然周五，包含尚未到来的本周五 | 自然月末，包含尚未到来的本月末 |
| 正式文件 | raw/tushare/stk_period_bar_adj_week/week_end=YYYY-MM-DD/part-000.parquet | raw/tushare/stk_period_bar_adj_month/month=YYYY-MM/data.parquet |
| 动态分区 | cn_a_stock_week_ends | cn_a_stock_months |

正式根固定/Volumes/datasource/data_lake；候选与运行staging固定/Volumes/datasource/data_lake_staging。原asset key和目录布局保留，正在形成的周期也写入同一周期文件，不每天另造一根周/月K。

trade_date是周期标签，end_date是源计算截至日期，后者可晚于历史周期，不能解释成每根K线内部最后交易日。请求中的start_date/end_date用于筛选trade_date，不是读取历史计算版本。完整21列、精度及源实测统一见[共享LLD](dagster-stock-weekly-alternate-source-raw-backfill-low-level-design-v1.md#source-field-contract)。

## 3. 请求方式与北交所硬口径

| 用途 | 请求 |
| --- | --- |
| 单股bootstrap/历史刷新 | ts_code=有效代码，freq=week或month；不传trade_date/start_date/end_date |
| 日常当前周期/欠账补交 | week按目标周五trade_date；month按目标月首至自然月末的trade_date范围，保留该月不同源日期；全市场分页，先欠账后当前，不逐日重放 |
| 北交所代码 | 确认映射的n_code或已确认直接使用新代码的新上市股票现码；不请求旧码，不在新码空/失败时回退旧码 |

DG现有Tushare请求从自身环境注入TUSHARE_TOKEN；这次只替换两频的传输方式，不导入Prod Settings/客户端，不安装Prod项目，不改其他DG数据集。HTTP地址和限流在DG专项入口集中解析，配置来源、默认、消费者与失败门禁见共享LLD §6.2。第1步已撤销错误导入及其新增依赖声明；未卸载环境包。

开工固定一次对象清单及映射，按有效请求代码去重。例如832000.BJ→920000.BJ，历史周/月也请求920000.BJ，不因历史日期早于换码而改回832000.BJ。新代码身份未确认时先列阻塞项，不猜映射、不仅按字符串前缀改码。所有bootstrap、手动、重试及因子触发入口遵守同一规则，测试记录真实出站参数。

“保留全部源数据”指已确认仍上市对象准入范围内的完整源字段和历史记录，不是保留全市场退市行情。全市场回包须先按共用上市集合筛选，记录源行数、准入行数和退市等范围排除数；范围排除不是技术失败。Raw保留准入记录的实际回包代码，不把旧码行改名为新码，不在Raw做证券归一去重或挑一套价格拼行。当前请求若意外回旧码，保留源证据并报告身份不符，不把该结果当新码历史刷新成功。

## 4. 先删除，再Bootstrap

1. **先准备新程序。** 完成直接源合同、全部DG写入口迁移、隔离正反测试，以及必要的小样本源行为和性能验证。此时不删除正式数据；成功样本可按同一请求/范围身份复用，不重复下载。
2. **进入独占重建。** 开工一次确认真实挂载、非空上市集合、新码、目标、源字段及空间，等待相关旧写者退出；所有日常、手动、旧Prod交付写入口均须服从同一重建准入和写锁，不能在删除后抢先重建目录。保留sensor名称和运行意图，不启停其他服务。
3. **先删除两个旧Raw根。** 仅核挂载、绝对路径、符号链接边界和无冲突写者，列目录元数据后删除以下两个固定目标；两根均不存在并记录删除阶段完成后，才启动正式bootstrap。待删Parquet不读内容、不数行情行、不算文件hash，不做备份或快照。

   ```text
   /Volumes/datasource/data_lake/raw/tushare/stk_period_bar_adj_week
   /Volumes/datasource/data_lake/raw/tushare/stk_period_bar_adj_month
   ```

   不删除共享父目录、其他Raw、Silver、staging、动态分区或Dagster历史记录；不重跑已关闭的三个重复数据集清退。
4. **下载完整历史。** 按股票×freq下载；每个独立请求完成后保存回包、请求参数和receipt。沿用Prod分页规则：limit=6000、offset从0开始，满页继续，少于6000行（含空末页）才结束；单页满额不能当整股历史截断或立即失败。具体规则及已有代码依据见LLD。失败、真实空源与身份不符分别记录，不生成空文件冒充完成，也不恢复旧行情兜底。
5. **只用新源片段组装。** DuckDB分批汇集本次成功捕获（含身份一致且可复用的验证样本），按周/月由一个协调写者生成候选；一个分区一次业务组装，不每下载一股重写历史。分区COPY的临时输出可能有多个物理片段；按下述中间修正将必要片段归并为单文件候选，不重新导入全源或计算业务数据。保留全部21列、源历史周期及合法NULL；完成字段、日期归属、键冲突、源行守恒与持久化校验。
6. **逐文件原子提交。** 首次目标应不存在；候选与目标同文件系统，在锁内os.replace，完成一个记一个。续跑只认本次已校验并提交的新文件，出现第三方写入即停止冲突单元，不删除或覆盖来路不明的文件。状态失败不撤销已提交文件，恢复读回后补记。
7. **一次收尾后交接。** 实际写入文件的读回与提交合并完成，准确登记物化/检查，最后汇总应完成与实际完成单元、文件及例外，不再全库扫描。文件完成和事件完成分开记录，事件失败只补事件。完成跨日追平并验收后转日常，再推进Silver。

删除开始到重建通过期间，两套Raw可能缺失或不完整，相关Silver生成与下游消费不能依据旧物化/检查判定新基线就绪。不承诺旧数据回退；失败后依靠新源片段、候选和逐文件checkpoint继续。

### 第8步中间修正：临时多片段归并为单文件候选（隔离验收通过，未正式续跑）

这是生产与消费代码合同不一致的bug，不是Tushare数据错误。DuckDB按period分目录输出可以产生多个Parquet，而接收代码把“正式分区只交付一个文件”误当成“临时输出只能有一个文件”。1990-12-21已有1行和3行两个片段，合计4个唯一键，与本次COPY记录一致，不能只保留第一片。

1. **复用成功COPY。** 保留原源片段、copy.json、全部输出及原身份；从候选接收阶段恢复，不重下周线、不重新导入CSV或重做全频率分区COPY。
2. **只归并必要分区。** 单片分区直接复用；多片分区用DuckDB读取该分区全部已列明片段，原样归并到独立的单文件候选。保留21列、Decimal、NULL和源日期，不去重、不挑版本、不改价。正式周线part-000.parquet、月线data.parquet的合同不变。
3. **检查一次并可续跑。** 沿用现有批量字段/键/日期/行数检查，行数必须等于copy.json记录，跨片段重复键仍拒绝；通过后才记校验完成。复用现有逐分区checkpoint绑定片段清单、版本及候选版本，取消后只续未完成部分，不把半成品当成功，不重复归并和校验已完成且版本一致的候选。
4. **先小样本补验。** 先证明旧代码对真实多片段输出失败，再覆盖周/月归并、漂移拒绝、取消恢复及零重复工作。记录必要归并的数量、SQL、耗时和空间，不为这次修复重跑完整bootstrap。原3GiB/2线程、显式6GiB RSS及空间额度不变，不新增CLI或配置。

具体文件、恢复状态及正反清单唯一见[共享LLD §5.12](dagster-stock-weekly-alternate-source-raw-backfill-low-level-design-v1.md#step8-candidate-fragments)。**本轮已完成代码修复与隔离验收，未正式续跑、不恢复自动化。** 修复前4项独立回归已证实原缺陷；固定生产版本144项直接回归通过，质量审计再补4项正反测试通过，合计148项去重。3万行/30片段组装为2个候选实测0.243秒，完成恢复0.028秒且SQL为0，只代表隔离样本。后续再按获准的第8步边界沿原run_id继续；月线是首次下载，不能算作重复下载。Silver、Prod、R3不推进。

## 5. 每日更新与复权历史刷新

每个交易日源发布后，先按已有完成记录补未完成的周/月，再刷新当前周和当前月；按(freq,周期)去重，同一周期只补一次，不逐日重放、不扫描历史行情寻找欠账。周五最后一次刷新失败，下周先补该周；月末失败，次月先补该月。允许trade_date晚于运行日，当前周期及欠账均按源键完整行upsert。周期刷新、周期最终完成、两频历史完成和事件待办分别记录；源尚未发布不能记当天成功，历史失败不能被last_refresh盖过而停止续跑。周中刷新不能推进“整周已结束”，月中亦然。节假日不生成日线式空分区，周五/月末只是坐标，不要求当天开市。

日常复用现有相邻交易日因子差异，按自上次成功消费以来的变化股票集合去重；同一股同时重新下载周、月完整历史，重复触发合并。bootstrap和主动历史下载直接取源端最新历史，不以因子变化、因子检查通过或先做本地复权重算为前提。本次不新增“自动发现全部历史因子修订”的能力，不引入日线/分钟及指标历史修复。end_date每天变化本身不是因子变更触发器。

后续单股完整历史下载成功后，以新回包替换该股票、该freq的完整历史：包含新增、改值和移除源已不返回的旧键，其他股票及未选频率保持不变。空源、缺页或失败不执行替换。首次bootstrap将按先删后建执行，届时不读取旧行情、不存在需继承的旧键，因此不增加旧数据核对或逐行清理。

同一次逻辑工作先规划周期与变更股票，收齐成功片段后统一汇集，一个分区一次组装/校验/提交；禁止先提交当前周期再用历史刷新重写一次。同键相同完整行合并，同键异值保留证据并停止冲突，不任意覆盖。新上市股票加入后补取该股两频历史；后续确认退市时不再请求该股，按受影响分区合并清理其Raw与Silver行。仅有停牌或代码变更不能当退市。日常只请求当前周期和真实变更股票，不每天刷新全市场历史。

两频直接源、状态/恢复和写入保护已完成前五步隔离验收；第6步旧合同/说明及本任务治理登记已收口；第7步小型组合验收通过，anchor补记冲突经确认最小修正关闭，详见共享LLD §5.8。该开发轮未重载，后续第8步已按批准加载定义并开始重建，真实状态见§5.10—5.12，不能由源码代替。正式切换须确认全部DG写入口已迁移、不保留旧Prod交付双写或旧码兜底；Prod本身继续原运行。保留sensor名称、运行意图和水位，不清空cursor强行重跑。部署、迁移及正式执行使用获准的精确清单。

## 6. 成本与非重复原则

设归并后的有效对象数N、频率数2，每股每频返回不足6000行且不重试时bootstrap约2N次请求；满页另计续页，恰好整页时还需一个空末页。此前5,576只对象快照对应约11,152次，不再沿用按周期约1,060次及35—90分钟的旧估算。源可能返回早于2010的历史，旧859/201文件与行数不是新下载的完成标准。

A阶段三股两频7次请求、2599行，探测客户端下载耗时合计1.524秒；1000+782分页及完整21列已有证据，全部保存复用。它不是最终DG执行器测量，未计每页worker启动、限流及事件；第7步已另用小型真实执行路径补齐这些成本，见共享LLD §6.1。旧1—3小时估计不作为执行承诺，localhost样本也不能替代真实远端耗时。N=5576且仅本任务占用280次/分钟时，11152次请求的理论配额下界约39.8分钟，只是下界。

独立入口和localhost真实HTTP进程验证配置/传输/退出；组装与恢复继续复用已下载6单元，不重复源连通性验证，不重新下载全部历史。进程复用/粒度、缓存及检查频度可按测量优化，保留取消、身份与失效语义。3GiB/2线程、4GiB观察阈值、16GiB spill/32GiB workspace均是待实际路径校准的实现选择，不是用户业务硬上限；不得在SQL中漏传policy或把历史RSS高水位当本任务实际峰值。

### 7.2 第7步：补证据并完成Raw程序验收

1. **先复用。** 复用原真实源回包、独立金样本、前五步测试及性能证据。按需求和代码版本判断适用性，不重复请求Tushare、审计正式Lake或执行完整bootstrap；最终清退使旧测试数量下降不构成失败。
2. **补一个小型完整场景。** 在临时根、localhost HTTP和独立instance，用少数股票、少量周期串起bootstrap文件→事件→跨周/月交接→真实日常job/check；包含一次取消和一次事件失败，验证复用、准确绑定和ready门禁。已独立覆盖的异常不全部重新塞进这个场景。
3. **只补缺失成本。** 记录真实HTTP执行器的worker启动、限流等待、传输/持久化及少量事件登记成本；文件阶段6.882秒和续跑0.107秒已有证据，文件路径未变且证据仍适用时不重复测。实测与推算分列，不把稀疏样本直接外推全市场，不因补测自动新增并发、配置或更紧上限。
4. **固定版本收尾。** 开发中只跑受影响测试；固定后集中一次周/月相关回归、隔离定义/治理检查及文档校验。按“要求→代码→正反测试→适用版本证据→通过/未完成”对账，文件、事件、交接分别结案。发现已确认业务口径、源行为或共享消费者冲突，先汇报，不能通过降门禁、旧链兜底或扩范围掩盖。具体入口、计数及停止条件见共享LLD §5.7。
