# DG 复权周线、月线直接源 Bootstrap 与每日更新方案 v1

更新：2026-10-16。已确认采用“先删除两个旧Raw根，再从Tushare重新bootstrap”；本轮调整文档，尚未开发、执行删除、下载或验收。文件名沿用以保留引用。DG重复数据集清退已完成。本轮主线为DG周/月Raw和Silver，其他系统任务后置，不在本文展开。

## 1. 目标与边界

DG只保留raw_tushare_stk_period_bar_adj_week和raw_tushare_stk_period_bar_adj_month。两者直接使用Tushare doc365的stk_week_month_adj，完整保留未复权、前复权、后复权三套价格及其他源字段。新程序先通过隔离验收，再物理删除这两个旧Raw根，随后从Tushare重新bootstrap。新基线只由新下载结果构建，不读取、合并旧行情，不保留源未返回的旧键，不用旧数据兜底；不再逐月修补或先做旧DG/Prod全量逐行比较。

对象使用当前确认仍上市股票清单；北交所请求一律使用确认的新代码。每股按week、month分别获取完整历史，不传时间参数，不以旧DG目录起点截断源返回。**周/月Raw不再保留退市股票行情：退市对象不规划、不请求、不重试或兜底；全市场回包中的退市行不入湖；首次通过删除整个旧Raw根移除旧存量，不另做逐行清理。不能从旧文件带回退市数据。** 上市集合、身份和北交所映射在一次运行内共用；换码不等于退市，必须先按确认身份区分，禁止按代码前缀或缺少映射猜退市。

执行顺序为：DG周/月Raw直接源重建及每日更新→DG周/月Silver生成及日常变更传递→两层完成并验收后，再单独处理Prod和R3。后两项不混入当前开发、执行或验收清单。本轮只改文档，不执行任何清理、下载或写湖。

## 2. 数据集与时间含义

| 项目 | 周线 | 月线 |
| --- | --- | --- |
| asset key | raw_tushare_stk_period_bar_adj_week | raw_tushare_stk_period_bar_adj_month |
| freq | week | month |
| 周期坐标trade_date | 自然周五，包含尚未到来的本周五 | 自然月末，包含尚未到来的本月末 |
| 正式文件 | raw/tushare/stk_period_bar_adj_week/week_end=YYYY-MM-DD/part-000.parquet | raw/tushare/stk_period_bar_adj_month/month=YYYY-MM/data.parquet |
| 动态分区 | cn_a_stock_week_ends | cn_a_stock_months |

正式根固定/Volumes/datasource/data_lake；候选与运行staging固定/Volumes/datasource/data_lake_staging。原asset key和目录布局保留，正在形成的周期也写入同一周期文件，不每天另造一根周/月K。

trade_date是周期标签，end_date是源计算截至日期，后者可晚于历史周期，不能解释成每根K线内部最后交易日。请求中的start_date/end_date用于筛选trade_date，不是读取历史计算版本。完整21列、精度及源实测统一见[共享LLD](dagster-stock-weekly-alternate-source-raw-backfill-low-level-design-v1.md#source-field-contract)。

## 3. 请求方式与北交所硬口径

| 用途 | 请求 |
| --- | --- |
| 单股bootstrap/历史刷新 | ts_code=有效代码，freq=week或month；不传trade_date/start_date/end_date |
| 日常当前周期 | freq及当前周五/自然月末trade_date，全市场按实际源容量分页；不逐股重复下载全历史 |
| 北交所代码 | 确认映射的n_code或已确认直接使用新代码的新上市股票现码；不请求旧码，不在新码空/失败时回退旧码 |

开工固定一次对象清单及映射，按有效请求代码去重。例如832000.BJ→920000.BJ，历史周/月也请求920000.BJ，不因历史日期早于换码而改回832000.BJ。新代码身份未确认时先列阻塞项，不猜映射、不仅按字符串前缀改码。所有bootstrap、手动、重试及因子触发入口遵守同一规则，测试记录真实出站参数。

“保留全部源数据”指已确认仍上市对象准入范围内的完整源字段和历史记录，不是保留全市场退市行情。全市场回包须先按共用上市集合筛选，记录源行数、准入行数和退市等范围排除数；范围排除不是技术失败。Raw保留准入记录的实际回包代码，不把旧码行改名为新码，不在Raw做证券归一去重或挑一套价格拼行。当前请求若意外回旧码，保留源证据并报告身份不符，不把该结果当新码历史刷新成功。

## 4. 先删除，再Bootstrap

1. **先准备新程序。** 完成直接源合同、全部DG写入口迁移、隔离正反测试，以及必要的小样本源行为和性能验证。此时不删除正式数据；成功样本可按同一请求/范围身份复用，不重复下载。
2. **进入独占重建。** 开工一次确认非空上市集合、新码、目标、源字段及空间，等待相关旧写者退出；所有日常、手动、旧Prod交付写入口均须服从同一重建准入和写锁，不能在删除后抢先重建目录。保留sensor名称和运行意图，不启停其他服务。
3. **先删除两个旧Raw根。** 仅核挂载、绝对路径、符号链接边界和无冲突写者，列目录元数据后删除以下两个固定目标；两根均不存在并记录删除阶段完成后，才启动正式bootstrap。待删Parquet不读内容、不数行情行、不算文件hash，不做备份或快照。

   ```text
   /Volumes/datasource/data_lake/raw/tushare/stk_period_bar_adj_week
   /Volumes/datasource/data_lake/raw/tushare/stk_period_bar_adj_month
   ```

   不删除共享父目录、其他Raw、Silver、staging、动态分区或Dagster历史记录；不重跑已关闭的三个重复数据集清退。
4. **下载完整历史。** 按股票×freq下载；每个独立请求完成后保存回包、请求参数和receipt。沿用Prod分页规则：limit=6000、offset从0开始，满页继续，少于6000行（含空末页）才结束；单页满额不能当整股历史截断或立即失败。具体规则及已有代码依据见LLD。失败、真实空源与身份不符分别记录，不生成空文件冒充完成，也不恢复旧行情兜底。
5. **只用新源片段组装。** DuckDB分批汇集本次成功捕获（含身份一致且可复用的验证样本），按周/月由一个协调写者生成候选；一个分区一次组装，不每下载一股重写历史。保留全部21列、源历史周期及合法NULL；完成字段、日期归属、键冲突、源行守恒与持久化校验。
6. **逐文件原子提交。** 首次目标应不存在；候选与目标同文件系统，在锁内os.replace，完成一个记一个。续跑只认本次已校验并提交的新文件，出现第三方写入即停止冲突单元，不删除或覆盖来路不明的文件。状态失败不撤销已提交文件，恢复读回后补记。
7. **一次收尾后交接。** 实际写入文件的读回与提交合并完成，准确登记物化/检查，最后汇总应完成与实际完成单元、文件及例外，不再全库扫描。文件完成和事件完成分开记录，事件失败只补事件。完成跨日追平并验收后转日常，再推进Silver。

删除开始到重建通过期间，两套Raw可能缺失或不完整，相关Silver生成与下游消费不能依据旧物化/检查判定新基线就绪。不承诺旧数据回退；失败后依靠新源片段、候选和逐文件checkpoint继续。

删除中断且尚未进入正式bootstrap时，只核原边界和无写者，继续删除剩余旧内容；**一旦进入正式下载阶段，续跑不得再次清空两个根**，即使其中已出现本次新文件。阶段记录缺失或文件归属不清先报告，不猜测删除。阶段事实复用本次执行记录，不新建长期状态框架。

下载不是源端同一时刻快照。若bootstrap跨交易日或周/月边界，结束交接时仅补开始至完成期间涉及周期的最终已发布版本，以及期间实际因子变更股票的历史；不重新下载其他已完成历史。这样不会把周一捕获的周中值当作周五最终值，也不靠伪造统一end_date宣称一致。

## 5. 每日更新与复权历史刷新

每个交易日源发布后刷新当前周和当前月，允许trade_date晚于运行日；周期内每天覆盖同一业务键。已完成周期水位与当天刷新完成日分开，周中刷新不能推进“整周已结束”，月中亦然。节假日不生成日线式空分区，周五/月末只是坐标，不要求当天开市。

日常复用现有相邻交易日因子差异，按自上次成功消费以来的变化股票集合去重；同一股同时重新下载周、月完整历史，重复触发合并。bootstrap和主动历史下载直接取源端最新历史，不以因子变化、因子检查通过或先做本地复权重算为前提。本次不新增“自动发现全部历史因子修订”的能力，不引入日线/分钟及指标历史修复。end_date每天变化本身不是因子变更触发器。

所有变更行先汇集到受影响周/月，一个分区一次提交，不因股数反复扫描/重写。新上市股票加入后补取该股两频历史；后续确认退市时不再请求该股，按受影响分区合并清理其Raw与Silver行。仅有停牌或代码变更不能当退市。日常只请求当前周期和真实变更股票，不每天刷新全市场历史。

现行周线仍消费Prod闭合批，月线仍只推进已完成月，均不满足新设计。切换时必须一次迁移全部DG写入口、检查和消费者，停止旧Prod交付对这两个目标的写入，不保留双写或旧码兜底；Prod本身继续原运行。保留sensor名称和运行意图，旧revision/历史记录只作追溯，新的刷新/完成周期坐标有明确迁移依据，不清空cursor强行重跑。部署、迁移及正式执行另列精确命令。

## 6. 成本与非重复原则

设归并后的有效对象数N、频率数2，每股每频返回不足6000行且不重试时bootstrap约2N次请求；满页另计续页，恰好整页时还需一个空末页。此前5,576只对象快照对应约11,152次，不再沿用按周期约1,060次及35—90分钟的旧估算。源可能返回早于2010的历史，旧859/201文件与行数不是新下载的完成标准。

串行耗时模型为请求数×实测均耗时；假设2—5秒只是推算，对应约6.2—15.5小时，尚非性能实测。并发、限流、重试和写盘收益须用老上市股票、确认新码北交所及新上市代表样本测定；样本下载直接复用，不另跑一轮正式重复下载。MCP的超时/502不能当空源或固定吞吐证据。

先测小样本再固定批次/并发/预算，不自行增加过紧门禁；不强制沿用旧Prod导出或日线参考预算。空间按源片段、候选、spill和新正式文件的实际共存峰值估算，不计旧文件备份；开工检查一次，写入按已知片段增量计量并在必要提交边界检查实际剩余空间，不每秒递归扫描累积目录。内存随单请求/计算批次增长，不常驻全部股票历史。配置来源、失效及消费者统一落共享LLD。

## 7. 验收与实施顺序

2026-10-16开发前准备状态：一次读取当前Silver上市集合为5,576只，含920000.BJ；最新上市代表为301569.SZ（2026-10-15）。源小样本验证遇阻：MCP请求超时（>30秒），项目SDK的首个limit=3/offset=0请求20.0075秒ReadTimeout，随即停止、未重试；没有成功下载新行情。随后已核对Prod当前代码：周/月均使用limit/offset，满页续取、短页结束，已有末页/预算拒绝替身测试。分页实现方式已确定，不再作为设计待定项；上述超时不证明分页不支持，也不能代表Prod自有HTTP路径不可用。本轮源连通性、吞吐及数值预算仍待小样本验收，不据此删除旧Raw。具体规则、文件清单和待补测量见共享LLD §1、§5—6；只补缺失样本，不重跑既有日期/21列审计。

先补齐Raw直接源合同/唯一写者及消费者迁移，再隔离测试和小样本测量；固定版本后进入独占重建，先删除两旧Raw根，再正式bootstrap、逐文件提交及日常交接。Raw通过后推进周/月Silver，两层完成再关闭本轮。Silver以这两套Raw为唯一行情输入，沿同一仍上市对象范围，规范身份/日期并保留三套源价格，不重算复权价；具体schema、版本择取、job/check和增量触发须在Silver开发前明确，不把本次文档更新当已实现。最小正反清单见[共享LLD](dagster-stock-weekly-alternate-source-raw-backfill-low-level-design-v1.md#acceptance)。本轮只改文档，未把新设计写成现行实现或正式执行许可。

不做旧DG—Tushare全量逐行审计、不从日线合成行情、不重算复权公式、不重复下载完成片段、不全历史反复检查、不做备份/Kopia。新数据是否正确以请求、源返回、写入范围和持久化事实验收，计算逻辑由独立金样本测试。
