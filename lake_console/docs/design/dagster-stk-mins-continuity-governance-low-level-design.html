Dagster 股票分钟线连续性治理 LLD

本文把股票分钟线连续性治理方案细化到代码级别，用作开发前的实现参考。 核心目标是消除“交易日空洞被后续日期跳过”的系统性风险：交易日历是 expected date source， dynamic partitions 和 readiness 只是运行状态；任何 expected date 缺注册、缺数据或 blocking checks 未绿时，下游不得推进后续日期。

状态M1-M11 已完成；性能优化专项 P0-P9 已完成；MACD/KDJ asset write、MACD/KDJ repair op 与最终验收已按本 LLD 收口。
范围只覆盖股票分钟线 raw / silver / qfq / qfq factor repair / MACD-KDJ daily 与 repair。
本轮动作按当前代码事实收敛 LLD；不运行 Dagster runtime，不读取正式 Dagster instance。
文档位置lake_console/docs/design/

3.2 数据结构

from dataclasses import dataclass
from collections.abc import Callable, Sequence

import dagster as dg

from orchestrator.defs.sensors.readiness import DatasetReadinessStatus


@dataclass(frozen=True)
class StockMinsContinuityStatus:
    partition_set_name: str
    expected_start_date: str | None
    expected_end_date: str | None
    expected_count: int
    registered_count: int
    ready_count: int
    first_missing_registered_date: str | None
    missing_registered_date_samples: tuple[str, ...]
    first_not_ready_trade_date: str | None
    first_not_ready_reason: str | None
    previous_expected_trade_date: str | None
    ready_through_trade_date: str | None
    next_actionable_trade_date: str | None
    blocked_reason: str | None

    @property
    def blocked(self) -> bool: ...

    def to_cursor_details(self) -> dict[str, object]: ...


@dataclass(frozen=True)
class StockMinsContinuitySelection:
    status: StockMinsContinuityStatus
    selected_trade_date: str | None
    selected_status: DatasetReadinessStatus | None

字段含义固定如下：

字段 含义 用途
first_missing_registered_date expected calendar 中最早未注册到目标 partition set 的日期。 阻止后续日期执行，指导 partition sensor 先补哪一天。
first_not_ready_trade_date 最早已经注册但目标资产未 ready 的日期。 作为 raw/silver/qfq/factor repair sensor 的唯一 run target。
previous_expected_trade_date 目标日期在交易日历里的上一开市日。 MACD/KDJ state 递推、qfq repair 因子比较、repair range 校验。
ready_through_trade_date 从 expected 起点开始连续 ready 到的最后一天。 告诉下游最多能安全基于哪一天继续。
next_actionable_trade_date 当前 tick 可以处理的那个日期；没有可处理日期时为空。 cursor 可观测，避免 UI 只看到模糊 skip reason。

3.3 交易日历读取

连续性模块只通过调用方传入的 DuckDB connection 读取 silver_trade_calendar，不得自己创建连接，也不得从正式 runtime 读历史。

def load_stock_mins_expected_trade_dates(
    connection,
    calendar_path: Path,
    *,
    min_trade_date: str,
    evaluated_at: datetime,
    same_day_register_start: time | None = None,
) -> tuple[str, ...]:
    """Return SSE open trade dates eligible for stock minutes continuity."""

SQL 口径与 cn_a_trade_day_sensor.load_completed_open_day_keys(...) 保持一致：

SELECT strftime(trade_date, '%Y-%m-%d') AS trade_date
FROM read_parquet(?)
WHERE exchange = 'SSE'
  AND is_open = true
  AND trade_date >= DATE ?
  AND trade_date <= DATE ?
ORDER BY trade_date

同日窗口规则：

  • 若今天是 SSE 开市日，且当前时间未到 same_day_register_start，今天不进入 expected dates。
  • 若今天是 SSE 开市日，且当前时间已到窗口，今天可以进入 expected dates。
  • 历史已完成交易日不受同日窗口限制。

def select_first_not_ready_trade_date(
    *,
    partition_set_name: str,
    expected_trade_dates: Sequence[str],
    registered_trade_days: Sequence[str],
    readiness_for_trade_date: Callable[[str], DatasetReadinessStatus],
    has_materialized_check_problem: Callable[[DatasetReadinessStatus], bool],
    window_limit: int = STK_MINS_CONTINUITY_WINDOW_LIMIT,
) -> StockMinsContinuitySelection: ...

select_first_not_ready_trade_date(...) 的行为：

  1. 把 expected dates 截到最近 window_limit 个，避免稳定态每 tick 深扫十几年历史。
  2. 从早到晚检查 expected date 是否已注册；发现缺注册，返回 first_missing_registered_date，不再检查后续 readiness。
  3. 对已注册日期按顺序调用 readiness_for_trade_date；第一个 not ready 日期就是 selected_trade_date。
  4. 如果该日期已经 materialized 但 blocking checks 未绿，selected_trade_date 必须为空，blocked_reason 写明人工处理，后续日期不推进。
  5. 如果窗口内全部 ready，则 ready_through_trade_date 等于窗口最后一天，selected_trade_date 为空。
窗口说明： STK_MINS_CONTINUITY_WINDOW_LIMIT = 10 是日常 sensor 稳定态性能保护，不是历史审计边界。 分区注册 catch-up 仍按交易日历补缺；超过 10 个 expected trade dates 的长停机恢复、全历史缺口红绿灯或 60 天容量审计，应另行走显式 audit / recovery 流程，本专项第一阶段不做。

4.8 stk_mins_qfq_factor_repair.py 与 op

目标：qfq factor repair 的 previous date 和 selected range 不再来自 registered partitions。

def execute_gold_stk_mins_qfq_factor_repair(
    *,
    lake_root: Path,
    duckdb_resource: DuckDBResource,
    trade_date: str,
    expected_trade_dates: Sequence[str],
    registered_partition_keys: Sequence[str],
    freqs: Sequence[int | str] = STK_MINS_QFQ_NATIVE_FREQS,
) -> GoldStkMinsQfqFactorRepairResult:
    normalized_trade_date = date.fromisoformat(trade_date).isoformat()
    previous_trade_date = previous_expected_trade_date(
        expected_trade_dates,
        normalized_trade_date,
    )
