Dagster Phase 3 指数数据生产链路设计（合并版）

本文件合并原“主要指数 Phase 3 方案”和后续“Index Daily 重构方案”的当前有效口径。 旧 active pool、旧 raw-by-trade-date、旧 history backfill、旧 repair job 已不再是可执行设计。 后续开发必须以本文件、重构设计和重构 LLD 为准。

当前准口径raw 按指数代码分区，silver 按交易日分区。
旧口径状态旧链路已从 active Definitions 退场，文档不再保留旧实现教程。
当前代码阶段raw-by-code、silver、主要指数日线 gold asset/job/checks 均已进入 active definitions。
后续重点只读审计历史分区覆盖和 serving 发布。

0. 文档状态与现行依据

已替代的历史阶段设计（2026-07-15 校正）：本文保留主要指数与早期 raw-by-code 链路的阶段证据；其中 raw-by-code 不是当前生产入口。当前指数日线权威是 raw by-date / prod core DB migration plan 与其 LLD；主要指数现行依赖以 Dagster asset/job topology 为准。

1. 合并后的核心结论

Phase 3 指数链路只保留一套方向：指数日线 raw 以 ts_code 为分区拉取和保存， silver_index_daily 继续以 trade_date 为分区生成。 指数池不再通过本地 PostgreSQL active pool 维护，而是通过 Dagster dynamic partitions cn_a_index_ts_codes 表达可生产指数集合。
问题 当前口径
指数代码集合从哪里来 cn_a_index_ts_codes dynamic partitions。第一版由连续性审计 CSV 初始化，后续增删改查通过 Dagster partition 管理能力或受控脚本完成。
raw 如何保存 raw_tushare_index_daily_by_code[ts_code]，物理路径按 ts_code 分区，文件内保存该指数的时间序列。
silver 如何保存 silver_index_daily[trade_date]，物理路径按交易日分区，从所有注册指数代码的 raw-by-code 文件中筛选当天记录生成。
日更如何触发 index_trade_day_sensor 只注册指数交易日；index_daily_sensor 在源站 ready 后触发 raw-by-code；silver_index_daily_sensor 在 raw 全部 ready 后触发 silver。
主要指数名单如何使用 主要指数名单已从独立 Dagster asset 退场，改为仓库内 seed 文件 src/orchestrator/seeds/market/major_indices.cn_a.csv。它是带生效日期的版本化参考数据，不再由 PostgreSQL metadata 表维护。gold_market_major_indices_daily[trade_date] 只要求当日已经生效的主要指数存在。

2. 当前资产图

cn_a_index_ts_codes dynamic partitions
  -> raw_tushare_index_daily_by_code[ts_code]
       path: raw/tushare/index_daily_by_code/ts_code=<TS_CODE>/part-000.parquet

cn_a_index_trade_days dynamic partitions
  -> silver_index_daily[trade_date]
       reads all registered raw_tushare_index_daily_by_code files
       path: silver/index_daily/trade_date=YYYY-MM-DD/part-000.parquet

raw_tushare_index_basic
  -> silver_index_basic
       used by major index seed checks

major_indices.cn_a.csv seed
  + silver_index_daily[trade_date]
  -> gold_market_major_indices_daily[trade_date]
       path: gold/market/major_indices_daily/trade_date=YYYY-MM-DD/part-000.parquet
raw raw_tushare_index_daily_by_code 以 ts_code 为 partition key。主入口 run config 提供 trade_date、write_mode=replace，asset 内部映射为源接口单日窗口。
silver silver_index_daily 以 trade_date 为 partition key。日期字段标准化为 DATE，change 标准化为 change_amount。
gold gold_market_major_indices_daily 首页主要指数日线结果。主要指数名单来自带生效期的 seed CSV，不再作为独立 asset 或 metadata 表维护；历史日期允许只输出当日已生效指数。

3. 当前 Jobs 和 Sensors

类型 名称 职责 边界
job index_daily_update_job 只 materialize raw_tushare_index_daily_by_code[ts_code] 及其 raw checks。 不生成 silver，不读取旧 active pool。
job silver_index_daily_update_job 只 materialize silver_index_daily[trade_date] 及其 silver checks。 不触发 raw；缺 raw 文件时失败。
job market_major_indices_daily_update_job 只 materialize gold_market_major_indices_daily[trade_date] 及其 gold checks。 不触发 index raw/silver，不调用 Tushare；主要指数名单只读带生效日期的 seed CSV。
sensor index_trade_day_sensor 从交易日历注册 cn_a_index_trade_days。 不触发 raw，不触发 silver。
sensor index_daily_sensor 判断目标交易日和 Tushare index_daily ready 后，为缺少目标日期 raw 的指数代码触发 index_daily_update_job。 单 tick 最大 500 个 run request；不触发 silver。
sensor silver_index_daily_sensor 判断 raw-by-code 全部 ready 后触发 silver_index_daily_update_job[trade_date]。 不调用 Tushare，不补 raw，只触发 silver job。
sensor market_major_indices_daily_sensor 判断 silver_index_daily[trade_date]、silver_index_basic、主要指数 seed 和 seed code 输入都 ready 后，触发 market_major_indices_daily_update_job[trade_date]。 默认停止；不触发 index raw/silver，不补 seed，不写自定义 run tags。

4. 旧实现禁止复活清单

下列名称只允许出现在历史审计、退场说明或数据库清理计划中，不允许重新作为 Phase 3 的生产入口、资产依赖、job selection 或实现方案。
旧对象 当前处置 禁止事项
旧指数 active pool asset 已从 active Definitions 删除。 不得作为 silver_index_daily 的上游，不得作为指数日线请求池。
旧指数 active pool job 已退场。 不得恢复为指数池维护入口。
旧指数日线 raw-by-date asset 旧 raw-by-trade-date asset 已删除。 不得重新按交易日聚合拉取 raw。
旧指数历史 backfill job 已退场。 历史重建使用当前 partitioned asset job / backfill 能力，不恢复旧普通 job。
旧指数按代码 repair job 已退场。 按代码修复应走 index_daily_update_job[ts_code]，不恢复旧 repair job。
goldenshare_lake_meta.index_daily_active_pool* 数据库遗留对象。是否 drop 需单独备份、清单和审批。 不得继续作为生产事实源读取。
