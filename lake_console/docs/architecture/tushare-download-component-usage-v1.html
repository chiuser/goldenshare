1. 接入前与快速使用

当前实现位于 DG 的 Python 工程，公开导入入口是 orchestrator.tushare_download。使用该工程现有运行环境；不要从其他独立工程跨目录导入 DG 源码，也不要为了调用组件自行修改 Python 搜索路径。财势乾坤等其他工程的接入需要单独装配，本文不表示它们已经接通。

  1. 向数据集接入交付确认：已登记的完整契约名、支持的模式、时间输入格式、允许的过滤与分类参数、完整业务字段。没有登记时先完成数据集接入。
  2. 确认进程启动环境已提供 token 和请求地址。下载器创建时自行读取，业务调用不传 token、地址、fields、limit 或 offset。
  3. 确定在哪个线程执行、如何接收进度，以及每个完整 unit 怎样校验和保存。需要持续响应页面的业务必须另开下载线程；已在独立任务执行进程中的业务可直接调用。

完整例子：按业务给出的日期清单下载并逐个处理

下面是可放入业务代码的完整函数。save_unit 是业务自己提供的同步函数：接收一个 UnitResult，完成自己的字段检查、日期归一化和保存后再返回；失败直接抛出异常。业务提交成功的记录由业务自己维护。

本例的前提是所登记契约支持 BY_POINT，并规定日期输入为 YYYY-MM-DD。例如传入 ("2026-10-19", "2026-10-20")，没有分类展开时共两个 unit，分别处理这两天；组件不会自己补入其他日期。

import logging

from orchestrator.tushare_download import (
    DownloadCancelled,
    DownloadControl,
    DownloadError,
    DownloadMode,
    DownloadTask,
    TushareDownloader,
)

logger = logging.getLogger(__name__)


def download_by_date(contract_name, dates, save_unit, *,
                     on_progress=None, is_cancelled=None):
    task = DownloadTask(
        contract_name=contract_name,
        mode=DownloadMode.BY_POINT,
        points=tuple(dates),
    )
    session = None
    try:
        downloader = TushareDownloader.load()
        session = downloader.download(
            task,
            control=DownloadControl(is_cancelled=is_cancelled),
            on_progress=on_progress,
        )
        with session:
            for result in session:
                save_unit(result)  # 业务保存；不要放进进度回调
                del result        # 业务不再持有这一批时及时释放引用
        return session.summary
    except DownloadCancelled:
        logger.info("下载已取消")
        raise                     # 由业务上层决定如何呈现取消
    except DownloadError as error:
        details = error.details
        if session is not None and session.summary.failure is not None:
            details = session.summary.failure
        logger.error(
            "下载失败 code=%s task=%s unit=%s stage=%s "
            "position=%s attempt=%s exhausted=%s cleanup=%s",
            int(error.code), details.task_id, details.unit_id,
            details.stage, details.source_position,
            details.attempt_number, details.retry_exhausted,
            details.cleanup_errors,
        )
        raise
    finally:
        if session is not None:
            summary = session.summary
            logger.info(
                "下载会话 status=%s delivered=%s/%s rows=%s "
                "requests=%s retries=%s progress_errors=%s",
                summary.status.name, summary.delivered_units,
                summary.total_units, summary.row_count,
                summary.request_count, summary.retry_count,
                summary.progress_error_count,
            )

download() 返回下载会话；进入 with 时校验输入、解析契约并准备资源，开始迭代时才发数据请求。每次循环得到一个完整 unit，处理完再领取下一个。with 负责正常完成、提前退出和业务异常时的收尾；不要省略。

下载器没有数据库或文件保存接口。save_unit 不属于组件；保存失败会原样抛给业务上层，下载器停止后续 unit 并关闭自身资源，不会重试业务写入，也不会撤销已经保存的 unit。

2. 配置怎么读取

TushareDownloader.load() 与 TushareDownloader() 等价：均在创建对象时通过组件配置单元读取并校验连接配置。配置读取能力从 DG 周月线现有实现中抽取；没有替换或收敛其他旧配置入口。

配置名来源与默认值业务需要知道什么
TUSHARE_TOKEN当前进程环境；无默认 token。缺少或去掉首尾空格后为空，创建下载器时报 1001。
TUSHARE_BASE_URL当前进程环境；未设置时默认 https://api.tushare.pro。显式设置为空不使用默认值；地址须为合法 HTTP(S) 地址，不含用户名和密码，否则 1001。

组件不会自行加载 .env 文件，也不读取其他工程的 Settings 或数据库配置。由现有业务启动流程把配置放入进程环境；业务无需再次读取并传给下载器。修改环境后创建新对象才会读取新值，已有对象继续使用创建时的配置。

当前技术默认值

项目当前值含义
单个 unit 工作内存上限2 GiB下载、解析、累积和排序的计数及预估上限；不预先分配，不等于整个进程实际内存上限。超限报 1302，不改成文件交付。
输入及请求大小上限1 MiB过大的代码、日期、分类清单或请求会被拒绝，不自动分批改变任务含义。
HTTP 响应体上限64 MiB还受解析工作空间预估限制，可能在达到该响应体大小前触发 1302。
连接 / 读取 / 单请求时间5 / 30 / 45 秒用于 HTTP 连接、读取及可检查处的单请求时间控制；不是任意阻塞都能被强制结束的保证，见取消说明。
同一页有限重试最多重试 3 次含首次最多 4 次；默认等待 1、2、4 秒，并遵守可解析的 Retry-After 较晚时间。

这些技术值当前不是 download() 的公开参数，也没有对应的业务环境变量。不要给下载器传自造配置参数。主动限频、账号额度及并发数量由业务调度保证；组件没有跨线程或跨进程的限频、额度及锁管理，也没有“最多两个 unit / 两个进程”的限制。

公开调用约定
TushareDownloader.load()无参数，创建独立下载器。配置错误在这里就可能抛出。
downloader.download(task, *, control=None, on_progress=None)返回会话。task 为 DownloadTask；后两项须用关键字传入。
with session: ... / for result in session会话只能进入一次；迭代返回 UnitResult。进入前不能迭代。同一下载器可依次建立多个会话，但只能有一个活动会话。
session.cancel()设置取消意图；在下载调用线程中使用，包括回调内。不是跨线程强制停止接口。
session.close()显式关闭，重复调用无副作用。不能在请求或回调执行中重入关闭；通常交给 with。
session.poll_progress()返回最后一份 DownloadProgress 或 None；不发请求、不生成新进度，不作跨线程通信。
session.summary / session.download_complete读取当前或关闭后的摘要 / 是否已交付全部计划 unit。最终摘要应在退出 with 后读取。

DownloadTask 的全部输入字段

字段类型 / 默认用途与限制
contract_namestr，必填接入方登记的固定完整契约名；不是字段清单，也不是可任意填写的 Tushare api_name。
modeDownloadMode，必填使用枚举成员；须在该数据集契约中声明支持。
objectstuple[str, ...] | None，默认 None明确代码清单，保留输入顺序；不去查股票池，不自动扩大为全市场。
pointstuple[str, ...] | None，默认 None明确时间点清单，按契约解析并从早到晚规划；不会生成交易日历。
time_rangeTimeRange | None，默认 NoneTimeRange(start, end)；边界及格式由契约定义。点模式中仅约束已给出的 points，不生成日期。
object_rangestuple[ObjectTimeRange, ...] | None每个代码自己的范围；元素为 ObjectTimeRange(object_code, time_range)，仅用于对应模式。
filtersMapping[str, SourceScalar] | None只能传契约在该模式下允许的过滤参数；不能塞入 fields、分页、连接信息或存储目标。
enum_valuesMapping[str, tuple[SourceScalar, ...]] | None选择契约允许的分类值；默认值、顺序、是否展开为独立 unit 均由契约决定。

SourceScalar 表示 bool | int | Decimal | str | None，没有 float；它是类型说明，不在包的公开导出列表中。构造 Decimal 时使用文本等准确输入。每个过滤参数还要符合契约自己的源类型与可空规则。

输入会在进入会话时复制、校验并固定；使用期间不要修改原来的字典或清单。None 表示没有提供，() 表示明确给出空清单：是否允许为空由契约决定。合法空任务为 0 个 unit，无数据请求、无进度事件；非法空任务报 1102。

重复代码、时间点或重复对象范围会被拒绝；对象代码不能是空白、带首尾空格、__ALL__、含 * 或用逗号拼接的多代码字符串。日期格式、范围顺序和点是否在范围内也会校验。组件不静默修剪、去重或补默认对象。

完整契约规定全部源业务字段、输入、模式及分页规则；调用时不传字段子集。HTTP 或 SDK 调用方式由已登记的代码 mapping 决定，业务无需选择。契约不包含本地创建时间等非 Tushare 辅助字段，也不替代业务表的存储定义。

4. 六种模式与 unit

unit 是一次完整交付的范围，由所选模式和契约共同确定。它不等于一页，也不固定等于一天。下面是不含分类展开的基础数量；某个分类被契约定义为独立 unit 时，数量再乘以该分类的选中值数量。

模式（固定值）必须提供一个 unit 是什么交付顺序
SNAPSHOT = 1不传对象或时间一次该接口范围内的快照，共 1 个。契约规定的分类顺序。
BY_POINT = 2points一个给出的时间点；给 3 个日期就是 3 个。时间从早到晚。
BY_OBJECT = 3objects一个代码的完整本次下载范围。业务给出的代码顺序。
BY_OBJECT_POINT = 4objects 和 points一个代码 × 一个时间点；2 个代码 × 3 天为 6 个。日期从早到晚，同一天按代码输入顺序。
BY_OBJECT_RANGE = 5objects + time_range，或 object_ranges，二选一一个代码的整个给定范围；一个股票 3 天仍是 1 个。代码或对象范围的输入顺序。
BY_RANGE = 6仅 time_range整个给定范围；一个月也是 1 个，全部完成才交付。本 unit 内按契约时间字段排序。

组件具备六种模式，不表示每个数据集都支持六种。点模式可选 time_range 仅作边界检查；其余模式不能混填不适用字段。若希望每天交付一次，应使用支持的 BY_POINT，自行提供日期清单；不能把一个月的 BY_RANGE 理解成每天交付。

from orchestrator.tushare_download import (
    DownloadMode, DownloadTask, ObjectTimeRange, TimeRange,
)


def task_examples(contract_name):
    # 用来说明输入形式；同一真实契约未必同时支持这些模式。
    dates = ("2026-10-19", "2026-10-20")
    codes = ("000001.SZ", "600000.SH")
    span = TimeRange("2026-10-19", "2026-10-20")
    return {
        "snapshot": DownloadTask(contract_name, DownloadMode.SNAPSHOT),
        "point": DownloadTask(contract_name, DownloadMode.BY_POINT,
                              points=dates),
        "object": DownloadTask(contract_name, DownloadMode.BY_OBJECT,
                               objects=codes),
        "object_point": DownloadTask(
            contract_name, DownloadMode.BY_OBJECT_POINT,
            objects=codes, points=dates,
        ),
        "object_range": DownloadTask(
            contract_name, DownloadMode.BY_OBJECT_RANGE,
            objects=codes, time_range=span,
        ),
        "range": DownloadTask(contract_name, DownloadMode.BY_RANGE,
                              time_range=span),
        "separate_ranges": DownloadTask(
            contract_name, DownloadMode.BY_OBJECT_RANGE,
            object_ranges=(
                ObjectTimeRange("000001.SZ", span),
                ObjectTimeRange(
                    "600000.SH", TimeRange("2026-10-20", "2026-10-20"),
                ),
            ),
        ),
    }

分类与分页不会改变字段契约

例如同一接口按板块类型区分概念、地域、行业，字段契约仍是同一份。契约可规定各分类独立交付，也可规定同一个 unit 内分组请求后完整交付；业务不能自行混合不同字段契约。每行的 request_input_index 可以追到本次哪组逻辑请求，组件不往源记录中补一个自造的分类字段。

分页大小、offset 递增、结束依据和是否内部拆小日期范围由契约定义。采用时间拆分的接口在不能再拆、首批恰好满页时继续正常分页；业务仍只收到原来的完整 unit。没有可靠源依据时，不以“相邻页内容一样”自行判错。上述是组件行为，不代表 namechange 专项真实验证已完成。

5. 返回数据怎么读取

每次迭代返回一个不可变 UnitResult，数据在内存中，不返回文件路径或 DataFrame。单个 unit 的所有分页、分类分组及内部日期拆分完成并排序后才交付一次；失败或取消时不交付半个 unit。

UnitResult 字段读取方式与含义
unitDownloadUnit：本批的对象、时间、模式、契约版本及 unit_id。
recordstuple[SourceRecord, ...]：完整记录。空元组也可能是合法成功结果。
observed_field_sets实际见到的字段名元组集合，按首次出现顺序保存；不是“契约字段已全部满足”的认证。
request_inputs各组逻辑源请求参数，以不可变键值对保存；不含分页位置，不等于每页实际参数。内部拆分的具体时间见进度中的 page_position。
statistics本 unit 请求、重试、接收及排序统计，见下表。
orderingtime_field、rule_version、comparable_count、uncomparable_count：排序依据和可比较 / 不可比较记录数。
terminationstrategy（1 单次、2 offset、3 时间拆分后 offset）、all_scopes_complete、accepted_scope_count、last_position。描述按契约完成请求，不证明业务数据完整或已经入库。
def inspect_unit(result):
    print(result.unit.ordinal, result.unit.unit_id,
          result.unit.object_code, result.unit.point,
          result.unit.time_range, result.statistics.row_count)
    for record in result.records:
        row = record.as_mapping()  # 单行新字典；缺少的源字段不会被补出来
        request_params = dict(result.request_inputs[record.request_input_index])
        # 这里可接业务校验、归一化及写入；本例只展示读取。
        print(row, request_params)

SourceRecord 固定有 fields、values、request_input_index 三个字段。前两个元组一一对应；as_mapping() 返回一个新字典。源数字按组件类型约定用 int / Decimal 等表达，业务需要 DataFrame 或 JSON 时自行按目标类型转换；不要默认 Decimal 能直接被普通 JSON 序列化。

组件只检查能否正确解析源响应，例如字段数和值数是否对应。源成功返回但缺少业务需要的列、业务值为 NULL、日期文本不合法等，由业务按完整契约判断；下载器不补列、补值、删行或去重，也不做业务日期归一化。

契约声明时间排序字段时，记录按时间从早到晚稳定排序；相同时间保持原先接收次序。缺少时间或无法比较的记录保留原内容，放在本 unit 末尾。未声明时间排序字段时保留接收顺序。跨对象的交付顺序仍服从模式，例如按股票范围下载时，先交第一只股票的完整范围，再交第二只；不把所有股票重新合成一张总表排序。

展开：DownloadUnit 与 statistics 的完整字段
字段组字段及含义
DownloadUnit 身份ordinal 从 1 起；unit_id 标识本次范围和契约内容；contract_name、contract_version、content_digest 标识契约。unit_id 不是保存成功证明或内置续跑记录。
DownloadUnit 范围mode、object_code、point、time_range；不适用值为 None。filters 为键值对元组，enum_values 为分类名及取值元组。
statistics 请求request_count 含失败尝试；retry_count 为实际发出的重试次数；successful_response_count 为成功解析的响应数，含随后不采纳的父范围探测页。
statistics 数据accepted_page_count、empty_page_count、row_count、split_count：采纳页数、其中空页数、最终行数、拆分次数。
statistics 时间elapsed_seconds、waiting_seconds、receive_seconds、sort_seconds，单位秒。unit 时间不含后续业务保存及 unit 完成回调；整个会话的时间范围见摘要说明。
逐个处理并释放结果。组件交付后不保留结果数据的额外引用，但业务保存的引用仍占内存；不要用 list(session) 把全历史长期积在内存，也不要让进度回调缓存所有完整结果。已返回的结果在会话关闭后仍可使用。

6. 进度回调契约

通过 on_progress=callback 注册可选同步函数，格式为 callback(progress: DownloadProgress) -> None。没有注册表示业务不接收通知。组件不支持 async 回调，不创建通知线程，也没有每秒心跳、开始、失败或结束事件；结束情况由正常返回、异常及最终摘要判断。

from orchestrator.tushare_download import DownloadProgressEvent


def on_progress(progress):
    if progress.event == DownloadProgressEvent.RETRY_SCHEDULED:
        print("准备重试", progress.page_position,
              progress.next_attempt_number,
              progress.retry_delay_seconds, int(progress.error_code))
    elif progress.event == DownloadProgressEvent.PAGE_COMPLETED:
        print("收到一页", progress.page_position,
              progress.page_row_count, progress.page_accepted)
    else:  # UNIT_COMPLETED；这里只接收摘要，不处理或保存数据
        print("完整批次已下载", progress.completed_units,
              progress.total_units, progress.progress_percent,
              progress.unit_row_count, progress.completed_row_count)
事件（固定值）通知时点专属字段
PAGE_COMPLETED = 1成功取得并处理一页后。时间拆分前的父范围探测页也会通知。page_position、attempt_number、page_row_count、page_accepted 有值；最后一项为 false 时该页没有计入最终数据。
RETRY_SCHEDULED = 2一次失败后，决定重试、等待前。不是“重试已发出”的证明。page_position、attempt_number、next_attempt_number、retry_delay_seconds、error_code 有值。
UNIT_COMPLETED = 3整个 unit 已下载并完成排序，返回给业务前通知一次，合法空结果也通知。页位置、页行数、页采纳、尝试次数、下次重试信息及错误码均为 None。

内部时间拆分没有单独事件；分页与重试只传摘要，不传数据。失败的尝试没有 PAGE_COMPLETED。回调收到的对象不可变，每份摘要不超过 4 KiB，不包含源记录、token 或完整请求清单。

如何理解“完成”和“已交付”

假设总共两个日期 unit：第一个下载完成的回调里，completed_units=1、delivered_units=0、进度 50%；回调返回后，循环才收到第一个结果。最后一个完成回调里是 completed_units=2、delivered_units=1、进度 100%。正常退出 with 后，最终摘要才是 delivered_units=2。进度 100% 不代表业务已保存，更不代表会话已经关闭。

回调必须快速返回。普通 Exception 只记入 progress_error_count 和 last_progress_error_type，不中断下载、不重试源、不补发回调；因此不能把必须成功的保存或校验放进回调。DownloadCancelled 是明确的取消信号，不会按普通通知错误吞掉；KeyboardInterrupt / SystemExit 等中断也继续向上传播。

7. 线程、进程与通知

下载器是同步工具。一次调用从创建对象、进入会话、请求、迭代、执行回调到关闭，都必须在同一进程的同一个调用线程中完成；同一实例不供多个线程或进程并用。组件不负责创建线程、进程、通信连接或队列。

业务运行位置怎样调用及通知
需要持续刷新页面的业务业务必须创建下载线程，并在该线程内创建和使用下载器。回调也在下载线程执行；业务用自己的安全队列等方式通知负责页面或状态的线程。
DG 等已在独立任务执行进程中运行的业务业务执行代码可在该进程的执行线程直接同步调用，回调也在这里执行。不要理解成回调自动跳到 DG 页面或服务进程。
接收状态的业务代码在另一个进程下载进程内的业务注册同一种标准回调，由这个回调通过业务已有的进程间通信或状态接口转发摘要。下载器不直接向其他进程调用 Python 函数。

业务另开线程的例子

下面复用第 1 节的 download_by_date。线程、队列和取消标志均是业务创建的；save_unit 也在下载线程里执行，须在该线程中使用适合的数据库连接等资源，不能直接拿页面线程的连接对象来用。

from queue import Full, Queue
from threading import Event, Thread

from orchestrator.tushare_download import DownloadCancelled


def start_download(contract_name, dates, save_unit):
    cancel_event = Event()
    notifications = Queue(maxsize=128)
    finished = Queue(maxsize=1)

    def notify(progress):
        try:
            notifications.put_nowait(progress)
        except Full:
            pass  # 本例业务选择丢弃拥堵时的进度显示，不能阻塞下载

    def worker():
        try:
            summary = download_by_date(
                contract_name, dates, save_unit,
                on_progress=notify, is_cancelled=cancel_event.is_set,
            )
            outcome = ("completed", summary)
        except DownloadCancelled as error:
            outcome = ("cancelled", error)
        except Exception as error:
            outcome = ("failed", error)
        finished.put_nowait(outcome)  # 独立队列保证普通完成/失败消息不被进度挤掉

    thread = Thread(target=worker, daemon=False)
    thread.start()
    return thread, cancel_event, notifications, finished

业务发起方定期用自己的页面机制读取 notifications 和 finished，需要取消时调用 cancel_event.set()。这是同进程线程通信例子，不是进程间通信实现；不得直接用于跨进程转发异常对象。页面线程不要立即 join() 等待下载，否则仍会阻塞刷新；业务退出时负责取消并等待线程结束。此示例不吞掉进程级中断，也不是通用线程管理库。

回调或其他线程不能重入 next(session)、close()、重新进入当前会话或启动同一下载器的第二个活动会话。需要其他线程或进程提出取消时，使用业务自己的安全标志，通过 DownloadControl 读取；不要从外部线程直接关闭活动会话，也不要把 poll_progress() 当作线程通信接口。

8. 取消、提前停止与关闭

DownloadControl(is_cancelled=checker) 可选传入无参数同步函数，每次返回严格的 bool。返回 True 表示取消；返回 None、0/1 等非 bool 值会报 1102。检查函数自身抛错会向上传播，不能按进度显示失败忽略。

发生在哪一步行为
请求分页、等待重试、排序等尚未完成 unit 时取消停止后续请求；丢弃本 unit 未完成数据；抛出 DownloadCancelled（1401），关闭后状态 CANCELLED。
在 PAGE_COMPLETED 或 RETRY_SCHEDULED 回调中取消同上；不再领取下一页或发出原计划的重试。
在 UNIT_COMPLETED 回调中调用 session.cancel() 或抛出 DownloadCancelled当前完整 unit 仍交付一次，然后停止后续 unit。若还有 unit，继续迭代会抛取消；直接退出会话也记录 CANCELLED。若当前已是最后一个 unit，按正常下载完成 SUCCEEDED 结束。
业务已经收到结果后，自己的处理代码抛出 DownloadCancelled原样向上传播，状态 CANCELLED；不适用“最后一个完成回调按成功结束”的特殊规则。
业务用 break 提前退出结果循环with 关闭资源。未交付全部且没有取消意图时为 STOPPED；如果已经交付全部则为 SUCCEEDED。
业务校验或保存抛普通异常保留原异常，关闭资源，状态 FAILED；不重试业务保存，也不再请求下一个 unit。
关闭资源又发生错误继续尝试关闭其余资源。已有原异常则保留它，清理问题记入摘要；没有原异常时抛 1304。

取消为什么可能需要等待

例如下载线程已向源发出请求，正在等返回；另一个业务线程设置取消标志时，当前网络调用可能还没返回，下载器要等它返回、读到可检查的位置或超时后才能响应。HTTP 读取和重试等待中有检查点，但 DNS、特殊 SDK 内部阻塞、慢回调、业务保存都不是下载器能随时强制打断的步骤。45 秒也不是所有这些情况的强制终止上限。

组件不创建额外下载子进程，不能通过杀一个内部进程来取消。业务如结束整个运行进程，下载器随进程结束；这不等于执行了正常关闭，也不保证正在进行的业务保存已完成。

失败或重启后怎样继续

运行中的临时源错误只重试当前页；进程重启后，未完成的 unit 从第一页开始。组件不持久化分页位置或业务提交状态。业务根据自己的保存记录重新构造未完成范围，并保证写入幂等。已经保存的 unit 保留；收到完成回调或 unit_id 相同，都不能作为该 unit 已正式保存的依据。

9. 最终结果与保存状态

正常退出、失败或取消后读取 session.summary，得到不可变 DownloadSummary。如果在创建下载器时就失败，还没有会话可读；如果进入会话失败，已有会话仍有失败摘要。实际抛出异常应一起保留，不能只看百分比。

状态（固定值）含义
CREATED=1 / READY=2 / RUNNING=3已创建但未进入 / 已准备好或交付后等待下一次迭代 / 正在下载当前 unit。
SUCCEEDED=4全部计划 unit 已交付，会话正常结束；不是数据库提交证明。合法 0 unit 任务也可成功。
STOPPED=5业务主动提前结束，且尚未全部交付；没有源失败或取消意图。
CANCELLED=6已按取消结束，见第 8 节完成回调的边界。
FAILED=7源错误、输入错误、业务处理异常或关闭失败等导致结束，结合异常和 failure 判断。
DownloadSummary 全部字段含义
task_id / status本会话标识 / DownloadStatus。
total_unitsint | None；完成准备后才有总数，早期失败可为 None。
completed_units / delivered_units已下载并排序完成数 / 已返回给业务的数量。
completed_row_count / row_count已完成 unit 累计行数 / 已交付累计行数；均不是业务已入库行数。
request_count / retry_count / successful_response_count累计实际请求、实际重试、成功解析响应数。
download_completebool；全部 unit 已交付。最后一个结果已交付后业务保存失败，可能为 True，同时 status 为 FAILED。
elapsed_seconds从创建会话到当前或关闭的秒数，包含业务在两次迭代之间的处理时间和回调时间，不是纯网络时间。
failure / cleanup_errorsErrorDetails | None / 关闭问题元组。只有取消标志、未抛异常就退出时，failure 也可能为 None，需结合 status。
progress_error_count / last_progress_error_type通知构造或回调的普通错误累计数 / 最后错误类型，可为 None；不包含源响应内容。
callback_elapsed_seconds所有回调执行累计秒数；过大时先检查业务回调是否阻塞。

poll_progress() 保留的是最后一份事件发生时的摘要：最后一个 UNIT_COMPLETED 通知的 delivered_units 仍未包含当前 unit，关闭不会补发更新事件。最终状态与交付数以 session.summary 为准。业务另行记录“校验通过、保存成功、提交完成”等自己的事实。

10. 错误码与异常处理

组件错误使用固定整数枚举 DownloadErrorCode，抛出 DownloadError。DownloadCancelled 是其子类，所以应先捕获取消，再捕获下载错误，完整处理例子见第 1 节。业务自己的保存、校验和取消检查函数等抛出的原异常不保证属于 DownloadError，应由业务外层按自己的规则处理。

码 / 枚举名问题发生在哪里自动重试业务怎样处理
1001 CONFIGURATION创建或校验连接配置失败，例如 token 缺失、URL 空白或不合法。否检查实际运行进程的启动配置，修正后创建新下载器；不要把 token 写入排障日志。
1101 CONTRACT完整契约、固定调用方式、支持模式或适配器定义不满足要求。否核对契约名及数据集登记状态；由组件 / 数据集维护方处理，不能靠业务补 fields 或分页参数绕过。
1102 INPUT对象、时间、过滤、分类、回调签名或会话调用方式不合法。否按模式检查参数及 None / 空清单，检查重复项、格式和重入调用。
1201 PERMISSION_OR_PARAMETER源明确拒绝权限、认证、积分或参数等；含已识别的相应 HTTP / 源错误。否核对 token 权限及对应源接口参数；组件收到的积分不足不是本地额度管理。
1202 RATE_LIMIT源明确限频，例如 HTTP 429。最多 3 次业务检查同 token 的总请求频率和并发调度；重试耗尽后保留失败范围，不无限重跑。
1203 TRANSIENT_SOURCE已识别的临时网络、连接、读取或源端服务故障。最多 3 次查看失败页、尝试次数及网络 / 源端状态；业务恢复从未保存 unit 开始。
1204 NO_VALID_RESPONSE没有能确认有效的响应，例如没有任何有效字段。最多 3 次与“有合法字段且 0 行”分开；核对源端或适配器，不能直接当作空数据成功。
1205 SOURCE_PROTOCOL响应无法按协议正确解析，例如 JSON 不合法、字段和值数量不符、可靠分页依据矛盾。否保留定位摘要，交组件 / 数据集维护方核对响应格式及契约；业务缺列校验不属于此码。
1302 CAPACITY任务输入、请求、响应或 unit 工作空间超过上限，或运行时内存不足。否确认在哪一步超限。若业务范围允许，可按契约选择较小任务分次下载；不能删字段、漏日期、返回半个 unit。技术上限调整由组件维护方评估。
1304 CLEANUP没有其他原异常时，组件关闭自身资源失败。否查看 cleanup_errors；已经交付的数据不能当作全部未发生，业务仍按提交记录核对。
1401 CANCELLED业务取消，异常类型为 DownloadCancelled。否呈现取消而非源故障；保留已提交 unit，下次从业务确认未完成范围重来。
1501 UNCLASSIFIED_SOURCE尚未识别的源错误，不能可靠归为权限、限频或临时故障。否带定位信息交维护方分析；不凭错误文本猜测后无限重试或当空结果。

自动重试只针对 1202、1203、1204 的同一页，且不能带有关闭失败。默认总尝试最多 4 次；第 4 次仍失败，抛出原对应类别并设置 retry_exhausted=True。业务不要无差别再套一层无限重试，也不要因显示进度失败重新下载或写入。

排障时保留哪些信息

error.code 为错误枚举；error.details 为 ErrorDetails，字段也可通过异常的同名属性读取。进入会话后失败时优先读取 session.summary.failure，它会合并当时的执行位置；单独的异常详情并不保证带齐所有位置字段，尤其创建 / 准备阶段。

ErrorDetails 全部字段用途

组件错误和标准进度不携带 token、完整响应体或任意源错误文本。排障通常只需要上述位置、计数、状态及安全类型信息。业务自有异常和自有日志仍由业务管理，不能把环境变量、连接配置对象或含 token 的请求内容整体打印。

11. 常见问题排查

看到什么先查什么
刚创建下载器就失败看是否 1001；检查当前运行进程是否真正拿到了启动配置，不要只确认磁盘有一份 .env。
填了 daily 等接口名，进入 with 就 1101业务填写的是完整契约名还是 api_name？该契约及请求 mapping 是否已登记？当前交付尚无真实登记。
传了一个时间区间，迟迟没有完整结果BY_RANGE 是整个范围一个 unit，BY_OBJECT_RANGE 是每个对象整个范围一个 unit。需要逐日交付时选契约支持的点模式并提供日期清单。
有分页进度但累计完成行数不涨completed_row_count 只累计完整 unit；看 unit_row_count。父范围探测 page_accepted=false 的行不会计入最终数据。
100% 后业务保存失败100% 是下载并排序完成，不是提交成功；查看原业务异常及最终 summary，按业务保存记录恢复。
没有收到开始、失败或最终结束回调接口只有页完成、准备重试、unit 完成三类；业务在退出 with 或捕获异常后自行转发最终摘要。
回调抛错了，下载仍继续这是通知隔离约定。查 progress_error_count 和 last_progress_error_type；把必须成功的逻辑移回结果处理循环。
取消后没有立刻结束，或页面卡住检查当前网络 / SDK、回调、业务保存是否仍阻塞；确认页面业务确实另开线程，并且没有在页面线程等待 join。
返回 0 行有合法字段的空结果可以成功。业务核对过滤、交易日、发布状态及应有数据范围；组件不保证每一天都有数据。
返回记录缺少业务需要的字段对照完整契约由业务检查并报告；不能默认缺列补 NULL，也不要误认为组件应该为业务补齐。
内存持续增加或报 1302区分当前 unit 超限和业务持有历史结果：检查 list(session)、结果缓存、DataFrame / 字典副本，及时释放；2 GiB 不是业务进程总内存保障。
数据缺少能比较的时间，排在最后查看 ordering.uncomparable_count，原行未被删除或改值；由业务判断缺失 / 错误日期怎样处理。
重启后又下载了上一批，或重复保存组件不存提交记录；业务按已提交 unit 或业务幂等键决定剩余范围，不能用回调或 unit_id 代替持久化事实。
